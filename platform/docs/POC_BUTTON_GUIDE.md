# 경희대 PoC 버튼 사용 안내

2026년 10월 19일 현재 `http://127.0.0.1:18100/`의 화면과 처리 코드를 대조한 안내입니다. 최초 메뉴 점검은 저장된 기록 조회로 확인했고, 후속 연결 점검에서는 실제 로컬 앱을 배포하여 측정, 운영 판단, 승인된 복제본 변경과 재측정, Prometheus 판단 및 종료 버튼까지 확인했습니다. 새 AWS VM은 배포하지 않았습니다. [검증 범위](../../docs/validation.md)을 참고하세요.

## 먼저 알아둘 구분

- **판단:** 요구사항이나 관측값을 입력하여 추천, 배포 판단 또는 운영 변경안을 새로 만듭니다.
- **실제 실행:** 승인된 계획으로 앱을 시작하거나, 변경 구성을 적용하거나, 종료합니다.
- **조회:** 저장 결과 또는 실행 상태를 불러옵니다. 새로운 배포나 성능 실험을 수행하는 버튼과 구분합니다.
- **비교 실험:** LLM 또는 판단 정책을 같은 조건에서 비교합니다. 비교 실행이 실제 앱 구성을 바꾸지는 않습니다.
- **모의 실행:** 과거 VM 비교 경로에서 실행·관측의 형식을 시험합니다. 실제 VM 실행 증거가 아닙니다.

계획 승인과 실제 실행은 별도입니다. 운영 판단과 실제 복제본 변경도 별도입니다. Revision은 실행 구성의 버전이고, 복제본은 그 구성 안에 있는 실행 수 설정입니다. Revision 번호가 올라간다고 복제본이 항상 늘어나는 것은 아닙니다.

## 현재 확인한 상태

- 플랫폼 상태 API 정상.
- 현재 화면의 실험은 앱 `STOPPED`; 마지막 실제 복제본 0개.
- 로컬 실행 대상: BERT Tiny, 배치 1·길이 64 또는 배치 8·길이 128.
- 요구사항 분석용 Qwen 3.5·4B, Llama 3.2·3B 모두 사용 가능으로 조회됨.
- AWS 연결 및 상태 조회 설정은 있으나 **새 실행은 비활성**. 정리 대기 0건.

종료된 실험, 미완료된 선행 단계, 다른 과거 실행 조회, 처리 중인 요청에 따라 버튼이 숨겨지거나 비활성화됩니다. 앱이 이미 종료된 현재 화면에서 배포·측정·복제본 적용 버튼이 비활성인 것은 이 조건에 따른 것입니다.

## 1. 실험 개요와 공통 이동

- **전체 흐름 직접 실행:** 요구사항 화면으로 이동합니다. 누르는 것만으로 앱이 배포되지는 않습니다.
- **이번 실험 결과 보기:** 현재 Flow의 단계별 결과를 요약해서 보여줍니다. 기존 AWS 실행과 정책 비교는 하단 참고 영역에서 펼칩니다.
- **실험 방법의 단계 링크:** 해당 작업 화면으로 이동합니다.
- **실험 경로·단계 설명 / 이 단계 설명 / 원문·상세 펼치기:** 설명이나 저장된 원문을 펼칩니다. 새 실험을 돌리지 않습니다.
- **새 실험:** 현재 화면의 선택을 초기화하고 새 요구사항 입력을 시작합니다. 기존 실험 파일을 삭제하거나 실행 중인 앱을 강제로 종료하는 버튼이 아닙니다. 실행 중에는 사용이 제한됩니다.
- **이 실험의 실행 기록 보기 / 다음 단계로 이동:** 같은 Flow의 다른 화면으로 이동합니다.
- **메뉴 열기·닫기:** 좁은 화면의 탐색 메뉴를 조작합니다.

## 2. 요구사항

### 조건 입력

실험 방식에서 로컬 실제 실행, 과거 VM 비교·모의 실행, AWS VM 실행을 고릅니다. 직접 조건을 지정하거나 자연어 요청을 선택한 LLM으로 분석합니다. 모델·배치·입력 길이, CPU·메모리·GPU, 복제본 범위, 지연·처리량 조건을 지정할 수 있으며 경로에 따라 표시 항목이 달라집니다.

직접 조건 지정 시 로컬 실행은 CPU만 선택할 수 있습니다. AWS GPU는 현재 최대 복제본 1개로 표시하고 고정하며, CPU 경로는 최대 2개까지 지정할 수 있습니다. 모델이나 실행 조건을 바꿔도 입력한 성능 목표는 유지됩니다. 자원 세부 조건과 LLM 비교 링크는 추가 설정에서 확인합니다.

- **분석에 사용할 LLM 선택:** 다음 자연어 분석에 쓸 Qwen 또는 Llama를 고릅니다. 선택만으로 비교 실험을 돌리지는 않습니다.
- **요구사항 분석하고 인프라 추천받기:** 새 Flow를 만들고 요구사항을 Profile로 정리한 뒤 후보를 조회합니다. 자연어 입력이면 선택한 실제 로컬 LLM을 호출합니다. 구조화 입력은 지정한 조건을 변환합니다. 이어서 추천 화면으로 이동합니다. 실제 앱 실행은 하지 않습니다.
- **대용량 조건 적용:** 과거 VM 비교에서 직접 조건을 지정할 때 추가 설정의 연구 시험 조건에 표시됩니다. CPU 256코어, 메모리 1024GiB의 큰 요구조건으로 후보가 없는 경우를 시험합니다. 하드웨어를 늘리거나 주문하는 기능이 아닙니다.
- **LLM 비교 결과 보기:** 실험 결과의 추가 비교 영역에서 LLM 비교를 펼칩니다.

## 3. 자원 추천·선택

- **후보 선택 / 전체 사양의 선택:** 선택할 수 있는 후보를 현재 Flow에 기록합니다. 요구사항을 충족하지 않는 후보는 선택할 수 없습니다. 추천 이유와 제외 이유도 확인할 수 있습니다.
- **같은 요구사항으로 자원 다시 조회:** 계획을 만들기 전 로컬 자원의 최신 가용량을 조회합니다. 기존 Flow와 분석된 요구사항을 유지하며 LLM을 다시 호출하지 않습니다. 후보가 없으면 필요한 양과 현재 가용량을 표시합니다. 계획이나 실제 실행이 생긴 뒤에는 이 버튼으로 선택을 바꿀 수 없습니다.
- **이 인프라로 계획 만들기:** 선택한 후보와 요구사항으로 배포 Agent를 호출하고 Guard 검증을 수행하여 계획을 저장합니다. 배포 계획 화면으로 이동합니다. 자원 선택과 계획 생성은 실제 VM 생성과 구분됩니다.
- **선택한 자원 상세 사양·실험 조건 / 전체 실험 사양 보기:** 사양과 기존 측정 조건을 펼칩니다.

로컬 경로에는 실제 PC 자원이 표시됩니다. 과거 VM 비교 경로는 저장된 CPU/GPU VM 측정 후보를 비교합니다. 로컬 PC에서 실행한 결과를 AWS VM 측정 결과로 취급하지 않습니다.

## 4. 배포 계획

- **배포 계획 만들기:** 추천 화면의 계획 만들기와 같은 계획 API를 호출합니다. 배포 가능 여부, Guard 결과, 최초 복제본 설정과 계획 명세를 만듭니다. 아직 계획이 없을 때 이 화면에서 이어서 시작할 수 있게 둔 진입점입니다.
- **배포 판단 Agent 적용:** 이 Flow의 배포 판단에 사용할 등록 Agent를 저장합니다. 이미 계획이 있고 판단 Agent가 바뀌면 기존 계획이 무효화되어 다시 판단해야 할 수 있습니다. 실제 배포를 수행하는 버튼은 아닙니다. 실행이 생긴 Flow에서는 변경을 제한합니다.
- **배포 구성·판단 근거 / 계획 명세 원문:** 승인된 최초 설정과 원문을 확인합니다.
- **배포 실행으로 이동:** 같은 계획으로 실행 화면을 엽니다.
- **Agent 등록·호출 검증:** 별도의 Agent 설정 화면으로 이동합니다.

## 5. 배포 실행

### 로컬 앱 실행

- **이 PC에 어플리케이션 배포:** 앱을 실행 모듈에 등록하고 승인된 계획의 전달 명세를 준비한 뒤 실제 프로세스를 시작합니다. 승인된 로컬 계획이 있어야 합니다.

실제 실행이 `RUNNING`으로 확인되면 같은 Flow의 모니터링 화면으로 이동합니다. 측정과 운영 변경은 각각의 버튼으로 요청합니다.
- **어플리케이션 등록 명세만 준비:** 앱 등록과 실행 요청 명세 준비까지만 수행하여 `PREPARED` 상태로 둡니다. 아직 모델 프로세스는 시작하지 않습니다.
- **상태·로그 조회:** 기존 AppDeploy 요청과 실제 실행 상태를 다시 확인합니다. 새 앱을 배포하는 버튼이 아닙니다.
- **어플리케이션 중지:** 현재 앱의 실행 프로세스를 종료합니다. 로컬에서는 해당 앱 그룹을 멈춥니다. AWS 경로의 **어플리케이션만 중지**는 VM 자체의 종료·정리와 별도입니다.
- **새 어플리케이션 배포 시작:** 종료·실패한 실험에서 새 조건 입력을 시작합니다. 누르는 즉시 재배포하지 않습니다.

### 과거 VM 비교의 모의 경로

- **Mock 실행 기록:** 승인된 계획에 모의 실행 기록을 붙여 예시 관측과 운영 판단을 이어 볼 수 있게 합니다. 실제 AWS VM이나 모델을 실행하지 않습니다.
- **이 PC에 실제 어플리케이션 배포 시작:** 로컬 실제 실행 경로의 새 요구사항 입력으로 전환합니다. 누르는 즉시 모델을 배포하는 버튼은 아닙니다.

### AWS 단일 VM 실행

현재 새 실행 설정은 꺼져 있습니다. 다음은 구현된 단계의 의미이며, 켜져 있는 로컬 버튼과 구분해야 합니다.

1. **현재 비용 검토:** 선택한 계획과 최대 실행 시간으로 현재 비용·의도를 검토합니다.
2. **이번 실행 승인:** 비용 검토 확인을 바탕으로 해당 실행을 승인합니다. 아직 VM을 생성하지 않습니다.
3. **준비 검사:** 승인 유효기간과 실행·정리 연결의 준비 상태를 검사합니다.
4. **VM·어플리케이션 실행:** 조건을 통과한 계획으로 실제 VM 생성과 앱 준비·실행을 요청합니다.
5. **VM 상태 조회:** 기존 클라우드 실행 요청의 진행과 실제 자원 상태를 확인합니다.
6. **어플리케이션·VM 종료 확인:** 앱과 소유 VM, 연결 자원의 종료·정리를 요청하고 확인합니다.

### 추가 실행 시험: CPU VM 수 변경

이 영역은 프로세스 수 변경과 별도인 CPU VM 두 대의 시험입니다. 각각 계획과 비용 검토를 준비한 두 CPU Flow가 필요합니다.

- **두 실행의 비용 함께 검토:** 두 Flow를 묶어 VM 두 대의 실행 의도와 공통 비용을 검토합니다.
- **두 VM 실행 승인:** 검토한 두 실행을 승인합니다.
- **첫 VM 실행:** 첫 번째 VM과 앱 실행을 요청합니다.
- **VM 1 → 2대 확장 요청:** 두 번째 VM을 추가합니다.
- **VM 2 → 1대 축소 요청:** 두 번째 VM을 종료하여 첫 VM을 남깁니다.
- **전체 종료·정리:** 두 실행을 종료하고 연결 자원을 정리합니다.
- **AWS 상태 조회 / 저장된 실험 선택:** 선택한 시험과 마지막 AWS 조회를 확인합니다.

이 버튼들은 명시적으로 요청하는 VM 수 변경입니다. 운영 정책이 VM 수를 자동으로 증감하는 기능으로 설명하면 안 됩니다.

## 6. 모니터링·운영 판단

- **운영 판단 Agent 적용:** 이후 운영 판단에 사용할 등록 Agent를 해당 Flow에 저장합니다. 선택만으로 복제본을 바꾸지 않습니다.
- **표시할 실행 선택 / 저장된 실측 불러오기:** 현재 Flow 또는 과거 실행의 실측·판단 기록을 조회합니다. 새 추론을 돌리는 버튼이 아닙니다. 다른 과거 실행을 조회하는 동안 현재 Flow의 측정·변경 적용은 제한됩니다.
- **현재 실행으로 돌아가기:** 과거 실행 조회를 끝내고 현재 작업 중인 Flow의 모니터링으로 돌아갑니다. 과거 실행의 판단을 현재 앱에 적용하지 않습니다.
- **현재 어플리케이션 실측하고 운영 판단 확인:** 실행 중인 앱에 실제 BERT Tiny 추론 요청 64회를 보내 지연, 처리량, 자원 사용을 측정합니다. 그 관측으로 유지·확장·축소를 판단하고 Guard를 거쳐 결과를 저장합니다. 필요한 운영 변경 구성이 Revision으로 기록될 수 있습니다. 실제 복제본 변경은 별도 적용 단계입니다.
- **현재 수집 조회:** Prometheus가 자동 수집한 현재 관측 구간을 조회합니다. 이 버튼이 추론 부하를 생성하지는 않습니다.
- **수집값으로 운영 판단:** 유효하고 신선한 Prometheus 관측을 운영 Agent와 Guard에 전달합니다. 측정 버튼과 관측 출처가 다르며, 마찬가지로 변경 판단을 수행합니다.
- **승인된 변경 적용:** 검증된 미적용 Revision의 목표 복제본을 AppDeploy에 적용합니다. 이때 실제 모델 프로세스 수가 바뀝니다. 현재 UI의 이 변경은 같은 자원의 앱 복제본 1~2개에 관한 것이며, 별도의 VM 수 변경 시험과 구분합니다.

변경을 적용하면 기존 측정값은 **변경 전 실측**으로 표시합니다. 새 복제본 구성에서 다시 측정한 뒤 다음 운영 판단을 확인해야 합니다. 실행 기록에는 실제 배포, 적용한 Revision과 복제본 수, 종료 확인도 남습니다.
- **운영 판단 확인:** 과거 VM 비교의 데모 관측 영역에서 CPU·지연·처리량 예시를 입력하여 판단을 시험합니다. 입력은 `demo_input`으로 구분되며 실측으로 취급하지 않습니다.
- **기존 피드백 결과 조회:** 응답이 불명확한 기존 판단 요청의 결과를 확인합니다. 새 판단을 중복 요청하는 버튼과 구분합니다.
- **부하별 운영 판단 기록 / 실제 추론 입력·결과 보기 / 실측 상세:** 같은 Flow의 관측·판단과 실제 연산 응답을 펼쳐 확인합니다.

고정된 작은 측정에서 SLO가 충족되면 KEEP이 나올 수 있습니다. 같은 측정 버튼을 반복해서 누른다고 반드시 확장이 발생하는 것은 아닙니다. 실제 확장 동작은 해당 부하와 SLO 조건에서 승인된 확장안이 나온 뒤 별도 적용으로 확인합니다.

## 7. 실험 결과

현재 Flow의 다섯 단계 결과를 먼저 보여줍니다. 현재 모니터링에서 선택한 다른 과거 Flow나 기존 연구 보고서를 이번 실험의 결과로 사용하지 않습니다. 전체 검증 통과를 일괄 표시하는 화면이 아닙니다.

- **현재 실험 결과 새로고침:** 저장된 이번 Flow를 다시 읽습니다. 새 배포나 추론을 요청하지 않습니다.
- **단계별 상세 보기:** 같은 실험의 요구사항, 자원 선택, 계획, 실행 또는 모니터링으로 돌아갑니다. 모니터링 상세를 열면 과거 조회 선택을 해제하고 이번 Flow를 보여줍니다.
- **이 실험의 전체 실행 기록:** 이번 Flow의 요청, 응답과 실제 변경 이력을 확인합니다.
- **기존 실험 자료와 추가 비교:** 과거 AWS 시험, 로컬 성능 비교와 추가 비교 기능을 펼칩니다. 처음에는 접혀 있습니다.

### 저장된 실행 증거

- **기록 다시 불러오기:** 저장된 CPU VM 배포, GPU CUDA 추론, CPU VM 수 변경, 로컬 운영 정책 평가를 읽습니다. 새로운 VM이나 성능 실험을 시작하지 않습니다.
- **실측값·관측 구간 / 원본 / 개별 실험 펼치기:** 해당 기록의 측정값·범위·출처를 봅니다.
- **배포 계획 / 배포 실행 / 모니터링 / 실행 기록 링크:** 그 증거에 해당하는 Flow를 엽니다. 현재 입력의 새 실행으로 바꾸어 보여주는 링크가 아닙니다.

### 요구사항 분석 LLM 비교

- **두 모델 실제 비교:** Qwen과 Llama에 고정된 3가지 요구사항을 각각 넣어 새 비교 실행을 시작합니다. 조건 추출 일치, JSON·Profile 통과, 사례 전체 일치와 전체 호출 시간을 비교합니다. 모델을 학습시키거나 앱을 배포하는 버튼은 아닙니다.
- **저장된 비교 불러오기 / LLM 비교 기록 선택:** 이전 비교 실험을 조회합니다.
- **이 모델 선택:** 다음 자연어 요구사항 분석에서 사용할 LLM을 선택합니다. 현재 입력과 이전 분석이 달라지면 재분석이 필요합니다.

### 배포 판단과 학습 정책 비교

- **규칙·Qwen·검증 비교 탭:** 같은 요구사항·선택 자원에서 규칙, Qwen 제안과 Guard 검증 결과를 비교합니다.
- **판단 방식 비교:** 현재 Flow를 입력으로 새 판단 비교를 실행합니다. 실제 앱 배포와 별도인 비교 기록입니다.
- **기존 결과 조회:** 이미 요청한 판단 비교의 결과를 조회합니다.
- **기존 연구 정책 비교 탭 / 기존 연구 정책 비교·유지·확장·축소 펼치기:** 배포 후보 선택 또는 운영 복제본 선택의 기존 연구 사례를 엽니다.
- **정책 선택 비교:** 선택한 기존 실측 사례로 학습 정책의 선택과 측정 보상 기준 선택을 비교합니다. 현재 앱에서 새 성능 데이터를 측정하거나 실제 구성을 변경하는 버튼이 아닙니다.
- **이 단계 사례 모두 비교:** 해당 단계의 기존 사례를 순서대로 비교하고 현재 Flow에 저장합니다. 새 학습을 수행하는 버튼이 아닙니다.
- **명세 변경 비교 탭 / 변경 전·후 명세 선택:** 저장된 Revision 사이에서 어떤 설정이 바뀌었는지 확인합니다. 선택만으로 과거 구성을 실행하거나 롤백하지 않습니다.

## 8. Agent 설정

실험 결과와 별도의 개발용 설정 화면입니다. 배포와 운영 역할별 Agent 선택은 해당 판단 화면에 유지합니다.

- **Agent 목록 조회:** 등록 정보와 배포·운영 역할별 사용 가능 목록을 읽습니다.
- **Agent 등록:** 지정된 로컬 HTTP 검증 Agent를 이름·버전으로 등록합니다. 임의의 다른 기관 서비스나 새 AI 모델을 자동 구축하는 기능은 아닙니다. 등록 후 사용할 역할의 화면에서 선택·적용해야 합니다.

## 9. 실행 기록

- **이벤트 펼치기:** 분석·자원 선택·판단·배포·측정·변경·종료의 시간순 기록과 원문을 확인합니다.
- **개별 삭제 / 전체 삭제:** 화면에 표시할 이벤트를 숨기는 복구 가능한 기록 변경입니다. VM이나 앱을 종료하지 않습니다.
- **삭제 기록 복원:** 숨긴 이벤트를 다시 표시합니다.
- **실험 식별정보·원본 연결:** Flow ID, 선택 자원·버전과 연결된 원문을 확인합니다.

## 워크숍에서 먼저 보여줄 흐름

**새 실험 → 요구사항 분석·추천 → 자원 선택·계획 만들기 → 승인 확인 → 실제 배포 → 실측·운영 판단 → 승인된 변경 적용 → 앱 중지 → 실행 기록 확인**

LLM·규칙·학습 정책의 비교는 이 기본 실행 흐름을 설명한 뒤 실험 결과의 접힌 추가 비교 영역에서 별도로 보여주면 각 버튼의 역할을 이해하기 쉽습니다. 기존 AWS 성공 기록 조회와 현장에서 새 AWS 실행을 하는 장면도 구분합니다.

## 구현 근거

- `platform/index.html`: 메뉴·버튼·펼침 영역.

- `platform/llm-comparison-ui.mjs`, `platform/validation-ui.mjs`, `platform/server/workflow-routes.mjs`: 새 비교와 저장 결과 조회의 구분.
