SCENARIO COMMUNICATION MAP

          
47개 검토 사례를 왜 준비했는가

        

        
47개 catalog는 “모두 성공시키는 예제”가 아니라, 어느 단계에서 왜 멈춰야 하는지 합의하기 위한 정적 계약 목록입니다. 이 페이지의 8개는 발표에 적합하도록 실제 context와 응답을 붙인 대표 흐름입니다.

      

      

      

        

          정상 경로
          
exact 자원값이 있는 요청

          
네 workload 유형 모두 CPU·memory·GPU·storage를 정확히 지정한 성공 예를 제공하여 두 번째 LLM 출력까지 진행할 수 있습니다.

        

        

          질문 경로
          
부족한 정보를 발명하지 않기

          
“적당한 사양”처럼 모호하면 Safeguard에서 명확화를 요청하고 Proposal을 호출하지 않습니다.

        

        

          거부 경로
          
LLM보다 먼저 막을 것

          
비밀, prompt injection, Target·provider·runtime·명령 요구는 모델 판단에 맡기지 않고 결정적으로 차단합니다.

        

        

          출력 경로
          
모델의 JSON도 신뢰하지 않기

          
중복 key, 임의 field, 자원 불일치, 준비되지 않은 상태는 후단 검사에서 fail-closed 처리합니다.

        

      

    


    

      

        

          
HUMAN + AI COLLABORATION

          
담당자 사이에서 오해하지 않을 경계

        

        
LLM_Op은 명령 실행기가 아닙니다. 자연어와 관측을 bounded proposal로 바꾸고, 다음 팀이 재검증할 수 있는 선언형 입력을 준비합니다.

      

      

        

          주체하는 일하지 않는 일
        

        

          시연자합성 prompt를 정확히 복사하고 raw 출력을 보존JSON을 고쳐 승인 결과를 만들지 않음
        

        

          Safeguard LLMallow · clarify · reject 제안보안 정책 편집, 자원값 생성, 권한 부여
        

        

          Proposal LLM제한된 action과 exact 자원 proposal 제안Target·provider·runtime·command 선택
        

        

          LLM_Op Guard입출력·semantics·readiness를 결정적으로 검증AppDeploy POST 또는 실제 배포
        

        

          AppDeployer 담당Manifest를 다시 검증하고 target-specific 동작으로 변환LLM 설명만 믿고 실행
