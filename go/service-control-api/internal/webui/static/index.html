CORE WORKFLOW

자동 분석 및 판단

요청을 LLM_Op Safeguard로 먼저 검증한 뒤 승인된 요청만 Revision 1 생성과 후속 운영 최적화로 연결합니다.

Qwen Safeguard · AppDeploy 없이 실행
실험 진행 방법처음 실행한다면 순서와 확인 항목을 펼쳐보세요.
  1. 1
    입력 방식과 Agent 선택

    자연어 요청 또는 구조화 App Spec을 선택하고 배포 판단 Agent를 확인합니다.

  2. 2
    Safeguard와 Revision 1

    1. Revision 1 생성을 누르면 LLM_Op Safeguard가 먼저 실행되고, 승인된 요청만 요구사항 분석·인프라 추천·Agent 판단·Guard 검증을 거쳐 최초 Manifest를 생성합니다.

  3. 3
    배포 상태 전송

    2. 배포 상태 전송을 먼저 누릅니다. 이 단계에서는 배포 상태만 같은 Flow에 기록됩니다.

  4. 4
    성능 Feedback 전송

    3. 성능 Feedback 전송을 누르면 같은 Flow의 SLO와 자원·추론 성능 지표가 입력됩니다.

  5. 5
    운영 최적화 판단

    OperationOptimizationAgent가 자동 실행되고 Scaling Guard가 KEEP·SCALE_OUT·SCALE_IN 판단을 검증합니다.

  6. 6
    Revision 2 확인

    승인된 운영 판단이 반영된 최적화 Manifest와 같은 Flow ID의 전체 실행 증거를 확인합니다.

핵심 완료 기준: 1. Revision 1 생성 → 2. 배포 상태 전송 → 3. 성능 Feedback 전송 → 운영 최적화 판단 → Manifest Revision 2가 같은 Flow ID에 누적되면 전체 Mock 실험이 완료된 것입니다. SIMULATED는 실제 VM 배포가 아닙니다.

외부 시스템 연동: Common JSON v1.0 application.analysis.request는 /api/v1/agent-control/application-analysis-requests로 전송합니다. 같은 message_id를 다시 보내면 기존 실행 결과를 반환하여 중복 배포 요청 생성을 방지합니다.
