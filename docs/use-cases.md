# 주요 활용 시나리오

## 요구사항 분석과 자원 추천

사용자가 자연어 요구사항과 분석용 LLM을 선택합니다. LLM_Op가 응용 조건을 `ApplicationProfile`로 구조화하고 Resource Ops가 자원 조건을 만족하는 후보를 추천합니다. 사용자는 조건 충족 여부와 사양을 확인한 뒤 실행 대상을 선택합니다.

분석용 LLM과 배포할 응용 모델은 다른 역할입니다. 예를 들어 Llama가 요구사항을 분석하더라도 실행할 응용은 BERT Tiny일 수 있습니다.

## 배포 판단과 실제 실행

Deployment Agent가 Profile과 추천 결과의 식별자 및 자원 제약을 검사하고 계획을 생성합니다. Guard 검증을 통과한 구성이 Revision 1로 기록됩니다. 이 시점에는 VM이나 응용이 실행되지 않습니다.

통합 PoC에서 사용자가 별도 실행을 요청하면 AppDeploy가 응용을 실행합니다. AWS를 사용할 때는 비용 검토, 실행 승인, 준비 검사가 먼저 필요합니다. VM 종료와 연결 디스크 정리까지 같은 실행 기록으로 추적합니다.

## 관측을 이용한 운영 변경

실제 추론 또는 Prometheus 관측을 운영 판단에 전달합니다. Agent가 성능 조건, 자원 사용률과 허용 복제본 범위를 확인하고 유지·확장·축소를 제안합니다. 변경 구성을 검증한 후 별도 적용하고 새 구성에서 다시 측정합니다.

복제본 수는 실행 방식에 따라 동일 PC의 프로세스 수 또는 별도 VM 수를 뜻할 수 있으므로 표시된 실행 대상을 함께 확인합니다. 목표 복제본, 적용한 Revision, 실제 관측된 수를 서로 구분합니다.

## 보상 예측 정책의 오프라인 비교

`poc/research_policy`는 원본 실측 실행 기록에서 후보별 보상을 학습합니다. 제약을 만족하는 후보를 비교하고 신뢰도와 학습 범위를 확인해 선택하거나 판단을 보류합니다. replay 결과는 실시간 VM 제어가 아니며, 실제 운영 개선 여부는 별도 반복 실험으로 평가해야 합니다.
