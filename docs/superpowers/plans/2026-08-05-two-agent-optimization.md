# Two-Agent Application Automation and Optimization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Promote the existing deterministic scaling logic to a Registry-authorized `OperationOptimizationAgent` while preserving the existing `AIApplicationAutomationAgent`, Guard, DesiredDeploymentSpec, reasoning comparison, and Mock Adapter flow.

**Architecture:** Keep the current one-shot deployment decision path unchanged. Add a second Internal Agent capability for post-deployment optimization, expose its authorization and execution evidence on the existing Flow, and reuse the existing scaling algorithm through an injected optimization runtime. Keep Qwen comparison optional on the results page and keep actual deployment outside geon.

**Tech Stack:** Go 1.25+, Echo, embedded HTML/CSS/JavaScript, JSON configuration, Go standard testing, Node browser tests.

## Global Constraints

- Work only on the existing `geon` branch.
- Do not modify AppDeploy or actual VM execution code.
- Preserve natural-language and structured App Spec inputs.
- Preserve existing API routes and Common JSON v1.0 envelopes.
- `DesiredDeploymentSpec` remains generated by geon only after Guard approval.
- Core Mock experiments must run without Ollama or a Runtime Agent endpoint.
- Runtime Agent failures must never silently fall back to an Internal Agent.
- `SIMULATED` and `READY` must not be described as actual deployment success.
- Do not add `config/inference_optimization.json` or `tmp/` to commits.
