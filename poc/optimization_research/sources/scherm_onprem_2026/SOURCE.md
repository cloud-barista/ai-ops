# Scherm B200 serving benchmark: pinned exploratory sample

The data come from the public [Scherm On-Premise LLM Inference Benchmark](https://huggingface.co/datasets/Scherm-AI/onprem-llm-benchmark/tree/e19edbaccec8add876073a3b0668e84115a59d0f), revision `e19edbaccec8add876073a3b0668e84115a59d0f`. The dataset card declares [CC BY 4.0](https://huggingface.co/datasets/Scherm-AI/onprem-llm-benchmark/blob/e19edbaccec8add876073a3b0668e84115a59d0f/README.md). Attribution and license apply to this local copy.

- `serving_ALL.csv` (`serving_ALL.csv`): 100,949 bytes, SHA-256 `d7f677cf0c4ccfd8c702c8458c4e6c3d324e90292bf13e5f09e065431e8d5f9e`; 528 aggregate rows, 14 model strings and 7 GPU labels. It mixes different machines, serving configurations, and sometimes missing TTFT measurements. Only the B200 Qwen2.5 AWQ TP2/TP4 pairs are used in the first exploratory experiment.
- Pinned serving runner (`source_scripts/run_serving.py`): SHA-256 `7c93282411f65487c850cb923538e0eebbe344d5dbcfb2246019beccf501a15a`. Its `ttft_ms_p95` CSV field is the **95th percentile over repeated run-level mean TTFT**, not the 95th percentile of individual request TTFT. The benchmark generator uses random input length 512, output length 256, and reports the median output tokens/second over successful repetitions.
- Pinned B200 job script (`source_scripts/job_serving_b200.sbatch`): SHA-256 `e2fb43b9d3be7d4852fec388c7eacecc83a85a9f123cc853822f32003adec7a4`. It passes `--tensor-parallel-size "$TP"` to vLLM, sets max model length 8192 by default, and runs the serving benchmark after the server responds. The filename includes `_tp2_` or `_tp4_` for the target comparison. CSV `gpu_count` is the count visible to `nvidia-smi` on the node, often **8 even for TP2 or TP4**; it is not used as the tensor-parallel allocation.

This benchmark records warm server performance. It has no AI-App registration request, actual per-request SLO target, VM lifecycle action, Ready time, deployment cost, or cross-institution infrastructure choice. Source scripts describe the intended command but the consolidated CSV does not independently attest every run's flags. The first analysis is exploratory because its coverage and outcome range were inspected before the method was scored.

The later B200 TP2 load-curve study uses the same pinned source and 7 Qwen2.5 AWQ models at concurrency 1/4/8 as inputs, with 16–512 as targets. RTX PRO 6000 legacy Qwen2.5 AWQ rows in the consolidated CSV have positive output throughput but no `n_ok`, TTFT aggregate, GPU count or VRAM metadata. The [pinned raw RTX example](https://huggingface.co/datasets/Scherm-AI/onprem-llm-benchmark/blob/e19edbaccec8add876073a3b0668e84115a59d0f/raw/rtx-6000/serving_NVIDIA_RTX_PRO_6000_Qwen_Qwen2.5-14B-Instruct-AWQ.csv) has a single `ttft_ms` column without the B200 repeat-aggregation definition. It is not a matching joint-metric validation set.
