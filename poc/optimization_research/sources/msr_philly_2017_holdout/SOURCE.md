# Microsoft Philly GPU trace: disjoint-machine holdout

This directory is a deterministic second sample of the public [Microsoft Research Philly trace](https://github.com/msr-fiddle/philly-traces/blob/29a1b87fa2d9ed80b83c9e3a37f3a88d382b031d/README.md). The [original 5% machine sample](../msr_philly_2017/SOURCE.md) was used for model development. This sample selects raw machine IDs whose `int.from_bytes(SHA256(machineId UTF-8), "big") % 100` lies in `[5,15)`, so the machine IDs cannot overlap. It contains every source GPU minute row on those machines, including `NA` cells and irregular CSV widths. The full archive and extracted CSV files are not retained.

The source is the same pinned commit and `trace-data.tar.gz` as the original sample: 1,055,988,361 compressed bytes, SHA256 `2037ccf63a725a02be718b0e1aeee6142c90b7f62d0d849295120e9f6ba13d2c`. The official trace carries a [CC BY 4.0 license](https://github.com/msr-fiddle/philly-traces/blob/29a1b87fa2d9ed80b83c9e3a37f3a88d382b031d/LICENSE); the maintainers ask users to cite Jeon et al., [*Analysis of Large-Scale Multi-Tenant GPU Clusters for DNN Training Workloads*](https://arxiv.org/abs/1901.05758), USENIX ATC '19. The license and attribution apply to these derivatives.

`scripts/fetch_philly_gpu_holdout.py` streams and audits the complete gzip/tar archive before promoting the selection. Collection audit (`gpu_util_holdout_audit.json`) SHA256 `5563e385f477ca091831dd48413ec24a39b2fa1cb955209c6992664e19bcd55f` records the pre-fetch protocol and model-spec hashes, archive byte count and SHA, all GPU rows, selected IDs, and duplicate keys. The full GPU CSV has 44,750,640 rows from 552 machines; the holdout has **4,040,392 rows from 47 machines**, zero exact duplicate selected machine-minute keys, and zero IDs shared with the original 21 machines. Raw Parquet SHA256: `d52b498fc24705e11d94075f605d32897dfc0b658167ee1da78c24d15aa73822`.

`scripts/normalize_philly_gpu_sample.py` fixes each machine's GPU slot width from its first source row. Later rows with another width remain present but unusable. The normalization audit (`gpu_util_normalized_first_width_audit.json`) SHA256 `ee870efa49dd556b688cde7ab495edaf01eaaa26a15d9e7196d94d9beb8a00bc` records 4,040,392 output rows, 2,280 width-invalid rows, first-row widths, and source-row sequence verification. All 47 machines passed the pre-set ≤1% width-mismatch rule; normalized Parquet SHA256: `146fe4318d6634120bdc10b2af9522be6c0a113c3213fb386a007b4d21edbdf8`.

Only 38 machines have any raw GPU rows in the fixed December 1–15, 2017 UTC test period; 37 contribute eligible current-below-80 decisions. The score-free gate audit (`../../../artifacts/philly_machine_holdout_candidates_v1/dry_run_audit.json`) and frozen protocol (`../../../reports/philly_machine_holdout_protocol_frozen.md`) specify the separate modeling decision. This telemetry has no user-facing latency SLO or measured VM scaling action. The machine holdout tests a GPU-utilization risk signal within the same cluster and period.
