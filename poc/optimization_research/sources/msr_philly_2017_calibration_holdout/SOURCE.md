# Microsoft Philly GPU trace: new-machine calibration sample

This directory is a deterministic third sample of the public [Microsoft Research Philly trace](https://github.com/msr-fiddle/philly-traces/blob/29a1b87fa2d9ed80b83c9e3a37f3a88d382b031d/README.md), from commit `29a1b87fa2d9ed80b83c9e3a37f3a88d382b031d`. It selects raw machine IDs whose `int.from_bytes(SHA256(machineId UTF-8), "big") % 100` lies in `[15,25)`. The original model used `<5`; a previous, already inspected holdout used `[5,15)`. This sample's IDs cannot overlap either group. It keeps all source GPU minute rows from the selected machines, including `NA` cells and irregular CSV widths. The full archive and extracted CSV files are not retained.

The pinned `trace-data.tar.gz` has 1,055,988,361 compressed bytes and SHA256 `2037ccf63a725a02be718b0e1aeee6142c90b7f62d0d849295120e9f6ba13d2c`. The official trace carries a [CC BY 4.0 license](https://github.com/msr-fiddle/philly-traces/blob/29a1b87fa2d9ed80b83c9e3a37f3a88d382b031d/LICENSE); the maintainers ask users to cite Jeon et al., [*Analysis of Large-Scale Multi-Tenant GPU Clusters for DNN Training Workloads*](https://arxiv.org/abs/1901.05758), USENIX ATC '19. This attribution and license apply to the sample.

The frozen calibration protocol (`../../../reports/philly_machine_calibration_protocol_frozen.md`) and development selection (`../../../artifacts/philly_machine_calibration_v1/development_selection.json`) were fixed before collection. `scripts/fetch_philly_machine_calibration.py` streamed and audited the complete gzip/tar archive before promoting only the selected rows. The collection audit (`gpu_util_calibration_holdout_audit.json`), SHA256 `d0651f320c7c2ea0cd13ab04abe09b60dc165153ce7cc576035a57586413fdde`, records the pre-fetch protocol/code/selection hashes, archive byte count and SHA, all GPU rows, selected IDs, and duplicate keys. The full GPU CSV has 44,750,640 rows from 552 machines. This sample has **3,512,172 rows from 42 machines**, zero exact duplicate selected machine-minute keys, and zero IDs shared with the prior samples. Raw Parquet SHA256: `6a6d40df227f4b5ef24c8cceba612508190e8e49a72c40d8d4ca2e26539c1647`.

`scripts/normalize_philly_gpu_sample.py` fixes each machine's GPU slot width from its first source row. Later rows with another width remain present but unusable. The normalization audit (`gpu_util_normalized_first_width_audit.json`), SHA256 `c187926d46d10aabc0f28a8ec9605cdca0a148b7dfe78856617d4a2851cbcb06`, records all 3,512,172 output rows, 1,980 changed-width rows, first-row widths, and the matching source-row index sequence. All 42 machines passed the pre-set ≤1% width-mismatch rule. Normalized Parquet SHA256: `1be463e5ccab9785611ef3c83dce3f4061c9be79c624d50773ed4a3ae4ec78a2`.

The score-free dry-run audit (`../../../artifacts/philly_machine_calibration_v1/test_dry_run.json`), SHA256 `d27e065314ba7311da9e2b977872504e86d8652439a956d9bdb2371b5740994e`, found 33 machines with eligible December 1–15, 2017 UTC `complete/below_80` decisions and passed the frozen quality gate. Its event counts are aggregate only; its row-level feature and observability fingerprint is fixed before scoring. This telemetry has no user-facing latency SLO or measured VM scaling action. The calibration test concerns an observed GPU-utilization risk signal within the same cluster and period.
