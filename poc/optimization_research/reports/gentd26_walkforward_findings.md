# GenTD26 요청 실행시간 보정의 시간순 반복 평가

## 결론

모델 ID별 잔차 보정은 하나의 2024-12-04~08 시험 구간에서만 좋아 보인 것은 아니다. **비중복 2일 시험 구간 5개 중 4개**에서 전역 잔차 보정보다 p90 pinball 손실이 낮았다. 전체 13,415건을 합치면 **2.775 → 2.637초(5.0% 감소)**다. 하지만 전체 관측 커버리지가 **90.0% → 88.9%**로 내려갔고, `IMG_2_IMG`는 **85.2%**, 모델 `M0003`은 **85.6%**에 머물렀다. 따라서 현재 정책을 90% 신뢰 상한으로 채택하기에는 근거가 부족하다.

이 평가는 동일한 공개 자료를 다시 나눈 **후향적 안정성 감사**다. 기존 그룹 보정 방식은 12월 4~8일 시험 결과를 본 뒤 설계되었으므로, 여기서 겹치는 기간의 결과를 독립적 재현이나 사전 등록 검증으로 해석하지 않는다.

## 방법

- 원본은 Alibaba [GenTD26 요청 추적 자료](https://github.com/alibaba/clusterdata/tree/8c132fb7717fbd44cf434cf81f2cd865a80072d5/cluster-trace-v2026-GenAI)의 `lora_request_trace.csv`다. SHA256은 `263fb88f1095f62d360cf89ded8cfc24fa2c5d111c1b16e7aaa9ccbfc4b37d78`. 성공 요청의 `exec_time_seconds`만 학습·평가했다.
- 각 시험 시작일은 11월 29일, 12월 1일, 3일, 5일, 7일이다. 매번 시험 시작 **4일 전까지의 가용 라벨만** 사용해 기본 p90 모델을 새로 학습한다. 다음 2일은 잔차 초기화, 다음 2일은 창·그룹 정책 선택, 그다음 2일은 시험이다. 정책 선택 점수에서도 시험 시작 시까지 가용하지 않은 라벨 910건을 제외했다. 이 요청은 나중에 가용해지면 시험 기간의 rolling 잔차에는 들어올 수 있다. 12월 8일이 마지막 관측일이라 마지막 시험은 653건이다. 시험 구간은 서로 겹치지 않는다. 후속 fold의 학습에는 이전 fold의 시험 요청이 들어갈 수 있다.
- 입력 특징과 기본 분위수 회귀기 설정은 [기존 요청 지연 실험](../scripts/evaluate_gentd26_request_latency.py)과 같다. 기본 모델은 각 fold에서 새로 학습했다. 모델 선택과 비교에 현재 요청의 실행시간, 성공 여부, 사용자 ID를 입력으로 쓰지 않았다. 성공 여부는 평가 모집단 정의에만 사용했다.
- 그룹 정책은 [기존 후보 집합](../scripts/evaluate_gentd26_subgroup.py)을 유지했다. 전역 잔차 창 200/500/1,000/2,000/전체 중 하나를 **정책 선택 구간**에서 먼저 고르고, 모델 ID·요청 종류별 창 50/100/200/500건 × 최소 지원 20/50/100건 × 수축 0/50/200을 같은 선택 구간에서 비교했다. 시험 성능으로 후보를 다시 선택하지 않았다.
- 강한 기준선은 기본 p90, 시험 전 고정한 잔차 분위수, 검증 선택 전역 rolling 잔차, 모델별 학습 요청의 p90 및 그 rolling 보정, 최근 실행시간의 경험적 p90이다. rolling 기준선은 각자 창을 정책 선택 구간에서 골랐다.
- **실제 완료 시각은 없다.** 모든 잔차 보정과 학습 라벨의 가용 시각을 `요청 생성 시각 + 기록된 실행시간 + 추가 1시간`으로 *가정*했다. 대기·기록 지연이 이보다 길 수 있다.

그룹 정책은 **10일 중 7일** 전역 정책보다 pinball 손실이 낮았다. 같은 날의 요청을 하나의 블록으로 재표본추출한 탐색적 95% 구간에서 그룹−전역 손실 차이는 **−0.221~−0.025초**, 커버리지 차이는 **−1.81~−0.44%p**였다. 블록이 10일뿐이고 정책 자체가 기존 시험 기간에서 발전했으므로 이 구간은 새 환경의 일반화 불확실성을 포괄하지 않는다.

전체 `IMG_2_IMG` 1,103건의 커버리지는 전역 **84.8%**, 그룹 **85.2%**였다. `M0003` 1,240건은 **80.7% → 85.6%**로 나아졌지만 90%에는 미달했다. 개선된 평균 손실에도 특정 작업과 모델의 상한 미달 문제가 남는다.

## 해석과 다음 조치

모델 ID별 최근 잔차는 요청 실행시간의 변화를 어느 정도 포착한다. 다만 12월 1일 시작 fold에서 손실이 악화했고, 전 구간의 커버리지가 전역 기준보다 낮다. 따라서 **분위수 손실을 낮춘 후향적 연구 결과**로 보관하고, 실제 상한·배포 판단에 연결하려면 별도 기간과 실제 라벨 도착 시각을 확보한 뒤 하위집단 커버리지까지 확인해야 한다. 이 자료에는 VM 추가·삭제의 반사실적 결과가 없으므로 Scale-out/in 판단의 효과로 읽을 수 없다.

재현:

```bash
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python scripts/evaluate_gentd26_walkforward.py
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python -m unittest discover -s tests -p 'test_gentd26_walkforward.py' -v
```

실행 코드: [`evaluate_gentd26_walkforward.py`](../scripts/evaluate_gentd26_walkforward.py). 각 fold의 후보 선택·시험 지표: [`metrics.json`](../artifacts/gentd26_walkforward_v1/metrics.json). 요청별 예측: `test_predictions.parquet` (`../artifacts/gentd26_walkforward_v1/test_predictions.parquet`). `scikit-learn` 버전은 1.6.1이다. 결과 JSON에 원본·현재 스크립트와 가져온 두 보조 스크립트의 SHA256을 기록한다. 라벨 가용·분할 순서·정책 선택·일자별 부트스트랩 테스트 6개를 통과했다.
