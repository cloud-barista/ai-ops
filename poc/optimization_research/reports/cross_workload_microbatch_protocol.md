# 서로 다른 GPU 작업 조건의 정확한 일괄 추론 규약

2026-09-29. 저장된 성능 모델과 물리 측정 원본은 변경하지 않는다. 이 실험은 연구용 GPU 형상 평가에서 **서로 다른 작업 조건의 8개 후보 격자**를 한 번의 모델 호출로 묶는다. 같은 격자에서 25개 SLO를 재사용하는 기존 `assess_gpu_shape_many`를 기준선으로 삼는다.

## 입력과 분리

- 저장 모델: `artifacts/performance_v1/performance_model.joblib` SHA-256 `7a934da440ea0c7473e4e59eb5fa0c8c57f347389272bd303cb0051ef918b161`.
- 원본: `data/audit_v1/measurements.parquet` SHA-256 `b7bba7963e8a309b6a8502a1d98eefb150476b1381ec016beeb68cbf63fae906`.
- `artifacts/slo_reuse_v1/manifest.json`을 재검증하고, 고정된 9개 모델 × 모델당 5개 작업 조건 × 조건당 25개 합성 SLO를 사용한다. 개발 모델은 `sha256(model_id)`의 사전식 순서상 앞 5개, 평가 모델은 나머지 4개다. 모델 ID를 통째로 나누어 배치 크기를 고른다.
- 작업 조건 격자에는 실행 전 알 수 있는 모델·입력·후보 CPU affinity/GPU 복제 수만 넣는다. 대상 실행의 측정 지연·처리량·GPU 계측과 결과 시각은 추론 입력에서 제외한다. 원본의 생성 SLO는 이 오프라인 반복질의를 구성하기 위한 값이며 실제 사용자 목표가 아니다.

## 방법과 기준선

기준선은 각 작업 조건의 25개 질의를 `assess_gpu_shape_many`에 한 번씩 전달한다. 이 경로도 이미 같은 격자의 25개 질의에서 예측을 한 번만 한다. 제안 경로는 유효한 요청의 고유 후보 격자를 첫 등장 순서로 모은다. 서로 다른 격자 최대 `B`개(`B ∈ {2,4,8}`)의 후보를 이어 붙여 한 번에 예측하고, 각 격자의 8개 원본 결과를 다시 나눈다. 모든 요청은 기존 `_assess_gpu_shape`로 SLO를 평가한다. 잘못된 요청, 지원되지 않는 모델·revision, 바뀐 후보 순서, 반복 질의의 상태·보류 이유·결과 순서는 기준선과 같아야 한다. 캐시는 함수 호출 안에서만 유효하다.

개발 모델에서 `B=2,4,8` 각각을 같은 모델별 입력 순서와 5회 반복으로 잰다. 모델별 median block time의 평균이 가장 작은 `B`를 고르고 동률이면 작은 `B`를 택한다. 그 뒤 평가 모델 4개에는 선택한 크기만 적용한다. 한 worker, 예열된 저장 모델, 5회 고정 난수 셔플, `perf_counter_ns`로 전체 함수 호출시간을 측정한다. 파일 읽기와 모델 적재는 시간에서 제외한다. 프로세스별 peak RSS는 모델·입력 로드와 예열을 포함한 같은 조건의 **별도 프로세스**에서 측정한다.

## 통과 조건과 해석

1. 전체 1,125개 질의의 최종 JSON과 각 고유 격자 8개 원본 예측이 정확히 같고, invalid/unsupported/mixed-order 합성 사례도 정확히 같아야 한다.
2. 고른 `B`로 평가 모델 각각의 median block time이 기준선보다 짧고, 평가 모델별 median의 평균을 비교한 속도 향상이 2배 이상이어야 한다.
3. 평가 모델별 peak RSS는 해당 기준선의 2배 이하여야 한다.

실패하면 기존 경로를 유지한다. 통과해도 이는 **이미 학습된 모델의 알려진 모델·호스트 배치 벤치마크에 대한 계산 최적화**다. 모델 ID 분리는 배치 크기 선택의 과적합을 줄이기 위한 것이며, 저장 모델 자체는 이 모델들의 다른 작업 조건으로 이미 학습됐다. 새 모델의 정확도, 실제 서비스 지연, 배포·스케일 행동 효과를 검증하지 않는다.

**사전 노출 고지:** 이 규약 작성 전에 45개 격자를 모두 사용한 원본 예측 호출시간을 5회 탐색적으로 측정했다. 따라서 평가 모델의 계산시간을 완전히 봉인된 외부 시험이라고 부르지 않는다. 여기서 고정하는 절차와 모델 단위 분리는 구현 선택의 사후 조정을 제한한다.
