# MaaS 전날 상태 보정의 실패 원인: 공개된 세 ID 집합 사후 진단

2026-09-29. [bucket 2 단회 시험](maas_state_day_calibration_holdout_findings.md)의 `NEW_ID_STATE_DAY_NO_GO` 판정 뒤 **이미 공개된 bucket 0·1·2의 정답을 다시 분석**했다. 이 문서와 [재현 코드](../scripts/diagnose_maas_state_day_no_go.py)의 수치는 가설 개발용이다. 새 성공 판정이나 독립 검증이 아니다.

동결 주 후보가 저장 모델보다 줄인 제곱오차 합계 가운데 최근 고사용률 상태의 몫은 bucket 0 **72.3%**, bucket 1 **94.0%**, bucket 2 **95.0%**였다. bucket 2의 `h=0` 50,202행에서는 Brier가 `0.021845→0.021827`로 거의 같았고, `h=1` 1,375행에서는 `0.170102→0.157544`로 낮았다. 개선의 대부분이 소수 상태에 몰려 있어 전체 상대 이득은 **1.37%**였다. ID별 제곱오차 합계는 795개 중 646개에서 낮았지만, 일부 ID의 큰 손익 때문에 사전 ID 재표집 구간 상한은 0을 넘었다. 상위 절댓값 10개 ID가 ID별 변화 절댓값 합의 **21.9%**를 차지했다.

전날 상태별 단순 Beta 표가 `h=1`에서 도움이 된다는 관찰을 바탕으로, **정답을 본 뒤** 그 상태의 `동결 주 후보`와 `전날 Beta 표`를 확률 척도에서 50:50으로 섞는 탐색안을 계산했다. `h=0` 예측은 주 후보 그대로 둔다. bucket 2 전체 Brier는 `0.025445→0.025390`, 저장 모델 대비 상대 이득은 **1.58%**로 늘었다. 그러나 이는 같은 bucket 2 정답을 보고 만든 방법이며, 원래 사전 **2%** 성공 조건에는 여전히 못 미친다. 이 혼합안의 bucket 2 ID 재표집 구간 `[−0.0008561, −0.0000021]`은 0 아래지만 **사후 방법 선택** 이후의 구간이므로 독립 확인으로 취급하지 않는다. 세 집합 모두 같은 MaaS 서비스의 같은 주간이다.

따라서 기존 후보의 NO-GO를 유지한다. 같은 주간의 새 해시 ID를 반복해서 열어 혼합비나 문턱을 고르는 것은 서비스·시기 일반화나 실제 `SCALE_OUT/IN` 효과를 해결하지 못한다. 위험 확률의 일반화 검증에는 다른 서비스·기간의 GPU 관측 결과가 필요하다. 스케일 정책의 효과 평가에는 같은 앱의 사용자 SLO, 조치 발행·Ready, 이후 요청 결과까지 연결된 자료가 추가로 필요하다. 현재 세 집합은 **30분 내 관측 GPU 고사용률 위험 예측** 연구에만 사용한다. [집계 JSON](../artifacts/maas_state_day_no_go_diagnostic_v1/results.json)은 세 bucket의 동결 점수 재현, 상태·날짜별 오차, ID 기여와 사후 혼합의 점수를 보존한다.
