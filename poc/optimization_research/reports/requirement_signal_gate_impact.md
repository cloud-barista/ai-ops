# 응용 요구 신호의 보수적 지원 조건: 모델 제외 예측 재평가

작성일: 2026-09-28. [재현 코드](../scripts/audit_requirement_signal_gates.py)는 이미 저장된 모델 전체 제외 예측을 다시 **분류·집계**한다. 모델을 재학습하거나 저장된 최종 모델을 호출하지 않는다. 상세 수치와 입력 해시는 [metrics.json](../artifacts/requirement_signal_gate_audit_v1/metrics.json), 각 실행의 통과·보류 사유는 gate_decisions.csv (`../artifacts/requirement_signal_gate_audit_v1/gate_decisions.csv`)에 있다.

## 핵심 판정

**제한적 GO — 오프라인 지원 범위 감사.** 새 [응용 요구 신호 API](../scripts/assess_requirement_signals.py)의 모델 크기·입력 조합 조건을 과거의 모델 전체 제외 fold에 적용할 수 있다. 다만 이는 **저장된 최종 API의 성능 측정이 아니다.** GPU 피크용 최종 조건부 모델은 주 캠페인의 9개 모델 ID를 모두 학습했으므로, 이 9개 ID에 대한 실제 API 호출은 GPU 피크 신호를 전부 `ABSTAIN`으로 낸다. 여기서는 각 fold에서 대상 모델을 빼고 학습했던 *당시의 고정 예측값*을 사용해, 대상이 신규 모델이었다면 지원 조건이 어떤 예측을 남겼을지 살핀다. 로컬 적재시간의 최종 저장 모델 역시 9개 모델을 학습했으므로 fold 점수와 동일한 추론 결과로 볼 수 없다.

이 지원 조건을 정확도 개선이나 안전 보증으로 해석하면 안 된다. 주 캠페인에서 GPU 피크 상한의 남은 6모델 평균 커버리지는 **95.12%에서 93.75%로 내려가고**, 90% 분위수 손실은 **16.02에서 18.66 MiB로 늘었다**. 크기 범위 안에 남은 ALBERT의 커버리지는 **62.5%**, 최악의 관측 피크 초과는 **320 MiB**다. 반면 로컬 적재시간의 주 캠페인 평균 절대 로그오차는 같은 크기 게이트 뒤 **0.246에서 0.229**로 작아졌다. 지원 조건의 효과가 신호마다 다르고, 표본 선택으로 성적표가 바뀐다.

## 적용한 조건과 분모

원본은 고정 SQLite 추출 (`../data/audit_v1/measurements.parquet`)의 동일 `icns` 호스트, RTX PRO 5000 Blackwell **GPU 0 하나**, CUDA replica 1, CPU affinity·thread 2, 성공·적격 실행이다. 주/새 입력/공간표본 캠페인의 원래 평가 기회는 각각 **575/18/44실행, 9모델**이다. 한 모델의 서로 다른 batch·길이·동시성 실행을 별도 신규 모델로 세지 않았다. 모든 분할의 donor는 [기존 split manifest](../artifacts/load_support_v1/split_manifest.json)에 고정된 **주 캠페인의 대상 모델 제외 집합**이다. 대상 실행 결과는 아래 통과·보류 규칙에 쓰지 않았다.

- **공통:** 작업 종류가 `inference`이고 같은 종류의 서로 다른 donor가 2모델 이상이며, 대상의 등록 파라미터 크기가 해당 fold donor의 최솟값과 최댓값 사이에 있어야 한다. 물리 프로필은 위 조건으로 고정한다.
- **관측 CUDA 예약 피크:** 공통 조건에 더해 `(batch_size, max_length, request_concurrency)` 조합이 그 fold의 주 캠페인 donor 입력 그리드에 있어야 한다. 고정 대역폭 `h=1`의 기존 fold 예측 (`../artifacts/vram_conditional_v1/forecasts.csv`)만 주 연구 모델로 평가했다. 기준선 전역·작업 종류 보정도 *똑같이 남은 행*에서 비교한다.
- **캐시된 로컬 적재시간:** 공통 조건만 적용한다. 적재시간 회귀기는 요청 batch·길이·동시성을 사용하지 않으므로 입력 조합 조건을 붙이지 않았다. 기존 fold 예측 (`../artifacts/load_support_v1/predictions.csv`)을 썼으며 기준선도 같은 행에서 평가했다.

`original_task_gate`는 동종 donor 수만 검사한 기존 연구 평가의 답변 집단이다. 새 크기·입력 조합 조건은 사후 적용한 **정적 지원 집단**이다. 표의 `답변/전체`는 모델별로 상관된 실행 수의 비율이며, 모델 수는 별도로 적었다. 수치 집계는 답한 모델 각각을 같은 가중치로 평균했다. `—`는 답한 행이 없어 점수를 정의할 수 없다는 뜻이다.

| 모델 전체 제외 캠페인 | 피크: 기존 답변/전체 → 새 답변/전체 | 피크 모델 수 | 피크 커버리지 / 90% 손실 MiB: 기존 → 새 | 적재시간: 기존 답변/전체 → 새 답변/전체 | 적재시간 모델 수 | 적재시간 MALE / MAE 초: 기존 → 새 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 주 캠페인 | 512/575 → 384/575 | 8 → 6 | 95.12% / 16.02 → **93.75% / 18.66** | 512/575 → 384/575 | 8 → 6 | 0.246 / 0.0387 → **0.229 / 0.0358** |
| 새 입력 조건 | 16/18 → **0/18** | 8 → 0 | 93.75% / 26.78 → — | 16/18 → 12/18 | 8 → 6 | 0.266 / 0.0396 → 0.243 / 0.0379 |
| 공간표본 조건 | 40/44 → **0/44** | 8 → 0 | 95.00% / 23.76 → — | 40/44 → 30/44 | 8 → 6 | 0.229 / 0.0363 → 0.216 / 0.0336 |

주 캠페인에서 생성형 Qwen의 **63실행**은 동종 donor가 없어 두 신호 모두 원래부터 보류됐다. 새 크기 조건은 RoBERTa와 가장 작은 BERT의 **각 64실행**을 추가로 보류한다. 둘은 각자의 모델 전체 제외 fold에서 donor 크기의 최댓값·최솟값을 벗어난다. 남은 **6모델 × 64입력 = 384실행**만 정적 지원 집단이다. 새 입력·공간표본 캠페인의 encoder **16/40실행**은 전부 donor의 정확한 입력 조합 64개 밖에 있으므로 피크 신호가 모두 보류된다. 로컬 적재시간에는 이 추가 조건이 없어서 크기 범위 안의 **12/30실행**에 답한다.

## 동일 표본 비교와 계열 전체 제외

주 캠페인의 384개 피크 허용 행에서 `h=1`의 평균 커버리지/90% 손실은 **93.75%/18.66 MiB**다. 같은 행의 전역 보정은 **94.27%/23.17 MiB**, 작업 종류만의 보정은 **92.71%/18.60 MiB**다. 따라서 `h=1`의 작은 손실 이득을 모든 비교군에 주장할 수 없다. 적재시간 허용 행의 크기 ExtraTrees MALE는 **0.229**, donor 중앙값은 **0.236**, 정적 Ridge는 **0.283**이다. 이 비교는 같은 6개 모델·384실행에 국한한다.

계열 전체 제외에서는 게이트가 성능을 개선한다는 해석이 더욱 맞지 않는다. BERT 4종을 한꺼번에 제외하면 적재시간 답변이 **256→128실행**, ExtraTrees MALE가 **0.278→0.289**로 악화된다. BERT 4종+DistilBERT 제외에서는 **320→192실행**, **0.417→0.517**로 더 크게 악화된다. 같은 허용 행의 정적 Ridge는 각각 **0.210/0.487**다. 피크 `h=1`은 주 캠페인 BERT 4종에서 **256→128실행, 90% 손실 18.15→19.12 MiB**, BERT+DistilBERT에서 **320→192실행, 23.50→26.95 MiB**다. 두 계열 제외 모두 새 입력·공간표본 피크 허용 행이 **0개**다. 입력 조건 제한은 미관측 조합에 대한 숫자 출력을 막지만, 이 자료로 일반화 성능을 검증할 수 있는 범위도 없앤다.

## 재현성과 한계

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 /usr/bin/python3 poc/optimization_research/scripts/audit_requirement_signal_gates.py
```

스크립트는 원본 SHA-256, 고정 물리 프로필, 11개 donor/held 분할, 모든 예측과 원본의 일대일 연결, 결과 라벨 일치, 원래 발표한 집계 점수 재현을 확인한 뒤 새 집계를 저장한다. [기존 GPU 피크 분석](vram_conditional_findings.md)과 [적재시간 분석](load_support_findings.md)의 최초 점수와 여기의 게이트 적용 전 점수는 일치한다. 새 게이트에 쓴 모델 크기는 이 파일에서는 **실행 후** `result_json`에 기록된 값이다. API가 요구하는 등록 시점의 실제 `model_parameter_bytes`, `source`, `available_at`을 검증할 수 없으므로 표의 답변율은 **실제 사전 등록 요청의 답변율이 아니다**. 새 모델 ID가 진짜 새 모델인지도 이 파일로 인증할 수 없다.

GPU 표적은 한 GPU에서 측정한 `torch.cuda.max_memory_reserved()` 피크다. **최소 VRAM, OOM 가능성, VM 메모리 또는 인프라 형상 요구량이 아니다.** 적재시간 표적은 로컬 캐시의 모델·토크나이저 로딩 구간이다. **VM 생성, 이미지 다운로드, 서비스 준비 또는 배포 완료 시간과 다르다.** 지원 게이트와 `h=1` 선택 모두 기존 SQLite를 살펴본 뒤 정해졌고, 세 캠페인은 독립 신규 모델 검증이 아니다. 이 근거로 실제 배포·스케일링 판단을 승격할 수 없다.
