# Azure Coding 공개 표본의 다음 5분 입력 토큰 총량 예측 규약

상태: **모델 점수 전 고정 규약**. 이 연구는 경희대의 배포·스케일링 판단기에 필요한 **사전 수요 신호**를 시험한다. 대상은 Azure Coding CSV에 *기록된 요청*의 다음 5분 `ContextTokens` 합계다. 공개 파일은 생산 요청의 일부이므로 이 합계를 전체 서비스의 유입량이나 실제 GPU 처리량으로 해석하지 않는다. 사용자 지연 SLO, 배포·스케일 조치, VM 효과의 정답도 없다.

## 출처, 노출과 분할

고정 원본은 `AzureLLMInferenceTrace_code_1week.csv` (`../data/external/azure_llm_2024/AzureLLMInferenceTrace_code_1week.csv`)이며 [출처 메모](../data/external/azure_llm_2024/SOURCE.md)의 공식 SHA-256은 `71de5c55cbc35f8f1ed0b6b7806b4cd1e9764b0058469725a6aac98023a1448f`다. `TIMESTAMP`(UTC)와 양수 정수 `ContextTokens`만 읽고 `GeneratedTokens`는 읽거나 사용하지 않는다. 정확히 2024-05-10 00:00부터 05-17 00:00 직전까지 5분 고정 구간 2,016개를 만든다. 입력의 시각·토큰 유효성, 시각 정렬, 구간 완전성을 확인한다. 기록이 없는 구간은 표본 합계 0으로 해석할 수 있지만 이번 사전 감사에서 각 구간에 행이 있음을 확인했다.

이 규약 전에 같은 파일의 **일곱 날짜 모두**에서 요청 수와 입력 토큰 합계의 일별 5분 최솟값·최댓값·중앙값을 읽었고, 2024-05-14~16은 기존 [출력 토큰 연구](azure_code_output_tokens_findings.md)의 시험 기간이었다. 그러므로 아래 05-14~16은 **블라인드 독립 시험이 아닌 후향 시간순 평가**다. 그 기간의 5분별 모델 점수는 이번 고정 전에는 계산하지 않았다. 기존 연구의 `GeneratedTokens` 정답은 여기서 쓰지 않는다.

| 용도 | UTC 날짜 | 5분 구간 수 |
|---|---|---:|
| 모델·기준선 고정값 학습 | 05-10~12 | 852 (첫 1시간 burn-in 제외) |
| 개발 검증 | 05-13 | 288 |
| 후향 시간순 평가 | 05-14~16 | 864, 날짜별 288 |

## 결정 시각과 고정한 방법

구간 `[t,t+300초)`의 입력 토큰 합계 `y_t`를 구간 시작 `t`에 예측한다고 가정한다. 직전 구간 `y_{t-1}`은 `t`까지 완전히 관측되고 입력 토큰 계수가 전달됐다고 **가정**한다. 실제 계측 전달 지연은 원본에 없다. 이전 12개 완료 구간의 평균 `m_t=mean(y_{t-12:t})`가 **1,000 입력 토큰 이상**인 시점만 쓴다. 그보다 작은 표본은 비율이 불안정하므로 예측을 보류한다. 평가 날짜 중 이 조건 때문에 5%를 넘게 빠지면 지원범위 게이트를 실패 처리한다. 주 학습 목표는 **상대 수요 `r_t=y_t/m_t`의 90분위**이고, 절대 토큰 예측은 `m_t×예측 r_t`다. 이 비율형 학습기는 나중에 별도 Coding→Conversation 전이를 검토할 수 있도록 서비스의 절대 요청 규모를 입력하지 않는다. Conversation 원본은 이 규약 작성 때 열지 않았다.

특징은 `y_{t-1},y_{t-2},y_{t-3},y_{t-12}`를 `m_t`로 나눈 값, 전날 같은 5분 슬롯의 비율 `r_{t-288}`, 최근 완료 12구간의 최대·경험적 90분위를 `m_t`로 나눈 값, 최근 6구간 평균과 그 앞선 6구간 평균의 비율, UTC 5분 슬롯의 sin/cos, 주말 표시다. 전날 값이 없으면 `NaN`으로 표시한다. 미래 요청·현재 목표 구간·출력 토큰은 입력하지 않는다. 평가 기간의 **이전 구간에 실제로 도착한 표본값**은 순차 온라인 피드백으로 특징에 쓸 수 있다.

주 학습기는 scikit-learn `HistGradientBoostingRegressor(loss='quantile', quantile=0.9, max_iter=150, learning_rate=0.05, max_leaf_nodes=7, min_samples_leaf=20, l2_regularization=1, early_stopping=False, random_state=42)` 하나다. 05-10~12에서 burn-in 이후 852구간으로만 적합하고 음수 비율 예측은 0으로 자른다. 학습 구간의 각 행 가중치는 `m_t/mean_train(m)`로 고정한다. 이는 절대 손실 `pinball(y_t,m_t×r̂_t)=m_t×pinball(r_t,r̂_t)`에 맞춘 것이다. 하이퍼파라미터 탐색·사후 재학습·보정은 하지 않는다.

네 고정 비교기는 (1) 학습 구간 전체 `r`의 **`m` 가중** 90분위 × 현재 `m_t`, (2) 직전 완료 12구간의 `y` 경험적 90분위, (3) 전날 같은 슬롯의 `r_{t-288}×m_t`, (4) 전날 같은 슬롯의 비율에 **학습 중 양쪽 비율을 관측한 564구간**의 `r_t-r_{t-288}` **`m` 가중** 90분위를 더한 뒤 `m_t`를 곱한 값이다. (3)·(4)의 첫날 결측은 학습 전역 비율 90분위로 대체한다. 모든 비교기의 음수 예측은 0으로 자른다. 가중 분위수는 값을 오름차순 정렬하고 누적 가중치가 전체의 90%에 처음 도달한 값을 택한다. (2)의 경험적 분위수는 NumPy 기본 선형 보간이다.

## 지표와 판정

각 5분 합계에 0.9 분위수 pinball 손실, 피복률 `mean(y≤prediction)`, 과소예측 비율과 평균 예측량을 기록한다. 상대 비율의 pinball도 보조로 기록하지만 채택 게이트에는 환산한 **절대 토큰 합계**의 손실만 사용한다. 개발 검증 05-13과 후향 평가 05-14~16의 날짜별·평균 일별 손실/피복률을 모두 보고한다. 한 날짜의 288개 구간은 시간상 상관돼 있으므로 독립 표본 288개나 통계적 신뢰구간으로 취급하지 않는다. **탐색 채택 게이트**는 후향 평가의 세 날짜 동일 가중 평균 pinball이 네 비교기 각각보다 최소 5% 낮고, 적어도 두 날짜에서 그날 최선 기준선보다 낮으며, 세 날짜 각각 피복률이 `[85%,95%]` 안에 있어야 한다. 실패해도 모든 고정 평가 수치를 보고하되 연구용 후보를 판단기에 채택하지 않는다. 이 게이트 통과조차 전체 서비스·새 주·새 모델·VM 스케일 정책 성능의 증거는 아니다.

코드·합성 시험·이 문서·원본 해시를 점수 전에 freeze JSON에 기록한다. 다른 연구의 저장 모델·평가 점수를 변경하지 않는다. 원시 요청 행이나 5분별 합계는 결과 산출물로 보존하지 않고 날짜별 집계와 모델 해시만 쓴다.
