# Chutes 모델별 다음 5분 TTFT p90: 점수 전 고정 규약

2026-09-29. 작성 시점에 `data/trace/train-00044-of-00045.parquet`의 **row-group 메타데이터(행 수·압축 크기·시작시각 최소/최대)**만 열었다. 같은 파일의 row group 65와 샤드 22의 row group 68은 앞선 [타당성 검사](chutes_serving_signal_feasibility.md)에서 이미 TTFT·결측·모델·인스턴스 분포를 열었으므로 **개발 자료**다. 아래 검증/시험 row group 71–76의 요청별 TTFT·`ct`·인스턴스 값과 이 규약의 모든 점수는 아직 보지 않았다. 이 규약과 구현 해시는 그 값을 보기 전에 `artifacts/chutes_ttft_tail_v1/frozen_manifest.json`에 고정한다.

## 출처와 제한된 추출

- 공식 [Harvard MadSys/Chutes 카드](https://huggingface.co/datasets/harvardMadsys/chutes_metadata), revision `85722e694bf7bb8a5a5ccdf70424fa5998372467`, CC BY 4.0. 원본 파일 `data/trace/train-00044-of-00045.parquet`의 크기 2,046,207,562 bytes, Hugging Face `X-Linked-ETag` SHA-256 `ca99b91b33d04bf56f3d0b26241c4a083a7e1579f0f571887eee4ee1004c90dd`를 확인한다.
- row groups **65–76만** 시간순으로 사용한다. 기존 표본 row group 65의 SHA-256은 `92fe8c48ab1aadfe33d214570a167cebb4bf01e0fdb7eda296304cc91c0eac71`이다. 나머지는 Parquet range read로 `invocation_id,function_name,chute_id,instance_id,started_at,completed_at,it,ot,ct,ttft` 열만 뽑고 파일별 SHA-256을 기록한다. `invocation_id`는 12개 그룹 전체의 중복 검사에만 쓰고 학습 특징에서 제외한다. 각 그룹 및 그룹을 이어 붙인 요청 시작시각의 단조성과 선택한 분할의 첫/마지막 5분 창 전체 포함 여부를 강제한다. 전체 94GB를 받지 않는다. 선택한 12개 그룹은 각 1,001,472행, 합계 12,017,664행이다. 메타데이터상 첫 시작은 정규화된 1970-12-27 22:13:39.495905, 마지막 시작은 1970-12-28 23:37:00.079495다. 이는 실제 달력 날짜가 아니다.
- **첫 수집은 row groups 66–73까지만** 한다. 학습·검증 지원량과 검증 점수를 계산한 뒤에만 사전 게이트를 확인한다. 검증 게이트를 넘으면 74–76을 내려받아 시험 지원량과 점수를 한 번 계산한다. 게이트 실패 시 시험 row group을 열지 않는다.

## 정답·결정 전 입력

5분 격자 `t`의 목표 `Y(m,t)`는 모델 `m`의 `[t,t+5분)`에 **시작한** `chat_stream`/`completion_stream` 요청 중 유효 TTFT의 경험적 p90(초)다. 한 요청이 유효하려면 시작·완료 시각이 있고 `0 < ttft ≤ completed_at−started_at+0.001s`이며 `completed_at ≤ t+65분`이어야 한다. 마지막 조건은 해당 5분 창이 닫힌 뒤 60분 이내에 완료된 요청만 같은 조건으로 남긴다. TTFT가 없는 요청·너무 늦게 끝난 요청은 정답에서 빠지므로 목표는 **기록되고 60분 내 완료된 스트리밍 요청의 조건부 p90**이다. 정상/실패 상태가 원본에 없어 모든 사용자 요청의 SLO라고 부르지 않는다. `it,ot,ct`는 유한하고 `0≤ct≤it`, `ot≥0`일 때만 캐시/토큰 집계에 사용한다.

`t`의 과거 입력은 `[t−30분,t)`에 시작한 스트리밍 요청의 **모델별 도착 수**와, 같은 구간에 **완료된** 유효 스트리밍 요청의 TTFT·토큰·캐시 기록뿐이다. 완료 기록에는 더 일찍 시작한 요청이 포함될 수 있으며 이는 완료 시점의 피드백이다. 완료가 `t` 이후인 과거 시작 요청의 TTFT·출력·캐시 값은 쓰지 않는다. `instance_id`가 요청 시작 순간에 알려졌는지는 원본에 없으므로 인스턴스별 분포는 **해당 5/30분 구간에 완료된** 스트리밍 요청에서만 계산한다. 공개 자료에 텔레메트리 전달시각은 없어서 완료 직후 기록을 읽을 수 있다고 가정하며, 실제 온라인 가용성을 증명하지 않는다. 도착 수는 `instance_id`가 없더라도 시작 시각과 모델이 있으면 센다. 인스턴스 결측률과 모델·분할별 유효 TTFT/스트리밍 시작 비율을 별도로 보고한다. 현재 5분 창의 요청 수·인스턴스·캐시·TTFT, 원본 `chute_models`의 현재 GPU/가격, 익명 user ID, 실제 날짜·요일은 입력에 넣지 않는다.

**결정 가능 여부는 과거만으로 정한다.** 과거 30분에 완료된 유효 TTFT가 ≥100개인 `(m,t)`를 적격으로 둔다. 최근 5분 완료가 ≥30개면 그 p90을 `last5`로 쓰고, 부족하면 과거 30분 p90으로 대체한다. 별도 `prior30`은 언제나 과거 30분의 p90이다. 이 두 기준선과 학습기 모두 **같은 과거 적격 행**에 예측을 낸다. 미래 유효 TTFT가 ≥100개인 창만 p90 정답의 표본 오차를 제한한 *조건부 오프라인 채점 집합*에 넣는다. 미래 요청 수는 입력·온라인 선택 기준이 아니다. 분할마다 고정 등록 모델×전체 5분 격자, 과거 적격 행, 그중 미래 채점 가능한 행의 수·비율을 각각 보고한다.

## 시간 분할과 결과 가용 시각

선택한 row group의 시작시각 범위에서 먼저 5분 경계를 고정했다. 원본 row groups **65–70은 학습 정답 창**, **71–73은 검증 정답 창**, **74–76은 시험 정답 창**을 모두 포함한다. 각 분할의 특징은 결정 시각 이전에 끝난 앞 그룹의 관측을 사용할 수 있다. 요청의 첫 시작 이후 **1시간**의 과거 이력 여유를 둔다. 그룹 경계에 걸린 5분 창은 각 분할에서 제외한다. 단일 row group 경계 자체를 모델 학습 경계로 착각하지 않는다.

| 역할 | 결정 시각 `t` (양끝 규칙 `[start,end)`) | 출력이 알려지는 시각 |
| --- | --- | --- |
| 학습 | 1970-12-27 23:15 ~ 1970-12-28 10:15 | 마지막 창 끝+60분 ≤ 11:15, 11:20 적합 전 |
| 검증 | 1970-12-28 11:25 ~ 16:00 | 마지막 창 끝+60분 ≤ 17:00, 17:05 게이트 전 |
| 시험 | 1970-12-28 17:05 ~ 23:30 | 모든 점수는 요청 완료 기록 후 오프라인 계산 |

학습 적합에는 **학습 정답만** 사용한다. 검증의 `t` 이전에 완료된 실제 과거 요청은 검증 입력으로 사용 가능하다. 시험에서도 검증 후의 이미 완료된 실제 과거 요청은 각 `t`의 입력으로 사용한다. 검증 결과로 모형/하이퍼파라미터를 조정하지 않는다. 시험 행의 라벨·수·분포는 검증 게이트가 통과한 뒤에만 검사한다. 정답 `completed_at`의 60분 상한은 학습·검증 피드백이 각각 정한 적합/게이트 시각 이전에 알려지게 한다. 시험의 결과는 모델 업데이트에 넣지 않는다.

## 모델 등록·품질 게이트

학습 기간 자료만으로 모델을 등록한다. 각 모델에 **과거 적격이면서 미래 유효 TTFT ≥100개인** 학습 창이 ≥12개이고, 그 창들의 유효 TTFT 요청이 합계 ≥1,000개여야 등록한다. **검증/시험 자료로 등록 목록을 바꾸지 않는다.** 모든 등록 모델×5분 격자를 분모로 평가 지원량을 보고한다.

점수를 내기 전 각 분할의 past-only 적격 행을 계산한다. 학습에는 조건부 채점 행 ≥500개, 등록 모델 ≥10개가 필요하다. 검증에는 적격 행이 전체 등록 모델×격자의 ≥20%, 조건부 채점 행이 ≥12개인 등록 모델 ≥10개와 **이 평가 모델들에서 합계 ≥300개**가 필요하다. 검증에서 이 기준을 만족한 모델 집합을 **시험 주 지표의 평가 모델로 고정**한다. 시험도 적격 행 비율 ≥20%, **고정 평가 모델 모두**가 각각 ≥12개 조건부 채점 행을 가져야 하며 그 모델들의 조건부 채점 행 합계가 ≥300개여야 한다. 하나라도 미달하면 시험의 주 점수를 내지 않고 지원 부족으로 판정한다. 시험 미래 지원량으로 평가 모델을 빼거나 새로 등록하지 않는다. 검증/시험에서 과거 적격 행 중 `ct` 유효 완료 요청의 비율이 ≥90%인 행이 ≥90%여야 캐시 특징을 평가한다. 어느 게이트든 실패하면 모델 학습·해당 분할 점수를 중지하고 원인과 지원량만 기록한다.

## 고정 비교 방법과 점수

모든 학습기는 같은 조건부 학습 행과 모델 균등 행 가중치 `N/(M×n_m)`를 쓴다. 정답은 `log1p(Y)`로 변환해 `HistGradientBoostingRegressor(loss='squared_error', max_iter=120, learning_rate=0.05, max_leaf_nodes=15, min_samples_leaf=30, l2_regularization=1, early_stopping=False, random_state=42)`로 적합하고, 출력은 `max(0.001,expm1(prediction))`초로 역산한다. 고정 학습 모델 ID는 학습 등록 목록의 정렬 순서로 one-hot 부호화한다. 같은 적합 모델을 검증·시험에 사용하며 검증을 합쳐 재적합하지 않는다.

1. `last5`: 직전 5분 완료 유효 TTFT의 경험적 p90; 30개 미만이면 과거 30분 p90.
2. `prior30`: 과거 30분 완료 유효 TTFT의 경험적 p90.
3. `base`: 모델 부호, 직전 5/30분 도착 수·완료 유효 TTFT 수, 직전 5/30분 TTFT p90, 과거 30분 평균 입력/출력 토큰 수를 쓰는 위 고정 학습기.
4. `instance_cache`: `base`에 과거 5/30분 **완료된 스트리밍 요청**의 서로 다른 인스턴스 ID 수와 최다 인스턴스 완료 비율, 과거 30분 **완료된** 유효 TTFT 요청의 `sum(ct)/sum(it)` 및 `ct>0` 비율을 더한 동일 학습기. 과거 관측 인스턴스 수는 실제 활성 replica 수의 추정치가 아니다.

주 지표는 각 행의 `|log(pred/Y)|`를 **모델별 평균한 뒤 모델 균등 평균**한 MALE이다. 고정 평가 모델의 개별 MALE, 전체 행 가중 MALE, 정답/예측 중앙값을 함께 보고한다. 정규화 날짜가 실제 달력은 아니지만 연속 1시간 시간 블록별 모델 균등 MALE도 보고한다. 블록은 평가 모델 5개 이상에서 각각 채점 행이 있을 때만 승패에 넣는다. 같은 서비스의 연속 약 하루 자료이므로 창 간 독립 신뢰구간은 주장하지 않는다.

**검증 통과 문턱**은 `instance_cache`의 주 MALE이 `last5`, `prior30`, `base` **모두**보다 상대 ≥5% 낮고, 평가 모델의 ≥60%에서 `base`보다 낮은 것이다. 실패하면 시험 원본을 열지 않고 미채택한다. **시험 채택 문턱**은 세 기준선 모두보다 주 MALE이 상대 ≥10% 낮고, 평가 모델 ≥70%에서 `base`보다 낮으며, 충분한 1시간 블록 ≥4개 중 ≥70%에서 `base`보다 낮은 것이다. 하나라도 실패하면 미채택한다. 통과해도 같은 서비스의 관측 지연 위험 *입력 신호*로만 남긴다. 실제 배포·스케일 조치, 비용이나 GPU 수량의 개선을 주장하지 않는다.
