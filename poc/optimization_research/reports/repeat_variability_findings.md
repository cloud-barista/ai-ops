# 반복 GPU 측정으로 확인한 성능값의 변동

## 자료와 질문

현재 주 실험의 각 자원 형상은 사실상 한 번씩 측정돼, 모델 예측 오차의 작은 차이가 반복 실행의 변동보다 큰지 직접 알 수 없다. 기존 SQLite의 별도 `khu-hf-live` 캠페인에는 같은 GPU 호스트·수집기 `v2`에서 **16개 고정 GPU 조건을 47회씩** 실행한 기록이 있다. 이 기록만으로 배치 p95 지연과 처리량의 반복 변동을 구했다. 수집기 `v1` 기록은 섞지 않았다. 이후 같은 수집기에서 실행한 `khu-hf-diverse-cpu-matrix`의 정확히 일치하는 16개 조건과도 비교했다.

각 반복 회차에는 같은 작업의 GPU 1개·2개 결과가 짧은 간격으로 측정된 6개 작업이 있다. 같은 회차의 로그 성능 차이를 이용하면 공통 호스트 변동을 상쇄할 수 있다는 가설도 점검했다. 이것은 운영 요청 지연이나 실제 사용자 SLO 자료가 아니라 반복된 배치 벤치마크다.

## 결과

| 16개 GPU 조건의 중앙값 | 배치 p95 지연 | 처리량 |
| --- | ---: | ---: |
| 47회 실행의 조건별 로그 표준편차 | **0.168** | **0.022** |
| 조건별 로그 표준편차의 90백분위 | 0.234 | 0.084 |
| 앞 27회와 뒤 20회 중앙값의 절대 로그 차이 | 0.019 | 0.005 |
| 이후 같은 수집기 캠페인 2회 측정 중앙값과의 절대 로그 차이 | 0.072 | 0.011 |

같은 회차의 GPU 2개/1개 로그 성능비를 쓰는 경우, 독립 측정이라고 가정했을 때의 분산을 실제 같은 회차 차이의 분산으로 나눈 값은 6개 작업의 중앙값에서 지연 **1.05**, 처리량 **0.96**이다. 1보다 크면 회차를 짝지어 얻는 분산 감소를 뜻한다. 범위는 지연 **0.90~1.32**, 처리량 **0.91~1.11**로, 이 자료에서는 짝짓기가 일관된 변동 감소 방법이라고 보기 어렵다.

## 연구에 미치는 영향

이 16개 조건에서 지연의 단일 실행 변동은 처리량보다 크다. 따라서 다른 실험에서 나타난 작은 지연 오차 차이를 운영상의 확실한 이득으로 읽기 전에 반복 측정으로 확인해야 한다. 다만 이 반복 자료의 입력 조건은 주 캠페인의 575개 작업 조건과 정확히 겹치지 않는다. 위의 **0.168을 주 캠페인 전체의 오차 하한이나 신뢰구간으로 옮길 수 없다.** 수집기 버전을 섞으면 지연 차이가 더 커진다는 [기존 canary 평가](host_state_canary_failed_hypothesis.md)의 문제도 그대로 남는다.
