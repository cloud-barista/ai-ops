# B200 TP2 저부하 계측에서 고부하 성능 곡선 예측: 탐색 규약

2026-09-29. 원본 `serving_ALL.csv`의 범위와 일부 값을 이미 열람했다. 이 연구는 **탐색**이며 맹검 또는 독립 시험이 아니다. [고정 원본](../data/external/scherm_onprem_2026/SOURCE.md)의 SHA-256 `d7f677cf0c4ccfd8c702c8458c4e6c3d324e90292bf13e5f09e065431e8d5f9e`을 확인한 뒤 실행한다. 같은 파일의 앞선 TP2→TP4 평가 결과도 이미 봤으므로, 이번 채택 기준 통과만으로 독립 검증이라고 주장하지 않는다.

## 과제와 표본

- GPU 라벨 `NVIDIA B200`, 모델명 `Qwen/Qwen2.5-*-Instruct-AWQ`, shard 파일명의 `_tp2_`, 성공 반복 `n_ok=10`, 양의 `output_tok_s_median`과 `ttft_ms_p95`만 사용한다. `(model, concurrency)` 중복은 오류로 처리한다.
- 각 모델에서 동시성 **1, 4, 8**의 성능은 신규 모델을 잠깐 계측해 얻은 입력으로 제공한다. **16, 32, 64, 128, 256, 512**의 6개 성능은 예측 대상이다. 1024는 모델 하나에만 있어 제외한다. 예상 지원량은 **7모델 × 6 = 42개** 고부하 셀이다.
- 대상은 `log(고부하 값 / 동시성 8 값)` 두 개다. 하나는 출력 토큰/초, 하나는 원본의 `ttft_ms_p95`다. 후자는 **반복 실행 평균 TTFT의 p95**이며 요청별 p95가 아니다.
- 대상 모델 ID 전체를 훈련에서 뺀 7회 평가를 한다. 대상의 동시성 1·4·8 입력만 모델에 제공하며, 대상의 동시성 16 이상 값은 그 모델의 예측·스케일링·초매개변수 선택에 사용하지 않는다.

## 고정 비교기와 후보

각 방법은 대상 모델의 동시성 8 실측을 예측의 기준 크기로 사용한다.

1. **8 유지:** 두 지표 모두 높은 동시성에서도 8의 값으로 예측한다.
2. **이상적 선형/지연 유지:** 출력 토큰/초는 동시성 비율 `c/8`을 곱하고 TTFT는 8의 값을 유지한다.
3. **donor 동시성 중앙비:** 나머지 6모델에서 같은 목표 동시성의 `log(값/8의 값)` 중앙값을 적용한다.
4. **저부하 기울기 외삽:** 대상 모델의 4→8 로그 기울기를 높은 동시성의 `log(c/8)/log(8/4)`배 적용한다. 출력률은 음의 기울기를 0으로, 첫 토큰 지연은 양의 기울기를 0으로 잘라서 성능 방향의 과도한 반전을 막는다. 출력률의 예측은 이상적 선형 증가를 넘지 않도록, TTFT는 8 값의 1/4배에서 4배 사이로 자른다.
5. **앵커 조건부 Ridge:** `StandardScaler + Ridge(alpha=10)`, 두 목표별 별도 회귀. 특징은 `log(c/8)`, 그 제곱, `log(8의 출력률)`, `log(8의 TTFT)`, `log(4/1의 출력률)`, `log(8/4의 출력률)`, `log(4/1의 TTFT)`, `log(8/4의 TTFT)`, 모델 크기(B), coder 여부, 그리고 목표 동시성 로그와 네 저부하 비율의 상호작용이다. 모델 ID one-hot은 쓰지 않는다. 표준화는 훈련 모델에서만 적합한다. 예측 로그비는 `[-4,4]`로 잘라 양수 출력을 보장한다.

## 점수와 탐색 채택 기준

각 지표의 `|log(예측/실측)|`를 모델 안 6셀 평균 후 7모델 동일 가중 평균한다. 가장 좋은 **단일 비교기**를 지표마다 구한다. Ridge를 다음 연구 후보로 유지하려면 두 지표에서 그 비교기보다 각각 **5% 이상** 낮아야 하고, 7모델 중 **5개 이상**에서 두 지표가 동시에 각각의 최선 비교기보다 낮아야 하며, 어떤 모델·지표에서도 해당 비교기의 오차보다 **20% 초과 악화**하지 않아야 한다. 분모가 0이면 해당 악화비는 분모·분자 모두 0일 때만 1로 정의한다. 하나라도 실패하면 `EXPLORATORY_NO_GO`다.

이 시험의 좋은 점수도 같은 B200 장비·Qwen2.5 AWQ 계열·warm vLLM·정해진 입력/출력 길이에서의 **부하 반응**일 뿐이다. 앱의 실제 사용자 SLO, VM 수, GPU 가격, Ready 시각 또는 조치 전후 결과가 없어 배포·스케일 명령의 정답으로 사용하지 않는다.
