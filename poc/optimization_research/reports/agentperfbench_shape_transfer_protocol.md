# AgentPerfBench의 새 AI 모델 GPU 형상 성능 전이: 점수 전 규약

2026-09-29 작성. 구현·점수 확인 전에 이 규약을 고정한다. 목적은 경희대의 **응용 조건을 반영한 인프라 형상 추천** 중, 한 GPU 형상에서 계측한 AI 서빙 응용의 다른 형상 성능을 예측할 수 있는지 평가하는 것이다. [AgentPerfBench 공식 데이터 카드](https://huggingface.co/datasets/agent-perf-bench/AgentPerfBench)의 `trace_replay/summary.parquet`만 사용한다. 고정 revision은 `722f2b9d8a6acd222811f4e210a96865f774f6ee`, 원본 파일 SHA-256은 `568efbdae473a830ba792317fb09cfba0ea4f667db67b93d28e72637a5c71d1e`이다. 로컬 SQLite와 공개 행을 합치지 않는다.

## 모집단과 정답

각 행은 `(model, engine, profile, concurrency, num_requests, hardware)` 실행 하나다. `duration_s`, `num_requests`, `request_throughput`, `input_token_throughput`, `output_token_throughput`, `p90_ttft_ms`, `p90_tpot_ms`, `p90_e2el_ms`가 유한·양수인 행만 쓴다. `request_throughput × duration_s`가 `num_requests`와 절대 오차 `1e-5` 이내인 **전 요청 성공** 실행만 쓴다. 원본은 성공 요청만으로 지표를 집계하고 성공률 75% 미만 실행은 공개 전에 제외했으므로, 이 필터의 판정 범위는 이미 공개된 실행이다. 실패 형상이나 미측정 형상의 성공을 추정하지 않는다.

작업 그룹은 `(model, engine, profile, concurrency, num_requests)`다. GPU 후보가 2개 이상이고 `input_token_throughput × duration_s`의 그룹 최대/최소 비율이 `1.00001` 이하, `output_token_throughput × duration_s`의 비율이 `1.05` 이하인 그룹만 주 평가에 쓴다. 이 조건은 같은 프로파일 이름이라도 실제 처리 토큰량이 크게 다른 실행의 비교를 피한다. 그룹 선별에 쓰는 토큰 총량은 **평가 집단 구성에만** 사용하고 예측 특징으로는 쓰지 않는다. 모든 필터와 제외 건수를 공개한다. `1.01`과 토큰량 제한 없는 경우는 사후 선택을 하지 않는 민감도 평가로만 낸다.

그룹에서 앵커는 결과를 읽지 않고 `(GPU 개수, 기종 순서)`가 가장 작은 관측 후보로 고른다. 기종 순서는 `2080Ti, 3090, A100-40GB, H100`으로 고정한다. 앵커를 제외한 각 형상의 `p90_e2el_ms`와 `request_throughput` 자연로그가 두 정답이다. 새로운 응용의 **그룹당 앵커 한 번**은 모든 방법에 동일하게 제공한다. 평가 대상 후보가 이미 공개 벤치마크에 존재한다는 조건부 결과이며, 실제 클라우드 후보 가용성은 모른다.

## 입력·분할

모델 ID는 분할 키로만 쓴다. 예측 입력은 공개 모델명에서 읽을 수 있는 명목 크기(예: `8B`, `70B`, `8x7B→56`), 모델 계열, 엔진, 프로파일, 동시성, 요청 수, 앵커 및 목표의 GPU 기종·개수, 앵커의 실측 `p90_e2el_ms`와 `request_throughput`만 허용한다. 모델 계열은 미지 계열에 대해 `unknown` 처리한다. 목표 형상의 지연·토큰 처리량·실행시간·성공건수·출력 토큰 총량은 입력 금지다. 원본 `run_id`도 입력 금지다. 명목 크기는 정확한 활성 파라미터 수로 해석하지 않는다.

바깥 평가는 **모델 9개를 하나씩 완전히 제외**한다. 대상 모델의 모든 그룹과 형상 결과는 학습·전처리 적합·방법 선택에 쓰지 않는다. 추가로 4개 계열을 하나씩 통째로 제외한 스트레스 평가를 낸다. 이 데이터에 시간축이 없으므로 시간순 일반화로 해석하지 않는다. 모든 범주 인코딩과 수치 결측 처리는 각 훈련 분할에서만 적합한다. 구현 단계에 이 규약의 분할이나 하이퍼파라미터를 결과에 맞춰 바꾸지 않는다.

## 사전 고정 비교

각 지표를 따로 적합한다. 모두 같은 앵커 관측과 같은 학습 행을 쓴다.

1. **앵커 복사:** 다른 형상의 로그 성능을 앵커 로그 성능과 같다고 본다.
2. **donor 형상비 중앙값:** 훈련 모델의 동일 `(앵커 hardware, 목표 hardware)` 로그 성능비 중앙값을 앵커에 더한다. 해당 쌍의 donor가 5행 미만이면 목표 GPU 개수/앵커 GPU 개수 쌍 중앙값, 그것도 5행 미만이면 전체 donor 중앙값을 쓴다.
3. **직접 ExtraTrees:** 아래와 같은 특징으로 목표 형상의 로그 성능을 직접 적합한다.
4. **형상비 ExtraTrees:** 같은 특징으로 `log(목표 성능)−log(앵커 성능)`을 적합하고, 추론 때 앵커 로그 성능을 더한다. 이것이 평가할 전이 방법이다.

두 ExtraTrees는 scikit-learn의 `ExtraTreesRegressor(n_estimators=200, min_samples_leaf=5, max_features=1.0, random_state=42, n_jobs=1)`로 고정한다. 범주형은 `OneHotEncoder(handle_unknown='ignore')`, 크기·동시성·요청 수·GPU 개수·앵커 로그 관측값은 수치형으로 넣는다. 로그 지표별 모델을 별도로 적합한다. 모델 크기 파싱이 불가능하면 결측으로 두고 훈련 중앙값으로 채운다. 결과가 난 뒤 모델·특징·필터를 조정한다면 반드시 별도의 탐색 결과로 표시한다.

## 점수와 채택 기준

주 점수는 대상 모델 내 후보행 MALE(`|log 예측−log 관측|`) 평균을 낸 다음 **9개 모델을 동일 가중**한 값이다. 두 지표를 각각 보고한다. 후보행 가중 전체 MALE, 모델별 점수, 모델 계열 전체 제외 점수, 두 성능을 앵커보다 개선/악화시키는 방향의 짝별 적중률도 낸다. 단순 후보 선택의 보조 검사는 같은 GPU 기종 내 여러 개수 형상을 가진 그룹에 한해 실제 후보의 중앙값으로 만든 두 제약을 동시에 만족할 것으로 예측된 최소 GPU 개수를 선택하는 것이다. 이 제약은 사용자 SLO가 아니라 후향적 검산용 합성 사례다. 실패 형상이 원본에서 사라졌을 수 있으므로 이 선택 결과를 운영 승인률로 해석하지 않는다.

형상비 ExtraTrees를 우선 연구 방법으로 **채택**하려면, 두 지표의 9모델 균등 MALE이 각각 가장 강한 단순 donor 형상비 기준선과 직접 ExtraTrees보다 최소 5% 작고, 각 지표에서 9개 모델 중 최소 6개를 이겨야 한다. 계열 전체 제외 어느 하나에서 두 지표 중 하나라도 직접 ExtraTrees보다 10% 넘게 나빠지면 채택하지 않는다. 합성 후보 선택에서 잘못 충족으로 판단한 건수가 직접 ExtraTrees보다 늘어도 채택하지 않는다. 하나라도 실패하면 `do_not_adopt`를 기록하고, 해당 데이터에서 확인된 좁은 성능만 설명한다. 이 기준은 실제 SLO, 가격, VM 생성·Ready 또는 Scale-out/in 효과의 검증을 대신하지 않는다.
