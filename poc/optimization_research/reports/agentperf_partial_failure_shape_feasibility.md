# AgentPerfBench 요청 일부 실패를 GPU 형상 선택 정답으로 쓸 수 있는가

2026-09-29 원본 적격성 점검. [공식 AgentPerfBench 카드](https://huggingface.co/datasets/agent-perf-bench/AgentPerfBench/blob/722f2b9d8a6acd222811f4e210a96865f774f6ee/README.md)는 성공률 75% 미만 실행을 제외하고, 공개 요약 지표를 성공한 요청에서만 계산했다고 설명한다. 같은 revision의 `trace_replay/summary.parquet` SHA-256 `568efbdae473a830ba792317fb09cfba0ea4f667db67b93d28e72637a5c71d1e`를 읽었다. 이 점검은 성능 전이 학습과 구별되는 **부분 완료 위험의 형상별 감독 정답** 적격성 검사이며 모델은 학습하지 않았다.

원본 2,932행에서 `request_throughput × duration_s`는 모두 정수 요청 수와 최대 `9.1e-13` 이내에서 일치한다. 이를 성공 요청 수로 해석하면 724행은 `num_requests`보다 적은 요청을 완료했다. 최저 공개 성공률은 75.0134%다. 그러나 요약 파일에는 요청별 오류·실패 이유와 공개 전에 빠진 실행의 후보 목록이 없다. 다음 숫자는 `model, engine, profile, concurrency, num_requests`가 **모두 같은** 공개 실행끼리만 비교했다.

| 관측 비교 | 수 |
| --- | ---: |
| 후보 GPU 형상 2개 이상인 그룹 | 761 |
| 같은 그룹에서 전 요청 완료와 일부 실패 형상이 함께 있는 그룹 | 56 |
| 혼합 그룹이 있는 모델 | 9개 중 8개 |

56개 혼합 그룹은 표면상 GPU 형상에 따라 완료 여부가 달라진 사례다. 하지만 같은 `(작업 조건, 형상)`의 반복이 없고 성공률 75% 미만 실행은 표본에서 삭제됐다. 따라서 혼합 여부가 형상의 안정된 실패 확률인지, 단일 실행의 일시적 변동인지 구분할 수 없다. 같은 그룹에서 혼합되지 않은 705개도 미공개 후보·실패 원인을 복원하지 못한다. 부분 실패를 OOM이나 인프라 부적합성으로 이름 붙일 근거가 없다.

**판정: 현재 요약 자료로 GPU 형상별 실패 확률 또는 안전 승인 모델을 학습·채택하지 않는다.** `전 요청 완료/일부 실패` 표시는 공개된 벤치마크 실행의 관측 품질 플래그로만 쓴다. 운영용 호환성 정답을 만들려면 실행을 시도한 **전체 후보 목록**, 요청별 성공·오류 원인, 같은 조건·형상의 반복, 그리고 실제 서비스 SLO가 필요하다. VM 배포·Scale-out/in 효과에는 추가로 조치 발행·Ready·이후 사용자 요청의 연결이 필요하다.

재현: `python scripts/audit_agentperfbench_support.py`의 `trace_replay.partial_failure_shape_support`에서 위 그룹 수를 확인한다. 스크립트는 고정 원본 세 파일의 SHA-256을 검사한다.
