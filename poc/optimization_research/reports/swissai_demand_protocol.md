# SwissAI 활성 모델의 10분 요청량 p90 예측: 사전 고정 탐색 규약

작성일: 2026-09-28. 이 문서는 **이 요청량 예측의 학습·검증·시험 점수를 계산하기 전에** 고정한다. SwissAI 원본은 이미 [전량 감사](swissai_trace_full_audit.md)했고, 같은 자료의 *요청 종료시간*은 [별도 탐색](swissai_exploratory_findings.md)에 사용했다. 따라서 이 실험은 새 과제의 사전 규약을 가진 **탐색**이며, 완전히 보지 않은 독립 데이터 검증으로 부르지 않는다. 2025-08-16 UTC 이후는 별도 후속 평가용으로 남겨 두고 이 규약의 학습·모델 선택·시험 점수에는 사용하지 않는다.

## 연구 질문과 자료

경희대의 Scale-out/in 판단기에 넣을 수 있는 **미래 수요 신호**를 연구한다. 활성 AI 모델에 대해 5분마다 다음 10분 요청 건수의 조건부 90분위수를 예측할 때, 과거 요청 도착량에 *이미 사용 가능해진 완료 결과*를 더하면 예측이 나아지는가? 정답은 해당 모델의 `created_utc_us`가 `[t,t+10분)`에 속하는 요청 수다. 이는 요청량 상한 예측이며 실제 적정 VM/GPU 수나 `SCALE_OUT/IN` 명령의 효과가 아니다.

입력은 고정 revision `c3dd66602b564ce189f7db81115620413e646cd5`의 SwissAI 원본을 전량 정렬한 `data/external/swissai_serving_trace/requests_sorted.parquet`이다. 원본 SHA256은 `79c92fd40752e40a6cac1fc897491ea2f54f37939dc4dcc48c96ea06383c81b7`, 축약 파일 SHA256은 `d5c2bf4cc038f936a9713f8fc7c0430703ddd1c03ed0518fb65aaf68e160997b`이다. 생성시각은 UTC가 명시되어 있다. 완료시각 중 시간대가 없는 값은 [감사](swissai_trace_full_audit.md)와 같이 UTC로 해석하되, 이 해석을 한계로 남긴다. 모델명은 내부에서 UTF-8 SHA256의 앞 10자리 별칭으로만 출력하며 원문 모델명·원시 요청 ID를 산출물에 기록하지 않는다.

## 시간 분할과 모델 선정

모든 경계는 UTC 자정이다. [기존 발생 건수 감사](swissai_exploratory_followup_protocol.md)가 고른 첫 충분한 시작일인 **2025-01-16**부터 시작한다. 학습은 `[2025-01-16, 2025-06-16)`, 검증은 `[2025-06-16, 2025-07-16)`, 시험은 `[2025-07-16, 2025-08-16)`이다. 이는 요청 **발생 건수만** 확인하고 정한 경계다. 각 기간의 전체 요청은 각각 7,195,026건, 1,521,213건, 5,911,771건으로, 긴 학습 이력과 한 달 검증·한 달 후행 시험을 제공한다. 모델 예측 점수·미래 요청량 분포·완료 결과는 경계 선택에 사용하지 않았다. 시험의 마지막 판단도 `t+10분 ≤ 2025-08-16 00:00 UTC`여야 한다.

모델 집합은 **학습·검증 기간 요청 수만으로** 선택한다. 학습 요청 ≥5,000건과 검증 요청 ≥10,000건인 모델 중 검증 요청 수 상위 **2개**를 고른다. 동률이면 별칭 사전순이다. 이 규칙의 결과는 아래와 같다. 시험 요청 수는 모델 선택에 사용하지 않는다.

| 모델 별칭 | 학습 요청 | 검증 요청 |
| --- | ---: | ---: |
| `45363f1dab` | 5,841 | 1,316,939 |

판단 시각 `t`는 각 5분 경계다. 학습 첫 120분은 전체 입력 이력을 채우기 위해 제외한다. 해당 모델이 `[t-60분,t)`에 요청을 하나 이상 받았을 때만 **활성**으로 정의한다. 정답 창 `[t,t+10분)`이 같은 분할 안에서 끝나야 해당 분할의 행으로 쓴다. 검증·시험의 입력에는 그 시각 이전의 다른 분할 요청과 완료 피드백을 쓸 수 있으나, 학습 계수·기준선 선택에는 해당 시험 기간의 정답이나 미래 피드백을 쓰지 않는다. 시험 중 이미 도착·완료된 과거 요청은 온라인 방식대로 다음 판단의 입력으로 사용할 수 있다.

## 무기록 공백과 판단 가능 시각

원본에는 수집기 생존 신호가 없다. 전역 요청이 오래 없는 시각을 실제 수요 0으로 단정하지 않기 위해, `t` 직전 10분 `[t-10분,t)`에 **어느 모델이든** 도착 요청이 없으면 그 시각의 예측을 보류한다. 또한 전역 연속 도착 사이에 **6시간 이상** 빈 구간이 생기면, 그 공백을 *끝내는 첫 요청의 도착 시각* `b`가 관측된 뒤 `[b,b+120분)`에는 예측을 보류한다. 이 120분은 가장 긴 입력 이력을 새로 채우기 위한 것이다. `b` 전에는 그 공백이 6시간으로 끝날지 알 수 없으므로 **미래의 다음 요청을 보고 과거 판단을 소급 삭제하지 않는다.** 처음 10분의 무기록은 여전히 진짜 무부하와 수집 누락을 구분할 수 없으며 결과의 한계로 기록한다.

## 시점별 특징과 비교 방법

두 학습기의 **행·정답·가중치·하이퍼파라미터는 동일**하다. 공통 입력은 해당 모델과 전체 서비스의 지난 5·10·30·60·120분 도착 건수 (`created_utc_us < t`), 해당 모델 별칭의 사전순 0/1 정수 부호, UTC 시각의 하루 내 분과 한 주 내 분의 사인·코사인이다. 모든 집계 창은 `[t-w,t)`다. `reported_input_tokens`, 완료시각, 최종 상태는 공통 입력에 없다. 전역 최근 10분 도착 조건은 두 학습기와 모든 기준선에 똑같이 적용한다.

완료 피드백을 추가하는 학습기는 요청의 `finished_utc_us`가 존재하고 `elapsed_us > 0`인 경우에만 `available_at = finished_utc_us + 1시간`으로 계산한다. `available_at < t`인 요청의 결과만 사용할 수 있다. 추가 특징은 **해당 모델**에서 최근 30·120분의 *결과 사용 가능 시각* 기준 완료 건수, 최근 120분 완료시간의 90분위수에 `log1p(min(초,3600))`를 적용한 값, 최근 120분 `ERROR` 비율, 최근 120분 완료 건수가 0인지 여부다. 분위수는 오름차순 `ceil(0.9×n)`번째 값을 쓴다. 분모가 0인 비율·분위수는 0으로 채우고 결측 표시를 함께 준다. 상태와 종료시간은 완료 전에 읽지 않는다. 실제 결과 전달 시각은 없어서 완료 뒤 1시간이라는 보수적 오프라인 가정이다.

학습기 두 개 모두 `HistGradientBoostingRegressor(loss='quantile', quantile=0.9, max_iter=200, learning_rate=0.05, max_leaf_nodes=15, min_samples_leaf=100, l2_regularization=1.0, early_stopping=False, random_state=42)`를 사용한다. 학습 자료 내 두 모델이 총 가중치의 절반씩 차지하도록 모델별 행에 `전체 학습 행 수/(2×그 모델 학습 행 수)` 가중치를 준다. 예측은 `max(0,q)`로 자른다. 검증 점수로 하이퍼파라미터·특징·가중치를 고치거나 시험 자료로 다시 적합하지 않는다.

단순 기준선은 (1) 직전 10분 요청 수의 지속, (2) 직전 120분의 서로 겹치지 않는 10분 창 12개의 경험적 90분위수(오름차순 11번째 값), (3) 학습 분할의 모델별 활성 판단 정답 90분위수 고정값이다. (3)의 분위수도 오름차순 `ceil(0.9×n)`번째 값이다. 모두 현재 `t`까지 끝난 도착 창만 사용한다. 세 방법의 검증 **두 모델 균등 평균** pinball 손실이 가장 낮은 하나를 **단순 기준선 대표**로 고정한다. 동률 순서는 (2), (1), (3)이다. 세 기준선 모두 시험 결과를 보고한다. 도착 정보만 쓰는 학습기가 주된 같은 용량 비교 대상이다.

## 품질 판정, 지표, 결론

원본·축약 파일 해시 또는 필수 열 검사가 실패하면 점수를 계산하지 않는다. 각 선택 모델에서 학습·검증·시험의 판단 가능 행이 각각 ≥500개이고, 정답 0과 양수가 각각 ≥100개여야 한다. 전역 격자의 판단 가능 비율은 각 분할에서 ≥20%, 활성 판단에서 최종 판단으로 남는 비율은 각 모델·분할에서 ≥50%여야 한다. 하나라도 실패하면 모델 성능 판정을 중단하고 자료 결손을 보고한다. 위 발생시각 감사에서는 이 조건을 모두 만족한다. 구현 시 집계가 위 표와 다르면 점수 계산 전에 시각·경계 구현을 다시 확인한다.

1차 지표는 `ρ₀.₉(y-q) = 0.9 max(y-q,0) + 0.1 max(q-y,0)`인 **p90 pinball 손실**이다. 두 선택 모델의 시험 손실 평균을 각각 계산한 다음 **두 모델의 평균을 다시 같은 비중으로** 합친 값을 주 점수로 쓴다. pooled 판단 행 기준 손실, 모델별 손실, 관측 포괄률 `P(y≤q)`, 평균 예측 건수와 실제 평균 건수, 5분 판단 기준 예측 처리시간·메모리를 함께 보고한다. 2025-07-16부터 7일씩 네 개 완전 블록과 마지막 3일을 따로 보인다. 중첩된 10분 정답과 적은 주별 블록 때문에 판단 행별 독립 신뢰구간이나 유의확률은 제시하지 않는다.

**탐색적 성공**은 품질 조건을 통과하고, 완료 피드백 추가 학습기의 두 모델 균등 평균 시험 손실이 (a) 도착만 쓰는 학습기와 (b) 검증으로 고른 단순 기준선보다 **각각 상대 5% 이상 낮고**, 선택한 두 모델 각각에서 도착만 쓰는 학습기보다 손실이 높지 않으며, 네 개 완전 7일 블록 중 **세 개 이상**에서 도착만 쓰는 학습기보다 낮고, 두 모델의 시험 포괄률이 각각 **85% 이상**일 때다. 블록에 판단 가능 행이 100개 미만이면 해당 블록은 판단 불가로 보고하며, 유효한 완전 블록이 네 개보다 적으면 성공을 선언하지 않는다. 비교 기준을 시험 점수를 본 뒤 바꾸지 않는다. 성공하더라도 완료 피드백의 *관측 요청량 예측 이득*만 뜻한다.

## 적용 범위와 후속 보류 자료

이 추적에는 배포 형상, VM/GPU 수, 준비 지연, 사용자 지연 SLO, 스케일 명령과 결과가 없다. 도착량 예측이 나아져도 필요한 노드 수나 scale 정책의 성과를 입증하지 못한다. 한 서비스의 두 선택 모델과 활동 시점만 평가하므로 새 모델, 수집 공백, 다른 CSP·지역으로의 일반화도 별도 과제다. 2025-08-16 이후는 이 평가에서 열지 않는다. 첫 시험 결과를 보고 새 특징이나 규칙을 만들면 새 규약으로 표시하고, 남겨 둔 기간의 예측 점수는 그 후속 규약을 고정하기 전까지 계산하지 않는다.
