# 측정 없는 정적 추천의 donor 보정 보류 문턱: 시험 전 규약

2026-09-28. 이 규약은 새 실험의 바깥 분할 점수를 계산하기 전에 작성했다. [기존 zero-probe 추천기](cold_start_policy_findings.md)는 원시 로그 여유 0과 전체 질의의 강제 선택률 25/50/75%를 비교했지만, **donor 모델만으로 양의 여유를 선택해 질의별 보류하는 규칙**은 시험하지 않았다. [결정 합의](decision_consensus_findings.md)와 [비대칭 여유](asymmetric_margin_findings.md)는 대상 모델에서 8개 후보를 이미 측정한 K8 예측을 다뤘으므로 이 문제와 입력 예산이 다르다. 동일한 기존 SQLite를 다시 사용하며 새 호스트·새 사용자 요청에 대한 확증은 아니다.

## 데이터, 모델, 외부 평가

원본은 SHA-256 `b7bba7963e8a309b6a8502a1d98eefb150476b1381ec016beeb68cbf63fae906`인 `poc/optimization_research/data/audit_v1/measurements.parquet`의 `khu-hf-local-exhaustive` 적격 GPU 4,600행이다. 9개 모델·575개 `workload_group`마다 GPU 1/2 × CPU affinity 2/4/8/16의 8개 후보가 있다. GPU 2개는 같은 호스트의 두 물리 GPU이지 VM 두 개가 아니다. 바깥 분할은 9개 모델 각각을 완전히 제외하는 주 평가와 BERT 4종 공동 제외의 보조 평가이다. 대상 모델의 성능 측정, 원래 수집기 SLO, 모델 ID는 입력에 넣지 않는다. 모델 파라미터 바이트는 역사적 `result_json`에서 읽은 메타데이터이며 등록 시 제공된다고 가정한다.

회귀기는 기존 `cold_start_policy.py`와 같은 `ExtraTreesRegressor(n_estimators=200, min_samples_leaf=2, max_features=1.0, random_state=42, n_jobs=2)` 하나이다. 입력은 그 코드의 `STATIC` 8개 정적 특징, 출력은 `log(latency_p95_ms)`와 `log(examples_per_second / batch_size)` 두 값이다. 바깥 fold의 25개 `(지연상한 L, 요청/초 하한 R)`은 **바깥 donor 모델의** 두 성능 분포에서 각각 10/25/50/75/90백분위를 조합해 만든다. 같은 workload의 25개 질의는 서로 상관된다. 합격 정답은 후보 실측 지연 ≤L 및 실측 요청/초 ≥R이다.

후보의 원시 로그 여유는 `min(log L−예측 log 지연, 예측 log 요청/초−log R)`이다. 양의 여유 문턱 `m`을 넘는 후보 중 GPU 수, 이어서 CPU 코어 수가 작은 첫 후보를 승인한다. 후보가 없으면 `ABSTAIN`한다. 비교할 고정 문턱은 `m=0`, `0.05`, `0.20`이다. donor 선택 후보는 **양의** `{0.05, 0.10, 0.20, 0.30, 0.50}`이며, 통과하는 값이 없으면 `ABSTAIN_ALL`이다. 전체 대상 질의를 사후 순위화해 승인 수를 맞추지 않는다.

## donor-only 문턱 선택

바깥 대상 H를 뺀 donor에서 다시 D를 하나씩 제외한다. 매 D 예측기는 H와 D를 뺀 모델에만 적합한다. D용 25개 SLO도 H와 D를 뺀 모델로만 만든다. D의 후보 실측은 문턱별 **donor 검증 점수**에만 쓰며 H의 후보 실측·SLO는 문턱 선택에 쓰지 않는다. 각 바깥 H에 대해 D들의 질의·승인·성공·잘못 승인을 합산한다.

선택 기준은 donor 합계에서 (a) 승인 중 잘못 승인율 ≤10%, (b) 0마진 성공 승인 수의 ≥50%를 유지하는 것이다. 아울러 **각 donor D**에서 후보 문턱이 합성 질의 ≥50개, 서로 다른 `workload_group` ≥5개를 승인해야 유효한 안전률 표본으로 취급한다. 이 floor를 못 채우면 승인 위반이 0건이어도 후보가 부적격이다. 모두 만족하는 양의 후보 중 **가장 작은 m**을 택한다. 적합 후보가 없으면 `ABSTAIN_ALL`을 택한다. 0마진 성공이 0이면 양의 후보는 부적격이다. 동률·경계의 `>=`를 고정한다. 선택된 m과 모든 donor 후보 점수, 원본·규약·코드 SHA-256을 동결한 다음에 바깥 H의 실측 정답으로 점수화한다. 바깥 점수에 맞춘 재선택은 하지 않는다.

## 보고 지표와 판단

9개 바깥 fold와 BERT4 fold는 섞지 않고 보고한다. 각 fold·방법에서 전체 질의, 승인, 성공, 잘못 승인, 실측상 가능한 질의, 가능했으나 보류한 질의, 승인 중 잘못 승인율을 낸다. `ABSTAIN_ALL`은 분모가 0인 승인율을 0%라고 표시하지 않고 미정의로 둔다. 전체 성공·잘못 승인 수와 **각 모델별** 수를 함께 표기한다. 또 실측상 8후보가 **모두 실패/일부만 성공/모두 성공**인 질의를 나눠 승인 구성을 보조 진단한다. 이 층화는 선택·게이트에 쓰지 않는다. 25개 합성 SLO가 한 측정을 재사용하므로 `workload_group`을 묶어 2,000회 paired bootstrap(seed 2026)을 하고, 선택 방법−고정 0.05의 성공 및 잘못 승인 건수 차이의 기술적 95% 구간을 낸다. 바깥 BERT4는 주 9분할과 원본 측정이 겹치므로 독립 재현으로 취급하지 않는다.

사전 연구 게이트: donor 선택법이 주 9분할 합계에서 0마진 대비 잘못 승인을 ≥25% 줄이고 성공 승인을 ≥75% 유지하며, 고정 0.05 대비 승인 중 잘못 승인율이 높지 않아야 한다. 또한 **각 바깥 모델**에서 합성 질의 ≥50개와 서로 다른 `workload_group` ≥5개를 승인하고, 0마진 성공 승인의 30%를 넘게 잃지 않아야 한다. `ABSTAIN_ALL`이나 최소 승인 floor 미달은 유효한 안전률 증거로 인정하지 않고 게이트 실패로 기록한다. BERT4 fold에서도 같은 방향인지 별도 보고한다. 이 게이트는 이미 알려진 자료에서 정한 탐색 기준이며 통과해도 실제 배포 안전성을 뜻하지 않는다.

고정 여유를 추가하는 만큼 승인 수가 줄 수 있다. 잘못 승인 수 감소만으로 우위라고 하지 않고 성공 유지와 승인 중 오류율을 함께 본다. 더 엄격한 문턱이 가장 싼 후보를 넘어 더 비싼 후보를 택할 수도 있으므로 선택 GPU·코어와 정확 최소 형상 비율도 보조 지표로 저장한다. 실제 사용자 SLO, GPU 종류·가격, VM 생성·삭제, 스케일링 전후 효과는 이 자료에 없다.
