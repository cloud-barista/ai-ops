# H100/vLLM 단계별 `/health` 준비시간 상한: 점수 전 탐색 규약

작성일: 2026-09-29. 이 규약은 학습기 점수를 계산하기 전에 고정한다. 원본의 행 구조와 200회 성공 여부, 조건별 대략적인 시간 범위를 이미 확인했으므로 **사후에 시작한 탐색**이다. 새 모델 계열·호스트·날짜의 독립 검증이 아니다.

## 질문과 자료

[공개 실험의 고정 커밋](https://github.com/mkurup27/cold-start-latency-on-serverless-inference/tree/39e20fbbbc26722650a9115b704fea52d6e32766)의 `data/final.jsonl` SHA-256은 `e70ff5175249a090ce3c2ece3e17251c27fb9e2429d03526b4d70e854d61c07b`이다. MIT 출처는 원본 저장소의 LICENSE에 남긴다. H100 80 GB 1대, vLLM 0.26.0, Qwen3 크기 0.6/1.7/4/8B, 캐시 조건 C0–C4 각 10회, 총 200회다. C0/C1/C3의 120회와 C2/C4의 80회는 서로 다른 실행 묶음이므로 캐시 조건 사이의 차이를 인과적인 절감 시간으로 해석하지 않는다.

정답은 각 단계 사건의 시각에서 **실험의 첫 `/health` 성공 시각까지 남은 초**다. 실패/검열 사례가 없어 준비 실패 위험은 학습할 수 없다. `first_token`은 준비 이후의 별도 관측으로만 확인하며 정답이나 입력에 쓰지 않는다. 이전 로컬 SQLite의 `load_seconds`는 캐시된 모델·토크나이저의 `from_pretrained` 적재 구간으로, 이 실험의 컨테이너 준비시간과 다른 정답이다.

## 단계와 결정 시점 정보

고정 단계: `pull_start`, `run_start`, `weights_loaded`, `compile_done`, `graph_capture_done`, `engine_ready`. 앞의 두 시각은 `t`, 뒤의 네 시각은 `vllm.markers.<name>.abs`에서 얻는다. 각 단계에서 사용할 수 있다고 **가정하는** 수치는 등록 모델명의 명목 파라미터 수(B), 그 단계 시각까지 `pull_start` 이후 경과한 시간, 그리고 오라클 실험 조건을 허용하는 방법에 한한 C0–C4 조건이다. 모델 ID 문자열 자체, trial 번호, `source`, 컨테이너 ID, 로그 경로, 요청 시도 수, 사후 GPU 상태, 미래 단계 시각, `spans_s`, 전체 실행의 파생시간은 특징에서 제외한다. 모델 크기는 등록 시 알 수 있다고 가정하고 원본 모델명에서 파싱한다.

공개 파일은 **단계 시각**을 담지만 그 단계 로그가 온라인 판단기에 언제 전달됐는지 `available_at`이 없다. 따라서 점수는 사건 시각에 단계가 즉시 보인다는 오프라인 가정에서만 유효하다. 실제 판단기로 쓰려면 단계 로그 전달 시각을 새로 기록해야 한다. C0–C4도 실험자가 만든 캐시 상태 메타데이터로서 실제 운영에서 자동 관측된 값이 아니다. 이를 쓴 방법은 `oracle-cache`, 쓰지 않은 방법은 `no-cache`로 분리한다.

## 학습·평가 방법

- **외부 분할:** 모델 크기 하나의 50회 전체를 보류하고 나머지 세 크기의 150회로 적합한다. 0.6B와 8B는 훈련 크기 범위 밖 외삽이다. 각 모델의 여섯 단계·다섯 캐시 조건을 같은 분할에 유지한다.
- **강한 단순 기준선:** 단계별 donor 잔여시간의 경험적 90분위(`no-cache p90`), 단계×조건별 donor 잔여시간의 경험적 90분위(`oracle-cache p90`). 각 단계×조건에는 donor trial 30회가 있다. NumPy 선형 보간 분위수이며 유한표본 피복 보장은 없다.
- **학습기:** 단계마다 별도의 `QuantileRegressor(quantile=.9, alpha=.01, solver='highs')`. 모델 크기와 단계까지의 경과시간을 donor에서만 표준화하고, `oracle-cache` 변형에만 C1–C4 원핫 열을 추가한다. 계수·전처리·모든 분위수는 외부 보류 모델의 결과를 사용하지 않는다. 음수 출력은 준비시간이므로 0초로 자른다. 두 변형 모두 같은 고정 설정으로 적합하며 시험 결과로 초모수를 고르지 않는다.
- **주 점수:** 90분위 pinball 손실을 각 보류 모델의 50 trial에서 먼저 계산해 네 모델을 동일 가중 평균한다. 단계별 평균과 전체 여섯 단계 동일 가중 평균을 구한다. 캐시 조건별 손실·피복률도 각 보류 모델의 10 trial에서 먼저 구해 같은 조건을 네 모델 동일 가중으로 집계한다. 여섯 단계는 같은 200개 실험을 재사용하므로 독립 1,200건으로 세지 않는다.
- **과소예측:** `실제 남은 시간 > 예측 상한` 비율, 과소예측 크기의 양수 부분 평균·최대, 5초 및 10초 초과 비율을 단계·조건·보류 모델별로 보고한다. 이 문턱은 연구 진단값이며 사용자 SLO나 허용 장애시간이 아니다. 네 모델밖에 없으므로 trial 행 부트스트랩을 독립 모델 일반화 구간으로 제시하지 않는다.

**탐색적 채택 기준:** 각 변형의 학습기는 대응하는 단순 기준선 대비 전체 여섯 단계 모델 동일 가중 pinball이 **5% 이상 낮고**, 5초 초과 과소예측 비율이 높지 않으며, 모델 전체 제외 네 분할 중 **최소 세 분할**에서 여섯 단계 평균 pinball이 낮아야 준비시간 연구 후보로 남긴다. 한 조건이나 단계만 개선되면 그 층의 진단 결과로만 적는다. 조건 사용 변형이 통과해도 캐시 상태의 실제 관측성과 독립 자료 검증이 없어 배포/스케일 명령에 연결하지 않는다.

## 게이트와 결과 경계

점수 전에 원본 해시, 정확히 4×5×10 성공 trial, 단계 시각 단조 순서와 `first_token ≥ health_ok`, 유한·비음수 잔여시간을 검사한다. 한 항목이라도 실패하면 점수를 내지 않는다. 원본에 실패 사례·명령 ID·VM 생성·삭제·실사용 요청 SLO가 없으므로, 어떠한 결과도 `DEPLOY/UPDATE/SCALE_OUT/SCALE_IN/KEEP`의 행동 효과, 캐시 개입의 인과 이득, 실제 CSP 대기시간 또는 준비 완료의 독립 증거를 뜻하지 않는다.
