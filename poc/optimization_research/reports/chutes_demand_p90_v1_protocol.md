# Chutes 모델별 다음 5분 요청량 p90: 점수 전 고정 규약

2026-09-29. 이 실험은 [Chutes TTFT 검증](chutes_ttft_tail_v1_findings.md)의 결측과 [SwissAI 상대 수요 가설](swissai_scale_adaptive_protocol.md)을 본 뒤 설계했다. 앞 실험의 학습 구간에서 고정한 35개 모델, 학습·검증 구간의 요청 시작 건수·활성 판단 지원량은 이미 확인했다. **이 새 목표의 학습기·기준선 검증 점수와 row group 74–76의 요청 값은 보지 않았다.** 따라서 검증은 탐색적 모델 선택, 후행 시험은 같은 서비스의 별도 시간 구간 확인으로만 해석한다. 이 규약·구현·합성 테스트의 SHA-256을 후보 점수 계산 전에 `artifacts/chutes_demand_p90_v1/frozen_manifest.json`에 고정한다.

## 목표·출처·시각

- 공식 [Harvard MadSys Chutes 카드](https://huggingface.co/datasets/harvardMadsys/chutes_metadata)의 revision `85722e694bf7bb8a5a5ccdf70424fa5998372467`, 샤드 `data/trace/train-00044-of-00045.parquet`(2,046,207,562 bytes, 연결 SHA-256 `ca99b91b33d04bf56f3d0b26241c4a083a7e1579f0f571887eee4ee1004c90dd)를 쓴다. 기존에 고정 추출한 row group 65–73을 재사용하고, 검증 통과 전에는 74–76을 추출·열람하지 않는다. 원본 정규화 시각은 실제 달력 날짜·요일이 아니다. CC BY 4.0이다.
- 5분 격자 결정시각 `t`의 정답 `y(m,t)`는 모델 `m`의 `chat_stream` 또는 `completion_stream` 요청 중 `started_at∈[t,t+5분)`인 **기록 건수**다. 단위는 요청/5분이고 0도 정답이다. TTFT, 요청 완료, `instance_id`, 캐시·토큰·상태 유무로 시작 요청을 제외하지 않는다. 요청 시작 기록의 실제 전달 지연 및 수집기 생존 신호가 없으므로 실시간 입력 가용성이나 실제 전체 수요를 입증하지 않는다. 정답은 해당 창 종료 `t+5분`에 관측 가능하다고 가정한다.
- 이전 [TTFT 고정 검증](../artifacts/chutes_ttft_tail_v1/validation.json)의 **학습만으로 선택된** `registry` 35개를 그대로 쓰며 목록·순서를 해시로 고정한다. 이 선택은 고요청·유효 TTFT 모델 쪽으로 편향될 수 있어 모든 모델로 일반화하지 않는다. 검증·시험 자료로 모델을 추가하거나 바꾸지 않는다.
- 해당 모델의 과거 `[t−30분,t)` 스트리밍 시작 건수가 **30 이상**일 때만 예측한다. 이 적격 여부는 결정 시점의 과거만으로 정한다. 미래 요청 수가 0이거나 작은 창을 사후 제외하지 않는다. 모델별·전체 서비스의 과거 `[t−5,t)`, `[t−10,t)`, `[t−30,t)`, `[t−60,t)` 시작 건수만 입력한다. 전체 서비스 집계에는 등록되지 않은 모델의 스트리밍 시작도 포함한다. 모델 ID는 학습 등록 순서로 one-hot 부호화한다. 인스턴스·TTFT·캐시·완료 후 토큰·익명 사용자·가짜 날짜/요일은 사용하지 않는다.

## 고정 비교 방법

모든 방법은 동일한 과거 적격 행에서 예측한다. 두 학습기는 학습 행에서 모델별 총 가중치가 같도록 행에 `N/(35 n_m)`을 주고, `HistGradientBoostingRegressor(loss='quantile', quantile=0.9, max_iter=200, learning_rate=0.05, max_leaf_nodes=15, min_samples_leaf=30, l2_regularization=1, early_stopping=False, random_state=42)`를 사용한다. 예측은 실수 요청 건수로 채점하며 음수만 0으로 자른다.

1. **직전 5분 지속:** 해당 모델의 `[t−5,t)` 시작 건수.
2. **과거 30분 경험적 p90:** 직전의 서로 겹치지 않는 5분 시작 건수 6개의 nearest-rank p90, 즉 오름차순 여섯 번째(최댓값).
3. **절대 수요 학습기:** 해당 모델·전체 서비스의 과거 5·10·30·60분 건수 각각에 `log1p`를 적용하고 모델 one-hot을 더해 미래 5분 시작 건수 `y`의 q0.9를 적합한다.
4. **상대 수요 학습기(후보):** 과거로 `s_m=max(1,m5,m30/6,m60/12)`, `s_g=max(1,g5,g30/6,g60/12)`을 구한다. 각 `w∈{5,10,30,60}`의 모델 입력은 `m_w/[s_m(w/5)]`, 전체 서비스 입력은 `g_w/[s_g(w/5)]`이며 모델 one-hot을 더한다. 정답 `z=log1p(y/s_m)`의 q0.9를 적합하고 `max(0,s_m×expm1(q_z))`로 되돌린다. 이는 SwissAI 방법을 다른 AI 서빙 추적과 5분 목표에 적용한 재검증이며 새 알고리즘의 최초성을 주장하지 않는다.

## 자료 게이트·지표·채택 문턱

사전 지원량 확인에서 35개 모델×학습 132개 창=4,620행, 검증 55개 창=1,925행이며 과거 적격은 각각 4,004/1,514행이었다. 학습 적격은 모든 모델 ≥72개, 검증은 모든 모델 ≥15개다. 학습/검증의 기록된 미래 시작은 2,623,340/1,164,833개다. 이 값은 새 예측 점수가 아니다. 구현 집계가 다르면 점수를 중단한다.

- 출처 revision·크기·해시, 기존 추출 파일 해시, 요청 ID 유일성, 시작시각 전역 단조성, 그룹별 1,001,472행, 첫/마지막 완전 창을 검사한다. 각 분할에서 전체 서비스의 시작 요청이 0인 5분 칸이 5%를 넘으면 수집 공백 가능성으로 점수를 중단한다.
- 학습 과거 적격 ≥3,000행·고정 35개 모델 모두 ≥50행, 검증 적격 ≥1,200행·모두 ≥12행이어야 적합/검증 점수를 낸다. 시험은 적격 ≥800행·고정 모델 중 ≥25개가 각각 ≥12행이어야 주 점수를 낸다. 시험의 평가 모델은 **사전 규칙에 따라 과거 적격 판단이 ≥12개인 고정 등록 모델**이며, 제외된 ID와 지원량을 공개한다. 시험 모델 선정에 미래 요청 수나 예측 오차를 쓰지 않는다. 지원량 게이트 실패 시 주 점수는 내지 않는다.
- 각 행의 q0.9 pinball 손실은 `0.9 max(y−q,0)+0.1 max(q−y,0)`이다. **주 지표**는 모델별 평균 손실을 구한 뒤 모델을 같은 비중으로 평균한 값이다. 전체 행 평균, 모델별 손실, 모델 균등·전체 행 피복률 `P(y≤q)`, 모델 균등 평균 과소예측량 `E[(y−q)+]`, 1시간별 모델 균등 손실을 함께 보고한다. 1시간 블록은 평가 모델 ≥10개·판단 ≥30행일 때만 승패에 넣는다. 연속 창을 독립 표본으로 취급한 신뢰구간은 주장하지 않는다.
- **검증 통과:** 후보 주 손실이 세 기준선 **각각**보다 상대 ≥5% 낮고, 절대 수요 학습기보다 손실이 낮은 평가 모델 비율 ≥60%, 후보의 모델 균등 피복률 ≥85%, 후보의 모델 균등 평균 과소예측량이 절대 수요 학습기 이하일 때만 통과한다. 어느 하나라도 실패하면 시험 row group을 열지 않고 미채택한다.
- **시험 채택:** 같은 손실 개선이 세 기준선 각각에 상대 ≥10%, 모델 승리 ≥70%, 충분한 1시간 블록 ≥4개 중 ≥70% 승리, 모델 균등 피복률 ≥85%, 모델 균등 과소예측량이 절대 수요 학습기 이하일 때만 채택한다. 모든 문턱은 시험 점수 전 고정한다.

성공해도 예측 대상은 **관측된 스트리밍 요청 수**다. 사용자 지연 SLO, 실제 GPU·VM 수, VM Ready 시각, 배포·스케일 조치와 결과가 이 추적에 연결되어 있지 않으므로 `SCALE_OUT/IN` 조치의 효과 또는 최적 인프라 형상을 주장하지 않는다.
