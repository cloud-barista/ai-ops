# Alibaba MaaS: 관측 상태를 반영한 GPU SM 위험 예측 사전 규약 v1

상태: **새 목표의 점수 계산 전 설계**. 현재 확보한 `bucket 0`의 140–144일에서 정답 지원량만 감사했다. 아래 목표에 대한 모델은 아직 학습하거나 점수화하지 않았고, `bucket 1`의 자원값·정답은 추출하지 않았다. 이 규약과 평가 코드를 고정한 뒤 140–142일 학습, 143일 보정, 144일 게이트를 순서대로 진행한다. 게이트를 통과한 경우에만 새 ID의 145–146일 시험을 단 한 번 연다.

## 연구 질문과 자료의 경계

경희대의 배포·스케일링 판단 모듈에 전달할 **관측 기반 위험 신호**를 연구한다. 현재 정상인 GPU 인스턴스에 대해 30분 동안 GPU SM 사용률의 5분 평균이 80% 이상으로 *관측되는 상태*와 관측 부족을 함께 예측한다. 관측 부족을 정상으로 바꿔 기록하지 않고, 정상·초과·미해결을 각각 예측하는 두 단계 모델이 고정된 단순 기준선 및 직접 3분류 모델보다 새 ID에서도 정확한지 시험한다. 80%는 연구자가 정한 지표 임계값이지 사용자 지연 SLO, GPU 메모리 OOM, 실제 `SCALE_OUT` 필요성의 정답이 아니다. VM 생성·삭제 및 배포 명령의 효과는 이 자료에 없다.

공식 [MaaS 설명](https://github.com/alibaba/clusterdata/blob/8a6295f9779ddc019add669eeca49c5f9f77b3a7/cluster-trace-v2026-maas/README.md), [스키마](https://github.com/alibaba/clusterdata/blob/8a6295f9779ddc019add669eeca49c5f9f77b3a7/cluster-trace-v2026-maas/docs/schema.md), [자료 목록](https://github.com/alibaba/clusterdata/blob/8a6295f9779ddc019add669eeca49c5f9f77b3a7/cluster-trace-v2026-maas/docs/data_download.md), [저장소 사용 안내](https://github.com/alibaba/clusterdata/blob/8a6295f9779ddc019add669eeca49c5f9f77b3a7/README.md)의 commit은 `8a6295f9779ddc019add669eeca49c5f9f77b3a7`이다. 주간 표는 20초 측정의 **5분 평균**이고 `time_s`는 각 5분 창의 시작이다. 21개 Parquet 조각은 날짜 분할이 아니며 총 140,906,827행이다. 주간 표에는 online/offline 종류나 사용자 요청·SLO 열이 없으므로 혼합 추론 인스턴스의 계측으로만 해석한다. 저장소 안내에는 연구·학습 사용 문구가 있으나 이 자료에 대한 명시적 재배포 라이선스는 확인되지 않았다. 원시 표본 행·ID 해시·행별 예측은 외부에 재배포하지 않는다.

원격 ZIP URL은 `https://tre-clusterdata.oss-cn-hangzhou.aliyuncs.com/cluster-trace-v2026-maas/data/instance_week_5min.zip`, 크기 4,812,189,789바이트, 수집 시 ETag `434E78D81E2A9F9F1FDEF3163DD0FCEC`이다. 전 조각 Range·CRC32·SHA256·스키마 감사는 `data/external/alibaba_maas_2026/instance_week_5min_audit.json` (SHA256 `3a24d64122dcf8e1fd9f68627acbd70dd878924483b29c334ae74a612e75cb88`)에 있다. 기존 `bucket 0` compact Parquet SHA256은 `6f52288916f7a8be8bacb2d911bc20294ab7f6685eda2b1f0f63cfc77af77e82`다. [출처 메모](../data/external/alibaba_maas_2026/SOURCE.md)에 추출·품질 감사가 있다. 원자료에서 GPU 메모리 사용률 100% 초과가 53,533행이고 원인이 공개되지 않아 **이번 목표와 입력에서는 GPU 메모리 열을 제외**한다. SM은 `[0,100]`의 유한값만 유효하다.

## 분리와 결정 시점

원본 `instance_id` UTF-8 바이트의 SHA256 첫 8바이트를 big-endian 정수로 해석한 뒤 `% 100`을 적용한다. 나머지 `0`은 개발용, `1`은 새 ID 시험용이다. 기존 compact 파일에는 나머지 `0`만 있다. 시험 ID는 21개 조각 모두에서 동일 규칙으로 추출해야 한다. 나머지 `0`의 145–146일은 이전 연구에서 이미 점수를 보았으므로 이 연구의 독립 시험으로 쓰지 않는다. 새 시험은 **ID 분리 + 이후 2일**이지만 같은 주의 공통 사건을 공유하므로 새 시간대·CSP·AI 응용으로 일반화된다는 근거는 아니다.

| 단계 | ID bucket | 결정 시점 `d` | 사용 |
|---|---:|---|---|
| 모델·빈 기준 학습 | 0 | 140–142일 | 모델 계수, 중앙값, 기준선 빈도 |
| 확률 보정 | 0 | 143일 | 미리 정한 온도 하나를 방법별 적합 |
| 개발 채택 게이트 | 0 | 144일 | 변경 없는 모델 점수, 통과/중단 |
| 독립 시험 | 1 | 145–146일 | 모든 앞선 산출물과 해시 고정 후 1회 평가 |

현재 행의 창 시작을 `t`라 할 때 결정 시점은 `d=t+600초`다. 현재 창은 `t+300`에 끝난다. 추가 300초 계측 전달 지연을 **가정**한다. 실제 전달 시각은 원자료에 없다. 입력은 `t, t−300, t−600`의 현재·과거 계측만 사용한다. 목표 창은 `t+600, t+900, …, t+2100`을 시작으로 하는 6개 창, 곧 `[d,d+1800)`이다. 정답 전달 가능 시각도 마지막 창 종료 뒤 300초인 `d+2100`으로 가정한다. 각 단계의 `d`가 해당 일 범위에 있고 `d+2100 ≤ 단계 종료 시각`인 후보만 쓴다. 이 규칙을 만족시키기 전에는 다른 단계의 행을 과거·미래 검색 테이블에 섞어 점수화하지 않는다. 경계의 과거 입력은 이전 날의 이미 발생한 계측만 허용한다.

현재 후보는 `(instance_id,t)`가 정확히 한 행, `cluster_id` 존재, `gpu_count>0`, `samples>0`, `0≤sm_util<80`일 때 결정한다. GPU 수는 분수일 수 있으므로 정수로 강제하지 않는다. 이 적격성에는 미래 창의 존재·결측·할당 변화가 일절 들어가지 않는다. 과거의 두 창은 같은 ID·시각에 유일하고 SM·samples·cluster·GPU 수가 유효하며 현재와 같은 `cluster_id`와 정확히 같은 `gpu_count`일 때만 입력에 사용한다. 그 밖에는 결측값과 과거 유효 플래그로 표시한다. ID는 조인·동일 ID 가중치·감사에만 쓰고 예측 입력에 넣지 않는다. cluster도 조인과 감사에만 쓴다.

미래 각 창도 같은 조건으로 **유일하고 유효하며 현재와 같은 관측 할당**일 때만 상태를 확정한다. 같은 ID·시각의 중복 행에서 높은 SM 한 행을 임의로 고르면 안 된다. 세 클래스는 다음 순서로 단 한 번 붙인다.

1. `H=OBSERVED_HIGH`: 적어도 한 미래 창이 유일·유효·같은 할당이며 `sm_util≥80`. 다른 미래 창이 누락되어도 관측된 초과는 확정한다.
2. `N=FULLY_OBSERVED_NORMAL`: 여섯 미래 창 모두 유일·유효·같은 할당이며 모두 `sm_util<80`.
3. `U=UNRESOLVED`: 나머지 전부. 중복·결측·비정상 측정·할당 변화가 있고 확정 H가 없으면 U다. 중복/비유효 창에 있는 높은 값은 H 근거로 쓰지 않는다.

여기서 위험은 **현재와 동일한 관측 할당의 여섯 창 SM 5분 평균 초과**라는 한정된 대상이다. 할당이 바뀐 창의 기존 할당 SM은 관측되지 않거나 정의하기 어려우므로 U 처리한다. U를 실제 변경 후 위험이나 동일 할당을 유지했을 때의 반사실 위험으로 읽지 않는다. `H/N/U`라는 기록 상태는 모든 현재 후보에 붙일 수 있으나 U에는 이진 정답을 정의·관측할 근거가 없다.

## 고정한 방법과 기준선

공통 입력은 `SM(t−600), SM(t−300), SM(t)`, 대응하는 `samples` 3개, 과거 두 창의 유효 플래그, 현재 `gpu_count`, 유효한 과거·현재 SM의 평균과 최대, `SM(t)−가장 오래된 유효 과거 SM`이다. 유효 과거가 없으면 해당 차이는 결측이다. 과거 비유효 창의 SM/samples는 `NaN`으로 놓는다. 현재 이후 측정값, 미래 창 유무, 후일 daily 표, 인스턴스 해시, 클러스터명, GPU 메모리 사용률은 입력하지 않는다. 각 방법의 학습에서 인스턴스 `i`의 행 수가 `n_i`일 때 각 행에 `N/(I·n_i)`의 가중치를 둔다. 따라서 합계는 전체 학습 행 수 `N`이고 각 ID의 총 기여가 같다. 보정과 모든 비교도 각 평가 단계 안에서 ID별 동일 총가중치를 쓴다.

**주 후보: 두 단계 관측 상태 분해.** 첫 이진 분류기는 전체 학습 후보에서 `P(H|X)=h`를, 둘째는 H가 아닌 학습 후보에서 `P(U|H 아님,X)=q`를 적합한다. 최종 확률은 `(p_H,p_N,p_U)=(h,(1−h)(1−q),(1−h)q)`다. 둘째 단계의 ID 가중치는 H 제외 학습 집합에서 다시 계산한다. 두 분류기 모두 scikit-learn `HistGradientBoostingClassifier`이며 `max_iter=150`, `learning_rate=0.05`, `max_leaf_nodes=15`, `min_samples_leaf=100`, `l2_regularization=1`, `early_stopping=False`, `random_state=42`로 고정한다. 추가 탐색·앙상블·재학습 선택을 하지 않는다. 분해 방식은 이 자료의 관측 의미를 반영한 **연구 가설**이며 새 알고리즘 발명이나 독창성 입증이라고 주장하지 않는다.

모든 비교기는 같은 학습 후보와 아래 사전 규칙을 따른다.

- 전체 빈도: 학습 집합의 ID 가중 클래스 수에 각 클래스 1의 Dirichlet 유사 횟수를 더해 3클래스 고정확률을 만든다.
- 조건부 빈도: 현재 SM `[0,5),[5,20),[20,50),[50,80)` × 유효 과거를 포함한 총 창 수 `1/2/3` × GPU 수 `(0,1],(1,4],(4,∞)`의 셀별 ID 가중 빈도에 전체 빈도 50행 상당을 더해 수축한다. 해당 셀이 비어도 전체 빈도로 예측한다.
- 다항 로지스틱: 동일 입력을 학습 집합 중앙값으로 대치하고 결측 지시자를 추가한 다음 학습 집합만으로 표준화한다. `C=1`, L2, `max_iter=1000`, `random_state=42`를 고정한다. 수렴 실패 시 중단하고 임의 모델로 대체하지 않는다.
- 직접 3분류 HGB: 주 후보와 같은 HGB 설정으로 `H/N/U`를 한 번에 적합한다.

각 방법의 원시 확률은 `[10⁻⁶,1]`로 자르고 행별 합이 1이 되도록 정규화한다. 143일 보정 데이터에서 `T∈[0.5,5]`인 **하나의 양수 온도**를 ID 동등가중 3분류 로그손실 최소화로 방법별 적합한다. 최종확률은 `p_k^(1/T)/Σ_j p_j^(1/T)`다. 결정적 최적화 실패 시 `T=1`을 사용하고 기록한다. 보정의 입력은 해당 방법의 143일 예측뿐이며, 144일 게이트는 온도나 하이퍼파라미터를 바꾸지 않는다.

## 평가와 사전 중단 규칙

주 지표는 모든 현재 후보의 ID 동등가중 3클래스 Brier `Σ_k(p_k−1[y=k])²`이다. 함께 행 동등가중 Brier·로그손실, H·U 각각의 one-vs-rest Brier와 10개 동빈도 구간의 ID 가중 ECE, 일별·6시간 블록별 결과, ID별 손실 분포를 기록한다. 확률 구간 보정은 H와 U를 각각 검사한다. 6시간 블록은 UTC 상대일의 `0–6/6–12/12–18/18–24시`다. 클래스 불균형을 숨기지 않도록 각 클래스의 행·ID 수와 최대 단일 ID 기여율을 함께 출력한다.

**개발 지원량 게이트를 점수보다 먼저 검사한다.** 143일 보정과 144일 검증은 각각 후보 50,000건 이상, H 1,000건·서로 다른 ID 200개 이상, N 20,000건 이상, U 5,000건·서로 다른 ID 500개 이상이어야 한다. 144일의 네 6시간 블록마다 H≥100, U≥1,000이어야 한다. 각 클래스에서 최대 단일 ID의 행 비율은 10% 이하여야 한다. 어느 하나라도 실패하면 후속 점수·bucket 1 추출을 중단한다. 140–142일 학습에도 H≥3,000, N≥100,000, U≥15,000과 각 클래스 ID≥200을 요구한다. 이는 작은 층 하나가 결과를 좌우하는 것을 막는 최소 조건이며 성능 보증은 아니다.

지원량을 통과하면 144일에 **한 번** 모델을 평가한다. 주 후보는 네 비교기 각각보다 ID 동등가중 3클래스 Brier가 5% 이상 낮고, 행 동등가중 3클래스 Brier가 각각보다 2% 이상 낮아야 한다. ID 동등가중 로그손실은 최선 비교기보다 1% 넘게 높지 않아야 한다. H와 U의 one-vs-rest ID 동등가중 Brier는 각자 최선 비교기보다 2% 넘게 나빠지지 않아야 한다. 4개 6시간 블록 중 최소 3개에서 주 후보의 ID 동등가중 3클래스 Brier가 그 블록의 최선 비교기보다 낮아야 한다. H의 ECE≤0.03, U의 ECE≤0.05가 필요하다. 모두 만족할 때만 **연구적 시험 진행**으로 판정한다. 실패하면 실패한 방법과 이유를 기록하고 bucket 1을 열지 않는다.

게이트 통과 시 규약, 지원량·학습·보정·평가 코드, 테스트, 의존 버전, 모든 적합 산출물 및 검증 JSON의 SHA256을 manifest에 기록하고 독립 점검받은 다음에만 bucket 1을 추출한다. 시험은 21조각 각각을 별도 HTTP Range로 원본 ETag·길이·CRC32·SHA256 확인 후 처리하고 조각을 버린다. 전체 4.8GB ZIP 복사본을 만들지 않는다. 시험 지원량은 후보 50,000건 이상, H≥500/ID≥200, U≥5,000/ID≥500, 양일 각각 H≥100 및 U≥1,000, 클래스별 최대 ID 비율≤10%를 요구한다. 지원량 실패 시 **모델 시험 점수를 계산하지 않는다.** 통과하면 고정 모델·기준선을 양일 합계와 날짜별로 단 한 번 비교한다. 연구 결과 채택 기준은 ID 동등가중 Brier에서 네 비교기 각각보다 5% 이상 낮고, 날짜별 둘 다 최선 비교기보다 낮으며, H/U Brier 비열화·ECE 기준을 개발 게이트와 똑같이 만족하는 것이다. 이 기준을 통과해도 실제 스케일 조치나 안전한 정책 채택 근거로 사용하지 않는다.

## 미해결 정답의 부분 식별과 보고 제한

관측된 H에는 `Y*=1`, N에는 `Y*=0`을 부여하고 U마다 **형식적으로** `Y*∈{0,1}`을 임의 보충할 수 있다. 어떤 보충에서든 전체 후보의 표본 비율은 `H/n ≤ rate(Y*=1) ≤ (H+U)/n`이다. 이는 기록과 일치하는 가능한 **이진 완성**의 산술 범위다. U에 변경된 할당이 포함되므로 실제 변경 후 위험, 변경이 없었을 때의 물리적 반사실 위험, 모집단 신뢰구간, 정책 안전 보증의 경계가 아니다. 입력 `X` 조건부의 어떤 형식적 완성에도 `P(H|X) ≤ P(Y*=1|X) ≤ P(H|X)+P(U|X)`라는 식별 부등식이 성립한다. 학습된 `p_H`와 `p_H+p_U`는 이 양 끝의 **추정치**일 뿐 보정·유한표본 보장은 따로 입증해야 한다. 모델 출력 범위가 임계값 0.10을 가로지르는 후보 비율은 탐색적 `ABSTAIN` 비율로만 보고하고 조치 명령으로 전환하지 않는다.

정답이 확정된 H/N만으로 계산한 이진 Brier는 **관측 라벨 조건부 성능**이다. U에서의 선택 편향 때문에 전체 후보 성능이라 부르지 않는다. 형식적 이진 완성 `Y*`에 대한 두 예측기 비교는 민감도 구간으로만 제시한다. 주 후보의 탐색적 점 예측을 `p=p_H+0.5p_U`, 같은 규칙의 기준선을 `b`라 할 때 U 행의 Brier 차이 `loss(p,Y*)−loss(b,Y*)`는 `Y*=0`에서 `Δ₀=p²−b²`, `Y*=1`에서 `Δ₁=(1−p)²−(1−b)²`다. H/N 행의 정확한 차이에 U 행별 `min(Δ₀,Δ₁)` 또는 `max(Δ₀,Δ₁)`를 더하고 동일한 고정 평가 가중치로 평균해 최선·최악 가능 차이를 보고한다. 이 범위가 0을 포함하면 완성된 이진 목표의 우열은 판정하지 않는다. 전체 후보의 이진 AP·recall은 점추정으로 보고하지 않는다.

## 비용과 현재 확인 결과

로컬 디스크 가용 공간은 감사 당시 약 5.6GiB다. bucket 0 compact는 약 83MB이고 현재 감사는 약 25초에 끝났다. 학습·보정·검증은 이 compact만 사용하며 메모리 수 GB와 수분–수십 분이 예상되지만 아직 계측값이 아니다. 미래 시험을 허용하더라도 네트워크에서 원격 ZIP 약 4.8GB의 조각을 순차 전송해야 한다. 전체 ZIP은 저장하지 않고 동시 임시 파일을 한 조각(원본 조각 최대 300MB 미만)으로 제한해 임시 디스크 사용을 0.5GiB 미만으로 설계한다. 전송·파싱 시간은 미측정이며 시도 전 디스크 여유를 다시 확인한다.

[지원량 감사 JSON](../artifacts/maas_sm_observability_v1/feasibility.json)과 [감사 코드](../scripts/audit_maas_sm_observability_support.py)는 **점수 없는** 140–144일 조사다. 학습 140–142일은 H 7,199, N 266,203, U 91,837 / 후보 365,239; 보정 143일은 H 2,848, N 81,818, U 28,966 / 후보 113,632; 검증 144일은 H 4,186, N 87,379, U 28,138 / 후보 119,703이다. 각 단계의 형식적 이진 완성 비율 산술 범위는 `[1.971%,27.115%]`, `[2.506%,27.997%]`, `[3.497%,27.004%]`다. 검증 H는 ID 972개, U는 ID 4,976개이고 네 6시간 블록 모두 H≥779·U≥5,623이다. 모든 단계의 ID별 지원량과 10% 단일 ID 기여 제한도 현재 감사에서 통과했다. 이 수치만으로 이진 위험의 예측력이나 정책 효용을 추정하지 않는다.
