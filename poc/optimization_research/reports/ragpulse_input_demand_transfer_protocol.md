# RAGPulse 표본의 다음 5분 입력 수요: 시험 전 규약

상태: **RAGPulse 원본 요청 본문을 받거나 읽기 전에 작성**. 이 시험은 [Coding 후향 성공](azure_code_input_demand_findings.md)과 [Conversation 전이 실패](azure_input_demand_cross_service_findings_v1_1.md)를 본 뒤 세운 새 가설을, 다른 공개 AI 응용의 요청 표본에서 **한 번** 확인한다. 실패를 보고 선택한 하루 보정법이라는 연구 경위를 숨기지 않는다. RAGPulse 시험 정답은 방법 선택에 쓰지 않는다.

## 원본·목표·분할

[RAGPulse 저자 저장소](https://github.com/flashserve/RAGPulse/tree/7da286becf0f049b2bcb1e5a11d9ba8eb638eff4)는 약 6주간 표집된 34,987개 RAG 요청을 공개한다. 대상은 `data/0_trace.jsonl`의 Git blob SHA-1 `a058ecc31c56648b20709a8c211f21dd97c7d08b`, 크기 9,961,760바이트로 고정한다. 저자 설명에 따른 `timestamp`는 시작 12:00부터의 상대 초, `input_length`는 입력 토큰 수다. 원본의 각 기록 시각이 포함되는 `[t,t+300초)`에 `input_length`를 합친 **공개 표본의 관측 입력 토큰 합계**만 예측한다. 기록이 없는 5분 구간은 *이 공개 표본*의 합계 0으로 취급하며 실제 서비스 전체 수요 0으로 해석하지 않는다. 요청 행을 임의로 중복 제거하거나 표본 외 요청량을 추정하지 않는다.

원본 시각을 첫 기준일의 상대 초 0으로 두고 42×288개의 고정 5분 구간을 만든다. `timestamp`가 `[0,42×86400)` 밖이면 중단하고, 음수·비정수·결측 `input_length`나 시각 역순, 원본 해시·행수 불일치도 중단한다. 첫 28일은 이력이며, **상대일 28–34의 연속 7일**이 고정 시험이다. 해당 7일과 상대일 27의 288개 구간씩을 모두 지원량 감사한다. 7일 시험 중 이전 완료 구간의 실제 값은 각 결정 시점에 사용 가능한 순차 피드백이라고 가정한다. 토큰 계수 전달 지연은 원본에 없어 검증할 수 없다.

## Coding 학습기와 보정

Azure Coding 원본 SHA-256 `71de5c55cbc35f8f1ed0b6b7806b4cd1e9764b0058469725a6aac98023a1448f`의 2024-05-10–12에서 첫 1시간을 제외한 852개 구간만으로 모델과 학습 기준값을 적합한다. 기존 [Coding 규약](azure_code_input_demand_protocol.md)의 90분위 HGB 하이퍼파라미터, `m_t=직전 12개 완료 구간의 평균`, `r_t=y_t/m_t`, 학습 가중치 `m_t/mean_train(m)`를 유지한다. 절대 날짜·요일·UTC 시간대를 RAGPulse에서 알 수 없으므로 **`weekend`, `clock_sin`, `clock_cos`를 모두 제외**한다. 나머지 8개 과거 수요 특징은 유지한다. Coding 05-13 개발 결과는 참고로 기록할 수 있지만 새 모델·임계값 선택에 사용하지 않는다. RAGPulse 값으로 모델을 재학습하지 않는다.

각 상대일 `d=28,…,34`의 시작에, 바로 앞선 **완료된 하루** `d−1`의 지원 구간만 써서 방법별 보정 배율 `α_d=weighted_q90(y_i/max(p_i,1), weight=max(p_i,1))`를 계산한다. `p_i`는 그 방법의 원래 예측 토큰이며, 입력은 해당 구간 시작 이전 값만 사용한다. 시험일 예측은 `α_d×max(p_t,1)`이다. 사후 관찰 때문에 도입한 방법인 만큼 사전에 고정한 단회 시험 이상으로 일반화 성과를 주장하지 않는다.

주 방법은 **전날 보정한 상대 수요 HGB**다. 비교기 네 개도 각자 같은 보정을 적용한다: Coding 학습 비율의 가중 90분위×현재 `m_t`, 직전 1시간의 경험적 90분위, 전날 같은 5분 슬롯의 비율×현재 `m_t`, 그 전날 비율에 Coding 학습 잔차 90분위를 더한 예측. 전날 비율 결측은 학습 전역 비율 90분위로 채운다. 보정하지 않은 다섯 방법의 점수도 맥락 정보로 기록한다. 모든 방법은 같은 구간에서 평가한다.

## 점수 전에 확인할 지원량과 성공 기준

구간 시작에 `m_t≥1,000` 입력 토큰이면 지원 구간이다. **상대일 27–34 각각 최소 274/288구간(95%)**이 지원돼야 한다. 또한 이전 하루의 다섯 방법 각각에서 보정 배율이 유한해야 한다. 한 조건이라도 실패하면 `SUPPORT_NO_GO_NO_SCORE`로 원본·일별 지원량만 기록하고 모델 시험 점수는 계산하지 않는다. 이것은 표본 자료에서 과도한 결측·저수요 시간을 임의로 제외해 좋은 점수를 만드는 것을 막는다.

지원량을 통과한 경우에만 상대일 28–34 각각의 90분위 절대 토큰 pinball, 피복률과 평균 관측·예측 토큰을 기록한다. 7일 동일 가중 평균 pinball을 주 지표로 사용한다. **채택 탐색 게이트**는 보정 HGB가 보정한 네 비교기 *각각*보다 손실 5% 이상 낮고, 일곱 날짜 중 최소 여섯 날짜에 그날 최선 보정 비교기보다 낮으며, 각 날짜 피복률이 85–95% 사이여야 모두 통과한다. 한 날짜 288개 창은 독립 실험 표본으로 세지 않고, 7일 결과도 서비스 일반화의 통계적 보증이 아니다.

원본 본문 다운로드 전에 규약·평가기·합성 시험·Coding 재학습 모델과 기준값의 해시를 `freeze.json`에 남긴다. 원본의 5분별 합계와 요청 내용은 결과 파일에 저장하지 않는다. 이 시험이 통과해도 실제 서비스 전체 토큰 유입, GPU 메모리·처리량, 사용자 SLO, VM `SCALE_OUT/IN` 효과를 입증하지 않는다.
