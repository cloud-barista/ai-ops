AI-MCMP: Azure 2023 공개 표본 감사와 달력 특징 없는 수요 모델 학습
2026-10-06 | 외부 성능 채점 보류; 새 모델3개 학습·재적합 검산 완료

1. 목적과 사전에 고정한 접근
Copilot 완료 오차 보정의 외부 서비스 적용 가능성을 확인하려 했다. 새 자료의 원시 행과 모델 점수를 보기 전에 실험을 고정했다.
공식 설명에 시간대가 명시되지 않은 자료에 UTC시각·요일 특징을 임의로 붙이지 않도록 7개의 과거 상대수요 특징만 사용한 HGB q90 모델3개를 별도로 학습했다.
학습은 기존 Copilot June3~5, 단순 비교기 선택은 June6이다. 외부 자료로 모델을 적합하거나 비교기를 고르지 않았다.
완료된 원시 예측 오차의 양수 q90 보정은 기존 window288/minimum96/scale>=1 규칙을 그대로 사용하며, 모든 기준선에도 같은 보정을 적용하도록 고정했다.

2. 데이터 출처와 원본 검산
공식 설명: https://github.com/Azure/AzurePublicDataset/blob/master/AzureLLMInferenceDataset2023.md
공식 설명은 2023-11-11에 수집한 LLM 추적 표본이라고 소개한다. 실제 내려받은 저장소 CSV는 그 문장의 하루 전체 추적이라고 가정할 수 없었다.
저장소 contents API의 파일 크기와 Git blob SHA1에 다운로드 바이트가 일치했다. 별도 SHA256도 저장했다.
두 파일 합계1,039,305바이트이며 기존 자료는 삭제하지 않았다. 요청 원본을 그대로 보존했다.
파일 | 행 | 최초 기록 시각 | 마지막 기록 시각 | 관측 시간 범위 | 실제 기록이 없는5분칸(24시간 표시 격자)
AzureLLMInferenceTrace_code.csv | 8819 | 2023-11-16T18:17:03.979960 | 2023-11-16T19:14:19.928016 | 57.27분 | 276
AzureLLMInferenceTrace_conv.csv | 19366 | 2023-11-16T18:15:46.680590 | 2023-11-16T19:14:08.402527 | 58.36분 | 276

두 CSV의 기록 날짜는2023-11-16이고 시간 범위는약1시간이다. 실제 파일에서 관측한 사실을 설명 페이지의 수집 날짜와 구분해 기록한다.
나머지 시간에 기록이 없다는 것은 실제 서비스 수요가0이었다는 증거가 아니다.
24시간 격자의0은 집계상 기록된 행이 없다는 뜻이다. 이 격자로 운영 무수요나 외부 모델 성능을 주장하지 않았다.
모든 기록된 호출 행을 세었고 ContextTokens/GeneratedTokens, 실패 여부 또는 중복 timestamp로 행을 선별하지 않았다.
시간대는 공개 설명에서 확인되지 않아 기록된 벽시계로만 순서·5분 구간을 정의했다. 이를 UTC라고 선언하지 않았다.

3. 학습한 모델 구성
scikit-learn HistGradientBoostingRegressor: quantile=.9, max_iter150, learning_rate.05, max_leaf_nodes7, min_samples_leaf20, L2=1, seed42, early_stopping=False.
7개 특징: 직전1/2/3/12구간의 호출 수를 직전1시간 평균으로 나눈 값, 과거1시간 최대/90분위 비율, 최근30분/이전30분 평균 비율.
타깃: 현재5분 구간부터 준비 완료 직후 구간까지의 최대 호출 수. 준비5/10/30분에 대응하는 관측 구간 길이는10/15/35분이다.
학습 타깃을 직전1시간 평균으로 나누고, 같은 평균/학습평균을 표본 가중치로 사용했다.
학습 행은851/850/846개다. 정답이 학습 경계 안에서 완료되는 행만 썼다.
새 모델3개를 joblib으로 저장했고 같은 학습 행으로 재적합한 모든 예측이 정확히 일치했다.
이 검사는 모델 재현성 증거다. 새 모델이 기존11특징 모델보다 좋거나 외부 서비스에서 좋은 성능을 냈다는 증거가 아니다.

4. 외부 시험 보류 판정
사전에 외부 첫10시간을 보정 이력 확보 구간으로 두고, 이후 완전한 타깃 원점 중 최소144개·80% 이상 지원을 요구했다.
데이터 지원 검사에서 각 조건의 지원 원점은23개, 지원률은13.77/13.86/14.20%였다. 이는 집계 격자의 수치 지원량이며 실제 관측된 완전 시험 창 수가 아니다.
실제 표본이1시간뿐이므로 필요한 과거1시간·최소96개 완료오차·시험 원점을 확보하지 못했다.
두 서비스×3준비 지연의6조건 모두 SOURCE_SUPPORT_NO_GO다. 외부 예측 손실·피복률을 계산한 조건은0개다.
외부 모델이 나쁘다고 판정한 것이 아니다. 외부 일반화 성능을 판단할 자료가 부족해 채점하지 않았다.
사후에 시간 간격을 압축하거나 최소96개를 낮추거나 표본을 반복해 긴 추적처럼 만들지 않았다. 기존 Copilot 피드백 개선 결과는 보존한다.

5. 검증과 수정 기록
나노초 경계, 동일 timestamp의 여러 행 보존, 달력/요일 미사용, 미래 입력 불변, 타깃 완료 경계, 다일 표본 거절의 테스트4개가 통과했다.
초기 테스트에서 Python3.10 ISO파서의7~9자리 소수초 처리 실패를 확인해, 점수·모델 학습 전 pandas 나노초 파서와 정수 구간 인덱스로 수정했다. 초기 실패 로그도 보존했다.
독립 검증기는 CSV시각의 시·분을 별도로 파싱해5분 호출 수와 지원 중단 판정을 확인했다. 원시 파일 바이트와 고정 입력 해시도 재확인했다.
외부 조건이 모두 지원 검사에서 중단해 replay파일이 생성되지 않았다. 검증기의 파일 없음 처리만 수정했고 원 검증기·동결값·수정 사유를 보존했다.
독립 검산된 외부 예측 행은0, 외부 미래 피드백 변이 검사는0이다. 이를 실행한 성능 검증이라고 표현하지 않는다.
모델재적합3개와 원본집계 검산은 완료됐다. 기존 모델·자료의 해시는 변하지 않았다.

6. 다음 자료 선택
하루라고 소개된 파일도 실제 timestamp범위부터 감사해야 한다. 요청 행 수나 파일 크기는 연속된 시간 이력의 대체물이 아니다.
현재 저장된 BurstGPT_3.csv는 공식 설명상110일이며 기존 감사도상대일225~334의110일을 확인했다. 달력 날짜·UTC를 쓰지 않는7특징 모델의 다음 전이 후보로 적합하다.
BurstGPT에서는 모델×API/Conversation 관측을 구분하고, 실제 요청이 없는 구간·자료 범위 밖·미관측을 구분하는 기간 마스크를 먼저 적용해야 한다.
해당 자료는 앞선 입력/출력 토큰·실행시간 연구에서 이미 열람됐으므로 새 전이 결과를 블라인드 독립 시험으로 부르지 않는다.
Chutes도 장기 자료지만 날짜가 정규화돼 있다. 달력 없는 모델로 연속 기간 일부를 별도 추출해 검증할 수 있으며, 기존 짧은 rowgroup을 이어 붙이지 않는다.
새 외부 자료의 실제 관측 범위를 확인한 뒤 개발/확인 기간과 기준선을 점수 전에 고정한다. 충분한 기간이 없으면 채점 보류를 유지한다.
수요 신호와 별도로 실제 스케일 효과에는 action→READY→트래픽 전환→사용자 결과의 연결이 필요하다.
