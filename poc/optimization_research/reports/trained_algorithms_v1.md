# 기존 SQLite를 이용한 추가 알고리즘 학습 결과

경희대 담당 범위 중 **응용 자원 신호**와 **배포·제어 추론의 불확실성**에 연결할 수 있는 학습 목표 세 가지를 기존 SQLite에서 골라 학습했다. 실제 사용자 요구→자원 형상 정답이나 VM Scale-out/in 전이 결과는 없으므로, 아래 점수를 운영 배포·스케일링 성능으로 해석하지 않는다. 입력 스냅샷은 원본 SQLite에서 만든 고정 측정 자료 (`../data/audit_v1/measurements.parquet`)다.

| 학습 목표와 방법 | 모델 제외 평가 결과 | 적용 범위 판단 |
| --- | --- | --- |
| 같은 GPU의 **관측 예약 메모리 피크 상한**: 정적 특징 Ridge 예측을 다른 모델의 교차검증 비율 잔차 90% 분위수로 보정 | 주/새 입력/공간표본 조건의 모델 평균 커버리지 `88/89/90%`; 단순 donor 오버헤드 상한보다 90% 분위수 손실이 `73.3→63.8`, `38.3→31.5`, `37.2→36.4 MiB` | 유일한 생성형 Qwen을 제외하면 커버리지 `17/63`; 모델 종류 donor가 둘 미만이면 보류한다. 관측 피크는 최소 VRAM·OOM 정답이 아니다. [보고서](vram_upper_findings.md) |
| **미래 단일 배치 측정의 지연·처리량 분포**: 이전 모델의 시간순 반복으로 분산 결합 강도와 폭을 학습 | `cutoff_last_k`에서 일부 CRPS가 소폭 개선됐으나 고정 5 수축·대상 Student-t를 일관되게 이기지 못함. CRPS 학습의 v1 처리량 `k=2` NLL은 `106.461`로 급격히 악화 | 학습법은 채택 보류. 실제 사용자 SLO·VM 확장 결과가 아니라 동일 형상의 벤치마크 변동이다. [보고서](learned_repeat_distribution_findings.md) |
| **로컬 모델·토크나이저 적재시간**: 모델 크기별 중앙값 ExtraTrees | 주/새 입력/공간표본의 모델 평균 절대 로그오차가 donor 중앙값 `0.522/0.503/0.493`에서 `0.391/0.388/0.363`으로 감소 | 유일한 생성형 Qwen을 제외하면 실제 적재 중앙값 `1.214초`에 `0.255초`를 예측했다. VM 부팅·이미지 다운로드·배포 완료시간이 아니다. [보고서](load_time_findings.md) |

각 실험은 대상 **모델 ID 전체를 제외**하고 주 캠페인의 다른 모델만 학습에 사용했다. VRAM·적재시간은 같은 호스트의 다른 입력 조건을 추가 평가했으며 BERT 계열 공동 제외도 따로 계산했다. 이 두 추가 캠페인은 주 학습 캠페인보다 **앞서 수집**됐으므로 시간 전진 검증은 아니다. 반복 실행은 실제 시작 시각순으로 내·외부 검증 시점을 나누었다. 이 세 방법은 같은 SQLite를 살핀 뒤 설계·비교했으므로 **탐색 결과**다. 다른 호스트·새 모델군에서 독립적으로 재검증되지 않았다.

재현 가능한 [VRAM 상한 학습 코드](../scripts/evaluate_vram_upper.py), [반복분포 학습 코드](../scripts/learned_repeat_distribution.py), [적재시간 학습 코드](../scripts/evaluate_load_time.py)를 저장했다. 모델 제외 행별 예측, 점수, 분할, 코드·자료 해시는 각 보고서의 아티팩트에 있다. 전체 주 캠페인으로 다시 학습한 VRAM 연구 모델 (`../artifacts/vram_upper_v1/research_estimator.joblib`), [반복분포 파라미터](../artifacts/learned_repeat_v1/trained_models.json), 적재시간 연구 모델 (`../artifacts/load_time_v1/size_only_extra_trees_all_main.joblib`)도 보존했다. 이 파일들은 실험 재현용이다. 실제 추천·배포 판단에 연결하려면 새 모델·하드웨어의 결과와 사용자 SLO·수명주기 전이를 별도로 측정해야 한다.
