# SwissAI 요청 출력 토큰 p90: 점수 전 탐색 규약

작성일: 2026-09-29. **상태: 학습·검증·시험 점수 계산 전.** 이 규약은 SwissAI 원본에서 아직 연구에 쓰지 않은 `reported_token_output`을 응용별 *관측 출력 길이*의 정답으로 삼는다. 실제 GPU 연산량·KV 메모리·필요 VM 수, 배포/스케일 조치의 효과를 정답으로 부르지 않는다.

## 연구 질문과 새로움의 범위

요청 접수 시점에 알려진 모델 식별자와 생성 파라미터, 과거에 완료된 요청만으로 **기록상 `DEFAULT`·양수 완료시간·출력 관측 요청의 출력 토큰 수 90분위**를 예측한다. 이는 경희대의 응용 요구 분석에 들어갈 수 있는 수요 신호를 검토하는 별도 서비스 실험이다. BurstGPT와 Azure에서 출력 토큰 수를 이미 연구했으므로 이 목표나 분위수 회귀 자체를 새 알고리즘이라고 주장하지 않는다. SwissAI는 그 둘과 다른 서비스이지만 같은 파일의 요청량·오류·유휴 재도착 연구를 이미 진행했으므로 여기의 날짜 시험도 완전히 미개봉인 독립 시험은 아니다.

## 시간 분할과 피드백 가용성

UTC 요청 시각으로 학습 `[2025-05-16, 2025-08-16)`, 검증 `[2025-08-16, 2025-09-16)`, 잠금 시험 `[2025-09-16, 2025-10-24)`를 사용한다. 앞선 기간은 과거 이력 준비에만 쓴다. 학습 레이블은 `finished_at+1시간 < 2025-08-16`인 학습 요청만 모델 적합에 쓴다. 검증으로 방법을 선택한 후 모델을 재학습하지 않고 시험에 적용한다.

과거 출력 통계는 **매 UTC 날짜 시작 `D`에 한 번만** 고정한다. 그 날짜의 모든 요청은 동일한 과거 통계를 사용한다. 1일 이력은 `D−1일 ≤ finished_at+1시간 < D`, 7일 이력은 `D−7일 ≤ finished_at+1시간 < D`인 위 주 모집단 요청만 센다. 학습·검증·시험에 같은 규칙을 적용한다. 검증 또는 시험 기간의 완료 결과도 다음 날짜 시작 전에 위 조건을 채웠을 때만 이후 날짜의 통계에 들어간다. 현재 요청이나 같은 날짜의 완료 결과는 그날 특징과 기준선에 들어가지 않는다. 이력이 비어 있으면 학습 특징의 통계값은 결측, 지지수는 0으로 둔다. 전체 학습기간 p90을 그 날짜의 과거 특징에 채우지 않는다.

요청 시점 특징은 `model`, UTC 시각/요일, 원본 `model_parameters`의 `temperature`, `top_p`, `frequency_penalty`, `presence_penalty`, `max_tokens`뿐이다. 이 파라미터가 원본에서 요청 시 제출된 값이라는 **가정**을 명시한다. 유한 수치 또는 숫자 문자열만 수치로 파싱하고 `null`·`"null"`·그 밖의 값은 결측 범주로 둔다. `seed`는 생성 샘플 ID에 가까워 일반화 입력에서 제외한다. `reported_token_input`은 공식 자료만으로 요청 접수 시점 가용성이 확인되지 않아 제외한다. 과거 출력 이력은 위 완료·1시간 조건을 만족한 요청만 센다. 모델 ID는 내부 결합에 쓰되 공개 결과에는 해시 별칭만 저장하고, 학습에 없던 모델은 미상 범주로 인코딩한다. 실제 로그 전달 지연이 없으므로 1시간은 보수적 평가 가정이다. 시간대 없는 `finished_at`은 기존 전량 감사처럼 UTC로 해석하고, 명시적 UTC 완료 기록만으로 별도 민감도 점수를 낸다.

## 고정 비교와 평가

1. 훈련 기간의 전역 출력 p90과 모델별 출력 p90을 기준선으로 둔다. 모델별 값은 표본 수 `n`에 대해 `(n×모델 p90+100×전역 p90)/(n+100)`으로 수축하고, `n=0`이면 전역값을 쓴다.
2. 날짜 시작 `D`에 위 7일 이력에서 **이미 가용한** 주 모집단 요청의 전역 및 모델별 경험적 p90을 온라인 기준선으로 둔다. 모델별 표본이 100건 미만이면 `n/(n+100)` 가중치로 최근 전역 p90에 수축한다. 최근 전역 결과가 없으면 훈련 전역 p90으로 돌아간다. 과거 7일은 요청 생성 시각이 아니라 `finished_at+1시간` 가용 시각으로 자른다. 해당 날짜의 모든 요청에는 동일한 기준값을 준다.
3. 학습 후보는 `HistGradientBoostingRegressor(loss='quantile', quantile=0.9, max_iter=120, max_leaf_nodes=15, max_depth=4, min_samples_leaf=200, learning_rate=0.05, l2_regularization=10, early_stopping=False, random_state=42)` 하나다. 출력 토큰을 원 단위로 적합한다. 입력은 위 요청 시점 특징과 가용 최근 1일·7일의 모델별 완료 수·출력 p50/p90 및 전역 출력 p90이다. 훈련은 적격 요청에서 UTC 날짜마다 고정 시드 42로 최대 5,000개를 뽑고, 검증·시험은 적격 행 전량을 점수화한다. 숫자 파라미터 결측과 학습 밖 모델 범주는 명시적으로 인코딩한다. 시험 점수를 보고 특징·모델·표본량을 바꾸지 않는다.
4. 검증 기간에서 주 지표인 **완전한 7일 블록별 평균 p90 pinball 손실을 블록 동일 가중 평균**한 기준선 하나를 1·2에서 선택한다. 남는 부분 블록은 전체 요청 가중 지표에 포함하고 별도 보고한다. 모든 후보의 요청 가중 손실, 명목 90% 포괄률, 모델별·7일 블록별 손실·포괄률, 미상 모델층, 전체 요청 대비 출력 관측률을 같이 보존한다. 모델·기준선의 예측 토큰은 0 이상으로 자르고, 실제 레이블을 이용해 예측을 자르지 않는다. `max_tokens`가 숫자여도 단위·의미 검증 전에는 예측의 강제 상한으로 사용하지 않는다.

**시험 점수 게이트:** 학습 모델의 검증 블록 동일 가중 pinball 손실이 선택 기준선보다 상대 5% 이상 낮고, 전체 검증 포괄률 및 요청 1,000건 이상인 검증 모델 각각의 포괄률이 85% 이상이며, 요청 1,000건 이상인 검증 모델의 과반에서 손실이 기준선보다 높지 않을 때만 시험 출력값으로 예측 손실·포괄률을 계산한다. 게이트가 실패하면 모델은 미채택하고 시험 예측 성능은 이 실험에서 점수화하지 않는다. 게이트가 통과하면 시험에서도 같은 손실·전체 및 모델별 포괄률 조건, 완전 7일 블록 과반 승리를 모두 요구한다. 포괄률 85%는 명목 90%와 차이가 있음을 드러내는 최소 연구 게이트이며 운영 안전 보장은 아니다.

## 무결성과 해석 한계

인제스트는 원본 전체의 출력 열을 읽고 레이블·요청 필드를 행 1:1로 결합하므로 시험 레이블의 물리적 미접근을 주장하지 않는다. 실행기는 원본·정렬본 해시, 파싱 오류, 중복 키, 분할 경계, 가용시각 경계를 먼저 검사한다. 품질·코드·규약·분할·기준선·학습기 설정을 manifest로 저장한 뒤 검증 결과를 계산한다. 별도 시험 채점 단계만 시험 레이블과 시험 예측을 결합해 손실·포괄률을 만들 수 있으며, 검증 게이트 통과와 frozen manifest 일치가 선행돼야 한다. 시험 원시 레이블을 포함한 행별 자료는 로컬에 보관하고 모델 문자열을 결과 문서에 공개하지 않는다. [출처·라이선스 기록](../data/external/swissai_serving_trace/SOURCE.md)의 로컬 연구·재배포 경계를 따른다.

이 정답은 **기록상 `DEFAULT`·양수 완료시간·출력 관측 요청의 출력 길이**다. `DEFAULT`가 성공이라는 의미는 확인되지 않았다. 토큰 수가 GPU별 처리시간·메모리·필요 노드 수로 직접 환산되지 않으며, 이 추적에는 VM/GPU 형상이나 실제 `DEPLOY/UPDATE/SCALE_OUT/SCALE_IN` 명령·준비 완료·요청 SLO가 연결돼 있지 않다. 학습 결과가 좋아도 경희대의 인프라 추천 또는 배포·스케일 행동 모델로 자동 승격하지 않는다.
