# 복사된 후보 격자의 값 동등성 재사용: 점수 전 규약

2026-09-29. v3는 같은 후보 **객체**를 공유할 때 검증과 격자 키를 재사용하지만, 내용이 같은 별도 리스트 1,125개를 입력하면 v2보다 느렸다. 이번 한 가지 변경 가설은 한 호출 안에서 검증된 후보 격자와 **값이 같은 별도 내장형 리스트·딕셔너리**의 검증 결과와 정규 키를 재사용하면, 저장 모델의 예측·판단 결과를 바꾸지 않고 복사 입력의 CPU 시간을 줄일 수 있다는 것이다. 이 문서는 v4 구현과 시간 점수를 얻기 전에 비교 방법과 채택 기준을 고정한다.

## 입력과 버전 고정

- 기준선 v2 SHA-256: `20e73cdcf39dbe7252399a3bff8eda9387ff592d046ea6483df15b13710e996d`.
- 기준선 v3 SHA-256: `644326f77be68fdd8b4a4050ab3bc0ee031ad8264519ecc54de0b051409e6299`.
- 공용 평가기 SHA-256: `e904a76d9e7940630e8a53f3f0e5d952bb98760fa74697bd7c42bfadb6a1e30e`; 예측기 SHA-256: `46c85961fb4d9388c99bc073522f8cf9c839065a1f4fe67a1b92aa33f3123075`.
- 저장 모델 SHA-256: `7a934da440ea0c7473e4e59eb5fa0c8c57f347389272bd303cb0051ef918b161`; 원본 Parquet SHA-256: `b7bba7963e8a309b6a8502a1d98eefb150476b1381ec016beeb68cbf63fae906`; 고정 45개 작업 선택 manifest SHA-256: `dcea7d8dc21ab6928da990d0fd3a4cfb6883fe1d01a831462c214d059d8ba679`.
- v4는 새 파일에 구현한다. 위 기준 파일과 저장 모델·원본은 수정하지 않는다. 해시가 달라지면 시간을 재기 전에 이 규약을 다시 고정한다.

## 변경 가설과 동등성 경계

각 요청의 최상위 필드와 SLO는 매번 검사한다. 이미 검증된 **동일 후보 리스트 객체**는 v3처럼 재사용한다. 다른 리스트는 첫 후보의 `workload_id`로 같은 작업 격자 후보를 좁힌 뒤, 여덟 딕셔너리의 내용·순서가 검증된 대표 리스트와 같은 경우에만 그 대표의 키를 재사용한다. 이 값 비교는 내장형 `list`/`dict`와 정확한 `str`/`int` 값에서만 사용한다. `bool == 1`, `2.0 == 2`, 사용자 정의 동등성처럼 원본 검증 결과와 값 비교가 달라질 수 있는 입력은 원본 전체 검증으로 보낸다. 오류가 있는 격자는 캐시하지 않는다. 요청과 번들은 호출 중 수정하지 않는 v2·v3 계약을 따른다. 예측 모형·지원 범위·SLO 선택 로직은 바꾸지 않으며, 기존 `_predict_grids`의 8격자 배치·실패 시 격자별 재시도를 사용한다.

기능 게이트는 v2·v3·v4의 **전체 정규 JSON 일치**, 모델 예측 호출 수 일치, 후보 상태 및 순서 일치다. 고정 manifest의 45격자×25 SLO를 (1) 동일 객체 공유, (2) 요청마다 `deepcopy`한 동등 격자로 만들고, 주 CUDA 캠페인의 575개 고유 격자도 비교한다. 세 경우의 모든 7쌍 순서 셔플에도 전체 JSON을 비교한다. 단위 시험에는 순서 변경·값만 다른 격자, 중복 형상·후보 오류, 잘못된 SLO/최상위 필드와 오류 순서, `bool`/`float`/하위 클래스 또는 비표준 값, 미검증/스키마 오류 번들, 지원 범위 보류, 독립적인 이유 리스트, 결합 예측 실패 재시도를 넣는다. v4에만 오류가 나거나 JSON이 달라지면 미채택한다.

## 시간·메모리 채택 기준

BLAS/OMP/MKL 각 한 worker, `max_grids=8`, 같은 입력 순서로 모델·Parquet 적재와 첫 완전 호출을 타이머 밖에 두고 **7쌍** 측정한다. 각 쌍의 세 경로 실행 순서는 고정 난수로 섞고, wall time과 process CPU time을 보존한다. 지표는 각 쌍의 v2/v4 및 v3/v4 wall time 비율의 중앙값이다. 새 v4를 복사 입력 경로에 채택하려면 복사 SLO 입력에서 v2보다 **1.20배 이상**, v3보다 **1.15배 이상** 빨라야 한다. 공유 입력에서는 v3 대비 **10% 초과 악화가 없어야** 하고, 575개 고유 입력에서는 v2·v3 각각 대비 **10% 초과 악화가 없어야** 한다. 별도 프로세스에서 재는 peak RSS는 세 입력 모두에서 v2·v3보다 **20 MiB 초과 증가하지 않아야** 한다. 모든 게이트를 통과해야 GO다. 하나라도 실패하면 특정 입력에 유리한 값이 나와도 v4를 기본 경로로 채택하지 않는다.

이 비교는 동일 호스트의 알려진 모델·배치에 대한 오프라인 CPU 판단 **계산 시간**만 평가한다. 생성 SLO는 실제 사용자 목표가 아니며, 실제 VM 형상이나 `DEPLOY`/`SCALE_OUT`의 인과 효과 또는 학술적 신규성을 검증하지 않는다.
