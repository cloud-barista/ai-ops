# 새 AI 모델을 위한 한 번의 기준 측정 기반 인프라 응답 전이

상태: 이 프로토콜에 따른 탐색적 실험 완료. 결과, 강한 기준선 및 실패한 ablation은 [연구 결과](anchor_conditioned_research_findings.md)에 기록했다. 예측 오차 개선은 관찰했지만, 강한 기준선 대비 측정 예산·선택 성능 우위와 학술적 독창성은 입증되지 않아 채택 판정은 보류한다.

## 풀려는 문제

처음 등록한 AI 모델은 과거 배포 결과가 없다. 모든 인프라 형상을 시험하는 데 시간과 자원이 든다. 한 가지 작은 형상에서 짧게 실행한 결과와 이전 응용들의 형상별 측정값으로, 나머지 형상의 지연시간·처리량을 예측하고 필요한 경우에만 두 번째 형상을 검증하는 문제를 다룬다.

현재 데이터는 한 호스트의 GPU 1/2개와 CPU affinity 2/4/8/16개로 구성된 완전 측정 행렬이다. 9개 AI 모델, 575개 입력 조건, 조건당 후보 8개다. 기준 측정은 **GPU 1개·CPU affinity 2개**로 고정한다. 나머지 7개 후보의 측정 결과는 학습 또는 최종 평가에만 사용한다.

## 선행연구와 필요한 차별점

- [Paragon, ASPLOS 2013](https://people.csail.mit.edu/delimitrou/papers/2013.asplos.paragon.pdf)은 소수의 새 응용 측정과 과거 응용 정보를 결합한다. 따라서 '한 번 측정한 뒤 다른 자원으로 전이' 자체를 최초라고 주장할 수 없다.
- [Quasar, ASPLOS 2014](https://people.csail.mit.edu/delimitrou/papers/2014.asplos.quasar.pdf)는 응용 QoS와 자원 효율을 함께 최적화한다.
- [CherryPick, NSDI 2017](https://www.usenix.org/conference/nsdi17/technical-sessions/presentation/alipourfard)은 클라우드 구성을 적은 시험 횟수로 찾는다.
- [Decision-Focused Learning](https://arxiv.org/abs/2112.03609)은 예측 오차보다 최종 선택 손실을 학습 목표에 반영한다. 의사결정 손실을 사용한다는 사실만으로 새 원리를 주장할 수 없다.

이 프로젝트의 **검증할 고유 설계**는 다음 조합이다: (1) 새 응용에서 측정한 기준 지연과 요청 처리량을 다른 형상의 **상대 반응 예측 입력**으로 사용하고, (2) GPU 수 변화의 물리적 처리량 기준을 먼저 빼고 남은 응용·부하별 잔차를 학습하며, (3) SLO 경계에 가까운 후보의 학습 비중을 높이고, (4) 예측은 두 번째 측정의 필요성을 결정하는 데만 사용하고 최종 선택은 그 측정값으로 확인한다. 각 요소의 기여를 분리해 비교한다. 기존 연구와의 완전한 중복 부재나 논문 수준의 독창성은 더 넓은 문헌 검토가 필요하다.

## 가설과 모델

모델 (m), 입력 조건 (x), 기준 형상 (a), 후보 형상 (c)에 대해 로그 배치 지연 (l), 로그 요청 처리량 (t)을 사용한다. 실측 기준값 (l_a,t_a)는 새 응용의 단 한 번 측정으로 얻는다.

```text
predicted log latency(c)    = measured log latency(a)    + f_L(x, anchor, c)
predicted log requests/s(c) = measured log requests/s(a) + log(GPU_count(c)) + f_T(x, anchor, c)
```

`f_L`, `f_T`는 이전 응용의 완전 측정 행렬에서 기준 대비 차이를 학습한다. 기준 형상에서는 차이를 정확히 0으로 둔다. GPU 수에 따른 `log(GPU_count)`는 출발점이며 선형 확장을 사실로 가정하지 않는다. 실제 비선형 효과는 잔차가 배운다.

학습 가중치의 연구 후보는 `1 + λ exp(-margin/τ)`이다. `margin`은 훈련 후보의 지연·처리량이 훈련 SLO 경계에서 얼마나 떨어져 있는지를 나타낸다. 테스트 결과를 본 뒤 λ·τ를 고르지 않는다. 기본 실험값은 λ=4, τ=0.2로 먼저 고정하며, λ=0 ablation을 함께 보고한다.

## 평가 계획과 판정 기준

1. **모델 단위 제외 평가:** 9개 모델을 하나씩 통째로 제외한다. 다른 8개 모델만으로 훈련한 뒤 제외한 모델의 기준 측정 1개로 7개 미측정 후보를 예측한다. 9개 모델별 결과와 모델 단위 bootstrap을 함께 제시한다. Qwen은 유일한 causal LM이어서 별도로 표시한다.
2. **예측 비교:** 무측정 절대 성능 모델, 절대 모델에 기준 잔차만 더한 방법, 후보별 평균 비율, 기준값을 출력에만 더하는 상대 모델, 제안한 **기준값 조건부 상대 모델**, SLO 경계 가중 모델을 비교한다. 주요 지표는 미측정 7개 후보의 지연·요청 처리량 평균 절대 로그오차다.
3. **선택 비교:** 기준 후보가 이미 SLO를 만족하는 그룹, 기준은 실패하지만 다른 후보가 만족하는 그룹, 모든 후보가 실패하는 그룹을 나눠 보고한다. SLO 목표는 요청/초이며 실측 `examples_per_second / batch_size`로 비교한다.
4. **측정 예산:** 기준 측정 후 다른 후보를 무조건 시험하는 방법과, 학습 모델이 가능성이 있다고 판단할 때만 두 번째 후보를 시험하는 방법을 비교한다. 두 번째 후보는 실제 측정값을 확인한 뒤 선택한다. 성공 회수율, 실제 위반, 평균 측정 횟수를 함께 보고한다.
5. **독립 캠페인:** 같은 호스트의 novel/space-filling 입력 조건에서 재검증한다. 다른 호스트의 remote 결과는 새 GPU·새 모델·수집 방식 변화가 동시에 일어나므로 스트레스 테스트로만 사용한다.

**방법 채택 기준:** 단순 기준 잔차 보정보다 새 모델의 미측정 후보 예측 오차가 모델 단위로 일관되게 줄고, 두 번째 측정 횟수 대비 SLO를 만족하는 후보의 회수가 좋아져야 한다. 예측만 좋아지고 선택 성과가 같으면 기여를 성능 전이로 한정한다. 개선이 없으면 고유 방법의 효과를 주장하지 않는다.

## 자료의 한계

기존 SLO는 수집 코드가 생성했다. 한 후보당 실행 1회라 지연 변동이 크며, 다른 호스트·실제 VM 가격·실제 scale 전환의 성과는 포함하지 않는다. 원본 생성 SLO에서 GPU 1개/2개에 CPU affinity 2개인 두 후보만 확인해도 측정상 가능한 357개 그룹을 전부 판정할 수 있다. 따라서 이 자료의 추천 문제는 제한적이고, **새 모델의 미측정 성능 예측과 필요한 측정 횟수**를 핵심 기여로 평가한다. 새로운 이종 인프라와 실제 응용 SLO를 확보하기 전에는 일반적인 클라우드 최적화 성과를 주장하지 않는다.
