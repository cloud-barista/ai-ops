# Philly 유휴 후 재활성화: 지연 정답 적응 확률의 탐색 규약 v3

**상태: 점수 전 동결 대상.** 이 방법은 [v1 규약](philly_idle_rebound_protocol.md)의 유휴 입력·2시간 재활성화 정답을 그대로 사용한다. [v2 검증 결과](philly_idle_rebound_validation_no_go.md)의 학습 493/6,345, 검증 229/4,839, 고정 Beta Brier 0.046015와 로지스틱 실패를 **알고 나서** 설계했다. 개발군 12월의 재활성화 양성 총수 232/6,290도 이미 알려져 있다. 따라서 이 실험의 검증과 같은 기계 12월 결과는 탐색·후속 확인 자료다. 다른 `[5,15)` 기계군의 **이 정답은 아직 열지 않았다**. 모두 같은 Philly DNN 훈련 클러스터의 GPU 계측이며, VM 축소 명령·사용자 SLO의 결과가 아니다. 이번 방법은 **감쇠 계수의 두 단계 수축 추정기**다. [Joulani 등(2013)의 지연 피드백 학습](https://proceedings.mlr.press/v28/joulani13.html), [Kárný(2014)의 순차 베이즈 추정·망각](https://doi.org/10.1016/j.ins.2014.01.048), [Shahrad 등(2020)의 서버리스 유휴 자원 정책](https://arxiv.org/abs/2003.03423)이 각각 관련 선행연구다. 이 조합이나 구성 요소의 학술적 최초성을 주장하지 않는다.

## 원본·시점과 점수 전 잠금

- 원본 정규화 Parquet SHA256 `15f1af4669acb9823d0e6d96291e799cf33f8a9c1813d4faf51b0b9eb618ad58`와 기존 원본·정규화 감사를 확인한다. v1의 `windows_for_machine`과 UTC 30분 판단 격자, 여섯 개 완전·유효 5분 창에서 모든 GPU의 기계 최대 사용률 `<10%`라는 입력 조건을 그대로 쓴다. 실제 수신 시각은 자료에 없고 최신 창 종료 뒤 5분 전달 지연을 가정한다. 현재 사용할 수 없는 `[d-300,d)` 창을 입력으로 쓰지 않는다.
- 개발 학습 `[2017-10-04,11-16)`의 완전 정답 6,345건·양성 493건으로만 고정 사전확률 `p₀=(493+1)/(6345+2)`를 만든다. v2 검증 JSON과 개발 적격성 JSON의 실제 파일 해시·집계 및 이 규약, v3 코드·테스트, 출처 해시를 **v3 freeze manifest**로 묶는다. 새 코드와 산출물은 기존 v1/v2 파일을 수정하거나 덮어쓰지 않는다.
- v3 지원량 감사는 출처 무결성을 검사한 뒤 `time_utc_s < 2017-12-01 00:00 UTC`만 읽는다. **검증 후보와 앵커의 집계 지원량만** 계산한다. 확률·Brier·행별 정답을 저장하거나 개발 후행 12월 및 다른 기계의 새 정답을 계산하지 않는다. v3 검증 확률 채점은 지원량 감사와 별도 단계이며, 이 규약·코드·테스트·freeze manifest가 고정된 뒤에만 허용한다.
- 방법 함수가 받는 fleet ID 집합 자체는 신뢰 경계가 아니다. 검증 지원량 감사는 실제 출처 정규화 감사의 **21개 개발 기계 ID 전체와 일치**하고 각 ID의 SHA256 해시 버킷이 `<5`임을 확인한 불변 집합만 넘긴다. 향후 다른 기계 시험 채점기도 같은 원본 출처의 ID 전체 및 `<5` 버킷을 다시 검사해야 한다. 후보 기계가 그 밖에 있으면 그 자신의 만기 앵커만 local에 허용하고, 다른 holdout 기계 ID가 이력에 섞이면 중단한다. 이 경계는 합성 테스트로 검사한다.

## 앵커와 지연 정답

- 앵커는 같은 기계의 입력 적격 판단을 시각 오름차순으로 보면서 **이전 앵커 판단 뒤 7,200초 이상** 지난 첫 후보로 정한다. 동일 기계·시각 중복은 오류다. 앵커 선택 함수에는 기계 ID와 판단 시각만 전달한다. 미래 관측 여부·재활성화 값은 앵커 선택에 전달하지 않는다. 다른 기계의 같은 시각은 ID 사전순으로 안정적으로 처리한다. 정답 미관측 앵커도 다음 앵커까지의 간격을 차지하며, 나중에 다른 후보로 소급 교체하지 않는다.
- 앵커 정답은 판단 `dⱼ` 뒤 `[dⱼ,dⱼ+7200)`의 24개 연속·유효 5분 창 중 기계 최대 GPU 사용률 `≥50%`가 있는지다. 하나라도 빠지면 `unknown`이고 갱신에서 제외한다. 마지막 창 끝과 전달 지연 300초를 더한 **정답 가용시각 `aⱼ=dⱼ+7500`**에서 완료된다. 예측 시각 `d`에는 **`aⱼ<d`**인 완전 정답만 사용한다. 미관측을 음성으로 바꾸지 않는다. 같은 기계의 업데이트 정답 구간은 앵커 간격 덕분에 겹치지 않는다. 다른 기계의 공통 시간 충격은 여전히 상관될 수 있다.
- 온라인 갱신 상태는 검증 시작 `2017-11-16 00:00 UTC`에 **비어 있다**. 학습 정답은 이미 `p₀`에 포함됐으므로 다시 앵커 합계에 넣지 않는다. 검증에는 만기된 검증 앵커만 더하고, 나중에 시험을 하게 된다면 그 상태와 그때까지 만기된 시험 앵커만 시간순으로 더한다.

## 고정 방법과 동일행 기준선

검증 후보의 기계 `m`, 시각 `d`에 대해 만기 앵커 `j`의 가중치는 `wⱼ(d)=2^(-(d-aⱼ)/(3×86400))`이다. 목표 기계의 결과가 전역 기준에 중복 반영되지 않도록 **fleet 계산에서 `m`을 제외**한다.

- fleet: `p_f⁻ᵐ(d)=(40p₀+Σ_{j:machine≠m} wⱼyⱼ)/(40+Σ_{j:machine≠m}wⱼ)`.
- 제안 기계별 확률: `p_m(d)=(20p_f⁻ᵐ+Σ_{j:machine=m}wⱼyⱼ)/(20+Σ_{j:machine=m}wⱼ)`.
- 유효 표본 수는 `ESS=(Σw)²/Σw²`(합계 0이면 0)다. 목표 기계를 제외한 **만기된 누적** fleet 앵커의 판단 UTC 날짜가 **5일 이상**, fleet `ESS≥100`, **누적 양성 앵커≥10건**이면 fleet 지원이다. 하루마다 10건을 요구하지 않는다. local은 해당 기계의 만기된 누적 앵커 판단 날짜 **3일 이상**, `ESS≥20`, 양성·음성 각각 **3건 이상**이면 지원이다. fleet 지원이 없으면 `p₀`, fleet만 지원하면 `p_f⁻ᵐ`, 둘 다 지원하면 `p_m`을 낸다. 이 지원 조건을 알기 위해서도 해당 판단 **전에 만기된** 라벨만 센다.

모든 기준선은 제안 방법과 **같은 입력 후보·같은 앵커·같은 만기 규칙**으로 모든 행에 확률을 낸다. 완전 정답 행에서만 동일행 지표를 계산한다. 아래 1–5번은 지원 보류 없이 만기된 증거를 즉시 쓰고, 6번은 제안법과 동일한 보류를 적용해 감쇠 가중치만 분리한다.

1. `frozen_train_beta`: 모든 행 `p₀`.
2. `expanding_fleet_40`: 목표 기계를 뺀 만기 앵커 전부를 무감쇠로 사용한 `(40p₀+Σy)/(40+n)`.
3. `decayed_fleet_3d_40`: 위 `p_f⁻ᵐ`, 지원 보류 없음.
4. `rolling_fleet_7d_40`: 목표 기계를 뺀 `d-604800≤aⱼ<d` 만기 앵커를 무감쇠로 사용한 `(40p₀+Σy)/(40+n)`.
5. `decayed_machine_3d_20`: 기계 `m`의 만기 앵커와 고정 `p₀`만 쓴 `(20p₀+Σwⱼyⱼ)/(20+Σwⱼ)`.
6. `expanding_hierarchical_40_20`: fleet은 목표 기계를 뺀 **무감쇠** `(40p₀+Σy)/(40+n)`이고, local은 그 fleet 확률에 수축한 **무감쇠** `(20p_fleet+Σ_{machine=m}y)/(20+n_m)`이다. 40/20과 fleet/local 지원 보류는 제안법과 동일하다. 이 비교가 감쇠 가중치의 추가 이득을 가른다.

합계가 0이면 해당 식은 `p₀`이다. 점수 동률(`|Brier₁-Brier₂|≤10⁻¹²`)일 때 대표 단순 기준선은 위 번호가 낮은 것을 고른다. 하위 위험 20%의 확률 동률은 `SHA256(machine_id UTF-8 || ':' || decision_utc_s 십진수)` 오름차순으로 깬다. 확률 보정·평가할 행을 정답으로 선택하지 않는다.

## 점수 전 지원량 게이트와 이후 채택 조건

검증 `[2017-11-16,12-01)`의 **모든 입력 적격 후보**를 분모로 한다. fleet 지원에 도달한 후보가 **50% 이상**이고, fleet와 local이 모두 지원되는 후보가 **10% 이상**이어야 한다. 출처·분할·검증 후보 건수가 기존 적격성 감사와 일치하고 이 두 지원량 조건도 통과해야 **별도 검증 확률 점수를 계산할 수 있다**. 실패하면 확률/Brier 없이 중단한다. 지원량 계산에는 앵커의 집계 양·음 건수만 사용하고 행별 정답·확률은 산출하지 않는다.

이 게이트를 통과하면 검증에서 제안법의 같은 행 Brier가 (a) `frozen_train_beta`의 알려진 0.046015034063580054보다 **상대 5% 이상 낮고**, (b) 위 **다섯 적응 기준선**의 최소 Brier보다 **상대 2% 이상 낮아야** 다음 집합을 열 수 있다. 기계 동일 가중 Brier도 여섯 기준선 전체의 최선보다 높지 않아야 한다. 고정 두 구간 `[11-16,11-23)`과 `[11-23,12-01)`의 Brier가 각각 높지 않고, 기계와 UTC 날짜를 각각 블록으로 한 짝지은 2,000회 재표집(seed 43)의 `제안−최선 단순 기준선` Brier 차 95% 구간 상한이 둘 다 0 미만이어야 한다. 하위 위험 20%의 실제 재활성 비율은 동일 건수의 최선 단순 기준선보다 높지 않아야 한다. 단순 기준선은 위 동률 순서로 검증에서 한 번 정한다. 검증 결과를 보고 식·임계값을 바꾸면 이 검증은 다시 탐색이다.

검증을 통과하고 후속 평가 규약·코드·선택 결과의 파일 해시를 별도로 동결한 뒤에만 개발군 후행 12월과 `[5,15)` 다른 기계의 이번 정답을 한 번 열 수 있다. 다른 기계의 fleet에는 `<5` 개발 기계의 만기 앵커만 넣고, local에는 대상 기계 자신의 만기 앵커만 넣는다. 다른 holdout 기계의 라벨을 fleet에 섞지 않는다. 기존 v1의 각 집합 자료 게이트, 양쪽 상대 5% Brier 개선, 기계·날짜 재표집 상한 <0, 기계 동일 가중·두 반구간 Brier 및 하위 20% 사건률 조건을 후속 GO 기준으로 유지한다. 통과해도 같은 클러스터의 관측 위험 예측 증거이며 실제 `SCALE_IN` 효과·새 서비스 전이를 입증하지 않는다.
