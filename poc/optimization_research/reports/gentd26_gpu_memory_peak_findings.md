# GenTD26 AI 서빙 컨테이너의 30분 GPU 메모리 관측 피크 예측

작성일: 2026-09-28. [시험 전에 고정한 규약](gentd26_gpu_memory_peak_protocol.md) SHA-256 `213a9183c86d712f74f291d0e1420d73e6ff112a88b2bbb935629d8bba07d030`, [선택 manifest](../artifacts/gentd26_gpu_memory_peak_v1/selection_manifest.json) SHA-256 `db2758343900870eb43d2603cb0b379db03a4bf7573fae65540e9b4de24ae1a9`에 따라 한 번 채점했다. **사전 연구용 게이트는 통과했다.** 그러나 결과는 같은 하루의 익명 AI 서빙 컨테이너에서 *기존 배정 아래 미래에 관측한 GPU 메모리 표본 최대값*의 예측이며, 최소 VRAM·GPU 수량이나 VM `SCALE_OUT/IN` 효과의 검증이 아니다.

## 데이터와 선택 절차

[Alibaba GenTD26의 고정 commit 설명](https://github.com/alibaba/clusterdata/blob/8c132fb7717fbd44cf434cf81f2cd865a80072d5/cluster-trace-v2026-GenAI/README.md)은 `pod_gpu_memory_used_bytes_anon.csv`를 컨테이너별 GPU 메모리 사용량 표본으로 정의한다. 입력은 약 60분에 해당하는 **64개 연속 57초 표본**이고, 마지막 입력은 결정 시각보다 342초 앞선다. 정답은 결정 뒤 **32개 연속 표본의 최대값**(30.4분)이다. 57초 간격이 끊긴 창은 제외했다. duty 계측은 같은 컨테이너·시각의 과거 입력 창에만 연결하고 결측과 실제 0을 구분했다. 데이터는 한 날짜 약 22.8시간이며 원본 메모리 161,413행·144개 익명 컨테이너다.

컨테이너 ID SHA-256으로 20%를 완전 보류했다. 나머지 개발 ID의 처음 8시간 **7,164건·92개 컨테이너**로 학습하고 다음 4시간 **3,672건·85개**로 기준선·학습기를 선택했다. 그 뒤 시간 구간의 완전 보류 ID **3,032건·28개**가 주 시험이며 개발 ID의 **11,185건·92개**는 시간 이동을 보는 보조 시험이다. 미래 정답이 경계를 넘는 행은 제외했다. 선택 단계에서는 전체 원본 CSV를 메모리에 읽되, 보류 ID와 시험 구간의 미래 정답을 구성하거나 점수화하지 않고 대상 수만 [dry run](../artifacts/gentd26_gpu_memory_peak_v1/dry_run.json)에 남겼다. 이전 적합성 감사에서 전체 trace의 시간별 급증 빈도를 이미 봤으므로 독립적인 새 날짜의 블라인드 검증은 아니다. 간격 285초의 연속 결정들이 30분 정답 창을 공유하므로 3,032행을 독립 사건 3,032개로 세지 않는다. 주 시험의 가능한 격자 결정 3,080건 중 연속 이력·미래 표본 조건을 통과하지 못한 48건은 제외했다. 따라서 평가 대상 자체가 미래 관측 완결성에 따라 선택된 오프라인 표본이다.

학습 구간의 `미래 피크−최근 60분 피크` 90백분위만 더하는 기준선이 검증 p90 pinball 손실 **1.050 GiB**로 네 기준 중 가장 낮았다. 최근 피크 자체는 **1.343 GiB**, 과거 4시간 피크는 **1.066 GiB**였다. 과거 메모리 특징으로 잔차를 학습한 고정 HistGradientBoosting 90백분위 모델의 검증 손실은 **0.914 GiB**였다. GPU duty를 더한 모델은 **0.912 GiB**로 0.28%만 개선해 사전 규약의 2% 선택 조건에 못 미쳤다. 따라서 시험 전에 **메모리 이력 전용 모델**과 위 전역 잔차 기준선을 고정했다. duty의 독립 기여를 입증한 결과가 아니다.

## 고정 시험 결과

낮은 pinball 손실이 좋고 coverage는 관측 미래 최대값이 예측 90백분위 이하였던 비율이다. 예측·정답의 GiB는 공개된 byte 값을 2³⁰으로 나눈 값이며, 익명화가 metric scaling을 포함하므로 실제 GPU 카드 용량 요구량으로 환산하지 않는다.

| 방법 | 검증 pinball / coverage | 주 시험 pinball / coverage | 개발 ID 후반 pinball / coverage |
| --- | ---: | ---: | ---: |
| 최근 60분 피크 | 1.343 / 68.5% | **0.562 / 82.6%** | **0.602 / 81.5%** |
| 검증 선택: 최근 피크 + 학습 잔차 p90 | 1.050 / 91.9% | 0.785 / 96.7% | 0.791 / 96.8% |
| 같은 컨테이너의 과거 완료 피드백 분위수 | 1.155 / 91.2% | 0.745 / 94.5% | — |
| 과거 4시간 피크 | 1.066 / 89.8% | 0.688 / 93.7% | 0.665 / 93.5% |
| **시험 전 선택: 메모리 이력 학습기** | **0.914 / 86.9%** | **0.669 / 96.5%** | 0.777 / 95.9% |
| 미선택: 메모리+GPU duty 학습기 | 0.912 / 87.9% | 0.641 / 96.0% | 0.727 / 94.9% |

선택 학습기는 주 시험에서 **검증 선택 기준선보다 pinball을 14.7% 낮췄다**(`0.785→0.669 GiB`). 28개 컨테이너 균등 평균도 `0.773→0.663 GiB`로 낮았고 21개 컨테이너에서 손실이 감소했다. 컨테이너 단위 2,000회 재표집(seed 43)의 학습기−기준선 손실 차 95% 구간은 **`−0.172~−0.058 GiB`**다. 같은 날의 컨테이너 차이만 반영하며 새 날짜·서비스 신뢰구간이 아니다. 고정 시험 전반은 `0.881→0.704 GiB`, 후반은 `0.685→0.633 GiB`였고 선택 학습기 coverage는 각각 **96.8% / 96.2%**였다. 적격 결정·컨테이너·급증 건수와 사전 손실·coverage·구간 기준이 모두 통과했다. [기계 판독 점수](../artifacts/gentd26_gpu_memory_peak_v1/test_metrics.json)에 각 게이트를 남겼다.

## 연구 해석과 제한

**검증에서 선택되지 않은 단순 최근 피크가 주 시험에서는 학습기보다 pinball 손실이 낮았다**(`0.562` 대 `0.669 GiB`). 다만 최근 피크 자체의 coverage는 **82.6%**라 90백분위 예측의 대안으로 그대로 사용하면 과소포괄한다. 과거 4시간 피크는 주 시험에서 학습기와 비슷한 손실(`0.688`)과 93.7% coverage를 보였고, 개발 ID의 같은 후반에서는 학습기보다 훨씬 낮은 손실(`0.665` 대 `0.777`)이었다. 전반 검증에서 고른 여유값이 후반에는 과도해진 **시간 분포 이동**이 결과에 크게 영향을 줬다. 주 시험의 선택 학습기 coverage **96.5%**도 명목 90%보다 높고 평균 초과 예측량은 **5.30 GiB**다. 따라서 사전 게이트 통과를 범용 운영 상한이나 일관된 최적 방법으로 읽지 않는다.

과거 4시간 피크와 비교하면 주 시험 손실 차는 `0.688→0.669 GiB`로 **2.8%**이고, 학습기가 이긴 컨테이너는 28개 중 13개다. 사후 탐색용 컨테이너 재표집에서 이 차의 95% 구간은 **`−0.160~+0.110 GiB`**로 0을 포함한다. 최근 피크보다 **2GiB 이상 높은 미래 피크**는 주 시험 195건·19개 컨테이너에서 나타났다. 이 *정답으로 정의한 사후 진단층*에서 학습기 coverage는 **55.4%**(`108/195`)였고 pinball은 `2.190 GiB`였다. 90백분위 모델이 정답으로 선택한 고위험층에서도 90%를 덮어야 한다는 뜻은 아니지만, 이 모델을 급증 감지나 메모리 부족 자동 판단으로 직접 쓰기 어렵다는 실무적 경고다. 미래에 0 메모리 표본이 포함된 51건에서는 coverage가 **78.4%**였고, 학습기간 후 처음 나타난 컨테이너는 단 **3개·94건**이다. 0값은 후반에 집중돼 원인이 불명확하며 지우거나 결측으로 바꾸지 않았다.

모델은 **기존 컨테이너에서 관측되는 메모리 피크의 오프라인 연구 입력 후보**로만 유지한다. 공개 trace에는 GPU 용량/할당량, OOM, 명령 시점·완료 시점, 사용자 SLO, 실제 계측 수신 시각이 없다. 342초 가용 지연은 로그에서 확인한 값이 아니라 가정이다. 같은 컨테이너 과거 완료 정답을 쓰는 보조 기준선은 완료 시각에 즉시 정답을 알 수 있다고 계산하므로, 342초 지연이 정답에도 적용된다면 가용성이 낙관적이다. 이를 342초 늦춰 다시 계산한 주 시험 손실은 `0.745→0.743 GiB`로 거의 변하지 않았고, 선택된 전역 잔차 기준선과 학습기의 비교에는 영향이 없다. 다른 날짜와 서비스에서 최근 피크·4시간 피크 기준선 및 실제 메모리 부족 사건을 함께 평가해야, 이 예측을 경희대 요구 형상이나 Scale-out/in 판단에 연결할 수 있다. 수치 개선은 표준적인 분위수 회귀의 관측 예측 이득이며 새로운 알고리즘의 최초성 증거는 아니다.

재현 명령은 아래와 같다. 새 출력 경로를 사용해 고정 산출물을 보존한다. [누출·연속성 테스트](../tests/test_gentd26_gpu_memory_peak.py)는 5개가 통과했다. 시험 예측은 `test_predictions.parquet` (`../artifacts/gentd26_gpu_memory_peak_v1/test_predictions.parquet`)에 보관했다. 별도 감사자가 원본에서 시험 3,032건의 키·정답, 모든 입력 특징, 학습 잔차와 저장 예측·점수를 재구성해 일치함을 확인했다.

```bash
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python scripts/evaluate_gentd26_gpu_memory_peak.py --stage select --output artifacts/gentd26_gpu_memory_peak_repro
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python scripts/evaluate_gentd26_gpu_memory_peak.py --stage score --output artifacts/gentd26_gpu_memory_peak_repro
```
