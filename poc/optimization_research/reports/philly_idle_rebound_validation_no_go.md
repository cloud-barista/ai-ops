# Philly 기계 유휴 후 GPU 재활성화: 검증 단계 중단

2026-09-28. [점수 전 연구 규약](philly_idle_rebound_protocol.md)의 새 목표는 기계 전체 GPU가 30분 연속 낮은 사용률을 보인 뒤 2시간 안에 다시 활성화되는지 예측하는 것이다. 이는 기존 [GPU 슬롯별 30분 고사용률 경보](philly_gpu_risk_findings.md)와 단위·시작 상태·임계값·시간 범위가 다르다. **검증 단계에서 로지스틱이 가장 강한 단순 기준선보다 나빠 후행 시험의 행별 예측·성능과 다른 기계군의 새 라벨을 열지 않고 중단했다.** 후행 날짜의 적격성·양성 건수는 아래에 따로 공개한다. 이 자료는 DNN 훈련 클러스터의 계측이며 실제 AI-App `SCALE_IN` 효과나 사용자 SLO 결과를 담지 않는다.

## 점수 전 자료 게이트

[동결 manifest](../artifacts/philly_idle_rebound_v1/freeze_manifest.json) SHA256 `6ff43a1045c39f30e4c422dcadb224ea6ed37f09ab3575f93681e6fc2b14d388`가 규약·감사 코드·합성 테스트·개발/기계군 원본 해시를 고정한다. [수정 후 개발군 적격성 감사](../artifacts/philly_idle_rebound_v1/development_eligibility_v2.json) SHA256 `f801c104c9a3df0784617d9820ef5b99b59721abcf898eac7cc4a1dc1609a65f`는 모델 학습·예측 없이 집계 건수만 저장했다. 5분 창은 기대 GPU 슬롯 모두에서 5개의 유효·고유 분을 요구한다. 최신 입력창 종료 `t+300`과 가정한 5분 전달 지연 뒤 결정 `d=t+600`을 구분하고, 정답은 `[d,d+7200)`의 24개 창에서 만든다. 기계 시계열 끝의 부족한 미래 창도 **미관측 정답으로 후보 분모에 남긴다.**

| 개발 기계군 분할 | 유휴 후보 | 미래 완전 | 재활성 / 비재활성 | 적격 기계 | 게이트 |
| --- | ---: | ---: | ---: | ---: | --- |
| 학습 `[10-04,11-16)` | 6,392 | 6,345 (99.26%) | 493 / 5,852 | 19 | 통과 |
| 검증 `[11-16,12-01)` | 4,839 | 4,839 (100%) | 229 / 4,610 | 13 | 통과 |
| 후행 날짜 `[12-01,12-16)` | 6,290 | 6,290 (100%) | 232 / 6,058 | 15 | **적격성만 확인, 성능 미채점** |

후행 날짜의 양성 건수는 모델 점수 전에 **자료 적격성 게이트**에서 집계한 값이다. 동결 규약을 쓰기 전에 개발 기계군의 대략적 목표 건수도 탐색했으므로, 이 날짜를 완전한 블라인드 시험이라고 부르지 않는다. 24시간 이력이 부분적인 후보는 학습 961건, 검증 41건, 후행 날짜 0건이었다. 미래 정답 미관측 학습 47건의 과거 24시간 유효 비율 평균과 관측 후보 평균 차는 **1.73%포인트**였고 사전 20%포인트 게이트 안이다. 검증·후행 날짜의 미관측 후보는 없었다. 기계×UTC일별 관측률 및 양성 기계·일·2시간 간격 묶음도 감사 JSON에 보존했다. 후행 날짜의 232개 양성 판단은 66개 근접 판단 묶음으로 나타나며 독립 사건 232개가 아니다.

## 학습과 검증 선택

[학습/검증 전용 v2 코드](../scripts/select_philly_idle_rebound_v2.py)는 정규화 Parquet를 `time_utc_s < 2017-12-01 00:00 UTC`로 읽고 `train`·`validation` 후보만 생성했다. Beta 확률표와 특성의 중앙값/표준편차 및 로지스틱 계수는 **학습 6,345건**에서만 적합했다. 검증 4,839건으로 세 기준선과 L2 로지스틱 `C∈{0.1,1,10}`을 비교했다. 세 회귀 모두 최대 2,000회 전에 수렴했고 실제 반복은 30/29/49회였다. [합성 테스트](../tests/test_philly_idle_rebound_selection.py)는 결정 뒤 GPU 값을 바꿔도 특징이 변하지 않음, 부분 이력·학습 전용 Beta, 12월 이전 로더 경계, 미수렴 후보의 검증 채점 중단을 확인했다. 감사 테스트와 합쳐 **14/14 통과**했다.

| 검증 방법 | Brier ↓ |
| --- | ---: |
| 학습 전체 Beta(1,1) | **0.046015** |
| 직전 2시간 고사용 여부별 Beta | 0.048078 |
| 마지막 고사용 시각 구간별 Beta | 0.049118 |
| 로지스틱 C=0.1 | **0.050831** |
| 로지스틱 C=1 | 0.051190 |
| 로지스틱 C=10 | 0.051215 |

규약의 검증 선택 규칙은 전체 Beta와 `C=0.1`을 골랐다. 최선 로지스틱 Brier는 선택 기준선보다 **10.47% 높았다**. 검증 재활성률도 229/4,839=4.73%로 학습 493/6,345=7.77%보다 낮았지만, 이 분포 차이를 성능 악화의 원인으로 단정하지 않는다. 세 C의 검증 AP는 0.0838 수준이었다. 모든 정확한 값과 선택은 [v2 검증 지표](../artifacts/philly_idle_rebound_v1/validation_metrics_v2.json)에, 선택된 계수와 학습 변환값은 v2 모델 (`../artifacts/philly_idle_rebound_v1/selected_model_v2.joblib`)에 보관했다. [v2 선택 manifest](../artifacts/philly_idle_rebound_v1/selection_manifest_v2.json)의 SHA256은 `c278604d148f262b2df1cd96b1e9a5cd0820b627b7ca60c975d16efa1c07967d`다. 모델 SHA256은 `642280bef32c0faa828e8b1226a71671dc240ae3335ad902013d36196fb5ed02`; v2 코드 SHA256은 `c5ee213bc464fd35f95f4a90af4f501f13c9e12f05a2349ba10ce331d076ee06`. 저장된 실제 파일 해시, 검증 JSON, 선택 manifest의 상호 참조를 다시 확인했다.

첫 선택 코드 v1은 세 후보 모두 수렴했다고 기록했지만 미수렴 시 명시적으로 중단하지 않았다. v2에서는 이 검사를 추가했다. v1 코드·모델·검증 지표·선택 manifest는 검토 전 사본 (`../artifacts/philly_idle_rebound_v1/pre_convergence_review/`)으로 보존했고 원래 v1 코드 경로도 복원했다. v1과 v2의 검증 Brier·선택값·모델 파일 SHA256은 동일하다. **선택 코드에 대한 독립 정적 검토는 검증 산출물 생성 이후였으므로 사후 검토**이며, 점수 전 독립 검토라고 기술하지 않는다.

## 판단과 재개 조건

원래 규약의 후행 날짜·다른 기계 공동 GO 조건은 **평가하지 않았다**. 검증 결과를 본 뒤 연구 비용과 홀드아웃 보존을 고려해 여기서 중단한 결정이므로 이를 사전에 정한 시험 게이트의 실패라고 부르지 않는다. 현재는 가장 단순한 학습 전체 재활성률을 연구용 참조로 남기고 로지스틱을 경희대 판단기에 채택하지 않는다. `[5,15)` 다른 기계군의 이 새 목표 라벨·모델 점수는 아직 열지 않았다.

향후 방법을 바꿔 재개하려면 새 점수 전 규약과 독립 평가 자료가 필요하다. 홀드아웃 해제 계약도 더 강화해야 한다: manifest의 **정확한 선택 코드·모델·검증 지표 경로와 실제 파일 해시**를 함께 검사하고, 검증 지표 안의 `freeze_manifest_sha256`과 원 규약 해시를 교차 검증하며, 개발 적격성 감사의 **분할별 gate**가 전부 통과했는지도 확인해야 한다. 현재는 이 후속 사항을 위해 동결 v1 감사 코드를 다시 수정하거나 홀드아웃을 열지 않는다. 실제 VM 축소 판단을 검증하려면 앱별 요청·사용자 SLO와 축소 명령/완료·전후 결과가 연결된 별도 자료가 필요하다.

재현 가능한 범위: `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 /usr/bin/python3 poc/optimization_research/scripts/select_philly_idle_rebound_v2.py`는 기존 산출물의 덮어쓰기를 거부하므로 새 실험 폴더에서만 다시 실행해야 한다. 검증 선택 전의 자료 감사 명령은 `python3 poc/optimization_research/scripts/audit_philly_idle_rebound.py --cohort development --output <새 JSON 경로>`다. `machine_holdout` 감사는 선택 manifest를 명시하지 않으면 거부한다. 선택 manifest는 만들어졌지만 검증 NO-GO 결정에 따라 그 호출은 하지 않았다. 이 보고서에는 후행 시험/다른 기계 성능 수치가 없다.
