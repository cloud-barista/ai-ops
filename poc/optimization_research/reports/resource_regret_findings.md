# 합성 SLO에서 최소 자원 추천의 후회 비용 평가

## 평가 대상과 기준

이 평가는 저장된 K=8 예측을 **자원 선택**에 연결한다. 외부 모델 하나를 제외하고 나머지 8개 모델의 측정 분포에서 지연 p95와 요청/초의 분위수 목표를 각각 5개씩 만들어 25쌍을 정했다. 후보 8개 중 예측상 두 목표를 만족하는 형상을 **GPU 수가 적은 순, 이어서 CPU 코어 제한이 작은 순**으로 선택했다. 실측상 목표를 만족하는 후보 가운데 같은 순서로 가장 싼 형상을 오라클로 삼았다. 동률 비용이나 화폐 단위는 만들지 않았다.

주 평가 모집단은 기준 측정에 사용된 각 모델의 workload 8개를 뺀 **미측정 workload 503개 × 목표 25쌍 = 12,575개 질의**다. 이 중 실측 가능 질의는 5,880개이고, GPU 1개만으로 가능한 질의는 3,398개다. 비교한 네 방법은 같은 모델별 GPU 1개·2코어 기준 측정 8회와 같은 측정 비용을 사용한다. [전체 575개 workload를 포함한 결과](../artifacts/resource_regret_v1/metrics.json)도 남겼다. 비교 방법 간 차이는 전체와 미측정 집합에서 같았다.

## 결과

| 방법 | 실측 가능 5,880개 중 성공 | 오라클 최소 형상 일치 | 잘못 승인 | GPU 1개가 가능한 3,398개 중 불필요한 GPU 2개 추천 |
| --- | ---: | ---: | ---: | ---: |
| 공유 모델 잔차 2차 모멘트 전이 | **5,308** | **5,099** | **531** | **191** |
| 부드러운 커널 전이 | 5,239 | 5,011 | 592 | 216 |
| 직접 Ridge 보정 | 5,234 | 4,938 | 547 | 285 |
| 전역 평균 보정 | 5,062 | 4,774 | 665 | 274 |

`성공`은 선택 형상이 실측 목표를 만족함을 뜻하고, `잘못 승인`은 선택했지만 실측 목표를 위반함을 뜻한다. `오라클 최소 형상 일치`는 **성공하면서** 실측 가능 후보 중 GPU·CPU 순서가 최소인 형상을 선택한 횟수다. 따라서 실패한 추천을 싸다고 평가하지 않는다. `불필요한 GPU 2개 추천`은 GPU 1개로 가능한 질의에서 GPU 2개를 골랐음을 뜻하며, 실패한 추천도 포함한다. 공분산 전이의 해당 191건 중 190건은 실측 목표를 만족했다.

공분산 전이는 커널 대비 성공 69건, 최소 형상 일치 88건을 더 얻고 잘못 승인 61건, 불필요한 GPU 2개 추천 25건을 줄였다. 하지만 성공한 추천 중 CPU 코어 제한을 불필요하게 높인 경우는 **19건**, 커널은 **13건**이다. 같은 GPU 수 안에서의 초과 코어 제한 합도 공분산 90, 커널 60으로 공분산이 나쁘다. GPU와 CPU를 임의의 단일 가격으로 합산하면 이 차이를 숨길 수 있어 별도 지표로 남겼다.

## 불확실성과 해석

모델별 쌍체 재표본화에서 공분산−커널의 `최소 형상 일치` 차이는 총 +88건이지만 모델당 평균의 기술적 95% 구간은 **[-0.22, 24.00]**이다. 같은 비교에서 불필요한 GPU 2개 추천 차이 -25건의 구간은 **[-6.56, 0.22]**다. 최소 형상 일치의 +88건 중 **61건은 BERT L4-H256, 23건은 ELECTRA-small**에서 나온다. 따라서 전체 합계만으로 일반적 비용 절감 효과를 주장할 수 없다. Ridge 대비 최소 형상 일치 +161건의 모델당 구간은 **[0.67, 40.78]**이지만 이 역시 탐색 후 계산한 기술적 구간이다.

25개 목표는 같은 workload의 측정값을 반복해서 질의한 **상관된 합성 조건**이다. 실제 사용자 SLO, VM 가격, 배포 결과가 아니고, 한 호스트·제한된 모델군에서 얻은 값이다. GPU 수→CPU 코어 제한의 순서 역시 임시 자원 선호 규칙이다. 이 평가는 기존 방법이 해당 데이터에서 비용에 민감한 추천에도 도움이 되는지 확인한 것이며, 새 알고리즘의 독창성이나 운영 효과의 검증이 아니다.
