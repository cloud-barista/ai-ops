# 저장된 성능 예측기의 8후보 일괄 채점

> 이 시간표는 최초 전역 입력 범위 판정 시점의 역사적 측정이다. 현재 코드는 [모델·장치별 지원 범위](saved_model_condition_support_fix.md)를 적용하고, 벤치마크 스크립트도 검증된 로더를 쓴다. 8후보 일괄/직렬 동등성은 현재 지원된 입력의 1회 smoke test에서 확인했으며 아래 60회 시간표를 다시 측정한 것은 아니다.

2026-09-28. 기존 SQLite 측정으로 학습해 저장한 ExtraTrees 성능 예측기는 여러 CPU/GPU 후보를 한 요청으로 받으면서도 후보마다 모델을 한 번씩 호출했다. [오프라인 예측 함수](../scripts/predict_performance.py)가 지원 범위 검사를 후보별로 유지하고, 통과한 후보만 한 번에 채점한 뒤 원래 위치에 결과를 돌려놓도록 수정했다. 저장된 모델과 원본 측정 파일은 변경하지 않았다.

## 사전 규약과 측정

[측정 전 고정한 규약](performance_batch_predict_protocol.md)에 따라 주 캠페인의 원본 행 순서에서 처음 등장하는 GPU 작업군을 골랐다. 해당 작업군에는 GPU 1·2개 × CPU 2·4·8·16코어, 총 8개 적격 후보가 있다. 동일한 저장 모델에서 새 일괄 호출과 기존 방식의 8회 직렬 호출을 비교했다. 모든 후보가 `PREDICTED`였고, **상태·예측값·후보 순서가 정확히 같았다.** 별도 단위 테스트는 중간에 `ABSTAIN`이 있는 입력에서도 출력 순서와 이유가 유지되고 모델 호출이 1회인 것을 확인한다. 중앙값 기준선 경로의 일괄 처리도 테스트했다.

같은 프로세스에서 각 경로를 10회 예열하고 호출 순서를 섞어 각각 60회 측정했다. 두 경로 모두 단일 추론 worker다. 함수 전체에는 지원 검사, DataFrame 구성, 모델 채점, 결과 구성 시간이 포함되며 저장 모델 로드는 제외된다.

| 8후보 예측 방식 | 평균 | 중앙값 | 95백분위 |
| --- | ---: | ---: | ---: |
| 후보별 8회 직렬 호출 | 165.28ms | 163.94ms | 175.55ms |
| 유효 후보 1회 일괄 호출 | **20.88ms** | **20.54ms** | **23.00ms** |

사전 기준인 출력 완전 동등성과 95백분위 **2배 이상** 개선을 통과했다. 이 실행에서 95백분위는 **7.63배** 빨라졌다. 이는 8개 후보를 한 번에 평가하는 오프라인 연구 함수에 한정된다. 모델 로드, JSON 전송, 플랫폼 API, VM 생성·배포 및 실제 사용자 지연은 측정하지 않았다. 합성 SLO 승인 안전성도 이 시간 측정으로 검증되지 않는다.

## 재현과 범위

- [벤치마크 코드](../scripts/benchmark_performance_batch_predict.py), 60쌍 원시 시간 (`../artifacts/performance_batch_predict_v1/timings.csv`), [집계·파일 해시](../artifacts/performance_batch_predict_v1/metrics.json).
- 연구 루트에서 `PYTHONPATH=/home/researcher/ai-mcmp/research OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 /usr/bin/python scripts/benchmark_performance_batch_predict.py`로 재현한다.
- 원본 모델을 저장한 Python 3.9.25·scikit-learn 1.6.1 환경에서 최종 지표를 측정했다. 다른 scikit-learn 1.5.2 환경의 예비 측정에서도 출력 동등성과 2배 기준은 통과했으나 절대 지연이 달랐다. 최종 표와 아티팩트는 원본 버전 측정만 반영한다.
- 한 호스트의 한 작업군만 시간 측정에 사용했다. 다른 CPU 부하나 후보 수의 p95 개선을 보장하지 않는다. 현재 예측기는 같은 호스트·이미 본 응용의 벤치마크 점 추정용이며 자동 `DEPLOY`/`SCALE_OUT` 승인기가 아니다.
