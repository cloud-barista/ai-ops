# GenTD26 요청시간 예측의 선택적 보류 실험

## 결론

**검증 구간 안에서 시간순으로 다시 나눠 만든 보류 규칙도 신뢰할 만한 p90 상한을 만들지 못했다.** 집단 표본 수만 확인하면 요청의 60.0%를 수락했지만, 수락 요청의 5개 시험 구간 중 최저 포괄률은 **88.0%**였다. 별도 검증 라벨의 최근 포괄률까지 확인한 규칙은 전체 요청의 **21.2%만 수락**했고, 12월 7일 시험 구간에서는 수락 요청의 포괄률이 **85.4%**였다. 따라서 어느 규칙도 배포·스케일링 판단에 사용하는 p90 상한 정책으로 채택하지 않는다.

12월 1일 시험 직전에는 검증 구간 뒤쪽의 포괄률이 **87.9%**여서 최근 포괄률 규칙이 전부 보류했다. 같은 규칙은 12월 5일 시험 직전에도 **88.9%**라는 신호로 전부 보류했지만, 그 구간의 보류 전 시험 포괄률은 **94.5%**였다. 반대로 12월 7일에는 검증 감사 포괄률이 **93.3%**였는데 수락한 요청의 시험 포괄률은 85.4%였다. 최근 관측값만으로 다음 2일의 변화를 확실히 구별하기 어렵다.

## 자료와 인과적 평가 절차

- 원본은 Alibaba [GenTD26 요청 추적 자료](https://github.com/alibaba/clusterdata/tree/8c132fb7717fbd44cf434cf81f2cd865a80072d5/cluster-trace-v2026-GenAI)의 `lora_request_trace.csv`다. 성공 요청의 `exec_time_seconds`를 예측한다. 실제 완료 시각이 없으므로 라벨은 **요청 생성 시각 + 기록된 실행시간 + 추가 1시간** 뒤에 가용하다고 가정했다.
- [기존 5개 시간순 시험](gentd26_walkforward_findings.md)의 학습·잔차 초기화·검증·비중복 2일 시험 경계를 유지한다. 기본 p90 모델은 각 시점에서 과거 라벨만으로 다시 학습한다. 검증 2일 중 **첫째 날의 감사 시작 시점까지 가용한 라벨**로 rolling 창, 그룹 정책, 92% 여유 시간 및 혼합비를 결정한다. 둘째 날의 **시험 시작 시점까지 가용한 라벨**은 그 고정 정책의 별도 감사에 쓴다. 첫째 날과 둘째 날의 라벨은 겹치지 않는다.
- **정책을 학습한 첫째 날**과 시험 시작 시점에 가용한 검증 표본 모두에서 요청 종류와 모델 ID가 **각각 100건 이상**이면 `support` 규칙이 수락한다. `audit_empirical`은 여기에 감사 전체 200건 이상·포괄률 90% 이상, 해당 요청 종류와 모델 ID 각각 감사 30건 이상·포괄률 90% 이상을 요구한다. `audit_wilson`은 감사 전체 200건 이상, 두 집단 각각 50건 이상, 그리고 전체·집단별 **단측 90% Wilson 하한이 90% 이상**일 때만 수락한다. 새 집단이나 표본 부족 집단은 보류한다.
- **이 문턱값들은 기존 5개 구간의 실패를 본 뒤 정한 후향적 가설**이다. 각 시험 구간의 실제 수락 여부를 계산할 때는 해당 시험 시작 전까지 가용하다고 가정한 라벨과 요청 메타데이터만 사용했고, 시험 라벨로 정책이나 문턱값을 다시 조정하지 않았다. Wilson 하한은 같은 분포에서 독립적인 관측을 가정하므로 시계열의 미래 보증이 아니다.

## 결과

5개 시험 구간의 원본 요청은 13,415건이다. 아래 손실과 포괄률은 **해당 규칙이 수락한 요청에 대해서만** 계산했다. 수락 집합이 서로 달라 손실의 크기만으로 규칙의 우열을 판단할 수 없다.

| 예측·보류 규칙 | 수락 건수 | 보류율 | 수락 건수의 포괄률 | 수락 건수의 p90 pinball 손실 |
|---|---:|---:|---:|---:|
| 기존 전역 rolling, 전부 수락 | 13,415 | 0% | 90.0% | 2.775초 |
| [기존 92% 보정](gentd26_coverage_guard_findings.md), 전부 수락 | 13,415 | 0% | 92.2% | 2.693초 |
| 검증 첫날만으로 재학습한 92% 보정, 전부 수락 | 13,415 | 0% | 90.6% | 2.698초 |
| `support` + 새 보정 | 8,044 | 40.0% | 92.5% | 2.507초 |
| `audit_empirical` + 새 보정 | 2,841 | 78.8% | 93.3% | 2.079초 |
| `audit_wilson` + 새 보정 | 879 | 93.4% | 90.2% | 2.016초 |

`audit_empirical`이 수락한 **같은 2,841건**만 기존 예측으로 다시 평가하면 전역 rolling은 포괄률 **93.5%**·손실 **2.211초**, 기존 92% 보정은 **93.9%**·**2.021초**였다. 새 보정의 93.3%·2.079초는 기존 보정보다 좋지 않다. 보류할 요청을 고르는 것과 수락 요청의 예측을 개선하는 것은 별개다.

| 시험 시작 | 새 보정 전부 수락 포괄률 | `support` 수락 건수·포괄률 | `audit_empirical` 수락 건수·포괄률 | `audit_wilson` 수락 건수·포괄률 |
|---|---:|---:|---:|---:|
| 11월 29일 | 91.5% | 755 · 91.7% | 713 · 91.4% | 713 · 91.4% |
| 12월 1일 | 84.4% | 1,177 · **88.0%** | 0 · 산출 불가 | 0 · 산출 불가 |
| 12월 3일 | 91.8% | 2,820 · 92.3% | 1,929 · 94.8% | 0 · 산출 불가 |
| 12월 5일 | 94.5% | 2,768 · 94.8% | 0 · 산출 불가 | 0 · 산출 불가 |
| 12월 7일 | 92.0% | 524 · 92.0% | 199 · **85.4%** | 166 · **84.9%** |

문제 집단에서도 유용한 수락 범위가 남지 않았다. `IMG_2_IMG` 1,103건 중 `support`는 261건을 수락하고 포괄률 **89.3%**였다. `audit_empirical`은 **8건만 수락**했다. 모델 `M0003` 1,240건 중 `support`는 782건을 수락하고 포괄률 **88.9%**였으며, 감사 규칙 두 가지는 **모두 보류**했다. 8건의 100% 관측 포괄률은 그 집단의 신뢰성을 뒷받침하지 않는다.

특히 12월 7일의 `M0001`은 시험 직전 감사에서 **252건 중 97.6%**가 상한 안에 들었다. 그러나 `audit_empirical` 규칙이 수락한 시험 `M0001` **166건 중 84.9%**만 상한 안에 들었다. 충분해 보이는 직전 표본도 짧은 시간의 분포 변화를 놓쳤다.

## 해석과 다음 단계

검증 라벨을 다시 나누면 정책 학습 표본이 줄어 새 보정 자체의 전체 포괄률이 기존 92% 보정의 92.2%에서 **90.6%**로 낮아졌다. 이 평가로는 보류 규칙이 미래 요청 상한의 신뢰성을 확보했다는 결론을 내릴 수 없다. 앞으로 별도 기간 또는 별도 서비스의 실제 완료 시각과 사용자 지연 SLO를 확보한 뒤, 보정·감사·최종 시험 구간을 미리 고정해야 한다. 불확실할 때는 **판단 보류 상태를 반환하는 인터페이스**까지만 연구 대상으로 둘 수 있다.

이 자료에는 실제 VM 증감 명령과 행동별 사용자 지연 결과가 없다. 본 실험은 요청 실행시간 예측의 선택적 보류만 평가하며, Scale-out/in 결정의 효과나 안전성을 평가하지 않는다.

재현:

```bash
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python scripts/evaluate_gentd26_selective_guard.py
python -m unittest discover -s tests -p 'test_gentd26_selective_guard.py' -v
```

실행 코드: [`evaluate_gentd26_selective_guard.py`](../scripts/evaluate_gentd26_selective_guard.py). 시간 경계, 라벨 가용 시각, 각 집단 증거, 규칙별 결과, 입력·코드 SHA256: [`metrics.json`](../artifacts/gentd26_selective_guard_v1/metrics.json). 요청별 보류 여부와 예측: `test_predictions.parquet` (`../artifacts/gentd26_selective_guard_v1/test_predictions.parquet`). 기존 92% 보정 산출물과 **13,415건의 시간·요청 종류·모델 ID·라벨이 행별로 일치**하는지 확인했고, 계약 테스트 4개가 통과했다.
