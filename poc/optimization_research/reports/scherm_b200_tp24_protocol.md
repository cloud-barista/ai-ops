# B200 온라인 추론 TP2→TP4 반응: 탐색 평가 규약

**상태: 탐색 규약, 모델 점수 계산 전 기록.** 공개 [Scherm 자료](../data/external/scherm_onprem_2026/SOURCE.md)의 `serving_ALL.csv` 528행과 B200의 대상 수, 두 지표의 범위는 이미 열람했다. 따라서 아래 모델 전체 제외 결과도 **맹검 독립 검증이 아니다.** 현재 SQLite의 배치 replica 형상과 이 자료의 vLLM tensor parallelism은 다른 작업이며 원시 행이나 계수를 합치지 않는다.

## 질문과 적격 단위

같은 B200 환경의 Qwen2.5 AWQ 모델에서 **TP2 측정값 한 쌍**(출력 토큰/초 중앙값, TTFT 반복 평균의 95분위)을 보고, 같은 모델·동시성의 **TP4** 두 지표를 예측할 수 있는가? 출처 revision은 `e19edbaccec8add876073a3b0668e84115a59d0f`, CSV SHA-256은 `d7f677cf0c4ccfd8c702c8458c4e6c3d324e90292bf13e5f09e065431e8d5f9e`다. B200 job/runner 스크립트 해시도 출처 기록에 고정했다.

`gpu == "NVIDIA B200"`, `model`이 `Qwen/Qwen2.5-`로 시작하고 `-AWQ`로 끝남, shard 파일명이 `_tp2_` 또는 `_tp4_`를 정확히 포함, `n_ok >= 10`, 동시성 양수, 두 지표 모두 양수·유한인 행만 후보로 둔다. `(model, tp, concurrency)` 중복이 있으면 스크립트 실행을 중단한다. 양 TP에 같은 모델·동시성 키가 있을 때만 한 쌍으로 만든다. 이 규칙으로 예상한 **7모델·64쌍**과 맞지 않으면 점수를 내지 않는다. 모델별 9개 안팎의 동시성 행은 독립 모델 64개가 아니다. TP 수는 `gpu_count` 열이 아닌 `_tpN_` 파일명과 공개 B200 실행 스크립트로 정의한다.

## 고정 비교

모델 ID 하나의 **모든 동시성 쌍을 통째로 제외**하고 다른 6개 모델만 학습한다. 제외 모델의 TP2 계측만 시험 입력으로 준다. 목표는 각각 `log(TP4 output_tok_s_median / TP2 output_tok_s_median)`와 `log(TP4 ttft_ms_p95 / TP2 ttft_ms_p95)`다. 모든 방식은 같은 적격 쌍을 평가한다.

1. 유지: TP4 출력률·TTFT를 TP2 값 그대로 예측한다.
2. 2배/유지: 출력률만 TP2의 2배, TTFT는 그대로 둔다.
3. donor 동시성 중앙값: 훈련 모델만의 해당 동시성 **로그 비율 중앙값**을 TP2 관측값에 곱한다. 해당 동시성이 훈련에 없으면 훈련 전체 중앙값을 쓴다.
4. 고정 Ridge: 등록 시 알 수 있는 모델 크기(B 단위)와 Coder 여부, 동시성, TP2의 두 로그 계측값을 사용한다. `StandardScaler`를 훈련 fold에만 맞추고 `Ridge(alpha=10)`을 두 목표마다 별도 적합한다. 모델 ID의 범주 인코딩·TP4 계측값은 특징에 넣지 않는다.

## 점수와 판정

모델별 평균 절대 로그오차(MALE)를 7개 모델에 동일 가중해 출력률과 TTFT에 각각 보고한다. 64쌍의 행 가중 MALE, 7개 모델별 손실, TP4 개선/악화 방향 적중도 함께 공개한다. 채택을 논할 탐색 문턱은 Ridge가 두 지표 모두 각 지표의 **최선 단일 기준선**보다 모델 균등 MALE을 5% 이상 낮추고, 적어도 5/7모델에서 두 지표 모두 해당 기준선보다 나쁘지 않으며, 어느 모델의 어느 지표도 해당 기준선의 1.2배보다 나쁘지 않은 경우다. 하나라도 실패하면 이 학습기를 형상 추천에 채택하지 않는다. 시험 fold를 보고 특징·규제 강도를 다시 고른 방법은 같은 결과로 채택 판정을 받지 못한다.

여기서 TTFT 열은 **요청별 p95가 아니라 반복 실행의 평균 TTFT에 대한 p95**다. 정답은 완료된 성공 실행의 throughput/TTFT이고, 실패한 서버 구성·OOM은 쌍에 없을 수 있다. 같은 Qwen2.5 계열·B200·한 수집 캠페인의 tensor-parallel 반응으로만 해석한다. TP를 VM 노드 수나 replica Scale-out으로 바꾸지 않으며 사용자 SLO·배포 결과를 검증하지 않는다.
