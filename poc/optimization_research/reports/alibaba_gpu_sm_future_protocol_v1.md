# Alibaba GPU 미래 기간 고정 모델 검증 계획

기존 상대 날짜 109~115일의 탐색 모델을 미사용 다음 7일인 day116~122에서 확인한다. 기간·모델·기준선·게이트는 새 계측값을 열기 전에 고정했다.

## 고정 모델과 자료

- 두 저장 모델과 학습 코드 SHA256은 옆 JSON에 기록한다. 재학습·특징 추가·alpha 변경·시험 점수로 선택을 하지 않는다. 선택 경로는 residual HGB alpha1, 기준선은 기존 검증에서 고정한 현재값 유지다.
- 실제 관측 구간 t는 day116 hour00~day122 hour22이며 정답 t+1은 그 기간에 포함된다. 첫 시점의 과거 2시간은 기존 day115 hour22~23을 읽는다. 사용 가능한 과거가 부족하거나 다음 구간이 미관측이면 제외하며 0 라벨을 만들지 않는다.
- 온라인 GenAI·1GPU 요청, 최근 3창과 다음 창에서 동일 서버·유효 SM, 중복 pod/시각 제외, 안정된 비결측 workload 조건과 기존 특징을 그대로 사용한다.
- 원본 시간별 행을 모두 보존하고 다운로드 CRC32, 저장 SHA256·행수·컬럼수를 검산한다. 전체 원본 ZIP은 보존하지 않는다.

## 평가 집합

- 주 확인은 4창 모두 단일 GPU 서버이고 workload hash bucket85~99인 집합이다. 학습 workload·pod와 겹치지 않아야 한다. 넓은 1GPU 요청 pod 집합은 별도 보조 확인으로 제시한다.
- 두 층은 별개 모델이므로 개선율을 합산하지 않는다. 같은 공개 클러스터의 새 날짜이며 새 클러스터 검증으로 부르지 않는다.
- 원래 학습 workload의 미래 날짜, 기존 train/validation/test 가공 예제 어느 곳에도 없던 workload, 전체 유효 workload 결과를 보조로 별도 보고한다. 보조 결과가 주 확인 실패를 대체하지 않는다.

## 사전 고정 판정

- 주 확인 최소 지지: 1,000행, 20workload, 10SM단위 초과 변화 30개, 변화가 있는 workload 5개, 7일 모두 유효 행 존재. 부족하면 INSUFFICIENT_DATA로 기록한다.
- PASS 조건은 현재값 유지보다 전체 행 MAE·workload 동일가중 MAE가 낮고, 변화 구간 MAE·절대오차 p95가 나빠지지 않고, 7일 중 5일 이상 행 MAE가 낮고, workload 단위 2,000회 재표집의 기준선-모델 MAE 차 95% 구간 하한이 양수인 것이다. 한 조건이라도 실패하면 NO_GO다.
- 직접 HGB, 최근 3창 평균, 학습 GPU 유형별 중앙값도 같은 고정 경로로 평가한다. 직접 HGB 대비는 잔차 구성의 추가 증거로 보고하되 주 게이트의 기준선을 시험 후 바꾸지 않는다.
- 고사용률 사례 수, 변화 workload 집중도, 학습에 없던 GPU 공개 유형을 기록한다. 알려진/미지원 GPU 유형의 하위 결과는 진단이며 새로운 채택 기준으로 사용하지 않는다.

## 검증과 해석

- 시간 경계·첫 시점의 과거 재사용·기간 종료·예측기 fit 금지·입력 파일 해시 변경 거부를 합성 테스트로 확인한다.
- 저장 예측을 frozen 모델에서 재계산하고 JSON 지표를 다시 계산한다. 모델 해시는 전후 같아야 한다. 평가 코드·freeze·자료·예측의 해시와 패키지 버전을 저장한다.
- 계측 전달은 구간 종료 직후라는 가정이다. 유효 동일 서버 다음 관측이 존재하는 조건부 예측이며 실패·OOM·사용자 SLO·실제 SCALE_OUT/IN 효과를 검증하지 않는다.
- period 선택 후 결과가 불리해도 날짜를 바꾸거나 모델을 조정하지 않는다. 실패와 지지 부족도 연구 결과로 저장한다.
