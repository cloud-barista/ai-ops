# 정적 배포 후보의 2단계 추론: 안전성·시간 기준 실패

2026-09-28. **SLO 경계에서 멀어 보이는 질의를 경량 모델로 끝내는 2단계 추론은 현재 KHU 정적 추천기에 채택하지 않는다.** 9개 모델 단위 제외 시험의 잘못 승인은 항상 강한 모델 `1,307건`에서 제안법 `1,383건`으로 늘었고, 성공한 정확 최소 형상 선택은 `3,775건`에서 `3,736건`으로 줄었다. 내부 donor 검증이 경량 경로를 허용한 것은 ELECTRA 한 모델뿐인데, 그 모델에서 잘못 승인이 `67→143건`으로 증가했다. 공정한 단일 스레드 강한 모델보다 제안법의 95백분위 채점 시간도 짧지 않았다. [점수 전 규약](cascade_inference_protocol.md)의 채택 게이트는 실패했다.

## 무엇을 측정했나

고정 SQLite 추출 (`../data/audit_v1/measurements.parquet`)의 `khu-hf-local-exhaustive` 적격 GPU 4,600행은 모델 9종·작업 575개마다 GPU 복제 수 1/2 × CPU affinity 2/4/8/16의 8개 형상을 모두 측정한다. 하나의 질의는 등록 모델 크기·배치·길이·동시성·작업 유형과 지연 상한/처리량 하한에서 이 8개 형상 중 GPU 수, 이어서 CPU 코어 수가 가장 작은 예측 합격 후보를 고른다. 실측 `latency_p95_ms`는 **배치** p95이고, 요청 처리량은 `examples_per_second / batch_size`로 보정했다. 25개 SLO 쌍은 외부 대상 모델을 제외한 훈련 모델의 측정 분위수로 만들었다. 총 14,375개 질의는 같은 575개 작업을 25번 묻는 **상관된 합성 목표**이며 사용자 요청 14,375건이 아니다.

경량 모델은 표준화 Ridge로 두 로그 성능을 예측하고, 강한 모델은 기존 200-tree ExtraTrees 회귀다. 경량 모델의 첫 합격 후보와 앞선 불합격 후보들이 SLO 경계에서 떨어진 로그 여유를 계산해, 여유가 선택 문턱보다 작거나 작업 종류/모델 크기가 donor 지원 밖이면 강한 모델에 보낸다. 모델 H를 외부에서 통째로 제외하고, 남은 donor D를 다시 하나씩 제외한 예측과 결과에서만 문턱을 선택했다. H의 실측 지연·처리량은 문턱·특징·추천에 사용하지 않았다. 직접 합격 HGB와 동일 강한 호출률 무작위 라우팅은 비교용이다. 전체 시험 질의를 한꺼번에 순위화하는 선택률은 **온라인 정책에 사용하지 않았다**.

## 정적 선택 품질

아래는 모델 하나씩 제외한 9분할을 합한 값이다. `정확 최소`는 실제 SLO를 만족하면서 정의한 GPU·CPU 순서의 최소 형상을 선택한 건수다. `동수 오승인`은 항상 강한 모델의 승인 수로 사후 맞춰 자른 위험 순위 진단으로, 그대로 실행할 온라인 정책이 아니다.

| 방법 | 승인 | 잘못 승인 | 정확 최소 | 강한 호출률 | 동수 오승인 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 항상 강한 모델 | 6,081 | 1,307 | 3,775 | 100% | 1,307 |
| 2단계 제안법 | 6,077 | **1,383** | **3,736** | 93.31% | **1,383** |
| 항상 경량 모델 | 5,525 | 1,518 | 3,171 | 0% | 1,863 |
| 직접 합격 HGB | 5,701 | 1,486 | 3,090 | 0% | 1,506 |
| 무작위 라우팅·동일 호출률 | 6,251 | 1,548 | 3,736 | 93.31% | 1,372 |

실측상 어떤 형상이든 합격 가능한 합성 질의는 6,746개였다. 8개 모델에서는 내부 donor의 사전 품질 제약이 `tau=∞`를 선택해 경량 예측을 계산한 뒤에도 강한 모델을 **항상** 호출했다. 따라서 이 분할들의 선택 결과는 항상 강한 모델과 같다. BERT 4종 공동 제외의 6,400개 질의에서도 `tau=∞`였고 두 방법 모두 승인 3,430·잘못 승인 85·정확 최소 1,913이었다. 이 계열 평가는 같은 원본 측정을 재사용하며 별도의 독립 검증이 아니다.

| 제외 모델 | 문턱 | 강한 호출률 | 잘못 승인: 강한→2단계 | 정확 최소: 강한→2단계 |
| --- | ---: | ---: | ---: | ---: |
| RoBERTa base | ∞ | 100% | 38→38 | 399→399 |
| Qwen 0.5B | ∞ | 100% | 292→292 | 134→134 |
| ALBERT base | ∞ | 100% | 792→792 | 198→198 |
| DistilBERT base | ∞ | 100% | 19→19 | 600→600 |
| BERT base | ∞ | 100% | 99→99 | 394→394 |
| BERT L2-H128 | ∞ | 100% | 0→0 | 1,025→1,025 |
| BERT L4-H256 | ∞ | 100% | 0→0 | 231→231 |
| BERT L4-H512 | ∞ | 100% | 0→0 | 407→407 |
| ELECTRA small | 0.4 | 39.88% | **67→143** | **387→348** |

ELECTRA의 문턱 `0.4`는 **안쪽 donor**에서는 오승인 `1,406→1,320`, 정확 최소 `3,320→3,308`로 사전 조건을 통과했다. 그러나 ELECTRA 보류 모델의 64개 작업×25 SLO 질의 중 962개를 경량 경로로 처리하면서 선택 137건이 달라졌다. 새 오승인 81건은 고유 작업 25개에서, 고쳐진 오승인 5건은 3개에서 나왔다. 25개 SLO가 같은 작업 실측을 재사용하므로 이 76건 차이를 독립 사건 76개로 해석하지 않는다. 이 사례는 donor에서 고른 경계가 새 모델의 판단 품질로 이전되지 않았음을 보여 준다. 어느 모델 특성이 역전의 인과 원인인지는 이 자료로 알 수 없다.

## 실제 CPU 채점 시간과 수정 검산

첫 점수 실행에서는 200-tree 모델의 `n_jobs=2`를 사용했고, 한 작업당 합성 SLO **하나**를 고정해 8개 후보 `predict`와 선택을 3회 반복했다. 기존 실행의 `n_jobs=1` 시간에는 타이머 안에서 `set_params(n_jobs=1)`과 복구를 한 비용이 섞였다. 그 시간은 **채택 판단에서 제외**했다. 원래 점수·규약·코드 파일을 바꾸지 않고 별도 [공정 시간 보정 코드](../scripts/cascade_inference_single_thread_benchmark.py)로 같은 적합 모델의 얕은 복사본을 타이머 밖에서 `n_jobs=1`로 설정해 다시 쟀다. 10개 분할 전체 후보 예측은 1/2 worker에서 최대 절대차 `2.7e-15` 이내였다.

아래 시간은 공정 보정 실행의 주 9개 모델, 575개 작업×3회=`1,725`개 **단일 SLO 질의/방법**이다. SLO 시나리오 25개를 25번 실제 호출한 것처럼 시간을 부풀리지 않았다. 모델 적합과 JSON/API 변환 시간은 포함하지 않는다.

| 채점 경로 | 평균 ms | p50 ms | p95 ms | 강한 모델 실제 호출률 |
| --- | ---: | ---: | ---: | ---: |
| 항상 강한 모델, 1 worker | **34.12** | 30.54 | **45.90** | 100% |
| 2단계, 강한 모델 1 worker | 33.00 | 30.38 | 46.71 | 94.26% |
| 항상 강한 모델, 기존 2 workers | 53.62 | 56.04 | 59.15 | 100% |
| 2단계, 강한 모델 2 workers | 51.36 | 56.68 | 60.20 | 94.26% |

경량 경로가 일부 질의의 시간을 줄여 평균은 작아졌지만, 1 worker만 쓰는 강한 모델의 p95보다 2단계 1-worker의 p95가 **0.82ms 길다**. 원래 2-worker 2단계는 1-worker 강한 모델보다 평균·p95가 모두 길다. 사전 규약의 평균 25%·p95 20% 개선 기준도 충족하지 못한다. 이는 이 환경에서 한 번 수행한 warm CPU microbenchmark이며 실제 플랫폼 지연의 보장은 아니다. 같은 작업에 SLO만 다르게 여러 번 묻는 실제 호출 패턴이 있다면 강한 회귀의 8개 출력을 캐시할 수 있으므로 추가 속도 이득은 더 작아질 수 있다.

## 결정과 재현

품질과 시간의 사전 기준은 모두 통과하지 못했다. 이번 2단계 방식을 경희대 판단 모듈의 기본 경로로 연결하지 않는다. 안전성을 높이려면 새 모델·호스트의 실제 배치 성능과 사용자 SLO가 따로 필요하다. 현재 SQLite는 모델의 정적 형상별 배치 성능을 평가하지만 실제 배포, VM 증감, 서비스 지연 또는 비용의 효과를 담지 않는다. 2단계 추론 원리의 학술적 신규성도 주장하지 않는다.
