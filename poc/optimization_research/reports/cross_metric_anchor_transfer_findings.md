# 지연·처리량 공동 잔차 전이 평가: 미채택

2026-09-29. [사전에 고정한 평가 규약](cross_metric_anchor_transfer_protocol.md)의 채택 게이트를 통과하지 못했다. 같은 8개 기준형상 측정으로 지연과 처리량의 잔차를 함께 조건화하면 주 캠페인 공유 인코더 8개의 지연 예측은 개선된다. 그러나 **미측정 형상 처리량 오차가 0.120705에서 0.126337로 증가**했고, 원래 생성 SLO의 성공 선택은 298건에서 295건으로 줄고 잘못된 승인은 13건에서 14건으로 늘었다. 두 새 입력 조건에서도 공동 방법의 처리량 오차가 기존 kernel과 Ridge보다 모두 컸다. 현재 방법은 인프라 형상 추천의 채택 후보로 사용하지 않는다.

## 평가 범위와 비교 조건

[구현](../scripts/cross_metric_anchor_transfer.py)과 [평가 러너](../scripts/evaluate_cross_metric_anchor_transfer.py)는 기존 SQLite의 고정 측정 스냅샷 (`../data/audit_v1/measurements.parquet`)을 사용했다. 주 캠페인에서 대상 모델을 통째로 제외하고, donor의 기준형상 잔차는 추가 내부 모델 제외 분할로 만들었다. 모든 방법은 대상 모델의 같은 GPU 1개·CPU affinity 2코어 **8개** 측정만 사용했다. 새 입력 조건에는 추가 측정이 없다. 대상 모델의 나머지 정답은 평가에만 사용했다. 기존 저장 예측과 다시 계산한 대조군의 최대 절대 차이는 `5.33e-15`였다. 파일 SHA-256, 프로브 위치·실측 GPU-wall 비용, 미지원 Qwen fallback, 독립 지표 절제 대조군은 점수 계산 전에 검증했다.

아래 MALE는 로그 예측의 평균 절대오차다. **주 평가 모수는 실제 측정한 8셀만 제외**한다. 주 캠페인에서 공유 인코더는 모델당 504셀, Qwen은 496셀이다. 새 입력 조건은 조건별 모든 8형상 셀을 포함한다. 기존 보고서의 작업당 7개 비기준 형상 MALE는 상세 결과 (`../artifacts/cross_metric_anchor_transfer_v1/per_model_metrics.csv`)에 보조열로만 남겼다. SLO 선택은 항상 전체 8후보를 사용한다. 처리량은 `examples_per_second / batch_size`다.

## 고정 게이트 결과

| 분할·조건 | 공동 MALE 지연 / 요청·초 | 독립 지표 MALE 지연 / 요청·초 | 원래 SLO 성공·오승인: 공동 / 독립 |
|---|---:|---:|---:|
| 공유 인코더 8개, 주 캠페인, 미측정 4,032셀 | 0.226669 / **0.126337** | 0.238524 / **0.120705** | 295·14 / 298·13 |
| 공유 인코더 8개, novel-matrix, 전체 128셀 | 0.301262 / 0.376598 | 0.322173 / 0.374769 | 11·0 / 11·0 |
| 공유 인코더 8개, space-filling, 전체 320셀 | 0.368940 / 0.343282 | 0.369474 / 0.352176 | 27·1 / 27·1 |
| BERT4 공동 제외, 주 캠페인, 미측정 2,016셀 | 0.320387 / **0.156639** | 0.334813 / **0.139592** | 173·7 / 174·6 |
| BERT5 공동 제외, 주 캠페인, 미측정 2,520셀 | 0.353371 / **0.146571** | 0.379201 / **0.124442** | 209·12 / 209·12 |

Qwen을 포함한 전체 모델별 제외 9개에서는 주 캠페인 미측정 4,528셀의 공동/독립 지연 MALE가 `0.230583/0.241121`, 처리량 MALE가 `0.133133/0.128127`이었다. 원래 SLO 성공 선택은 `335/338`, 오승인은 `19/18`이었다. Qwen에는 정렬 donor가 없어 두 방법 모두 기존 단일 지표 kernel fallback을 썼다. 따라서 **공유 인코더 8개** 결과가 교차 지표 방법의 주 비교다. 공유 인코더 8개의 원래 SLO에서 정답상 가능했던 작업은 309개였고, 실제 최소 `(GPU 수, CPU affinity)`를 성공적으로 고른 수는 공동 290개, 독립 294개였다.

새 입력 조건 처리량의 사전 비교 기준도 통과하지 못했다.

| 새 조건, 공유 인코더 8개 | 공동 | 기존 kernel | 기존 Ridge |
|---|---:|---:|---:|
| novel-matrix 요청·초 MALE | 0.376598 | **0.355711** | **0.342775** |
| space-filling 요청·초 MALE | 0.343282 | **0.324187** | **0.313138** |

고정 게이트는 주 캠페인의 두 MALE가 모두 독립 방식보다 낮고, **각** 새 조건의 처리량 MALE가 kernel과 Ridge 모두보다 낮으며, BERT4·BERT5 공동 제외에서 지연·처리량 오차와 원래 SLO 오승인이 악화되지 않아야 한다. 첫째 조건은 처리량에서, 둘째 조건은 두 캠페인 모두에서 실패했다. BERT4와 BERT5 주 캠페인에서도 처리량이 악화했고 BERT4 오승인은 6건에서 7건으로 증가했다. [기계 판정과 각 비교값](../artifacts/cross_metric_anchor_transfer_v1/metrics.json)의 `frozen_adoption_gate`는 `do_not_adopt`다. 점수를 본 뒤 가중치·선택 기준·게이트를 변경하지 않았다.

## 생성 SLO와 25개 반복 질의

위 표의 오승인은 **원래 생성된 목표**에서 선택 형상의 실측 결과가 목표를 위반한 작업 수다. 별도의 [25개 합성 목표 규칙](counterfactual_slo_findings.md)은 donor 훈련 자료만으로 목표값을 만들고 같은 측정 작업에 25번 묻는다. 그 수를 서로 독립인 앱·사용자 요청 25개로 해석할 수 없다. 아래는 주 캠페인의 반복 질의 합계이며 채택 게이트에는 쓰지 않았다.

| 분할 | 관련 반복 질의 수 | 성공 선택 공동 / 독립 | 오승인 공동 / 독립 |
|---|---:|---:|---:|
| 전체 모델별 제외 9개(Qwen fallback 포함) | 14,375 | 6,113 / 6,143 | **625 / 574** |
| BERT4 공동 제외 | 6,400 | 4,690 / 4,690 | **257 / 248** |
| BERT5 공동 제외 | 8,000 | 6,038 / 6,024 | **422 / 389** |

개별 목표·모델·캠페인 수치는 SLO 행 (`../artifacts/cross_metric_anchor_transfer_v1/slo_scenarios.csv`), 전체 요약은 집계 CSV (`../artifacts/cross_metric_anchor_transfer_v1/macro.csv`)에 기록했다. 프로브 manifest (`../artifacts/cross_metric_anchor_transfer_v1/split_manifest.csv`)는 대상별 8개 주 측정과 외부 0개, 예측 (`../artifacts/cross_metric_anchor_transfer_v1/predictions.parquet`)은 모든 후보 형상의 재계산 값을 담는다.

다출력 공분산은 기존에 알려진 통계 개념이다. 이번 실험은 한 호스트에서 수집한 소수 인코더와 생성 배치 SLO를 대상으로 한 **로컬 후향 구성·평가**다. 기존 시험·새 조건이 이전 연구에 이미 열람된 자료이므로 독립 검증이 아니다. 새로운 고유 알고리즘, 새 앱으로의 일반화, 실제 VM 선택·스케일 제어 효과를 입증하지 않는다.
