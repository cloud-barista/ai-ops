# SwissAI Qwen 접두 버킷 재사용: 전체 수집·점수 전 규약

작성일: 2026-09-29. **상태: `qwen3-32b-buckets.jsonl` 전체 원본 미수집, 미래 재사용 레이블과 검증·시험 점수 미열람.** 이 규약은 경희대의 *배포·제어에 특화된 추론 최적화* 중 입력 접두 캐시의 오프라인 연구를 정의한다. 사용자 SLO, GPU 메모리, 실제 캐시 적중·TTFT·처리량, VM 배포·스케일 조치의 효과를 학습하거나 평가하는 규약은 아니다.

## 출처와 사전 적격성 확인

- 공식 [SwissAI 데이터 카드](https://huggingface.co/datasets/eth-easl/swissai-serving-trace/blob/c3dd66602b564ce189f7db81115620413e646cd5/README.md)의 고정 revision `c3dd66602b564ce189f7db81115620413e646cd5`을 사용한다. 카드의 `qwen3-32b-buckets.jsonl`은 **3,994,435행·4,617,817,342바이트**의 Qwen/Qwen3-32B 요청 메타데이터에 `token_count`와 `bucket_ids`를 더한 파일이다. 버킷은 16개 입력 토큰 단위, 우측 패딩으로 생성된 결정적 식별자다. 공식 저장소 API의 LFS SHA-256은 `58b2265b98a10ec3bb2a0b455c520731c1296967906c7adc7b6d3710a013e402`다. 파일의 별도 라이선스 텍스트는 확인되지 않았고 카드 메타데이터는 `other`이므로 원시 ID·행 자료를 대외 재배포하지 않는다.
- 아직 전체 파일을 받지 않았다. 공식 `resolve` 파일에 HTTP `Range`로 **첫 4,194,304바이트**, 가운데 `2308908671–2313102974`, 끝 `4613623038–4617817341`만 읽었다. 각 구간의 경계에서 불완전한 JSONL 행은 버린 뒤 각각 **8,056 / 4,736 / 6,387행**을 파싱했다. 총 19,179개 표본은 모두 `status=DEFAULT`, `model=Qwen/Qwen3-32B`였고 `len(bucket_ids)=ceil(token_count/16)`이었다. 첫 구간에서 네 개 **완전** 블록을 가진 7,081행의 길이 4 버킷 접두열은 4,803종이며 중복 접두열에 속한 행은 3,429개다. 가운데 구간은 4,736행 중 길이 4 접두열 177종, 중복 행 4,580개다. 세 구간은 무작위·시간 대표 표본이 아니며, **60분 안의 재사용률이나 캐시 이득의 근거가 아니다.** 가운데 파일 위치의 시각은 2025-08-05~09였으나 첫 위치는 08-21, 끝 위치에는 07-03과 09-06이 섞여 있어 **파일 행 순서는 시간순이 아니다.**
- 기존 고정 원본 `trace.jsonl` (`../data/external/swissai_serving_trace/trace.jsonl`)의 별도 전량 감사에는 정확한 이름 `Qwen/Qwen3-32B`가 4,949,821건이고, 그중 `DEFAULT`가 3,994,437건이다. 버킷 카드 행수와 2건 차이가 있으므로 버킷 파일을 원본의 완전한 1:1 부분집합이라고 가정하지 않는다. 원본·버킷의 고유 `id` 대조와 누락 이유는 본 실험의 입력 감사에서 별도로 확인한다. 원본의 완료시간·출력토큰·상태 결과는 학습 특징에 넣지 않는다.
- 같은 revision의 `qwen3-32b-bucket-reuse.jsonl`에는 `reused_buckets` 등 이미 계산된 필드가 있지만 산출 순서와 정보 경계가 카드에 정의되지 않았다. 이를 입력·정답·비교 기준으로 **사용하지 않는다.** 원시 `bucket_ids`와 생성 시각에서 시간순으로 재사용을 다시 계산한다.

## 정보 경계와 정답

결정 시각은 요청의 `created_at`이며, 요청의 입력 토큰을 받은 뒤 **prefill 직전**을 가정한다. 이때 `token_count`, 해당 요청의 `bucket_ids`, 과거 요청의 버킷·도착시각만 사용할 수 있다고 가정한다. 실제 시스템의 토큰화·전달 완료 시각은 공개되지 않았다. 현재 요청의 `finished_at`, `reported_token_output`, 미래 요청, 공개 원본의 사전 계산 재사용 필드, 실제 캐시 결과를 특징으로 쓰지 않는다. `created_at`의 명시 UTC와 시간대 없는 형식은 기존 SwissAI 감사처럼 후자를 UTC로 해석하고 형식별 표본 수를 보고한다.

한 요청에서 `n=floor(token_count/16)`개 **완전한** 16토큰 블록만 쓰고, `bucket_ids[:n]`을 이 요청의 버킷 접두열 `P`로 정의한다. 우측 패딩된 마지막 미완전 블록은 제외한다. `n=0`, 비정수·음수 길이, 길이 불일치, 잘못된 ID, 중복 요청 ID는 별도 건수로 감사하며 주 학습·평가에서 제외한다. `P`는 정확히 일치하는 **버킷 ID 순서**다. 식별자 충돌 가능성과 패딩 때문에 원문 토큰 또는 전체 프롬프트의 동일성을 증명한다고 말하지 않는다.

지도학습 정답 `Y60(P,t)=1`은 `t<t'≤t+60분`에 도착한 **다른** 적격 Qwen 요청의 첫 `n`개 완전 블록 버킷 ID가 `P`와 모두 같을 때다. 없으면 0이다. 미래 요청이 `P`보다 길어도 이 `n`개가 같으면 양성이다. 현재 요청의 **전체 완전 블록 접두열**을 대상으로 하며, 임의 위치의 개별 버킷 중복은 양성이 아니다. 같은 마이크로초의 요청은 서로의 미래가 아니며, 분할 끝 전에 60분 창이 온전히 끝나지 않으면 정답 미관측으로 제외한다. 원본 자체의 수집 공백과 누락 요청은 확인할 수 없으므로 음성은 **공개 추적에서 미관측**이라는 뜻만 갖는다.

## 시간순 분할과 점수 전 게이트

원본의 `created_at`을 UTC 마이크로초로 파싱한 뒤 `(created_utc_us, SHA256(id)의 바이트 순서)`로 정렬한다. 동일 시각 묶음의 특징·캐시 적중은 그 묶음을 상태에 반영하기 전에 계산한다. 묶음 내 향후 상태 변경은 ID 해시 순서로만 처리하고 동시 시각 재사용을 점수로 세지 않는다. 분할은 **버킷 결과를 보기 전에** 로컬 원본의 Qwen 도착 날짜 건수만 참고해 다음 절대 시각으로 고정한다.

| 구간 | UTC 생성 시각 | 용도 |
| --- | --- | --- |
| 학습 | 2025-05-14 00:00 ≤ t < 2025-08-01 00:00 | `Y60` 학습과 과거 이력 |
| 검증 | 2025-08-01 00:00 ≤ t < 2025-08-08 00:00 | 모델·캐시 입장 문턱 선택 |
| 잠금 시험 | 2025-08-08 00:00 ≤ t < 2025-08-23 00:00 | 고정 방법의 1회 최종 점수 |
| 후행 보조 | 2025-08-23 00:00 ≤ t < 2025-09-07 00:00 | 주 선택과 독립성을 주장하지 않는 사후 진단 전용 |

각 분할의 처음 **60분은 이력·캐시 준비에만 사용하고 점수에서 제외**한다. 분할마다 과거 빈도·캐시를 비워 시작한다. `Y60`이 분할 끝을 넘어가면 그 판단은 제외한다. 학습기는 학습 행에서만 적합하고 검증에서 문턱을 하나 고른 뒤 계수·특징·문턱을 고정한다. 시험 시 `Y60`이나 캐시 적중을 보고 정책을 수정하지 않는다. 기존 SwissAI 자료의 다른 목표·날짜 분포는 이미 탐색됐으므로, 이 시험도 **새 서비스의 독립 일반화 검증은 아니다.**

전체 다운로드 후, 정답을 열기 전에 파일 바이트 수·SHA-256·행수, `id` 중복, 시각 파싱, 모델·상태, 버킷 형식과 `ceil(token_count/16)` 일치, 분할별 적격 요청 수·고유 접두열 수·동시 시각 수를 감사해 고정한다. 출처나 구조가 다르면 점수를 중단한다. 학습·검증의 `Y60`만 연 뒤, 각 구간 양성·음성이 **각각 10,000건 이상**, 검증에서 양·음성이 각각 100건 이상인 UTC 날짜가 **3일 이상** 없으면 학습·시험을 중단하고 지원 부족으로 보고한다. 이 하한은 정확도 보증이 아닌 첫 실험의 실무 게이트다. 시험 정답·히트율은 개발 게이트를 통과하고 코드·모델·선택 기록을 해시로 동결하기 전에는 계산하지 않는다.

## 고정 학습·캐시 비교

요청의 입력 특징은 `n`, `token_count mod 16`, UTC 시간·요일, 직전 5분의 **이 모델 전체** 도착 수, 현재 `P`가 직전 5분·60분에 나온 횟수와 마지막 관측 뒤 경과시간, 현재 `P`의 첫 1·2·4개 완전 블록 접두열의 직전 60분 등장 횟수다. 길이가 1·2·4에 못 미치면 해당 특징은 결측으로 둔다. 각 입력은 `t`보다 **엄격히 이른** 요청으로만 계산한다. 원시 `id`, 버킷 ID 정수, 요청 출력·완료정보는 학습 특징이 아니다. 기준 확률은 학습 전역 양성률과 직전 60분의 같은 `P` 경험 빈도를 학습 전역률에 20건 상당으로 수축한 값이다. 학습 후보는 고정 `HistGradientBoostingClassifier(max_iter=100, max_leaf_nodes=15, max_depth=3, min_samples_leaf=100, learning_rate=0.05, l2_regularization=10, early_stopping=False, random_state=42)` 하나다. 학습량을 제한해야 하면 UTC 날짜마다 `SHA256(id)` 순서로 최대 5,000행을 **레이블과 무관하게** 선택한다. 검증·시험은 적격 전량을 평가한다. `Y60`의 Brier·AP·양성률을 날짜별·전체로 보고하며, 캐시 적중과 혼동하지 않는다.

주 캐시 실험은 같은 시간 정렬 요청을 **고정 4,096개 완전 블록** 예산의 하나의 Qwen 버킷 접두 트리에 재생한다. 보조 예산은 1,024와 16,384블록이다. 트리 루트는 무료, 깊이 1인 완전 접두 노드 하나가 1블록을 쓴다. 요청의 첫 `min(n,C)`개 노드만 저장 대상이며, 적중 `h`는 캐시에 **연속으로** 존재하는 루트 이후 블록 수다. `n>C`도 점수 분모 `n`은 유지하고 비중을 별도 보고한다. 60분간 접근되지 않은 노드와 그 자손은 만료한다. 저장 용량이 넘치면 하위 노드가 없는 leaf부터 제거해 접두 연결을 보존한다. LRU는 가장 오래 접근하지 않은 leaf, LFU는 캐시 입장 뒤 접근 횟수가 가장 적은 leaf를 제거하며 동률은 오래된 접근, 그다음 버킷 접두 해시 순으로 푼다. 두 기준선은 모든 새 접두 노드를 입장시키며 캐시에 남은 히트 노드는 갱신한다.

학습 후보의 정책은 **같은 LRU 제거 규칙**을 사용하되, 현재 `P`의 `Y60` 예측 확률이 문턱 `τ` 이상일 때에만 새 노드를 입장시킨다. 이미 캐시에 있는 접두 적중은 `τ`와 관계없이 갱신한다. `τ∈{0,0.1,0.2,0.4,0.6,0.8}`에서 검증의 4,096블록 *총 적중 완전 블록 / 총 요청 완전 블록*을 가장 높이는 하나를 고르고, 동률이면 작은 문턱을 고른다. `τ=0`은 LRU와 동작이 같아야 하며 합성·실자료 동등성 검사로 확인한다. 각 정책은 같은 요청·동시 시각 처리·TTL·블록 예산을 사용한다. 시험 주 지표는 4,096블록 적중 비율이고, 보조 지표는 두 예산의 비율, UTC 날짜별 적중 비율, 캐시 점유율·만료/축출 수다. 적중 블록은 실제 GPU의 KV 점유 bytes나 절감된 prefill 시간으로 환산하지 않는다.

검증에서 선택한 학습 정책이 4,096블록에서 LRU·LFU **둘 다**보다 적중 비율이 상대 5% 이상 높지 않으면 시험을 열지 않고 미채택한다. 통과하면 선택 기록과 구현 해시를 잠그고 시험을 한 번 채점한다. 시험에서도 같은 상대 5%와, 적격 요청이 양수인 UTC 날짜의 과반에서 더 강한 기준선보다 높은 적중 비율을 모두 만족해야 이 **자료 내부 오프라인 캐시 대안**으로 남긴다. 실패하면 미채택한다. 어떤 결과도 실제 캐시 서버 성능이나 배포·스케일 정책의 개선으로 승격하지 않는다.

## 기존 연구와 한계

이 저장소의 SwissAI 출력 길이·요청 도착량·유휴 재도착과 달리 **입력 버킷 접두의 미래 재사용과 캐시 입장**을 다룬다. 하지만 [NeurIPS 2025 LPC](https://papers.neurips.cc/paper_files/paper/2025/hash/414f642a1ea9350006669774cba9bcd4-Abstract-Conference.html)는 학습형 접두 캐시 축출을, [MLSys 2025 Marconi](https://proceedings.mlsys.org/paper_files/paper/2025/hash/7c180af017258d239bac6248d1eb26ac-Abstract-Conference.html)는 재사용 가능성에 따른 입장·축출을, [USENIX ATC 2025 KVCache Cache in the Wild](https://www.usenix.org/conference/atc25/presentation/wang-jiahao)는 실제 요청 재사용의 편향과 업무량 인식 축출을 이미 연구했다. 따라서 **`Y60` 분류기, LRU/LFU 비교, 접두 캐시 자체를 경희대 고유 발명이라고 주장하지 않는다.** 이 규약은 공개 SwissAI 한 모델의 정보 경계·강한 기준선·재현 가능한 거절 게이트를 먼저 확립한다. 독창적 방법을 주장하려면 해당 선행법과 실제 엔진의 GPU 메모리·TTFT·처리량을 동일 조건에서 비교할 새 구현과 관측이 더 필요하다.
