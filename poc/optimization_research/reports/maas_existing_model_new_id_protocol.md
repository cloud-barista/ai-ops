# 저장된 MaaS GPU 위험 모델의 새 인스턴스 ID 시험 규약

2026-09-29. **상태: 새 ID bucket 1 원본에 접근하기 전에 작성한 규약.** 기존 [상태·결측 인식 MaaS 탐색](maas_state_followup_findings.md)은 ID bucket 0의 상대일 140–143으로 학습하고 144일에서 정규화·하이퍼파라미터를 정했으나, 145–146일의 결과까지 이미 봤다. 이번 시험은 이 결과를 본 뒤 **저장된 단일 로지스틱(`new_pooled`)을 주 후보로 선택**한 후속 확인이다. 새 ID의 결과에 따른 모델·기준선 변경은 허용하지 않는다. 원래 [전날 인스턴스 잔차 전이](maas_day_ahead_instance_transfer_findings.md)는 실패했으므로 그 후보에 대한 새 bucket 1 점수는 계산하지 않는다.

## 출처와 단회 시험 범위

[공식 Alibaba MaaS 주간 5분 추적](https://github.com/alibaba/clusterdata/blob/8a6295f9779ddc019add669eeca49c5f9f77b3a7/cluster-trace-v2026-maas/README.md)의 21개 조각, 140,906,827행에 대해 [전량 감사](../data/external/alibaba_maas_2026/SOURCE.md)의 URL·크기·ETag·멤버별 SHA-256·CRC32을 그대로 요구한다. `instance_id` UTF-8의 SHA-256 첫 8바이트 정수를 100으로 나눈 나머지 **1**인 ID만 추출한다. 기존 개발 표본은 나머지 **0**이며 ID가 겹치지 않아야 한다. 원본 ID는 저장하지 않고 공개 익명 ID의 무염 해시도 행 파일로 대외 배포하지 않는다.

판단과 정답은 기존 `evaluate_maas_state_followup.py`의 `construct_cohorts`를 **변경 없이** 적용한다. 주 분석은 과거 세 창이 완전·유효하고 현재 SM<80%·GPU 메모리<90%인 `complete/current_normal`이다. 판단은 현재 5분 창 시작 `t+600초`, 정답은 판단 이후 30분의 여섯 창 중 SM≥80% 또는 GPU 메모리≥90%가 한 번이라도 관측되는가이다. 라벨 가용은 정답 창 종료 후 5분으로 가정한다. 과거·미래 창이 중복·누락·무효인 경우 기존 규칙대로 제외하고 정답 관측률을 별도 기록한다. 시험 상대일은 **145–146**만이며 다른 bucket 1 날짜를 재학습·보정에 쓰지 않는다.

## 고정 예측과 같은 행 기준선

1. **주 후보:** 저장된 `new_pooled.joblib`과 기존 metrics의 학습 전용 여섯 중앙값을 사용한다. 특징 목록·계산은 원래 코드의 `FULL_FEATURES`와 `make_features` 그대로다. 새로운 적합이나 절편 조정은 하지 않는다. 새 ID 점수화 전에 bucket 0의 저장 시험 예측 53,513개를 동일 모델로 전부 재현해야 한다.
2. **기존 확률표 `p₀`:** 원래 학습 140–143일의 저장 `any_recent_threshold` Beta 확률을 그대로 적용한다. 새 ID 정답으로 재추정하지 않는다.
3. **더 강한 단순 비교기:** bucket 0의 `complete/current_normal` **학습만**에서 `any_recent_high∈{0,1}`별 Beta(1,1)률 `0.033061253175105165 / 0.7215373459028281`을 다시 산출·일치 확인하고 고정한다. 이 비교기는 이전 시험 점수를 본 뒤 추가한 것이므로 이번 새 ID 시험 전에만 사전 비교기로 고정된다.
4. **보조 학습 비교기:** 저장된 `new_state_full_normal.joblib`을 같은 입력·중앙값에 적용한다. 이 모델은 bucket 0 시험에서 주 후보보다 행 Brier가 조금 높고 AP는 높았다. 이번 시험의 주 후보를 사후 교체하지 않는다.

새 ID 원본을 열기 전에 규약·추출기·평가기·합성 테스트, 원본 감사, 모델·기준선 metrics와 joblib 해시, bucket 0 재현 결과를 `release_manifest.json`에 고정한다. 어떤 파일이 바뀌면 원격 추출을 거부한다. 새 ID 추출 후에는 **지원량 집계만** 먼저 저장하고, 그것이 통과했을 때만 저장 모델을 적용해 한 번 채점한다.

## 지원량·성공 판정

주 분석의 새 ID 시험 적격 행 **≥50,000**, 신규 초과 사건 **≥1,000**, 적격 ID **≥500**, 양성 ID **≥50**을 요구한다. 각 시험일에 적격 행 **≥20,000**·양성 **≥300**이어야 하고, 현재 정상 입력 후보 가운데 30분 정답이 관측된 비율은 전체 **≥75%**여야 한다. 어느 하나라도 실패하면 확률 점수를 계산하지 않고 지원량 부족으로 보고한다. 결측·중복·미래 미관측의 정확한 건수와 사건 집중도를 함께 남긴다.

지원량 통과 시 같은 행에서 주 후보의 **행 Brier가 두 단순 비교기 각각보다 상대 ≥5% 낮고**, 두 날짜 각각에서 둘보다 낮고, **ID 동일가중 Brier가 둘보다 낮아야** 한다. AP는 두 단순 비교기 최고값보다 0.005 이상 낮지 않고, 날짜별 상위 5% 경보의 동점 기대 신규 초과 포착도 두 비교기보다 낮지 않아야 한다. ID를 2,000번 짝지어 재표집(seed 43)한 `후보−강한 단순 비교기` 행 Brier 차의 95% 백분위 구간 상한도 0 미만이어야 새 ID 확인 성공으로 기록한다. 하나라도 실패하면 미채택한다. 상태별 보조 모델의 점수는 주 후보의 기준을 바꾸지 않는다.

ID가 새롭지만 같은 2026년 MaaS 주간·서비스에 속하므로 독립 **ID** 확인일 뿐 시기·서비스·GPU 세대 일반화가 아니다. 원본의 온라인/오프라인 작업 종류, 실제 scale 명령·Ready·사용자 SLO·대체 조치 결과가 연결되지 않는다. 성공해도 관측 GPU 고사용률의 **위험 입력**에 한정하며 실제 `SCALE_OUT/IN` 정책은 채택하지 않는다.
