# Alibaba MaaS 5분 인스턴스 자원 위험 예측: 사전 실험 규약

작성일: 2026-09-28. **인스턴스 Parquet의 행·통계·정답 또는 모델 점수를 읽기 전에** 기본 규약을 고정했다. 기본 규약 작성 당시 확인한 것은 공식 문서, 원격 ZIP의 HTTP 헤더와 ZIP 중앙 디렉터리뿐이다. 이후 부분 조각의 무결성·계측 품질 감사 중, **전체 표본·정답·모델 점수를 보기 전에** 분할 끝 경계의 라벨 가용시각을 바로잡았다. 마지막 정답 창의 끝에 추가 5분 전달 지연을 더한 시각까지 분할 안에 들어야 학습·검증에 쓸 수 있다. 이 수정은 아래 시간 경계에만 적용하며 자료 선정·특징·임계값·성공 기준은 바꾸지 않았다. 이 실험은 경희대 배포·스케일링 판단 모듈의 *모니터링 위험 입력*을 연구한다. 실제 `SCALE_OUT`, `SCALE_IN` 명령의 정답이나 효과를 학습·검증하지 않는다.

## 자료와 연구 질문

- 공식 출처: Alibaba의 [MaaS 2026 설명](https://github.com/alibaba/clusterdata/blob/8a6295f9779ddc019add669eeca49c5f9f77b3a7/cluster-trace-v2026-maas/README.md), [스키마](https://github.com/alibaba/clusterdata/blob/8a6295f9779ddc019add669eeca49c5f9f77b3a7/cluster-trace-v2026-maas/docs/schema.md), [다운로드 목록](https://github.com/alibaba/clusterdata/blob/8a6295f9779ddc019add669eeca49c5f9f77b3a7/cluster-trace-v2026-maas/docs/data_download.md), 고정 Git 커밋 `8a6295f9779ddc019add669eeca49c5f9f77b3a7`.
- 대상은 `instance_week_5min/`이다. 공식 설명은 1주일(상대일 140–146), 21개 Parquet, 140,906,827행을 밝힌다. 한 행은 `(instance_id, time_s, cluster_id, gpu_count)`별 20초 원계측의 **5분 평균**이며, `time_s`는 `[time_s, time_s + 300)` 창의 **시작**이다. 사용 필드는 `sm_util`, `gpu_mem_util`, `gpu_count`, `samples`이다. Parquet 조각은 날짜 분할이 아니다.
- 질문: 인스턴스의 최근 자원 상태만으로 향후 30분에 높은 GPU SM 또는 GPU 메모리 사용률이 **관측될 위험**을 현재 상태 지속보다 잘 예측할 수 있는가? `SM ≥ 80%` 또는 `GPU 메모리 ≥ 90%`는 **이 연구가 정한 경보 임계값**이다. Alibaba의 SLO, 하드웨어 고장 임계값 또는 최적 스케일 기준이 아니다. 5분 평균의 초과 여부이므로 순간 최고값은 알 수 없다.
- 원 저장소는 [연구·학습 목적 사용을 허용](https://github.com/alibaba/clusterdata/blob/8a6295f9779ddc019add669eeca49c5f9f77b3a7/README.md)한다고 적는다. 별도의 표준 라이선스는 확인되지 않았다. 원자료 재배포를 전제하지 않는다.

## 원본 취득과 첫 감사

공식 `instance_week_5min.zip` URL은 2026-09-28에 HEAD `200`, `Content-Length=4,812,189,789`, ETag `434E78D81E2A9F9F1FDEF3163DD0FCEC`, `Accept-Ranges: bytes`였고 16바이트 Range GET은 `206`이었다. 끝 128 KiB의 중앙 디렉터리에는 21개 Parquet 멤버가 있고, 모두 ZIP 저장 방식(method 0)이며 가장 큰 멤버는 254,428,076바이트였다. 이는 **파일 메타데이터 확인**이며 Parquet 행은 아직 읽지 않았다. 현 디스크 가용 약 9.58 GB에서는 ZIP과 전체 추출본을 함께 둘 수 없다.

1. 같은 URL·길이·ETag의 ZIP 중앙 디렉터리에서 각 멤버의 오프셋·길이·CRC32를 읽는다. 멤버명은 `instance_week_5min/part_*.parquet` 21개만 허용한다. 각 멤버를 HTTP Range로 **순차** 취득해 최대 한 조각만 임시 저장한다. Range 요청에 `200`이 오거나, 길이·ETag·CRC32·Parquet 스키마가 다르면 평가를 멈추고 감사 실패로 남긴다. 조각별 SHA256과 수신 헤더를 기록한다. 전체 ZIP을 저장하거나 일부 조각을 한 날짜로 취급하지 않는다.
2. 21개 조각 **모두**에서 `instance_id`의 UTF-8 문자열 표현에 대한 SHA256 첫 8바이트(빅엔디언 정수) `mod 100 == 0`인 인스턴스를 선택한다. 같은 ID는 모든 조각에서 일관되게 약 1% 표본에 들어간다. 표본 선정은 자원값·시각·정답을 보지 않는다. 인스턴스 ID의 문자열 정규화 규칙과 전체/선택 ID·행 수를 기록한다.
3. 전체 조각의 필수 열·자료형·NULL 수, `time_s mod 300`, `day=floor(time_s/86400)` 범위, `samples`, `gpu_count`, SM·메모리 사용률의 유한성·범위를 감사한다. 선택 ID에 대해 `(instance_id,time_s,cluster_id,gpu_count)` 중복, 같은 ID·시각의 서로 다른 클러스터/할당 행, 5분 간격 결측, 클러스터·할당 변화를 센다. 20초 원계측 기준 창당 `samples=15`가 기대되지만 정확히 15라고 가정하거나 15 미만을 자동으로 무부하로 바꾸지 않는다. `samples=0`, 비유한 지표, `gpu_count≤0`, 사용률이 `[0,100]` 밖인 행은 유효 계측에서 제외하고 수를 보고한다. 공식 의미와 실제 범위가 맞지 않으면 모델 평가 전에 원인을 기록하고 중단한다.
4. 연결성 감사에서는 **21개를 모두 훑은 고정 ID 표본**을 사용한다. 각 분할의 현재 행 중 판단 시각과 미래 30분 창의 **추가 5분 전달 지연 후 가용시각**이 모두 해당 분할의 시간 범위에 있는 행을 분모로, 과거 세 창과 미래 여섯 창이 연속·유효·고유한 비율 및 탈락 이유를 계산한다. 미래 행의 부재는 위험 없음이 아니라 **정답 미관측**이다. 전체와 일자·클러스터·현재 GPU 할당량별 결측률을 함께 보인다. 현재 행에서 이후 할당·클러스터가 변한 비율도 결과 해석을 위해 보고하지만 미래 상태를 입력 특징으로 쓰거나 1차 평가 대상을 고르는 데 쓰지 않는다.

## 시각, 입력, 정답

창 시작을 `t`라 한다. 그 행의 평균은 `t+300`에야 완성된다. 실제 전달 시각이 공개되지 않았으므로 **추가 5분 전달 지연**을 둔 `d=t+600`을 판단 시각으로 고정한다. `d`에서 사용할 수 있다고 가정하는 최신 창은 `[t,t+300)`이고, 그보다 오래된 연속 세 창 `[t-600,t-300)`, `[t-300,t)`, `[t,t+300)`만 모델 입력에 쓴다. 관측 실제 `available_at`이 없어 이 역시 온라인 가용성을 입증하지 못하는 오프라인 가정이다.

정답은 `d`에서 시작하는 여섯 창 `[d,d+300)`부터 `[d+1500,d+1800)` 중 하나라도 `sm_util≥80` 또는 `gpu_mem_util≥90`인지다. 여섯 창 전부 유효하고 인스턴스·시각별 유일할 때만 이진 정답을 붙인다. 세 과거 창도 같은 조건을 요구한다. 현재가 이미 임계값 이상인 행을 포함한 **전체 유효 코호트**가 1차 평가 대상이다. 현재 임계값 미만인 행에서 새 초과가 나타나는 *진입 위험*을 미리 정한 2차 층으로 따로 보고한다. 같은 미래 창을 공유하는 여러 판단은 독립 사건으로 세지 않는다.

입력은 세 과거 창의 SM·GPU 메모리 사용률과 `samples`, 현재 `gpu_count`, 그리고 세 창의 사용률 평균·최대·첫째-셋째 변화량이다. `instance_id`, 같은 날 집계된 daily 테이블의 모델·응용 정보, 이후 창의 자원값·할당 변화와 정답은 입력하지 않는다. `cluster_id`는 층별 진단에만 사용한다. CPU·호스트 메모리 등 추가 필드의 사용은 이 파일의 1차 모델 밖에 둔다. 이 선택으로 새 애플리케이션 메타데이터의 가용 시점을 가정하지 않는다.

## 시간 분할과 비교 방법

분할은 **판단 시각 `d`**로 정한다. 학습은 day 140–143 (`140×86400 ≤ d`와 `d+1800+300 ≤ 144×86400`), 검증은 day 144 (`144×86400 ≤ d`, `d+1800+300 ≤ 145×86400`), 시험은 day 145–146 (`145×86400 ≤ d`, `d+1800+300 ≤ 147×86400`)이다. 각 분할의 마지막 정답 창이 끝난 뒤 **추가 5분**이 지나기 전에 분할 경계가 오면 그 판단을 버린다. 이로써 day 144의 모델 적합과 day 145의 기준선·정규화 선택에는 해당 시점까지 가용한 정답만 들어간다. 검증·시험 특징에 과거 분할의 이미 완료된 창을 사용하는 것은 허용하되, 학습 계수와 확률표는 학습 정답만 사용한다. 시험일 점수로 모델이나 임계값을 변경하지 않는다.

세 확률 기준선을 학습 자료에서 만든다. (1) 전체 학습 양성률, (2) **최신 창**이 연구 임계값을 넘었는지에 조건부인 양성률, (3) **최근 세 창 중 하나라도** 넘었는지에 조건부인 양성률이다. 조건부 확률은 각 이진 집단에 Beta(1,1) 평활을 적용한다. 검증 Brier가 가장 낮은 기준선을 고정해 시험의 주 비교 대상으로 삼고, 세 기준선의 점수도 모두 공개한다.

학습 모델은 L2 로지스틱 회귀 하나다. 위 숫자 입력의 표준화 계수는 학습 구간에서만 적합한다. `C ∈ {0.1, 1, 10}` 세 후보 중 검증 Brier가 가장 낮은 것을 고른다. 동률이면 작은 `C`를 택한다. 클래스 가중치, 시험 재학습, 사후 임계값 조정은 쓰지 않는다. 수집·정제 규칙을 변경해야 한다면 이 규약의 결과를 별도 탐색으로 표시하고 새 고정 규약 후 평가한다.

## 품질 게이트, 지표, 결론 기준

원본 무결성 또는 스키마 감사가 실패하면 점수를 산출하지 않는다. 다음 **표본 적격성 게이트**도 시험 점수 계산 전에 감사표로 확인한다: 각 분할에서 현재 관측 후보 중 과거 3·미래 6창이 유효한 비율 ≥20%; 학습·검증·시험 각각 적격 판단 ≥2,000개, 양성 ≥100개, 음성 ≥100개, 양성 인스턴스 ≥30개. 못 넘으면 모델을 시험하지 않고 부족한 연결성·사건 수를 결과로 남긴다. 이 기준은 자료를 보기 전에 정한 실험 실행 조건이며 모집단 대표성을 보장하지 않는다.

1차 점수는 **Brier score**다. 불균형을 드러내기 위해 양성률, 평균정밀도(AP, 무작위 기준은 그 구간 양성률), 각 시험일 상위 **5%** 경보에서의 precision·recall·인스턴스당 평균 경보 수를 함께 보고한다. 동점 확률의 경보 순위는 `SHA256(instance_id || ':' || d)`의 오름차순으로 고정한다. 같은 30분 정답 창이 겹치므로 행 단위 신뢰구간을 쓰지 않는다. 각 시험일 점수, 현재 정상/초과 층, 클러스터·GPU 할당량별 표본 수와 결측을 공개한다. 불확실성 요약이 필요하면 인스턴스 단위로 짝지어 재표집하되, 시험일이 2일뿐이라는 한계를 유지한다. 운영 비용·SLO 개선 수치는 계산하지 않는다.

이 파일에서 말하는 **탐색적 성공**은 모든 품질 게이트를 통과하고, 고정 시험에서 학습 모델 Brier가 검증으로 고른 최선의 기준선보다 전체 **상대 5% 이상** 낮으며 두 시험일 각각 낮고, AP와 상위 5% 경보 recall이 그 기준선 이상인 경우다. 이 조건이 충족돼도 한 주·동일 플랫폼의 관측 위험 예측 가능성만 뜻한다. 실제 scale 명령의 원인·결과, 새 서비스나 VM으로의 일반화, 학술적 신규성은 주장하지 않는다. 실패·조건부 통과·결측으로 평가 불가도 모두 그대로 보고한다.

## 해석상 제한

관측된 높은 사용률은 **기존 할당 정책 아래의 결과**다. 기간 중 GPU 수가 바뀌면 이후 위험값도 그 영향 아래 관측되지만 변경 명령·준비 시간·반사실 결과는 없다. 따라서 이 예측으로 `SCALE_OUT`이 지연을 낮췄다거나 `SCALE_IN`이 안전하다고 판정할 수 없다. QPS와 사용자 지연은 이 인스턴스별 5분 표에 없고, 별도 `app_metrics.csv`는 일부 시간별 응용 사례다. 자료 간 `app_id` 연결을 당장 모델 입력으로 추가하지 않는다. 실제 경희대 판단기의 행동 효과를 평가하려면 [실행·결과 데이터 계약](scale_effect_data_contract_v1.md)의 시각·할당·SLO·명령·완료 연결이 별도로 필요하다.
