# GPU 2개 관측으로 GPU 1개 정적 성능을 예측한 결과

작성일: 2026-09-28. [점수 계산 전 고정한 규약](static_scale_in_protocol.md) SHA-256 `0a9e9e496503029150d51757ae3fe69cee09207b00bddb46496fe307fea6eed4`를 따랐다. **현재 SQLite에서는 실제 VM 축소의 안전성을 확인할 수 없다.** 아래 `축소 가능`은 같은 호스트에서 GPU 1개를 **따로 실행한 배치 벤치마크**가 수집기 생성 지연·처리량 목표를 만족한다는 뜻이다. GPU 2개 값은 독립 replica 두 개의 합산 성능이며, 운영 서비스의 라우팅·축소 전환 결과가 아니다.

## 자료와 방법

고정 SQLite 추출본의 주 캠페인에는 9개 모델×575개 작업이 있으며, 각 작업에 GPU 2개/CPU affinity 2개 현재 형상과 GPU 1개/CPU affinity 2개 대안 형상의 물리 측정이 정확히 한 쌍 있다. GPU 2개가 두 목표를 만족한 357작업 중 GPU 1개도 만족한 작업은 **249**, 만족하지 못한 작업은 **108**이다. 처리량은 원본 `examples_per_second`를 `batch_size`로 나누어 요청/초 단위를 맞췄다.

원본 시각을 직접 비교하면 **575쌍 전부에서 GPU 1개 실행이 GPU 2개 실행보다 먼저 시작됐다**. 따라서 `GPU2 관측 후 GPU1을 선택`하는 평가는 시간순 온라인 재연이 아니라 이전에 측정된 정적 대안의 결과를 숨기는 오프라인 비교다. 운영 중 축소 후 결과 또는 그 인과 효과로 읽을 수 없다.

모델 하나를 완전히 제외하고 나머지 8모델로 `GPU1/GPU2`의 로그 지연·요청 처리량 응답을 학습했다. 제외 모델에서는 현재 GPU 2개 결과·작업 특징만 보았다. 단순 비율 규칙(`GPU1 지연=GPU2 지연`, `GPU1 요청/초=GPU2 요청/초÷2`)의 배수·안전 여유와 각 학습기의 여유값은 **donor 모델만 교차검증**해 고른 다음 제외 모델에 적용했다. 비교 학습기는 donor 응답 중앙값, 정적 특징 ExtraTrees, 현재 GPU 2개 모니터링을 더한 ExtraTrees다. donor에서 승인 건수 대비 잘못 승인 비율 5% 이하를 만족하는 조합 중 안전 승인을 최대로 하는 규칙을 고른다. 이 기준은 운영 안전 보증이 아니다.

| 모델 전체 제외, 주 575작업 | 배치 p95 평균 절대 로그오차 | 요청/초 평균 절대 로그오차 | 승인 / 안전 / 잘못 승인 |
| --- | ---: | ---: | ---: |
| 단순 비율 + donor 선택 여유 | 0.898 | 0.172 | 246 / 232 / 14 |
| Donor 중앙 응답 | 0.493 | 0.142 | 241 / 229 / 12 |
| **정적 특징 학습** | **0.260** | 0.109 | **248 / 240 / 8** |
| 정적 특징 + 현재 계측 | 0.267 | **0.100** | 247 / 239 / 8 |

오차는 **9개 모델별 평균을 다시 동일 가중 평균**한 값이다. 단순 비율의 오차는 `(지연×1, 처리량÷2)` 점 예측이고, 행동 열은 donor에서 고른 여유를 적용했다. 정적 학습기는 같은 시험에서 단순 규칙보다 안전 승인 **8건 많고** 잘못 승인 **6건 적었다**. 9모델 각각에서 안전 승인 수는 단순 규칙 이상이며, 잘못 승인 수는 이하이다. 현재 GPU 계측을 더하면 처리량 오차는 감소했으나 지연 오차와 안전 승인은 약간 악화되어 **계측의 독립 결정 이득은 확인되지 않았다**.

시험 결과를 본 뒤 공통 여유값을 다시 고르는 사후 안전/승인 곡선 (`../artifacts/static_scale_in_v1/frontier_posthoc.csv`)도 진단용으로 저장했다. 주 캠페인에서 잘못 승인 **최대 8건**인 지점의 최대 안전 승인은 단순 비율 `213`, donor 중앙값 `215`, 정적 학습 `240`, 계측 추가 `239`다. 이 곡선은 시험 정답으로 문턱을 고른 것이므로 위 donor 선택 규칙의 성능이나 실제 운영 문턱으로 바꾸어 해석하지 않는다.

## 분포 이동과 실패 사례

| 보조 평가 | 검토 가능 / 정적 가능 | 단순 비율 안전·오승인 | 정적 학습 안전·오승인 | 계측 추가 안전·오승인 |
| --- | ---: | ---: | ---: | ---: |
| 새 입력 조건 `novel-matrix`, 동일 9모델 | 13 / 12 | 11 / 0 | 11 / 0 | 11 / 0 |
| 새 입력 조건 `space-filling`, 동일 9모델 | 33 / 23 | **22 / 0** | 21 / 1 | 21 / 0 |
| BERT 네 모델 공동 제외, 주 256작업 | 180 / 139 | 127 / 3 | 125 / 0 | **128 / 0** |
| 원격 GPU·새 모델 2종, 24작업 | 22 / 18 | 17 / 0 | 17 / 0 | 17 / 0 |

`novel-matrix`와 `space-filling`은 동일 모델·동일 호스트의 새 입력 조건이지 독립적인 새 모델 검증이 아니다. 원격 24작업은 다른 GPU·호스트·모델 종류가 동시에 바뀌며, 모든 방식의 승인 결과가 **동일**하다. 원격의 정적 학습 오차는 배치 p95 `0.145`, 요청/초 `0.097`로 단순 비율 `0.933/0.123`보다 낮았으나 두 모델만으로 일반화를 확정하지 않는다. BERT 공동 제외에서 계측 추가 방식이 128건 안전·0건 오승인이었지만, 새 입력 조건에서는 그 우위가 이어지지 않았다.

주 시험의 잘못 승인 8건 중 **5건이 Qwen 1모델**에 집중됐다. 정적 학습의 Qwen 승인 38건 중 잘못 승인은 5건(13.2%)으로, donor에서 목표로 한 5%를 벗어난다. 전체 `8/248=3.2%`만 인용하면 이 실패를 가린다. 추가 입력 `space-filling`에서 정적 학습은 단순 규칙이 안전하게 승인한 한 건을 놓치고 한 건을 잘못 승인했다. 따라서 정적 학습을 운영 `SCALE_IN` 자동 승인기로 채택하지 않는다.

## 해석과 재현

이번 실험은 기존에 평가한 GPU1→GPU2 정적 용량 예측의 **역방향**을 직접 검증한다. `SCALE_IN`이라는 이름의 lifecycle 파생 DB는 쓰지 않았다. 그 DB의 결과는 정적 측정쌍의 재표현이고, 실행 후 GPU 사용률이 특징에 들어가며, 샘플/초를 요청/초로 취급한 라벨 오류가 있기 때문이다. [원본·파생 출처 감사](untapped_signal_audit.md). 이번 특징은 현재 GPU 2개 행의 성능·계측과 결정 전 작업 정보만 사용한다. 테스트는 GPU 1개 목표값과 계측을 바꾸어도 예측·선택 규칙이 변하지 않음을 확인한다.

donor 교차검증으로 고른 규칙과 제외 모델의 시험 점수는 **같은 실행에서 저장**됐다. 점수 계산보다 먼저 별도 시각으로 고정된 규칙 manifest는 없으므로, 사전 규약·코드 해시보다 강한 블라인드 채점 증거로 제시하지 않는다.

소수 프로파일과 학습된 자원 반응으로 형상을 고르는 원리는 선행연구가 있다. 이 결과는 **경희대의 정적 축소 용량 평가 과제에서 학습기가 도움이 될 수 있다는 탐색 근거**이지 새 알고리즘의 최초성 증거나 실제 VM 축소의 인과 효과가 아니다. 실제 판단에는 사용자 요청 시계열, 사용자 SLO, VM·replica 증감 명령과 완료시각, 전환 중 지연·실패, 재확장 비용이 연결된 자료가 필요하다. [후속 계측 계약](scale_effect_data_contract_v1.md).
