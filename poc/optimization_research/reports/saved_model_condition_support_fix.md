# 저장 성능 모델의 모델별 입력 지원 범위 수정

## 결과

저장된 성능 모델의 추론 진입점에 **훈련 분할의 모델·revision·장치별 조건 범위**를 추가했다. Qwen에서 측정하지 않은 `batch_size=16`과 CPU에서 학습하지 않은 GPU 전용 작업 조건은 이제 `ABSTAIN`한다. 기존 모델 파일을 재학습하거나 변경하지 않았고, 계속 승인되는 입력의 예측값은 이전과 정확히 같다. 이 변경은 연구용 정적 배치 성능 추정의 입력 지원 판정만 좁힌다.

## 문제와 수정

기존 저장 번들은 batch 크기·입력 길이·동시성·반복 횟수를 **전체 모델의** 최솟값과 최댓값으로 검사했다. Qwen의 훈련 배치는 1·2·4·8이고 반복 횟수는 6이지만, 다른 모델의 배치 16 때문에 Qwen 배치 16도 `PREDICTED`였다. 여덟 GPU 후보 평가기는 이런 결과에 합성 SLO를 적용해 `RESEARCH_ESTIMATE`를 반환할 수 있었다. [재현 및 원인 감사](saved_model_integrity_followup_2026_09_29.md)에 입력 예가 있다.

`load_verified_bundle`은 고정 SHA-256을 확인한 **동일한 Parquet 바이트**에서 원 학습의 `khu-hf-local-exhaustive` 훈련 분할(seed 42)을 재구성한다. 각 `(model_id, model_revision, device)`에 대해 배치·길이·동시성의 훈련 최솟값과 최댓값, 실제 관측된 반복 횟수를 메모리에 저장한다. 공용 `predict_records`가 기존 범위와 이 조건별 범위를 모두 검사하므로 GPU 후보 평가기와 직접 예측 CLI가 동일하게 보류한다. 범위 안의 미관측 정수와 미관측 다변량 조합은 여전히 **보간 입력**일 수 있으며, 이를 물리적으로 검증된 설정이라 부르지 않는다.

## 고정 평가

[재평가 코드](../scripts/evaluate_saved_model_condition_support.py)와 [기계 판독 결과](../artifacts/model_condition_support_v1/metrics.json)는 기존의 전역 지원 판정과 새 판정을 같은 저장 모델로 비교한다. 숫자는 적격 행 기준이다.

| 평가 캠페인 | 이전 승인 | 새 승인 | 새 승인 작업 그룹 | 새 승인 행의 모델 / 중앙값 기준선 그룹 MALE |
| --- | ---: | ---: | ---: | ---: |
| 원 학습 캠페인 전체 | 4,856 | 4,828 | 575 | 재평가하지 않음: 훈련 행 포함 |
| `local-novel-matrix` | 108 | 56 | 5 | `0.3610 / 1.5727` |
| `local-space-filling` | 296 | 100 | 9 | `0.3482 / 0.6687` |

새 게이트가 기존에 거절한 행을 승인한 경우는 없다. 남은 행의 모델 예측값은 기존 결과와 **정확히 동일**하다. 주 캠페인에서 추가로 보류한 28행은 모두 CPU의 검증·시험 분할이며 GPU 행은 그대로 유지된다. 위 MALE은 두 타깃(배치 p95 지연, 처리 샘플/초)의 작업 그룹 균등 절대 로그오차 평균이다. 승인 집합이 크게 바뀌었으므로, 이 값과 예전 전체 승인 집합의 점수 차이를 정확도 향상으로 해석할 수 없다. 특히 외부 지원 그룹이 각각 5개·9개뿐이라 새로운 일반화 주장을 뒷받침하지 않는다.

Qwen 정상 입력은 직접 CLI에서 `PREDICTED`, 같은 입력의 배치 16은 `outside_model_condition_range:batch_size`로 `ABSTAIN`하는 것을 확인했다. GPU 평가기의 Qwen 배치 16·동시성 6·길이 32·반복 8, CPU의 GPU 전용 범위 차단을 회귀 시험에 넣었다. 옛 joblib을 직접 읽어 `predict_records`에 넘겨도 지원 맵이 없으면 `missing_training_condition_support`로 보류한다. 과거 예시 CPU 입력도 이제 보류하며, [현재 승인 예시](../examples/performance_supported_input.json)를 분리했다. 저장 모델 SHA-256은 `7a934da440ea0c7473e4e59eb5fa0c8c57f347389272bd303cb0051ef918b161`, 추출 Parquet SHA-256은 `b7bba7963e8a309b6a8502a1d98eefb150476b1381ec016beeb68cbf63fae906`으로 유지했다.

## 사용 범위

이 모델은 같은 호스트의 이미 본 AI 모델에 대해 정적 배치 벤치마크 지연·처리량을 추정한다. 현재 지원 판정은 모델·장치별 **주변 범위** 검사다. [재평가 코드](../scripts/evaluate_saved_model_condition_support.py)에서 훈련에 실제 등장한 값들만 장치별로 조합해도 가능한 3,806개 작업 조건 중 **3,365개(88.4%)가 공동 측정되지 않았다.** 이들을 승인한다면 미측정 조합의 보간 예측이지 측정된 구성의 재현이 아니다. 반대로 정확한 공동 조합만 허용하면 작업 조건 전체 제외 분할에서 GPU 검증 행 1,432개가 모두 제외되어 현재 일반화 평가를 할 수 없다. 따라서 모든 조합의 성공, 사용자 요청 SLO, 새 GPU·호스트 일반화, 실제 VM 배포·스케일 효과를 보증하지 않는다. 저장 모델의 [원 실험 보고서](../artifacts/performance_v1/experiment_report.md)는 당시 전역 지원 판정의 역사적 점수이며, 별도 캠페인에 현재 지원 판정을 적용한 수치는 이 문서를 따른다.
