# Philly GPU 추적 자료의 30분 고사용률 위험 예측

2026-09-28. 경희대의 배포·스케일링 **판단 입력**을 연구하기 위해 공개 GPU 계측에서 미래 사용률 사건을 예측했다. [원본 제공처](https://github.com/msr-fiddle/philly-traces/blob/29a1b87fa2d9ed80b83c9e3a37f3a88d382b031d/README.md)는 Microsoft Philly DNN 학습 클러스터의 GPU별 1분 사용률을 공개한다. 이 자료에는 이번 판단과 연결된 사용자 지연 SLO, VM 증감 명령, 명령 전후 결과가 없다. 따라서 아래 점수는 **GPU 위험 확률**의 오프라인 정확도이며 `SCALE_OUT` 또는 `SCALE_IN` 정책의 효과가 아니다.

## 먼저 고정한 자료와 평가

- [평가 규약](philly_gpu_risk_protocol_frozen.md)은 실제 후보·정답 집계 전에 `2026-09-28 13:08:10 UTC`에 동결했다. [후보·표본 게이트](philly_gpu_risk_dry_run_gate.md)를 모델 채점 전에 실행했고, [학습·채점 구현 해시](philly_gpu_risk_scoring_implementation_note.md)도 실제 점수 전에 기록했다.
- 원본 압축 파일의 SHA256은 `2037ccf63a725a02be718b0e1aeee6142c90b7f62d0d849295120e9f6ba13d2c`이다. GPU CSV **44,750,640행·552기계**를 전량 형식 감사하고, 기계 ID 해시 규칙으로 선택한 **21기계·1,704,704행**만 분석했다. 시각·GPU 슬롯 폭 복원은 [출처·전처리 기록](../data/external/msr_philly_2017/SOURCE.md)을 따른다. `machine_list`의 GPU 수 불일치 [보고](https://github.com/msr-fiddle/philly-traces/issues/8)를 고려해 GPU 슬롯 수를 각 기계의 첫 원시 GPU 행에서 정했다.
- 판단 시각보다 앞선 세 개의 5분 GPU 사용률 창을 특징으로 사용했다. 정답은 판단 뒤 30분의 여섯 5분 창 중 **해당 GPU 슬롯 평균 사용률이 80% 이상인 창이 하나라도 있는지**다. 판단 시각에 현재 창이 무효인 후보에는 확률을 내지 않는다. 학습 `2017-10-04`–`11-15`, 검증 `11-16`–`11-30`, 시험 `12-01`–`12-15` UTC로 시각순 분리했고, 정답 관측 완료 시각도 분할 안에 두었다.
- 주 방법은 현재 80% 미만/이상 상태별 L2 로지스틱 회귀와 관측 품질 입력이다. 검증 Brier로 정규화 강도와 다섯 Beta 확률표 중 **가장 강한 단순 기준선**을 골랐다. 같은 특징을 쓰는 상태 통합 모델과 품질 입력 제거 모델을 따로 비교했다. 사전 성공 기준은 현재 80% 미만·완전 과거 창에서 단순 기준선 대비 시험 Brier 상대 5% 이상 개선, 시험 전·후반 모두 개선, AP 및 날짜별 상위 5% 경보 recall 비악화였다.

원본 슬롯 폭 불일치율의 기계별 최댓값은 **0.0568%**로 사전 1% 게이트를 통과했다. 원시행이 있는 슬롯×5분 창의 입력 유효율도 학습 **98.73%**, 검증 **99.74%**, 시험 **100%**로 사전 50% 게이트를 통과했다. 후보 **1,419,566개** 중 미래 창이 모두 관측된 것은 **1,418,428개**다. 모델을 평가할 수 있는 층은 완전 과거·현재 80% 미만/이상 두 개뿐이다.

## 시간순 시험 결과

Brier는 낮을수록 좋고 AP·경보 recall은 높을수록 좋다. 아래는 모두 **같은 시험행**의 비교다.

| 완전 과거·현재 80% 미만, 217,750건 | Brier | AP | 날짜별 상위 5% 경보 recall |
| --- | ---: | ---: | ---: |
| 검증 선택 Beta 기준선: 현재 상태×최근 초과 | 0.067942 | 0.5194 | 0.2922 |
| 상태별·품질 입력 로지스틱, 주 방법 | **0.054683** | **0.7708** | **0.3205** |
| 같은 입력의 단일 통합 로지스틱 | **0.054578** | 0.7708 | 0.3218 |
| 상태별 로지스틱, 품질 입력 제거 | 0.054685 | 0.7708 | 0.3205 |

주 방법의 기준선 대비 Brier 차이는 **−0.013259, 상대 19.52% 감소**다. 시험 날짜를 먼저 고정한 두 반구간에서도 `0.043379 < 0.058949`, `0.064117 < 0.075447`였고, AP와 경보 recall도 낮아지지 않아 **사전 주 판정은 통과**했다. 날짜별 Brier는 **15일 모두**, 기계별 Brier는 **16기계 중 15기계**에서 기준선보다 낮았다. 동일 기계를 단위로 짝지어 2,000회 재표집한 Brier 차의 95% 백분위 구간은 **[−0.018370, −0.008255]**였다. 기계 사이 시기 충격과 16기계라는 표본 수 때문에 새 클러스터로의 일반화 구간은 아니다.

그러나 **제안한 방법의 개별 성분은 확인되지 않았다.** 현재 80% 미만층에서 단일 통합 모델의 Brier `0.054578`이 주 방법 `0.054683`보다 조금 낮으므로 **상태별 분리의 이득은 실패**했다. 두 모델의 기계 재표집 Brier 차 구간 `[−0.000186, 0.000422]`도 0을 포함한다. 주 방법과 품질 입력 제거 모델의 차이 `−0.000002`도 사실상 0이며, 해당 기계 재표집 구간 `[−0.000006, 0.000001]`은 0을 포함한다. 모든 시험행에서 과거 관측 마스크는 참이고 관측 간격은 300초로 같으며, 부분결측 시험행은 0건이다. 따라서 **관측 품질 입력의 이득은 판단 불가**다. 이 결과를 상태별·결측 인식 새 알고리즘의 독립 검증 성공으로 부르지 않는다. 검증된 것은 이 자료의 완전 관측·현재 정상층에서 **최근 GPU 사용률을 학습한 확률 모델이 강한 단순 확률표보다 정확했다**는 좁은 주장이다.

현재 이미 80% 이상인 별도 층은 시험 양성률이 **97.39%**였다. 주 방법과 검증 선택 기준선의 Brier는 각각 `0.022593`, `0.025559`, AP는 `0.9940`, `0.9739`였다. 기계별 재표집 Brier 차의 95% 구간 `[−0.007254, 0.000200]`은 0을 포함하고, 기계별로는 **14기계 중 8기계**에서만 주 방법이 낮았다. 이 층은 사건이 이미 거의 지속되는 상황이므로 새 초과 조기경보 능력의 근거로 삼지 않는다.

## 재현성과 연구 결정

[시험 지표 JSON](../artifacts/philly_gpu_risk_v1/metrics.json)과 행별 시험 확률 (`../artifacts/philly_gpu_risk_v1/test_predictions.parquet`)에 전체 층별 지표, 날짜·기계별 Brier, 사전 게이트 및 코드·입력 해시를 보관했다. 시험 확률은 **293,352행**, Parquet SHA256은 `04ce609b36c468cfbec021c3a4900a3a08cc818b9f6c3cf95a0efc8f58bd5d4f`다. 실행 명령:

```bash
python3 scripts/evaluate_philly_gpu_risk.py --expected-dry-run-sha256 bccc573ea0f4f8fca9357d72bdc56f60788c85c31c2065d75f639322412bbf0f
```

저장된 시험 예측에서 9개 확률 열의 Brier·AP·날짜별 상위 5% 경보, 날짜·기계별 Brier, 여섯 쌍의 기계 단위 부트스트랩 구간과 시험 반구간을 **독립적으로 재계산**해 JSON 보고값과 `1e-14` 미만의 오차로 일치함을 확인했다. 시험 두 완전 관측층의 미래 정답 관측률은 100%다. 위 양성률은 이 두 층의 **선택된 GPU 슬롯 판단**에만 해당하며 전체 기계·GPU의 사건율은 아니다.

자료·게이트·모델·평가지표는 시험 점수 전에 고정했다. 저장된 후보 특징과 미래 관측성은 정규화 원본에서 재생성한 같은 키·값·순서와 대조한 뒤 정답을 학습·평가에 사용했다. [Philly 관련 합성 테스트](../tests/test_evaluate_philly_gpu_risk.py)는 구현 경계와 누출 금지 조건을 확인한다.

이번 결과는 경희대 판단 모듈의 **관측 위험 신호 연구**에 남긴다. 운영 명령과 연결하려면 응용별 요청·SLO, 자원 형상, 스케일 명령 시각, 실행 성공/실패, 전후 사용자 결과를 연결해야 한다. 필요한 필드는 [실행·결과 데이터 계약](scale_effect_data_contract_v1.md)에 정리했다. Philly는 DNN 학습 클러스터이고 동일 기계가 시간순 학습·시험에 함께 나타날 수 있다. AI-App 서비스나 새로운 GPU 기계에 대한 성능, VM 증감의 인과 효과는 이 평가로 확인되지 않았다.
