1. 통합 목적과 기관 경계
======================================================================

목적은 여러 연구 출력을 출처·시간·단위를 보존한 근거로 연결하고, 이후 경희대 판단 계층이 안전하게 읽을 수 있게 하는 것이다. 현재 자료만으로 모든 자원 항목과 실제 동작을 자동 결정하는 통합 모델을 만들었다고 주장하지 않는다.

기관 | 제공하거나 수행하는 것 | 경희대 모듈과 연결
경희대 | 앱 요구 해석, 추상 형상 추천, 위험/수요 입력, 배포·스케일 판단 및 추론 최적화 | 예측·증거·보류, 향후 행동 판단
이노그리드 | 앱 등록/버전/운영 정보, 모니터링 수집·관리, 실제 명세 변환·응용 실행 | 구조화 앱·관측·피드백 제공, 경희대 결과를 실행 흐름에 연결
ETRI | 인프라 조회, 기본 추천·스케줄링, 실제 CSP/리전/VM 선택과 생성·삭제 | 자원 유형/가용량/가격/상태 제공, 실행 요청과 실제 자원 결과

한 VM에 하나의 주요 AI 응용을 가정한다. 빈패킹, CPU affinity 제어, GPU 공유, 우선순위 프로세스 스케줄러, K8s 배포를 현재 필수 통합 항목으로 추가하지 않는다. 기존 실험의 affinity·pod 기록은 연구 데이터의 조건이며 해당 플랫폼 기능 개발을 뜻하지 않는다.

실행 흐름의 기관 경계
경희대 추상 형상/판단
 → 이노그리드가 실행 흐름을 관리하고 인프라 요청
 → ETRI가 실제 CSP·리전·VM을 결정·제어
 → ETRI가 생성 결과를 이노그리드에 반환
 → 이노그리드가 응용을 배포·상태 및 사용자 결과를 연결
 → 경희대가 가용한 완료 결과를 후속 판단·보정에 사용
이 구조는 역할 설계이며 현재 연구 데이터의 실제 실행 로그가 이 경로를 모두 증명하지는 않는다.

4. 공통 연구 결과 객체: 신규 구현 전 초안
======================================================================

이 절의 필드명은 새 API 명세 확정값이 아니다. 기존 계약을 수정하지 않고 별도의 연구 증거 봉투로 설계한다. 기존 객체에 없는 필드를 임의 삽입하거나 Go에서 해석된다고 가정하지 않는다.

필드 | 의미와 규칙
evidence_version | 연구 결과 봉투의 버전; 기존 증거 버전과 별도
module_id,module_version | 형상/수요/위험/SM/요구 신호 및 코드 버전
model_id,model_version,model_sha256 | 예측기 식별자; 응용 model_id와 구분
application_ref | app_id,app_version,profile_id,workload_id와 연결된 원본 식별자
request_id,correlation_id | 요청·결과 추적; 원래 연구 함수에 없으면 Adapter가 실제 요청에서 부여
decision_at,time_basis | UTC 절대시각 또는 relative_seconds와 명시적 origin; 임의 날짜 생성 금지
observation_window | 특징으로 사용한 과거 창의 시작·끝
forecast_window,target_definition | 예측 대상 기간과 최대/합계/사건 정의
latest_input_available_at | 판단에 사용한 입력 중 가장 늦은 실제 가용 시각
ready_delay_minutes | 준비 지연 관련 수요에만 사용; 해당하지 않으면 null
support_status | SUPPORTED/UNSUPPORTED/INSUFFICIENT_HISTORY 등 제안값; 기존 status와 대응표 필요
result_status | RESEARCH_ESTIMATE 또는 ABSTAIN; 실행 승인과 구분

feedback | 보정 유무,원시 예측,보정량,적격 표본 수,완료 경계와 마지막available_at

숫자 규칙
- 값 미존재/미지원/보류는 null 또는 estimate 부재로 표현한다. 0으로 채우지 않는다.
- p0,p_final은 확률 0~1이며 GPU사용률 80%와 같은 단위로 더하지 않는다.
- 토큰 합계·호출 수는 requests/sec가 아니다. 집계bin_seconds=300과 대상 범위를 함께 둔다.
- peak 창은10/15/35분이지만 단위는 '그 창 안의 최대 5분 기록량'이다.
- 배치p95와사용자E2Ep95는 다른 metric_id를 쓴다.
- CPU affinity cores와VM vCPU, 프로세스replicas와nodes는 다른 필드다.
- 선택된 후보가 없으면 selected=null이며, downstream이 큰 VM이나KEEP를 자동 대입하지 않는다.
- 모델의q90를 확정 상한이라고 쓰지 않는다. 통합 시 실제 피복 검증을 별도로 남긴다.

5-1. 정적 형상과 v7
기존 로더: scripts/assess_gpu_shape.py의load_verified_bundle(model_path,source_path).
모델: R/artifacts/performance_v1/performance_model.joblib.
자료: R/data/audit_v1/measurements.parquet.
계산: scripts/assess_gpu_shape_microbatch_v7.py의assess_gpu_shape_microbatch_v7(bundle,requests,max_grids=256).
실제 요청 키: batch_latency_p95_limit_ms,min_requests_per_second,candidates.
후보키: 학습 10 특징 + application_id,workload_id,host,device_name.
공통 workload/model/revision/device/host/device_name/batch/max_length/concurrency/repeats가 같고 1/2replica×2/4/8/16affinity8형상이 완전해야 한다. 입력지원 검사가 하나라도 실패하면 요청 전체 ABSTAIN을 유지한다.
기존 출력: status,reasons,candidate_assessments,selected,scope,provenance 등. 후보 결과의gpu_replicas,cpu_affinity_cores,predicted_batch_latency_p95_ms,predicted_requests_per_second,batch_latency_margin_ms,requests_per_second_margin,meets_estimated_slo를 보존한다.
시간 의미: 정적 실험 조건 성능이며 특정 미래시간열 예측이 아니다. 공통 봉투에는 요청 시각을 기록하되 새 시간 예측 성과로 표시하지 않는다.
v7은 model/candidate/SLO/보류 규칙을 바꾸지 않는다. 256격자·1,024행이상2worker를 사용하고 tree누적순서를 유지한다. 작은입력은 직렬, 큰 예측 실패는 기존 격자추론으로 재시도한다. 온라인 동시성 CPU 비용은 추가 검증 과제다.
기존 형상 증거: contracts/gpu_shape_evidence_v0.2.0.schema.json; generate_gpu_shape_evidence_v0_2.py/validate_gpu_shape_evidence_v0_2.py. 기존 증거 필드는 새봉투와 대응하되 삭제·재명명하지 않는다.

5-2. 구조화 요구 신호

contracts/requirement_signal_evidence_v0.1.0.schema.json과 생성/검증 코드는 요청·결과·출처를 묶는 기반이다. 이를 앱 설명·사용자 자연어를 이해한 최소 RAM 정답으로 대체하지 않는다. 현장 metadata의 dtype/revision/replica 정의와 일치하는지 확인해야 한다.

5-3. Philly 기본 위험과 슬롯 보정

BurstGPT는 scripts/burstgpt_sparse_calls.py의 design/targets와 저장 모델을 사용한다. 전체24개에는 상대·절대 비교 모델이 함께 있다. 지원된 집합·지연의 상대(stabilized) 모델을 선택한다. cohort 키는 ChatGPT|API log, ChatGPT|Conversation log, GPT-4|API log, GPT-4|Conversation log다. Copilot 서비스 키와 합치지 않는다.

보정에는 raw_prediction_id, scale, 고정 모델 버전, 완료 target_id, 완료·전달 시각, 적격 표본 수를 연결한다. 보정 후 예측의 잔차를 다시 쌓는 방식으로 바꾸지 않는다. 부모 모델이 변경되면 기존 잔차 이력을 분리하는 규칙을 합의하고 검증해야 한다.
조건별 개선은 검증 범위 정보다. 성공 조건만으로 운영 모델 자동 선택기를 학습했다고 말하지 않는다.

7. 시점·피드백·재현성 규칙
======================================================================

공통 시간 검사(초안)
1. observed_at은 관측이 발생한 시각, available_at은 판단측에서 사용할 수 있게 된 시각이다.
2. 판단 시각D의 특징은 창이 완료됐고 available_at≤D여야 한다.
3. target_completed_at>D면 피드백에서 제외한다. 완료됐어도 target_available_at>D면 제외한다.
4. 지연 peak 정답은 origin+h+1에서 완료된다. 12:00/10분 준비는12:15에 정답이 완료된다.
5. Philly는 전날의 판단 중 정답 완료·전달 조건을 만족하는 기록을 현재 코어의 순서대로 사용한다.
6. 이전 원시 예측·target·scale·model 버전을 연결해 잔차를 계산한다. 원시 관측 수정이나 버전 변경 시 이력을 그대로 재사용하지 않는다.
7. 실제 available_at이 없으면 assumed_immediate_at_window_close를 가정으로 명시한다. 실제 전달 로그처럼 표현하지 않는다.
8. BurstGPT 상대시간을 UTC로 변환할 기준이 없으면 상대 origin/bin_index를 보존한다. 절대시각·요일 특징을 새로 만들지 않는다.
9. 관측된0, 결측, 수집 실패를 구분한다. heartbeat가 없으면 실제 무호출을 확인하지 못했다는 한계를 남긴다.
10. app/model/host/slot/workload 식별자 변경·action 재시도·중복을 확인한다. 같은 사건을 독립 학습 사례로 중복 계산하지 않는다.

모델·환경검증
현재 bundle의 학습 자료/모델 해시, 특징 순서, 라이브러리 버전과 source 조건을 대조한다. 모델 로드가 성공해도 지원 검사를 생략하지 않는다. 검증 실패는 기존 함수의 거절을 유지한다.
정적 예측 캐시는 한 묶음 호출 안에서만 유효하다. model/input이 달라진 다음 호출에 재사용하지 않는다. v7은 출력 동등성을 유지하는 계산 변경이다. private sklearn API 버전이 바뀌면 출력·지원·성능을 다시 확인해야 한다.
소스 해시는 출처 연결과 변경 검사의 근거다. 실제 action 성공, 사람 검토 metadata, 전자서명까지 보증하는 것은 아니다.

9. 추가로 확보해야 하는 입력·정답·사건
======================================================================

앱 요구: app_id/version/profile_id, model_id/revision/dtype, 작업 종류, 입력 크기·토큰 범위, 동시성, 사용자 SLO, 비용 한도, 이미지, 필수 labels·배치 조건, 근거와 사람 승인 라벨.
자원 후보: resource_id, CSP/리전, CPU/RAM/GPU 종류·수·메모리, 총량·가용량, 건강 상태, 가격·통화·시간 기준·유효기간, 출처와 관측·가용 시각.
처리 용량: 같은 앱·revision·형상·입력 복잡도에서 반복 측정한 E2E 지연·오류·요청률과 토큰/호출 처리량. 출력 토큰·동시성·batch 영향을 포함한다. 이 대응이 없으면 수요를 GPU/VM 수로 환산할 수 없다.
배포 판단: decision_id, correlation_id, policy_version, 판단 시각, 사용한 입력 중 가장 늦은 available_at, 추상 형상, Operation과 후보 점수·지원·보류 근거.
실행 사건: 실행측 action_id와 decision 연결, 명령 접수·재시도·실패 이유, 요청·접수·완료 시각, 실제 준비된 VM/replica 수, READY/FAILED, 트래픽 라우팅 전환·버전.
사용자 결과: request_id, 실제 처리 deployment/action 연결, 입력 크기, 시작·종료·가용 시각, 성공·오류·E2E 지연, 부하·가격. 비교 창과 비개입·통제군을 고정한다.

현재 scale_action_events v0.2.0은1회+1replica SCALE_OUT의 좁은 수집 형식이다. 예시는 합성이다. Scale-in/Update/Keep 전체를 포괄하지 않으며 명령 요청을 실제 적용 성공으로 바꾸지 않는다.
실제 판단 효과 학습에는 요청→action 접수→READY→라우팅→사용자 결과의 시간 연결과 적절한 비교 조건이 필요하다. 공개 GPU/호출 trace로 이 결과를 대체할 수 없다.

11. 다음 개발 순서와 완료 조건
======================================================================

단계 1. 기관 계약 합의
앱/SLO/모니터링 입력, resource 후보·가격, 공통 식별자·available_at, 형상 추천 범위, 연구 증거 전달 위치, 별도 서비스 또는 내부 모듈 방식을 합의한다.
완료 조건: INNO/ETRI/KHU의 필드 제공자·단위·시간·누락 동작·버전 책임을 명시한 합의문. 현재 문서는 그 합의 완료를 뜻하지 않는다.

단계 2. 연구 Adapter와 조회형 연결
기존 스키마 검증과 모델 해시를 유지하는 wrapper, 서비스·지연 라우팅, 공통 증거·보류, 완료 피드백 이력 변환을 구현한다. 별도 검토 없이 기존 Go formal 계약을 수정하지 않는다.
완료 조건: 저장 자료 재생에서 기존 출력의 단위·지원·시점을 보존하고 실행을 자동 발행하지 않는 연결 검증.

단계 3. 실제 용량·요구·실행 기록 확보
새 앱/호스트/CPU/RAM/GPU 후보를 실제 사용자 SLO로 반복 측정하고 action/READY/라우팅/요청 결과를 연결한다. train/calibration/confirmation은 app/model/host/time으로 분리한다.
완료 조건: 미사용 확인 집합, 재현 가능한 용량 대응, 자원 부족·실패 경계, 실제 READY/available_at 분포. 기존 노출90작업을 새로운 독립 시험으로 재사용하지 않는다.

단계4. 판단 정책의 offline/Shadow 검증
간단한 기준선과 예측 입력 정책을 같은 비용·SLO·준비·축소 진동 조건에서 비교한다. cooldown·히스테리시스·최소 유지 시간은 가정을 명시해 평가한다.
완료 조건: 같은 단위의 실제 지표 개선을 확인하고 보류·실패·가능했지만 누락한 사례도 보고한다. 가상 slot 비용을 실제 GPU/VM 비용으로 바꾸지 않는다.

단계 5. 제한된 실제 효과 확인
합의된 범위의 canary/통제 실험에서 행동 전후의 요청 SLO·비용·READY·자원 수 변화를 관측한다.
완료 조건: action과 결과가 연결되고 비교군·교란을 명시한 증거. 이 조건 전에 학습된 통합 오토스케일러가 완료됐다고 주장하지 않는다.

이 순서는 재개 후 개발 계획이다. 현재의 실험 중지 상태를 해제하거나 실행 승인으로 해석하지 않는다.
