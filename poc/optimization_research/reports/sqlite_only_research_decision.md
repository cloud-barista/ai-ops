# 기존 SQLite만 사용할 때의 AI-MCMP 연구 결정

## 결론

현재 자료로 먼저 다룰 수 있는 문제는 **AI 응용의 CPU/GPU 형상별 배치 지연·요청 처리량 예측**이다. 예측값으로 정적 후보를 거르는 연구는 가능하다. 같은 64개 입력 조건을 공유하는 encoder에서 도움이 된 [소수 기준 측정·잔차 전이](anchor_residual_transfer_method_v1.md)와 현재 GPU1 계측에서 동일 호스트 GPU2 용량을 예측하는 [계측 조건부 상대 반응](replica_capacity_method_v1.md)을 **구체적인 연구 방법 후보**로 정리했다. 기존 원리의 학술적 최초성이나 범용 효과는 주장하지 않는다. 자연어 요구사항의 정답, 실사용 SLO, VM 가격, 시계열 부하와 Scale-out/in 실행 결과는 없어서 요구사항 해석 모델이나 동적 제어 정책을 학습·검증할 수 없다. [자료 진단](../data/audit_v1/data_audit.md), [문헌 검토](novelty_position_review.md)

별도 `khu-live-placement` lifecycle SQLite도 조사했다. 거기 적힌 `SCALE_OUT`/`SCALE_IN`은 실제 운영 전이가 아니라 서로 다른 정적 복제 측정을 짝지은 결과다. 후보 특징의 실행 후 GPU 사용률 누출과 샘플/초를 요청/초로 취급한 SLO 라벨 오류도 있어 그대로 학습 정답으로 쓰지 않는다. [원본·파생 DB 감사](untapped_signal_audit.md)

## 현재 남길 두 연구 후보

| 사용 시점 | 입력과 학습 방식 | 관측된 이점 | 채택 제한 |
| --- | --- | --- | --- |
| 배포 전 형상 평가 | 새 모델의 GPU 1개·CPU 2코어 입력 조건 8개를 재고, 이전 모델의 내부 교차검증 잔차 공분산으로 나머지 조건을 추정한다. 별도 학습한 자원 반응 모델이 GPU/CPU 형상 성능을 예측한다. | 같은 64개 조건을 공유하는 encoder 8모델에서 커널보다 지연/처리량 오차와 생성 SLO 선택이 좋았다. | BERT 계열 공동 제외에서는 지연 이점이 소멸·역전됐고, 새 입력 조건에서 처리량 이점도 재현되지 않았다. 연구용 예측기 후보로만 보관한다. |
| 현재 형상 계측 후 재형상화 | GPU 1개 벤치마크의 성능·GPU/CPU 계측을 이용해 GPU 2개에서의 반응을 학습한다. 처리량은 `현재 요청/초 × 2 × exp(학습한 로그 잔차)` 형태다. | 샘플 수를 제외한 계측 4개로 모델 단위 제외 GPU 2개 처리량 오차가 주 캠페인 0.112→0.096, 새 space 조건 0.171→0.125로 줄었다. | BERT 계열 공동 제외의 주 조건에서는 이득이 없고 novel 조건에서는 역전됐다. 가상 Scale-out 승인 성과도 상충한다. GPU 2개는 같은 호스트에서 각각 전체 작업을 실행한 replica이며, 합산 처리량은 [벤치마크 용량](replica_benchmark_semantics.md)이다. 실제 VM 추가/삭제가 아니다. |

첫 후보는 [공분산 전이](cross_model_covariance_findings.md), [계열 제외](family_holdout_transfer_findings.md), [중심화 공분산의 계열 제외](family_holdout_centered_findings.md), [반복 측정의 새 조건](live_repeat_transfer_findings.md)에 기록했다. 훈련 donor의 모델×조건 내부검증으로 새 조건 보정기를 골라도 처리량 역전이는 막지 못했다. [방식 선택 실험](support_hybrid_transfer_findings.md) 둘째 후보의 학습·결정 평가와 원자료 누수 검사는 [모니터링 실험](telemetry_conditioned_scaling_findings.md)에 있고, [계열 제외](telemetry_family_holdout_findings.md)에서 이득의 불안정성을 확인했다. [순열 대조](telemetry_permutation_control_findings.md)는 작업에 맞는 계측값에 처리량 예측 정보가 있다는 내부 근거를 준다. 둘 다 이미 탐색한 SQLite 결과에 맞춰 연구됐으므로 **새 방법의 독립 성능 검증이나 선행연구 대비 최초성**을 뜻하지 않는다.

## 다른 담당 항목에서 새로 검증한 학습 목표

| 경희대 항목 | SQLite에서 학습한 대상 | 확인한 범위와 결론 |
| --- | --- | --- |
| 배포·제어 추론 최적화 | 고정 형상의 처음 2·3·5·10회 반복으로 미래 배치 지연·요청 처리량의 **단일 실행 분포**를 예측한다. 다른 모델의 셀 내 변동 폭을 분산 prior로 학습한다. | 시간순 모델 제외 평가에서 2회 측정의 지연 CRPS는 donor 분산 수축이 대상 셀 단독 정규·Cauchy보다 낮았다. 5회 측정에서는 단독 정규·Student-t가 네 버전×지표 모두에서 CRPS 우위였다. 반복 횟수·측정비용 연구로 남기며 실제 배포/스케일 행동으로 사용하지 않는다. [결과](repeated_measurement_distribution_findings.md) |
| 응용 요구 분석의 자원 신호 | 등록 시 파라미터 바이트를 확보한다고 가정하고, 작업 조건에서 같은 GPU의 **관측 PyTorch 예약 피크**를 예측한다. | 모델 하나씩 제외한 주 조건의 오차는 줄었지만, BERT 계열 공동 제외의 새 조건에서 역전되고 피크 과소예측이 잦았다. 최소 VRAM·OOM 가능성의 정답이 아니므로 GPU 적합성 판단에 사용하지 않는다. [결과](vram_peak_findings.md) |

두 실험 모두 같은 기존 SQLite를 탐색한 뒤 방법을 정했으므로 독립 검증이나 학술적 최초성의 근거는 아니다. 첫 실험은 기존 평균 성능 예측과 다른 *반복 변동*의 학습 목표이고, 둘째 실험은 메모리 **적합성**이 아닌 *관측 피크*의 회귀다.

후속 [알고리즘 학습 결과](trained_algorithms_v1.md)로 관측 GPU 예약 피크의 상한 보정, donor 반복분포에서 예측폭 학습, 로컬 모델 적재시간 예측을 추가했다. 연구용 학습 모델과 모델 제외 예측값을 저장했다. VRAM 상한은 유일한 생성형 모델에서 실패했고, 반복 예측폭 학습은 강한 기준선을 일관되게 넘지 못했으며, 적재시간은 새 모델 종류에서 크게 과소예측했다. novel·space 입력 캠페인은 주 학습 캠페인보다 먼저 수집됐으므로 **입력 조건 홀드아웃**이지 시간상 미래 검증이 아니다. 세 결과는 실제 VM 부팅·OOM·Scale-out/in 정답을 대신하지 않는다.

## 추가 가설의 반증

- **수요·GPU별 비대칭 SLO 여유값:** 대상 모델을 제외한 donor만 4/4 교차 적합해 지연·처리량 여유값을 따로 학습했다. 25개 합성 목표에서 대상 모델별 승인 수를 똑같이 맞춘 6,281건의 잘못 승인은 조건별 방법 301건, 고정 로그 여유값 0.05와 K8 0마진 기준 각각 282건이었다. 원래 수집 SLO의 동수 342건에서도 9건 대 7건이었다. 조건별 보정은 같은 승인 규모의 단순 기준보다 나아지지 않아 채택하지 않는다. 동수 승인은 위험 순위 진단이며 실제 배포 정책이 아니다. [사전 규약과 결과](asymmetric_margin_findings.md)
- **CPU 사전 측정으로 GPU 사용량 줄이기:** CPU 2코어에서 새 모델의 8개 입력 조건을 측정해 GPU 형상을 예측했다. 모델 전체 제외에서 CPU만 사용한 지연/처리량 로그오차는 `0.399/0.386`으로 GPU 4회 기준 `0.231/0.158`보다 컸다. GPU 4회에 CPU를 합치면 처리량 오차가 `0.158→0.153`으로 조금 줄지만 지연 오차는 `0.231→0.235`, 수집 목표의 잘못 승인은 `9→13`으로 악화됐다. CPU 실행은 모델당 평균 529 wall초가 더 필요했고, 25개 가상 SLO의 일부 이득은 Albert에 집중됐다. 실행 기록상 CPU 8회를 모두 마친 뒤 첫 GPU 측정을 한 모델도 없으므로 이 절차는 순서를 바꾼 오프라인 평가다. [실험과 비용](cpu_preprofile_transfer_findings.md), [직접 선행연구](cpu_proxy_novelty_review.md)
- **현재 GPU 실행 계측으로 CPU affinity 증설 예측:** 같은 GPU 1개·2코어 측정을 입력으로 사용할 때, 계측 4개를 더한 주 캠페인의 지연 로그오차는 `0.21745→0.21718`로 사실상 같고, 두 새 입력 캠페인에서는 더 나빴다. CPU 증설로 구제 가능한 주 캠페인의 가상 목표 110건 중 성공 선택은 기준선 8건, 계측 추가 5건이었다. affinity 한도는 VM CPU 수가 아니며, 형상 결정 이득은 확인되지 않았다. [실험](vertical_telemetry_probe_findings.md)
- **GPU 복제의 물리 병목 공식:** 두 GPU는 각각 전체 작업을 실행하므로 고정 작업을 병렬화하는 Amdahl 모형과 목표가 다르다. GPU 1개·CPU 2코어의 주 575쌍 중 523쌍에서 합산 GPU 2개 처리량이 2배를 넘는다. 처리량을 2배 이하로 제한하는 예측기의 가능한 최소 로그오차 `0.1699`도 기존 계측 기준선 `0.0961`보다 높다. CPU 시간은 모델 로드와 전체 실행을 포함해 추론 구간의 직렬 CPU 병목을 분리할 수 없다. [프로토콜 및 오차 하한](replica_bottleneck_identifiability_findings.md)
- **기준 형상·자원 반응 잔차 분리와 GPU2 sentinel:** 기존 모델의 상대 자원 반응을 새 모델의 GPU2 측정 한 번으로 보정해 보았다. 모델 전체 제외에서 공동 전이의 지연/요청 처리량 로그오차는 `0.2824/0.1750`, 강한 8회 기준 측정은 `0.2381/0.1268`이었다. 평균 GPU-wall도 `7.82`초 대 `6.96`초였다. BERT 네 모델 공동 제외와 새 입력 조건에서도 두 오차가 악화됐다. donor만으로 보정한 신뢰도 게이트는 13개 평가 대상 모두에서 닫혀 공동 전이의 도움이 확인되지 않았다. [완전 중첩 분할과 결과](relative_response_sentinel_findings.md)
- **성능 우세 형상 한 번 측정:** GPU2/core2가 주 캠페인 463/575작업의 단일 우세 형상이지만, 이를 한 번 측정하는 규칙은 새 작업에서 우세 여부를 증명하지 못한다. 원래 생성 SLO의 가능 작업 357개는 모두 잡지만 251개는 GPU1로도 가능해 불필요한 GPU를 쓴다. 훈련 모델만으로 만든 25개 목표에서는 가능 질의 6,746개 중 17개를 놓치고, 모든 작업을 직접 측정하는 총 GPU-wall은 모델당 8회 방식보다 45.83배 크다. 직접 측정의 정확성과 모델 전반에 전파하는 추정은 비용·보장 범위가 다르며, 이 단순 규칙의 최초성도 없다. [Pareto 감사](pareto_one_probe_assessment.md)
- **메모리 적합성:** 성공 GPU 실행 7,985건에서 OOM은 없었고 실패 10건은 모델 파일 접근 오류였다. GPU별 VRAM 예약 피크가 장치 용량에서 멀며 두 호스트의 성공 모델도 겹치지 않아 최소 VM RAM/VRAM이나 GPU 종류의 정답을 만들 수 없다. 관측 피크 회귀와 별도로, 실제 적합성 판단에는 학습된 피크 점추정 대신 보수적 호환성 필터가 필요하다. [적합성 감사](memory_feasibility_review.md), [피크 회귀](vram_peak_findings.md)

## 연구 항목별 작업 범위

1. **요구사항 분석:** 현재는 배치 크기, 입력 길이, 동시성, 모델 크기, 작업 종류 등 SQLite에 있는 구조화 특징을 읽는 수준으로 한정한다. 등록 모델 크기·작업 조건으로 같은 GPU의 관측 예약 피크를 예측할 수 있지만, 최소 VRAM 요구량으로 출력하지 않는다. 자연어 요청을 목표 CPU·메모리·GPU·노드 수로 바꾸는 지도학습의 정답이 없으므로 그 모델을 학습하지 않는다.
2. **인프라 추천:** 형상별 성능 예측을 연구의 중심으로 둔다. 훈련 모델 전체 제외, 모델 계열 공동 제외, 새 입력 조건, 동일 수집기 버전 반복 측정을 따로 보고한다. GPU 개수·CPU 코어를 고르는 정적 검증 결과를 실제 VM 비용 절감이라고 표현하지 않는다. 가격·메모리 한도·여러 VM 후보가 없기 때문이다.
3. **배포·스케일링 판단:** 현재 실행의 모니터링을 통한 GPU 복제 후 용량 예측까지만 연구한다. `SCALE_OUT`/`SCALE_IN`의 실제 효과, 전환 시점, 지연, 실패, 안정성은 현재 자료로 평가할 수 없다. 시계열 제어 모델을 합성 정답만으로 훈련해 운영 성과로 제시하지 않는다.
4. **배포·제어 추론 최적화:** 같은 GPU-wall 측정 비용에서 정적 프로브 8개를 기준으로 둔다. 기존 순차 프로브 규칙, 비용·SLO 가중 프로브, 두 자원 형상 프로브는 강한 기준선보다 전반적으로 낫지 않았다. 저장 모델이 고른 형상을 먼저 확인한 [8후보 사후 재생](sequential_shape_confirmation_findings.md)은 주 시험의 확인 횟수를 줄였지만 최소 형상 선택과 일부 별도 캠페인의 GPU 시간을 악화했다. 별도로 반복 측정의 미래 분포·구간을 평가했으며 2회에서는 donor 변동 학습이 일부 도움이 됐지만 5회에서는 대상 셀 기준선이 더 좋았다. [다음 실행 합격 감사](repeat_confirmation_findings.md)에서는 경계 근처 합성 목표에서 직전 합격 뒤에도 다음 회차 실패가 있었고, 3회 연속 합격 규칙의 위험 감소가 두 수집기 버전에서 일치하지 않았다. 측정 횟수의 비용·불확실성을 제시할 수 있어도 배포 승인 오류 개선은 아직 검증하지 못했다.

## SQLite만으로 마무리할 검증

- 원본·추출 스냅샷과 모델/조건/계열 분할을 고정하고, 모든 비교에서 관측 GPU 실행 횟수와 GPU-wall을 맞춘다.
- 새 방법을 고를 때는 지연·처리량의 모델별 오차, 성공·잘못 승인, 승인 건수, 최소 자원 선택을 함께 제시한다. 25개 합성 목표는 한 작업의 상관된 질의이므로 모델 또는 작업 단위로 불확실성을 계산한다.
- 여러 차례 방법을 본 novel-matrix, space-filling, live 캠페인을 **새로운 독립 test set**이라고 부르지 않는다. 현 SQLite에서 가능한 결론은 탐색적 발견과 반증이다.
- 학술적 방법 기여를 채택하려면 가까운 선행연구(경험적 GP, 소수 프로파일, 계측 기반 확장 예측)와 다른 기술적 핵심을 명시하고, 두 예측 지표 및 실제 결정 품질에서 강한 기준선을 넘겨야 한다. 현재 어느 후보도 이 문턱을 넘지 못했다.

따라서 현재의 연구 산출물은 학습 코드, 재현 가능한 분할·예측값, 실패 사례를 포함한 검증 보고서로 관리한다. 이 결과를 경희대 핵심 모듈에 연결하더라도 `Deployment Spec`의 CPU/GPU 요구와 판단 근거를 제시하는 **실험용 추천**으로 범위를 명시한다.
