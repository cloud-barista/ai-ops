# Azure Coding 공개 표본의 다음 5분 입력 토큰 수요 예측

## 결과

**고정한 후향 시간순 게이트는 통과했다.** 2024-05-10~12의 Coding 공개 표본으로 상대 입력 토큰 수요의 90분위 HGB를 한 번 학습하고, 05-13 개발 검증 뒤 하이퍼파라미터를 바꾸지 않은 채 05-14~16의 세 날짜를 평가했다. 각 날짜의 288개 5분 구간이 모두 적격이었다. 주 방법은 환산한 절대 입력 토큰 예산의 pinball 손실에서 네 비교기 모두보다 5% 이상 낮고, 날짜별 최선 기준선보다 3/3일 낮았으며, 세 날짜의 경험적 피복률이 85~95% 안에 있었다.

| 방법 | 05-13 개발 pinball ↓ | 05-14~16 날짜 동일 가중 pinball ↓ |
|---|---:|---:|
| **상대 90분위 HGB** | **436,001** | **418,627** |
| 학습 비율의 `m` 가중 전역 90분위 | 826,834 | 855,670 |
| 직전 완료 1시간 경험적 90분위 | 717,199 | 798,835 |
| 전날 같은 시각의 상대 비율 | 1,633,253 | 1,009,301 |
| 전날 상대 비율 + 학습 잔차 90분위 | 856,755 | **742,048** |

숫자는 **기록된 표본의 5분 입력 토큰 합계**에 대한 평균 pinball 손실이며 단위는 입력 토큰이다. 가장 낮은 비교기 손실 742,048에 비해 학습기 손실은 43.6% 낮다. 이 기준선은 학습 자료의 비율 잔차만으로 고정했으며 05-14~16 결과에 맞춰 고르거나 조정하지 않았다.

| 날짜(UTC) | 적격 5분 구간 | HGB pinball ↓ | HGB 피복률 | 평균 관측 입력 토큰 / 구간 | 평균 예측 예산 / 구간 |
|---|---:|---:|---:|---:|---:|
| 05-14 | 288/288 | 414,611 | 93.75% | 28,193,307 | 31,892,459 |
| 05-15 | 288/288 | 420,361 | 92.01% | 28,636,240 | 32,338,557 |
| 05-16 | 288/288 | 420,910 | 93.75% | 27,245,071 | 30,787,026 |

05-13 개발 검증의 HGB 피복률은 90.63%였다. 각 날짜의 5분 구간은 같은 서비스의 시간상 연속 관측이므로 864개의 독립 실험으로 세지 않는다. 세 평가일은 모두 같은 주의 Coding 서비스다.

## 학습 대상과 시간 경계

[점수 전 규약](azure_code_input_demand_protocol.md)대로 `TIMESTAMP`와 `ContextTokens` 두 열만 읽어 16,803,695개 요청을 UTC 5분 구간 2,016개로 묶었다. 각 구간 `[t,t+5분)` 시작에서 직전 **완료된** 12구간의 평균 `m_t`를 사용한다고 가정하고, `r_t=현재 5분 합계/m_t`의 90분위를 학습했다. 학습 손실을 절대 토큰 pinball에 맞추기 위해 각 학습 구간의 가중치를 `m_t/학습 평균(m)`으로 두었다. 5월10일 첫 1시간은 이력이 없어 제외했으므로 학습 852구간, 학습 전날 잔차 기준선은 양쪽 비율이 있는 564구간으로만 적합했다. 모델과 네 기준선은 `m_t`를 곱해 절대 토큰 예산으로 평가했다. 05-14~16의 이전 완료 구간은 순차 피드백으로 사용했지만 현재·미래 구간의 입력 토큰이나 출력 토큰은 특징에 넣지 않았다.

입력 토큰 합계를 사용하려면 완료된 구간의 토큰 계수가 다음 결정 전에 전달돼야 한다. 이 전달 시각은 원본에 없으므로 **가정**이다. `ContextTokens`가 요청 접수 시점에 알려지는지도 로그만으로 검증할 수 없다. 원본은 생산 요청의 공개 **일부**이므로 이 결과는 전체 Azure 수요·GPU 점유율·필요 VM 수의 검증이 아니다. 사용자 지연 SLO 및 실제 배포·스케일 조치와도 연결되지 않는다.

## 증거 범위와 재현

같은 Coding CSV의 05-14~16은 이전 [출력 토큰 연구](azure_code_output_tokens_findings.md)에서 이미 시험 기간이었다. 이번 규약 전에 일곱 날짜 모두의 요청 수와 **입력 토큰 합계의 일별 5분 최솟값·최댓값·중앙값**도 확인했다. 현재 예측 목표와 그 5분별 후보 점수는 그때 계산하지 않았으나, 이번 비교를 **블라인드 독립 시험**이라고 부르지 않는다. 출력 토큰 연구의 정답 `GeneratedTokens`는 읽거나 결합하지 않았다.
