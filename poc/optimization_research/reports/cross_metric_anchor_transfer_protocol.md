# 지연·처리량 공동 잔차 전이: 사후 탐색 규약

2026-09-29. 현재 [소수 측정 공분산 전이](cross_model_covariance_findings.md)는 배치 지연과 요청 처리량의 오차 표면을 **각각** 조건화한다. 한 실행에서 나온 두 지표의 로그 잔차가 관련돼 있어, 같은 8회 기준 측정에서 두 지표를 함께 조건화하면 미측정 형상 예측이 달라질 수 있다. 기존 SQLite의 시험·새 조건은 여러 연구에서 이미 열람됐으므로 이는 **사후 탐색**이다. 다출력 공분산 자체를 새로운 원리나 실제 스케일 정책으로 주장하지 않는다.

## 자료·분할·예산

- 고정 입력은 `data/audit_v1/measurements.parquet`, SHA-256 `b7bba7963e8a309b6a8502a1d98eefb150476b1381ec016beeb68cbf63fae906`이다. 주 캠페인의 GPU 8후보 완전 격자 575개에서 모델 ID 하나씩 완전히 제외한다. 이전 모델의 기준형상 잔차도 이전 모델 하나씩 더 제외한 안쪽 분할로만 만든다.
- 대상 모델에서 선택할 기준 측정은 기존 `select_probes(..., 'medoids', seed=42)`의 **GPU 1개·CPU affinity 2코어, 8개 작업 조건**과 동일하다. 동일 작업과 실측 `GPU 개수 × wall_seconds`를 모든 학습 방법에 적용한다. 미측정 대상의 정답·SLO 결과·GPU2 결과는 학습이나 방법 선택에 사용하지 않는다.
- 주 캠페인의 공유 encoder 8모델, 정렬 donor가 없는 Qwen fallback, BERT4 및 BERT+DistilBERT5 계열 공동 제외, 같은 모델의 `novel-matrix`·`space-filling` 새 입력 조건을 **분리**해 보고한다. 새 입력 조건의 기준 측정은 0회다. 절대 성능 및 자원 반응 예측기는 기존 코드와 동일하게 둔다.

## 한 가지만 바꿀 후보

정렬된 donor `m`의 기준형상 로그 잔차를 조건 `i`, 지표 `o∈{latency,rps}` 순으로 `R_m[i,o]`라고 한다. 원 방식의 각 지표 내 prior를 정확히 보존하면서 교차 지표 블록만 추가한다.

1. 경험 prior는 `K_emp = mean_m vec(R_m) vec(R_m)^T`로 정의한다. 평균은 0으로 둔다. 모델당 donor 표면을 공통 작업 좌표에 정렬하고, 같은 작업 donor가 2개 미만이면 부드러운 kernel만 쓴다.
2. 부드러운 prior는 기존 작업좌표 kernel `0.4 + 0.6 exp(-d²/2)`와 donor 전체의 두 지표 로그 잔차 2×2 이차 모멘트 `C_output`의 Kronecker 곱이다. 대각 분산은 기존 코드와 같이 각 지표별 `max(mean(residual²),0.02²)`다. 비대각은 donor의 `mean(residual_latency×residual_rps)`이고 2×2 행렬이 양의 준정부호인지 검사한다. 전체 prior는 `0.5 K_emp + 0.5 K_smooth`다.
3. 두 지표의 8개 관측 잔차, 총 16개를 동시에 조건화한다. 관측 블록에는 각 지표의 평균 prior 분산 × `0.05`를 해당 지표 대각 잡음으로 더한다. 수치해를 구한 뒤 관측된 8×2 위치는 실제 잔차로 덮어쓴다. 정렬 donor가 없는 Qwen은 기존 커널 fallback과 **정확히 같은 단일 지표 예측**을 기본으로 한다. Qwen에 교차 prior를 적용한다면 별도 보조 결과로만 둔다.
4. 절제 대조군은 동일 joint prior에서 교차 지표 블록만 0으로 만든 것이다. 그 출력은 기존 `residual_covariance`와 `posterior_residual`의 독립 지표 예측과 `1e-10` 이내로 일치해야 한다. 일치하지 않으면 점수를 산출하지 않는다. 추가 대조군은 기존 부드러운 kernel, 직접 Ridge, 전역 평균 보정, zero-shot이다.

## 결과와 중단 기준

모델별·캠페인별로 미측정 형상의 지연·요청/초 평균 절대 로그오차(MALE), 생성 SLO의 성공 선택·실측 위반·가능하지만 보류, 실제 최소 `(GPU 수, CPU affinity)` 일치를 기록한다. 처리량은 `examples_per_second / batch_size`다. 별도 [합성 SLO 25개 그리드](counterfactual_slo_findings.md)를 재사용하면 같은 작업에서 반복한 관련 질의로 표시하고 모델/작업군별로 집계한다. 전체 평균 외에 대상 모델별 악화도 반드시 제시한다.

공동 방법의 **실용적 채택 후보**는 같은 프로브 예산에서 공유 격자의 두 MALE가 모두 독립 지표 방식보다 낮고, 새 입력 조건 두 캠페인의 처리량 악화가 사라지며, 계열 공동 제외의 지연·처리량과 잘못 승인 수를 악화시키지 않을 때만 검토한다. 어느 조건이든 실패하면 이 공동 전이 가설은 미채택하고 결과를 그대로 남긴다. 지금 자료는 한 호스트·소수 encoder·생성 배치 SLO이며, 이 조건을 통과해도 새 앱·VM·실사용 SLO의 독립 검증이나 학술적 최초성은 입증되지 않는다.

구현 전 검사: joint prior의 대칭·양의 준정부호, 대각 블록 기존 방식 일치, 교차 블록 제거 시 예측 일치, 모델/계열 분할 누수 없음, 미측정 결과 교란 불변성, 같은 8개 프로브와 GPU-wall 비용. 점수와 모델 파일은 기존 산출물을 덮어쓰지 않는다.
