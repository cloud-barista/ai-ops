# 기존 반복 측정에서의 희소 프로파일 전이 검증

## 질문과 분리 방법

주 캠페인에서 성능이 좋았던 모델 간 잔차 공분산 전이가, 나중에 수집한 **새 입력 조건**에도 도움이 되는지 확인했다. 추가 측정은 하지 않았다. 같은 `icns` 호스트, RTX PRO 5000 Blackwell, 수집기 `khu-hf-direct-collector/v2`의 `khu-hf-live` GPU 기록을 사용했다. live에는 **모델 8종, 작업 조건 10개, 자원 셀 16개**가 있고 각 셀은 47회 반복됐다. 주 캠페인과 일치하는 작업 조건은 없다.

각 모델을 하나씩 제외하고 다른 모델의 주 캠페인 데이터로 절대 성능 모델, 자원 응답 모델, 잔차 사전분포를 학습했다. 제외한 모델에서는 주 캠페인의 GPU 1개·CPU 2코어 작업 8개를 정적 medoid로 골라 그 결과만 관측했다. live 결과는 학습·프로브 선택에 넣지 않았으며, **47회 측정의 셀별 중앙값을 평가에만 사용**했다. 따라서 752개 실행을 독립적인 752개 작업으로 세지 않았다. 8개 앵커의 실제 GPU 실행 시간은 모델당 평균 7.48초다.

기존 [공분산 전이 구현](../scripts/cross_model_covariance_external.py)과 같은 예측기를 사용했다. 비교한 방법은 공분산 보간, 매끄러운 커널, Ridge 잔차 전이, 그리고 앵커를 쓰지 않는 절대 성능 모델이다. 모두 같은 live 정적 조건을 받는다. 공분산·커널·Ridge는 같은 8개 주 캠페인 앵커를 쓴다. causal LM을 제외하면 같은 작업 종류의 공여 모델이 있어 공분산 보간을 적용했다. causal LM에는 같은 작업 공여 모델이 없어 커널 fallback이 적용됐다.

## 반복 측정 중앙값의 예측 오차

절대 로그 오차의 16개 셀 평균이다. 처리량은 `examples_per_second / batch_size`로 계산한 초당 요청 수다. GPU 2개는 6개 작업에서만 측정됐다.

| 방법 | 배치 p95 지연 오차 | 요청 처리량 오차 | GPU 1개 지연 / 처리량 | GPU 2개 지연 / 처리량 |
| --- | ---: | ---: | ---: | ---: |
| 모델 간 잔차 공분산 | 0.2275 | 0.2683 | 0.2159 / 0.2876 | 0.2468 / 0.2362 |
| 매끄러운 커널 | 0.2292 | 0.2681 | 0.2214 / 0.2802 | 0.2423 / 0.2479 |
| Ridge 잔차 전이 | 0.2628 | **0.2425** | 0.2375 / 0.2507 | 0.3050 / 0.2288 |
| 앵커 없는 절대 성능 모델 | 0.6652 | 0.5834 | 0.7233 / 0.7019 | 0.5683 / 0.3860 |

공분산과 커널은 거의 같다. 공분산의 지연 이득은 **0.0018 로그 단위**이고 처리량은 **0.0003 로그 단위 더 나쁘다**. 모델별 평균을 동일하게 가중하면 커널이 지연·처리량에서 모두 약간 더 좋다. 공분산 사전분포가 live의 새 조건까지 우월하게 전이된다는 근거는 없다. 8개 앵커를 쓴 세 방식은 앵커 없는 절대 모델보다 오차가 작지만, 그 이득이 공분산 고유의 이득은 아니다.

## 제한된 GPU 선택 결과

GPU 1개와 2개가 모두 측정된 **6개 작업**에서만 기존 기록의 생성 SLO를 적용해 가장 적은 GPU를 고르게 했다. 4개 작업은 두 선택지 중 하나가 실제로 SLO를 만족했고, 2개는 둘 다 만족하지 않았다. 각 자원 셀의 47회 반복에서 SLO 충족 여부는 모두 동일했다. 단, 이는 운영 사용자가 제시한 SLO가 아니다.

| 방법 | 선택한 작업 | 실제 충족 | 잘못 충족 판단 | 가능한 작업을 놓침 | 최소 GPU 정확 선택 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 공분산 / 커널 / Ridge 각각 | 4 | 3 | 1 | 1 | 3 |
| 앵커 없는 절대 성능 모델 | 4 | 4 | 0 | 0 | 4 |

세 잔차 전이 방법의 실패 작업도 같다. BERT base의 GPU 2개 충족을 놓쳤고, ELECTRA의 실제 불충족 GPU 2개를 충족으로 판단했다. 6개 작업이라 통계적 우열을 주장할 수는 없지만, **예측 오차 감소가 이 데이터의 배포 선택 개선으로 이어지지 않았다.** 실제 가격, VM 형상, 사용자 요청 지연은 측정하지 않았다.

## 해석

이 평가는 기존 SQLite에서 확보 가능한 추가 시간·입력 조건 검증이다. 주 학습 데이터와 모델, 호스트, GPU, 수집기는 공유하므로 새 모델·호스트 일반화 시험은 아니다. 10개 live 작업은 선택 과정에서 사용한 자료였을 가능성도 있어 사전 등록된 확증 실험으로 볼 수 없다. 특히 GPU 선택은 6개 쌍뿐이다.

현재 증거에서는 모델 간 공분산 전이를 **새로운 범용 추천 알고리즘의 검증된 성과로 주장하지 않는 것**이 맞다. 모델별 희소 프로파일 자체는 새 조건에서 절대 성능 모델의 오차를 줄였지만, 이 자료의 실제 배포 의사결정 이득과 학술적 고유성은 입증되지 않았다.
