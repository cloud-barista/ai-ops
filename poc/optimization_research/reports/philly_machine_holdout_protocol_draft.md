# Philly GPU 위험 예측: 미관측 기계 홀드아웃 평가 규약 초안

**상태: DRAFT, 2026-09-28 13:28 UTC.** 이 문서는 새 기계의 GPU 값·미래 정답·예측 점수를 열기 전에 작성했다. 구현과 입력·모델 해시를 확인해 별도 `FROZEN` 기록을 남기기 전에는 확인 평가를 실행하지 않는다. 이미 공개한 [기존 평가](philly_gpu_risk_findings.md)의 시험 결과를 본 뒤 설계한 **후속 확인 실험**이므로, 최초 실험의 사전 등록으로 소급해 부르지 않는다.

## 검증 질문과 독립성의 범위

기존 Philly 평가에서 완전 관측·현재 GPU 사용률 80% 미만층의 **단일 통합 로지스틱**은 상태별 모델보다 Brier가 조금 낮았다. 이번 질문은 그 **이미 선택한 통합 모델**이, 학습·검증·기존 시험에 한 번도 들어가지 않은 `machineId`의 GPU 슬롯에서도, 기존 검증 기간에 선택한 강한 단순 확률표보다 향후 30분의 80% 이상 사용률 사건을 더 정확히 예측하는가이다. 모델·기준선·임계값·특징·시간 분할은 새 기계에서 다시 선택하지 않는다.

독립성은 **원시 `machineId`의 비중복**을 뜻한다. 같은 2017년 Philly 클러스터와 같은 시험 날짜를 공유하므로 클러스터·시기·사업자 외삽이 아니다. 공개 원본에 물리 장비의 ID 재사용 또는 교체를 확인할 연결 키가 없다면 물리 서버까지 독립이라고 단정하지 않는다. 정답은 GPU 슬롯의 5분 평균 사용률 사건이며 사용자 지연 SLO, 자원 부족의 원인, `SCALE_OUT/IN` 정답 또는 VM 조정 효과가 아니다.

| 항목 | 새 기계 홀드아웃 규칙 |
| --- | --- |

| 기존 표본 | `int.from_bytes(SHA256(machineId UTF-8), "big") % 100 < 5`인 21개 기계. [동결된 기존 규약](philly_gpu_risk_protocol_frozen.md)·정규화 자료·모델 학습에만 사용 |
| **새 홀드아웃** | 같은 해시 정수의 나머지가 **`5 ≤ r < 15`**인 원시 GPU CSV 기계의 **모든 분 행**. 기계 수·활동 기간·GPU 값과 무관하게 먼저 선택. `r<5`와 교집합은 비어야 함 |
| 시험 판단 | UTC `[2017-12-01 00:00, 2017-12-16 00:00)`, 각 판단의 `d+2100초 ≤ 2017-12-16 00:00` |
| 판단 특징·정답 | [기존 규약](philly_gpu_risk_protocol_draft.md)의 첫 원시행 슬롯 폭, 5분 창, `d=t+600초`, 과거 세 창, 미래 여섯 창, 완전 관측/부분결측, 현재 정상/초과 정의를 **그대로** 적용 |

원본은 압축본 전체 SHA256·tar 멤버 무결성 검사를 마친 뒤에만 파생본으로 승격한다. 새 기계 행의 `source_row_index`, 원문 시각·PDT/PST, 원문 비8열 JSON, GPU `NA`를 보존한다. 모든 원시 GPU CSV 행을 검사하고 위 해시 구간의 행이 빠짐없이 들어왔는지 원본 스캔 수와 파생본 수·행순서로 검증한다. 첫 원시 행으로 기대 GPU 슬롯 폭 2/4/8을 고정하며 `machine_list`의 GPU 개수, 관측 후 최빈 폭, 미래 자료로 폭을 고치지 않는다. 폭 불일치 행은 전 슬롯 무효로 둔다. 기존 21기계와 새 기계의 **원시 ID 및 SHA256 ID 교집합이 0**이고, 새 파생본의 모든 기계가 `5≤r<15`임을 검사한다.

새 기계의 12월 이전 분 행은 원시 계측 품질 감사와 12월 1일 직전 입력 창을 완성하는 데에만 쓸 수 있다. 새 기계의 10–11월 미래 정답은 **생성하지 않고**, 해당 기간의 사용률 요약·모델 선택 결과도 학습, 대체, 표준화, Beta 확률표, 재보정에 **사용하지 않는다**. 새 기계의 시험 정답은 게이트 집계와 마지막 한 번의 점수 계산에만 쓴다.

## 새 값을 열기 전에 잠글 모델과 비교

1. 기존 정규화 표본 (`../data/external/msr_philly_2017/gpu_util_normalized_first_width.parquet`) SHA256 `15f1af4669acb9823d0e6d96291e799cf33f8a9c1813d4faf51b0b9eb618ad58`, [후보 생성 코드](../scripts/prepare_philly_gpu_risk_candidates.py) SHA256 `e89fd8a48c8491d02194540fc362a1d50f264f589a60e52e6c3dfd3fdc25d795`, [학습 코드](../scripts/philly_risk_models.py) SHA256 `27eee299b7b4a30844712200e85696719aea116699711e4620a12672dfed5606`, [지표 코드](../scripts/philly_risk_metrics.py) SHA256 `bc9bf2dfbd78e9e88405fe531d9163402c19309d2eaa05f0e994e1aaba81de72`을 고정한다. [기존 결과 JSON](../artifacts/philly_gpu_risk_v1/metrics.json)과 시험 예측 Parquet SHA256 `04ce609b36c468cfbec021c3a4900a3a08cc818b9f6c3cf95a0efc8f58bd5d4f`도 입력 증거로 잠근다.
2. **기존 21기계만** 사용해 원래 시간 분할의 학습 `[2017-10-04, 2017-11-16)`에서 pooled-quality L2 로지스틱을 다시 맞추고, 기존 검증 `[2017-11-16, 2017-12-01)`의 Brier로만 `C∈{0.1,1,10}`을 고른다. 원래 결과의 pooled `C=10`, 과거값 학습 중앙값 `[49.8783333333, 49.8733333334]`와 일치해야 한다. 원래 `StandardScaler` 평균·분산과 계수·절편을 출력 해시가 있는 **모델 명세**로 저장한다. 검증 또는 새 홀드아웃으로 재학습하지 않는다.
3. **기존 21기계의 완전 과거 학습행만** 사용해 [기존 Beta(1,1) 확률표](../scripts/philly_risk_models.py)의 `state_recent=(current_high, any_recent_high)` 표를 다시 만든다. 이것은 기존 검증의 현재 정상층에서 다섯 표 중 선택된 기준선이다. 새 홀드아웃에서 다른 표를 선택하거나 표의 사건률을 다시 계산하지 않는다. 빈 집단은 기존 규칙의 1/2이다. 원래 시험 예측의 `pooled_quality`·`selected_beta`와 재구성 모델이 같은 키에서 `1e-10` 이내로 일치해야 새 기계 채점에 들어간다. 기존 시험 예측은 **재현 검증**에만 쓴다.
4. 모델 명세에는 학습·검증 행수, 선택 `C`, 특징 순서, 두 과거 중앙값, 표준화 모수, 회귀 계수·절편, Beta 키·확률, 각 코드·원본·기존 결과 해시와 UTC 생성 시각을 기록한다. **새 기계 GPU 값이나 정답을 열기 전에** 이 명세와 홀드아웃 수집·정규화·후보·평가 코드의 SHA256 및 본 초안의 최종 SHA256을 별도 동결 기록에 남긴다. 기존 시험을 본 뒤 풀링 모델을 고른 사실도 동결 기록에 남긴다.

## 점수 전 품질·표본 게이트

새 자료의 집계는 **모델 확률이나 시험 Brier를 계산하기 전에** 별도 `dry_run` 감사 JSON으로 저장하고 SHA256을 고정한다. 후보 특징과 미래 관측 여부·정답은 분리해 저장하며 행별 정답은 `dry_run` 산출물에 싣지 않는다. 시험 예측기는 원본 정규화 자료에서 후보·미래 관측성의 **키·값·순서**를 재생성해 저장본과 대조해야 한다. 다음 게이트는 결과를 본 뒤 완화하지 않는다.

| 게이트 | 사전 기준 |
| --- | --- |
| 원본·표본 | 위 압축본 해시·크기·tar 무결성 통과, 해시 버킷 범위 정확, 기존 기계와 교집합 0, 원본 선택행과 파생본 행수·순서 일치. 실패하면 모든 점수 중단 |
| 기계 원시 폭 | 첫 행 2/4/8 슬롯 형식이 아니거나 **그 기계의 기대 폭 불일치 원시행 비율 >1%**면 해당 기계 전체를 점수에서 제외하고 이유·행수를 공개. 제외 전·후의 기계 수·원시행 수·12월 활동 기계 수를 공개 |

미래 창이 하나라도 무효인 후보는 정답 미관측이며 음성으로 대체하지 않는다. 새 기계의 현재 80% 이상·완전 과거층은 새 시험 게이트와 기존 학습·검증 게이트가 모두 통과할 때에만 **보조 점수**를 낸다. 기존 부분결측층은 원래 학습·검증·시험 게이트가 실패했고 검증 선택 기준선이 없으므로, 새 홀드아웃에서 적격 후보가 생기더라도 **후보·관측률·양성 집계만 보고하고 확률 점수는 계산하지 않는다**. 그 성과를 주 결과에 합치지 않는다. 모든 층에서 후보 대비 정답 관측률과 사용 가능한 기계·날짜·슬롯 분포를 보고한다. 점수 대상에서 빠진 기계를 조용히 제거하거나, 기계 수를 GPU 슬롯 수로 대체하지 않는다.

## 고정 성공 판정과 보고

**주 시험층은 새 기계의 완전 과거·현재 80% 미만 행**이다. 정확히 같은 적격행에 대해 `pooled_quality`와 **기존 검증 선택 `state_recent` Beta**의 Brier를 계산한다. Δ는 `Brier(pooled) − Brier(Beta)`로 두어 음수가 개선이다. 성공은 아래 조건을 **모두** 만족할 때만 선언한다.

1. `1 − Brier(pooled)/Brier(Beta) ≥ 0.05`이고 전체 Δ<0.
2. 동일 기계를 단위로 **짝지어 2,000회 재표집, 시드 43**으로 구한 행 가중 Δ의 95% 백분위 구간 **상한 <0**. 행·GPU 슬롯·겹친 시간창을 독립 표본으로 재표집하지 않는다.
3. 고정된 두 시험 달력 반구간의 Brier가 각각 Beta보다 낮고, 기계별 Brier 차를 동일 기계 가중으로 평균한 값도 <0. 긴 관측 기간이나 슬롯 수가 많은 일부 기계의 영향은 기계별 차·행수와 함께 공개한다.
4. 전체 AP와 **각 UTC 날짜에서 확률 상위 `ceil(0.05×그날 적격행 수)`를 합친 경보 recall**이 Beta보다 낮지 않다. 확률 동률은 기존 `SHA256(machine_hash:gpu_index:decision_utc_s)` 오름차순 규칙을 그대로 따른다.

행 가중 Brier·AP·경보 precision/recall, 기계 동일 가중 평균 Brier 차, UTC 날짜별·기계별 결과, 두 반구간과 기계 재표집 구간을 **성공 여부와 관계없이** 보고한다. 모든 기존 Beta 표의 새 기계 점수도 민감도 자료로 나열할 수 있지만, 새 홀드아웃에서 가장 좋은 표를 골라 주 기준선을 바꾸지 않는다. 현재 초과층의 지속 위험과 부분결측층의 관측 품질 효과는 별도 탐색 결과로 제한한다. 부분결측 시험 표본이 충분하지 않으면 품질 마스크의 이득을 다시 주장하지 않는다.

성공해도 결론은 **같은 Philly 클러스터·2017년 12월의 다른 식별 기계에서 GPU 고사용률 위험 확률이 단순 표보다 정확했다**는 범위다. 실패하거나 게이트가 미달하면 그 결과와 실패 이유를 그대로 보존한다. 이후 모델을 고쳐 다시 시험한다면 이 홀드아웃을 개발·탐색 자료로 재분류하고 **새로운 미사용 기계나 기간**을 다음 확인 평가용으로 정해야 한다.
