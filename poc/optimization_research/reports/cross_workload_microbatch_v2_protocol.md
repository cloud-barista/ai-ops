# 서로 다른 작업 조건 묶음 추론의 중복 검증 제거 규약

2026-09-29. [v1 결과](cross_workload_microbatch_findings.md)와 45격자 탐색 프로파일을 이미 본 뒤 세운 **소프트웨어 최적화 실험**이다. 이 데이터에 관한 독립 시험이나 새 학습 모델 평가로 해석하지 않는다. 저장 성능 모델·원본 측정·v1 평가 함수는 고정한다.

## 변경 가설

v1은 1,125개 SLO 질의를 먼저 검사해 45개 후보 격자를 모으고, 각 결과를 만들 때 같은 질의를 다시 검사한다. 지원되지 않은 후보의 사유 목록을 결과끼리 공유하지 않기 위해 원시 예측 전체도 질의마다 깊게 복사한다. 각 질의의 검사 결과와 후보 격자 키를 한 호출 안에서 재사용하고, 결과에 노출되는 가변 사유 목록만 새로 만들면 같은 JSON을 더 적은 CPU 시간에 계산할 수 있다.

## 고정 비교와 게이트

- 비교 대상은 현재 `assess_gpu_shape_microbatch(..., max_grids=8)`과 새 경로다. 둘 다 같은 저장 모델의 한 worker를 사용하고, 모델·Parquet 읽기와 첫 예열은 타이머 밖에 둔다. 고정 [45격자 manifest](../artifacts/slo_reuse_v1/manifest.json)의 9모델×5조건×25합성 SLO를 한 호출에 넣는다. 묶음 크기는 v1 사전 선택값 **8**로 고정한다.
- 575개 주 캠페인 격자의 최종 JSON과 45격자·1,125질의의 원시 후보/최종 JSON이 완전히 같아야 한다. 잘못된 입력, 지원 범위 밖 후보, 중복 질의, 후보 순서 변경, 합친 예측 호출 예외에서 8후보별 재시도도 동등해야 한다. 결과 하나의 사유 목록을 호출자가 수정해도 다른 결과는 바뀌지 않아야 한다.
- 두 경로를 같은 프로세스에서 각각 예열한 뒤, 고정 난수로 순서를 바꿔 5쌍 측정한다. 전체 1,125질의 함수 시간의 중앙값을 보고한다. 새 경로가 v1보다 **1.20배 이상 빠르고**, 출력 동등성·실패 경계가 모두 통과할 때 연구용 구현으로 남긴다. 이 속도는 사용자 요청 지연이나 VM 배포시간이 아니다.

이 규약은 v1의 사전 선택·평가 게이트를 대체하지 않는다. 9모델 모두 저장 성능 모델의 학습에 들어갔고 이 코드 변경에는 신규 모델 정확도 검증이 없다.
