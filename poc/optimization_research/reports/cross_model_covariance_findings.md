# 이전 모델의 오차 공분산을 이용한 소수 측정 전이: 탐색 실험

## 검증한 질문

새 AI 모델의 GPU 1개·CPU 2코어 성능을 4·8·16개 작업 조건에서만 측정했을 때, **이전 모델에서 함께 변하던 예측 오차의 패턴**으로 나머지 작업 조건과 자원 형상의 성능을 더 잘 추정할 수 있는가?

이는 현재 데이터에서 새로운 방법의 한 요소가 도움이 되는지 확인한 탐색 결과다. 선행연구 대비 최초성이나 다른 GPU·VM에서의 효과를 입증한 결과는 아니다.

**문헌상 경계:** 과거 작업의 공분산이나 공통 사전분포를 이용해 새 작업의 소수 관측을 전이하는 원리 자체는 이미 연구되었다. [Bonilla 등의 multi-task Gaussian process(2007)](https://papers.nips.cc/paper_files/paper/2007/hash/66368270ffd51418ec58bd793f2d9b1b-Abstract.html)는 입력과 작업 사이의 공분산을 모델링했고, [MAGMA(2022)](https://link.springer.com/article/10.1007/s10994-022-06172-1)는 공통 평균을 통한 작업 간 전이와 불규칙한 관측 그리드를 다뤘다. [Empirical Gaussian Processes(2026)](https://arxiv.org/html/2602.12082)는 이전 작업의 경험적 공분산으로 새 작업의 부분 관측을 조건화하고 새로운 입력 위치로 보간한다. 따라서 **경험적 오차 공분산과 소수 관측의 조건화 자체를 신규 원리로 주장할 수 없다.** 여기서 시험한 대상은 자원 성능 모델의 *모델 단위 교차검증 잔차*를 이전 모델에서 추출해 적은 GPU 앵커 측정과 결합하고, 여러 자원 형상 및 SLO 선택까지 평가하는 구체적인 구성이다.

## 방법과 정보 경계

1. 바깥 분할에서 모델 ID 하나를 완전히 제외한다. 나머지 모델로 절대 지연시간·요청/초 모델과, 앵커 값에 조건화된 자원 반응 모델을 학습한다.
2. 학습 모델 각각의 앵커 예측 오차는 그 모델을 다시 제외한 **안쪽 모델 단위 교차 검증**으로 구한다. 같은 작업 조건을 공유하는 이전 모델의 오차 벡터로 공분산을 만들고, 50%의 부드러운 커널 공분산과 섞는다.
3. 새 모델에서 측정할 작업은 정적 작업 좌표의 공간을 고르게 덮도록 고른다. 별도로 공분산을 최대한 줄이는 프로브 선택도 시험했다. 측정된 `k`개 앵커의 오차를 조건부 공분산으로 나머지 작업에 전이한다.
4. 추정한 앵커 성능을 이미 학습한 자원 반응 모델에 넣어 각 작업의 8개 자원 형상을 예측한다. 측정되지 않은 새 모델의 성능 결과는 입력에 들어가지 않는다.

구현의 경험적 행렬은 `K = 평균_m(r_m r_mᵀ)`인 **비중심 2차 모멘트**다. 평균 0인 잔차 prior의 공분산으로 사용하지만, 실제 donor 잔차의 평균이 0이 아니라면 공통 오차 방향의 외적도 들어간다. 따라서 현재 개선을 순수한 조건 간 공분산 효과라고 분리해 해석할 수 없다. 중심화 공분산과 donor 평균 표면을 나눈 추가 실험이 필요하다.

8개 encoder 모델은 동일한 64개 작업 조건을 공유한다. Qwen은 63개의 다른 causal-LM 조건만 있어 정렬되는 같은 작업의 이전 모델이 없다. Qwen은 공분산 전이 없이 커널만 쓰는 fallback으로 따로 집계했다. 모델 크기는 등록 시 알 수 있는 정적 메타데이터라고 가정했고, 고정된 DB의 JSON에서 크기 필드만 읽었다. 새 작업 조건을 예측할 때는 주 캠페인에서 확인한 모델 크기를 전달하여 미측정 외부 행의 결과 JSON을 읽지 않았다.

모든 방법은 해당 모델의 **모든 작업 조건에서 앵커를 제외한 7개 자원 형상**에 대해 오차를 평가했다. SLO 선택은 8개 형상 전체에서 동일한 관측 결과와 동일한 oracle 분모를 사용한다. 요청 처리량은 `examples_per_second / batch_size`다. GPU 측정 비용은 `GPU 개수 × wall_seconds`이며 `wall_seconds`가 모델 로딩 시간을 이미 포함하므로 로딩 시간을 다시 더하지 않았다.

## 핵심 결과: 모델당 앵커 8개 측정

아래 오차는 모델별 평균 절대 로그오차(MALE)의 평균이다. 괄호의 SLO 성공은 oracle이 실제로 가능한 작업 수를 분모로 한다. 모든 공간 선택 방법은 **같은 8개 작업을 측정했으므로 측정 비용이 같다.**

| 데이터 | 방법 | 지연 MALE | 요청/초 MALE | SLO 성공 | SLO 위반 | 모델당 평균 GPU-wall |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 공유 그리드 encoder 8개 | 공간 선택 + 이전 모델 오차 공분산 | **0.235** | **0.119** | **298/309** | **13** | 5.76초 |
| 공유 그리드 encoder 8개 | 공간 선택 + 부드러운 커널만 | 0.247 | 0.135 | 290/309 | 17 | 5.76초 |
| 공유 그리드 encoder 8개 | 공간 선택 + ridge | 0.251 | 0.142 | 292/309 | 15 | 5.76초 |
| 공유 그리드 encoder 8개 | 공간 선택 + 전체 평균 오차 | 0.296 | 0.228 | 286/309 | 17 | 5.76초 |
| 공유 그리드 encoder 8개 | 공분산으로 프로브 선택 + 공분산 전이 | 0.249 | 0.123 | 293/309 | 11 | 7.42초 |
| Qwen 1개, 정렬 donor 없음 | 공간 선택 + 커널 fallback | 0.262 | 0.188 | 40/48 | 5 | 16.54초 |
| 전체 9개 | 공간 선택 + 오차 공분산 또는 fallback | 0.238 | 0.127 | 338/357 | 18 | 6.96초 |

공유 그리드에서 같은 공간 프로브를 쓴 경우, 이전 모델의 경험적 오차 공분산은 커널만 사용한 방법보다 지연 MALE이 모델 평균 **0.0118** 낮고 요청/초 MALE이 **0.0160** 낮았다. 8개 모델 중 개선된 모델은 각각 6개와 7개였다. 모델을 재표본추출한 95% 기술적 구간은 지연 **[0.0029, 0.0239]**, 요청/초 **[0.0022, 0.0338]**이었다. SLO 성공은 총 8개 더 많았다. Ridge 대비 개선은 각각 **0.0157 [0.0043, 0.0280]**, **0.0229 [0.0093, 0.0389]**이며 SLO 성공은 총 6개 더 많았다. 이 구간은 방법을 탐색한 뒤 같은 데이터에서 계산했으므로 확증적 신뢰구간으로 해석하면 안 된다.

이 평균 개선은 균등하지 않다. `google/bert_uncased_L-4_H-256_A-4` 한 모델이 커널 대비 지연 오차 개선 합계의 약 50%, 처리량 개선 합계의 약 55%를 차지한다. 이 모델의 새 작업 조건에서는 처리량 오차가 공분산 보간으로 오히려 커진다. 모델별 이질성은 이후 자료에서 검증할 핵심 위험이다.

**공분산에 따른 프로브 선택은 채택할 근거가 약하다.** 공유 그리드에서 k=8일 때 공간 선택보다 지연·요청/초 MALE과 SLO 성공이 모두 나빴고 실제 GPU-wall도 더 들었다. 따라서 이 데이터에서 유용했던 부분은 *프로브 선택*보다 *측정한 오차를 이전 모델의 공분산으로 전이하는 부분*이다.

## 새로운 작업 조건 평가: 처리량 개선은 재현되지 않음

같은 모델의 이전에 보지 않은 두 캠페인(`local-novel-matrix`, `local-space-filling`)을 별도로 평가했다. 모델별 주 캠페인에서 고른 **동일한 앵커 8개만 측정**했으며, 새 작업 조건에서는 성능을 한 번도 측정하지 않은 채 예측했다. 학습에는 제외 모델을 뺀 이전 모델의 주 캠페인만 사용했다. 이전 모델의 오차 표면을 작업 좌표에서 커널로 보간한 뒤 공분산을 만들었다. 새 작업 조건은 주 캠페인의 조건과 겹치지 않는다.

| 공유 그리드 encoder 8개 | 방법 | 지연 MALE | 요청/초 MALE | SLO 성공 | SLO 위반 |
| --- | --- | ---: | ---: | ---: | ---: |
| Novel matrix, 16개 작업 | 경험적 공분산 보간 | **0.320** | 0.379 | 11/11 | 0 |
| Novel matrix, 16개 작업 | 커널만 | 0.346 | 0.361 | 11/11 | 0 |
| Novel matrix, 16개 작업 | Ridge | 0.342 | **0.348** | 11/11 | 0 |
| Space filling, 40개 작업 | 경험적 공분산 보간 | 0.369 | 0.352 | 27/29 | 1 |
| Space filling, 40개 작업 | 커널만 | **0.350** | 0.324 | 26/29 | 1 |
| Space filling, 40개 작업 | Ridge | 0.402 | **0.314** | 26/29 | 1 |

**새 작업 조건에서 요청/초 예측은 공분산 보간이 커널과 ridge보다 두 캠페인 모두 나빴다.** Novel matrix의 지연은 공분산 보간이 더 좋았지만, space filling의 지연도 커널보다 나빴다. Space filling에서 SLO 성공이 한 건 많은 것만으로 오차 악화를 상쇄했다고 판단하기 어렵다. 따라서 현재 실험이 지지하는 효과는 *공유 그리드 안에서의 잔차 전이*에 한정된다. Qwen은 새 작업 조건에서도 같은 작업의 donor가 없어 커널 fallback만 적용되었다.

## 예산 변화와 남은 검증

공유 그리드 8개 모델에서 공간 선택 + 오차 공분산의 지연/요청 MALE 및 SLO 성공은 다음과 같다.

| 앵커 예산 | 지연 MALE | 요청/초 MALE | SLO 성공/309 | 평균 GPU-wall |
| ---: | ---: | ---: | ---: | ---: |
| 4 | 0.260 | 0.128 | 296 | 3.00초 |
| 8 | 0.235 | 0.119 | 298 | 5.76초 |
| 16 | 0.233 | 0.103 | 300 | 12.68초 |
| 모든 64개 측정 | 0.226 | 0.091 | 300 | 50.18초 |

이 실험은 한 호스트와 한 GPU 종류의 8개 encoder 모델에 경험적 공분산 효과가 집중된다. Qwen 한 모델은 커널 fallback의 사례일 뿐이며, 다른 작업 종류로 공분산이 전이된다는 증거가 아니다. 새 입력 조건 평가에서 처리량 악화가 나타나므로, 현재 방법을 범용 추천 알고리즘의 검증된 개선으로 제시하면 안 된다. 수집 과정에서 만든 SLO는 독립적인 사용자 요구 분포가 아니다. 새 GPU·VM, 다른 응용 종류, 실제 사용자 SLO, 여러 번 반복한 측정으로 미리 정한 방법을 다시 검증해야 연구 기여 범위가 분명해진다. 정적 모델 크기를 등록 단계에서 얻지 못하는 경우의 성능도 별도 확인이 필요하다.
