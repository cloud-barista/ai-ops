# Alibaba MaaS SM 관측 상태 연구: 학습 전 지원량 감사

상태: **지원량 통과, 모델 점수 없음, 새 ID 시험 자료 미추출.** [사전 규약](maas_sm_observability_protocol_v1.md)의 `bucket 0` 개발 구간만 읽었다. 감사 결과는 [기계 판독 JSON](../artifacts/maas_sm_observability_v1/feasibility.json)에 있으며 [재현 코드](../scripts/audit_maas_sm_observability_support.py)는 원본 compact SHA256과 21조각 감사 메타데이터를 먼저 검증한다. 다른 연구의 기존 시험 산출물을 이 실험의 점수로 재사용하지 않는다.

| 단계 | 현재 정상 후보 | H: 유효한 SM≥80 관측 | N: 여섯 창 정상 | U: 미해결 | H ID / U ID | 단일 ID 최대 H / U |
|---|---:|---:|---:|---:|---:|---:|
| 학습 140–142일 | 365,239 | 7,199 | 266,203 | 91,837 | 2,595 / 17,465 | 3.74% / 0.50% |
| 보정 143일 | 113,632 | 2,848 | 81,818 | 28,966 | 895 / 5,235 | 3.23% / 0.51% |
| 검증 144일 | 119,703 | 4,186 | 87,379 | 28,138 | 972 / 4,976 | 3.27% / 0.49% |

검증일 6시간 블록 네 개에서 H는 각각 779, 1,194, 1,168, 1,045건이고 U는 7,384, 8,098, 7,033, 5,623건이다. 단계별 후보·클래스·ID 수와 단일 ID 비중은 규약의 지원량 게이트를 통과했다. 학습 단계의 365,239건은 학습 종료시각까지 정답이 전달된 후보만 포함한다. 기존 140–143일 통합 집계의 140–142일 행을 그대로 합산하지 않았다.

U에 임의의 이진 정답을 형식적으로 부여할 경우 가능한 **표본 비율**은 학습 `[1.971%,27.115%]`, 보정 `[2.506%,27.997%]`, 검증 `[3.497%,27.004%]`다. U가 검증 후보의 23.5%이므로 확정 H/N 행만 골라 계산하는 이진 성능을 전체 후보 성능으로 간주할 수 없다. 이 구간은 가능한 기록 보충의 산술 범위이지 실제 할당 변경 뒤의 위험이나 정책 효과에 대한 경계가 아니다.

원본 [MaaS 공식 스키마](https://github.com/alibaba/clusterdata/blob/8a6295f9779ddc019add669eeca49c5f9f77b3a7/cluster-trace-v2026-maas/docs/schema.md)의 주간 값은 5분 평균이며 조각은 날짜별 분할이 아니다. 감사에서는 같은 ID·시각의 중복을 제외하고, 유효한 단일 미래 창의 초과만 H로 확정했다. `cluster_id` 결측은 개발 compact 140–144일에서 0건이지만 코드상 결측은 유효한 할당으로 취급하지 않는다. GPU 메모리 사용률은 원자료에 100% 초과값 53,533건이 있어 이번 SM-only 목표·입력에서 제외했다. 같은 주의 다른 ID에 대한 시험은 가능해도 새 시기·서비스·CSP 일반화 시험은 아니다.

원격 ZIP 4.812GB를 로컬에 보관하지 않았고, 새 ID bucket `1`의 145–146일 측정값이나 정답은 아직 읽지 않았다. 로컬 디스크 여유는 감사 시점 약 5.6GiB다. 따라서 다음 단계는 **bucket 0의 학습·보정·검증을 수행하고 규약의 개발 성능 게이트로 중단 여부를 결정**하는 것이다. 통과하더라도 평가 코드·모델·manifest 해시를 고정하고 독립 검토를 마친 뒤에만 bucket `1`을 읽는다.
