# 정적 배포 후보 판단의 2단계 추론 비용 실험 규약

2026-09-28. 이 규약은 시험 점수를 계산하기 전에 작성했다. 목표는 경희대의 8개 CPU/GPU 후보 점수화에서 **경량 모델의 결정이 충분히 멀리 떨어진 SLO 경계에 있을 때 강한 모델 호출을 생략**해, 실제 CPU 채점 시간을 줄이면서 정적 후보 선택 품질을 유지할 수 있는지 탐색하는 것이다. 2단계 추론 자체를 새 학술 원리로 주장하지 않는다.

## 자료와 정답

- 원본은 `/path/to/aiops/runs/khu-hf-local-exhaustive/executions.sqlite3`의 물리 실행이며, 읽기 전용으로 추출한 `poc/optimization_research/data/audit_v1/measurements.parquet` SHA-256 `b7bba7963e8a309b6a8502a1d98eefb150476b1381ec016beeb68cbf63fae906`를 사용한다. `campaign=khu-hf-local-exhaustive`, `eligible`, `device=cuda`인 4,600행은 9개 모델·575개 `workload_group`의 GPU 수 1/2 × CPU affinity 2/4/8/16, 정확히 8후보씩이다.
- 입력은 등록 시 모델 크기라고 가정하는 `result_json.model_parameter_bytes`, `batch_size`, `max_length`, `request_concurrency`, `repeats`, `workload_task`, `replica_count`, `cpu_core_limit`, 그리고 요청별 지연 상한 `L` 및 처리량 하한 `R`이다. 과거 결과 JSON에서 읽는 모델 크기가 실제 등록 입력으로 제공되지 않으면 같은 정책을 사용할 수 없다. 모델 ID, 후보의 관측 지연·처리량·GPU 사용률, 실행 후 계측은 예측 입력에서 제외한다.
- 관측 정답은 `latency_p95_ms <= L` 그리고 `examples_per_second / batch_size >= R`이다. GPU 수 다음 CPU affinity가 가장 작은 합격 후보를 정적 오라클로 둔다. 이 자료에는 실제 사용자 SLO·VM 가격·배포/스케일 명령 효과가 없다. GPU 2개는 동일 호스트의 두 복제 프로세스다.
- 각 외부 분할의 학습 모델에서만 지연·요청/초 분포의 10/25/50/75/90백분위를 구해 25개 `(L,R)` 쌍을 만든다. 같은 575개 작업의 25개 질의는 상관되므로 독립 사용자 요청으로 세지 않는다. 수집기 원래 SLO는 주 비교에 쓰지 않는다.

## 모델과 경계 규칙

1. 경량 모델은 수치 특징을 표준화한 Ridge 회귀로 두 로그 목표(`log(latency_p95_ms)`, `log(examples_per_second / batch_size)`)를 예측한다. 강한 모델은 기존 `cold_start_policy.py`와 같은 `ExtraTreesRegressor(n_estimators=200, min_samples_leaf=2, max_features=1.0, random_state=42, n_jobs=2)`이다. 직접 합격 `HistGradientBoostingClassifier`도 기존 설정의 별도 기준선으로 평가한다.
2. 로그 지연 여유 `a_i=log L-pred_log_latency_i`, 처리량 여유 `b_i=pred_log_rps_i-log R`로 각 후보의 예측 합격을 판정한다. GPU 수·CPU 코어 순서의 첫 합격 후보를 선택한다. 후보가 없으면 `ABSTAIN`한다. 외부 시험 질의 전체의 점수 순위나 사후 승인율로 온라인 cutoff를 정하지 않는다.
3. 경량 모델이 고른 첫 합격 후보의 두 여유와 그보다 싼 후보들의 실패 여유를 사용해, 각 예측에 같은 크기의 오차가 생겨도 첫 합격 후보가 바뀌지 않는 **결정 반경**을 계산한다. 합격 후보가 없으면 모든 후보의 실패 여유에서 반경을 정한다. 반경이 donor에서 선택한 `tau`보다 작으면 8행 전체를 강한 모델로 다시 채점한다. 작업 종류가 donor에 없거나 모델 크기가 donor 범위 밖이면 무조건 강한 모델을 호출한다. 이 지원 규칙은 강한 모델의 정확도 보장을 뜻하지 않는다.
4. `tau` 후보는 `{0, 0.02, 0.05, 0.10, 0.20, 0.40, 0.80, infinity}` 로그 단위로 고정한다. 외부 대상 모델 H를 제외한 donor에서 다시 D를 하나씩 제외해 두 회귀기를 적합하고 D의 합성 SLO 질의를 평가한다. 각 D의 SLO 분위수는 H와 D 모두를 제외한 모델에서만 만든다. 후보 `tau` 중 donor의 강한 모델보다 **잘못 승인 총수가 증가하지 않고**, 성공한 정확 최소 선택이 강한 모델의 99% 이상이며, 개별 donor의 잘못 승인율이 2%p 이상 증가하지 않는 방법에서 강한 모델 호출률이 가장 낮은 것을 선택한다. 동률은 더 큰 `tau`; 통과 후보가 없으면 `infinity`를 쓴다. 외부 대상 H의 결과는 `tau` 선택에 들어가지 않는다.

## 비교와 분할

- 바깥 평가는 모델 ID 하나를 통째로 제외하는 9분할이 주 평가다. BERT 네 모델을 함께 제외하는 계열 분할도 별도로 평가한다. 어느 결과도 독립적인 새 검증 표본이 아니다. 기존 SQLite는 많은 방법을 이미 탐색하는 데 사용했다. `local-novel-matrix`와 `local-space-filling`은 주 캠페인보다 먼저 수집됐고 기존 평가에 쓰였으므로 이번 시험에서 재점수화하지 않는다.
- 기준선은 항상 강한 모델, 항상 경량 모델, 직접 합격 분류기, 그리고 대상 결과를 사용하지 않고 2단계 방법의 강한 호출률과 맞춘 결정적 무작위 라우팅이다. 무작위 라우팅은 **사후 설명용**이다. 2단계와 단순 경량·강한 모델은 질의별 고정 0 여유 cutoff, 직접 분류기는 고정 0.5 확률 cutoff로 선택한다.
- 저장 지표는 분할·방법별 승인/보류, 성공, 잘못 승인, 정확 최소 형상, 가능했으나 보류한 질의, 강한 모델 호출률이다. 같은 승인 규모의 잘못 승인·정확 최소 형상도 별도 **진단 곡선**으로 제시하되, 이는 보류 질의의 순위를 사후 절단하므로 온라인 정책 점수로 사용하지 않는다. 각 모델과 BERT 공동 분할을 따로 보고하며 합성 질의의 행 수만으로 불확실성을 과소평가하지 않는다.
- 채점 시간은 훈련 후 같은 프로세스에서 모델을 예열한 뒤, **한 workload와 한 SLO의 8후보 질의**에 대해 `perf_counter_ns`로 잰다. 고정 난수로 각 workload당 25개 중 하나의 SLO를 고르고 순서를 섞어 3회 반복한다. 한 번의 2단계 경로는 경량 `predict(8행)`과 필요 시 강한 `predict(8행)`을 모두 포함한다. 항상 강한 모델에도 동일한 8행 호출을 사용한다. 기존 구현의 `n_jobs=2`와 **같은 적합 모델을 `n_jobs=1`로만 바꾼 8행 predict**를 별도 시간 기준선으로 잰다. 두 설정의 예측 수치가 같은지 검사한다. 평균·p50·p95와 강한 호출률을 기록한다. 25개 합성 SLO를 실제로 25번 채점한 시간 절감으로 계산하지 않으며, 같은 workload에 SLO만 바뀌면 강한 회귀 출력 8개를 재사용할 수 있음을 결과에 명시한다.

## 중단/채택 기준과 한계

이번 자료에서 2단계 방법을 실험용 기본 경로로 바꾸려면 기존 `n_jobs=2` 강한 모델 대비 평균 warm CPU 채점 시간이 25% 이상 짧고 **p95도 20% 이상 짧아야** 한다. 더 공정한 단일 스레드 강한 모델보다 평균 또는 p95가 느리면 채택하지 않는다. 동시에 주 9분할 합계에서 자연 cutoff의 잘못 승인 수가 늘지 않고, 성공한 정확 최소 선택이 강한 모델의 99% 이상이어야 한다. 같은 승인 수로 잘라 비교한 사후 진단에서도 잘못 승인 수가 강한 모델보다 많으면 채택하지 않는다. **각 모델별 악화는 합계와 별도로 보고**하고, 어느 한 모델의 승인 중 잘못 승인율이 강한 모델보다 2%p 이상 높으면 채택을 보류한다. 이 사전 게이트 역시 이미 살펴본 자료에 맞춰 설정한 탐색 기준이며 확증적 오류 통제가 아니다. 기준을 통과해도 실제 배포 효과나 외부 일반화는 주장하지 않는다. 처리 시간이 원래 작아 개선의 실용성이 낮거나 경량 단계가 시간을 늘리면 기각한다.

모든 분할은 같은 호스트·이미 관찰한 모델군에서 수행되며 독립 사용자 요구가 아니다. 유일한 생성형 모델을 제외하면 donor에 생성형 표본이 없고, 그 경우 경량 출력을 신뢰하지 않는다. 모델/계열 단위가 통계적 독립성의 상한에 가깝고 25개 SLO는 한 측정을 반복 사용한다. 이 실험은 **정적 추천 판단의 계산비용과 오승인 신호**만 답한다.
