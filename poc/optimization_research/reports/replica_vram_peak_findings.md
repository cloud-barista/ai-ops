# GPU 1개 관측 피크로 GPU 2개 장치별 예약 피크 상한 예측

## 판정

**학습기는 연구용 상한으로 채택하지 않는다.** [점수 전 고정 규약](replica_vram_peak_protocol.md)의 소형 90% 분위수 모델은 기존 GPU 1개 피크를 그대로 쓰는 기준선보다 주 시험의 pinball 손실을 `4.752→2.935 MiB`로 낮추고 예측 상한을 평균 `15.50 MiB` 줄였다. 그러나 모델 균등 피복률이 **89.36%**로 고정 기준 `≥90%`에 못 미쳤다. ALBERT `81.25%`, DistilBERT `82.81%`, BERT-base `80.86%`는 모델별 `≥85%` 기준도 어겼다. 관측 예약 피크의 상한을 더 낮게 예측할 때 놓치는 사례가 늘었으므로 이 출력을 GPU 메모리 적합성 또는 배포 승인에 사용하지 않는다.

## 관측 대상과 지원 범위

고정 물리 실행 추출 (`../data/audit_v1/measurements.parquet`)의 주 캠페인 `khu-hf-local-exhaustive`에서 같은 작업·CPU affinity에 대한 GPU 1개 측정과 **그 뒤 시작된** GPU 2개 측정을 2,300쌍 연결했다. 9모델·575개 작업 조건·4개 CPU core limit이다. GPU 2개 실행은 별도 프로세스 두 개가 각자 같은 전체 벤치마크를 수행한다. 여기의 라벨은 그 두 프로세스가 각 장치에서 보고한 `torch.cuda.max_memory_reserved()` 피크 중 **큰 값**이다. 상위 DB의 예약 메모리 열은 두 값을 합한 값이다. 2,300행 모두 합계가 확인됐고 39행에서는 장치별 값이 달라 합계/2가 라벨과 달랐다.

GPU 2개 최대 피크와 기존 GPU 1개 피크의 차이는 2,300쌍 중 증가 137, 동일 309, 감소 1,854개였다. 중앙값은 `−40 MiB`, 범위는 `−126…+280 MiB`다. GPU 1개는 수집기 프로세스에서, GPU 2개는 새 자식 프로세스들에서 실행된다(수집기 (`/path/to/aiops/khu_policy_agent/live_collector.py:1593`)). 그러므로 이 차이를 GPU를 추가한 인과적 메모리 변화, 작은 GPU에서의 실행 가능성, 최소 VRAM으로 해석하지 않는다. 기준값으로 사용할 GPU 1개 피크도 **같은 입력의 현재 실행을 끝낸 뒤에만** 알 수 있다.

주 학습·평가는 동종 donor가 있는 encoder 추론 8모델 × 64작업 × 4 CPU 설정 = **2,048쌍**이다. 각 대상 모델을 통째로 제외한 뒤 나머지 encoder 7모델 1,792쌍으로 학습했다. 로컬의 유일한 causal LM인 Qwen은 252쌍에서 학습기 `ABSTAIN`이다. Qwen에서 GPU 1개 피크를 그대로 쓰면 피복률은 **88.89%**이고 최대 과소예측은 **280 MiB**다. 전체 평균에 Qwen을 섞어 이 지원 실패를 숨기지 않는다.

## 같은 표본의 세 방법

세 방법은 같은 대상 GPU 1개 측정을 입력으로 사용한다. `unchanged_gpu1`은 이를 그대로 상한으로 쓰고, `donor_q90_delta`는 donor의 `(GPU2 장치별 최대 − GPU1)` 차이의 전역 90% 분위수를 더한다. 모든 모델 제외 fold에서 이 분위수는 `0 MiB`라 두 기준선의 예측이 같다. `hgb_q90_delta`는 donor의 이 차이를 GPU 1개 피크·모델 파라미터 바이트 수·배치/길이/동시성·반복 수·CPU core limit에서 예측한다. 대상 GPU 2개 값이나 실행 뒤 노드 계측은 특징에 없다. 모델의 설정과 승인·보류 게이트는 [규약](replica_vram_peak_protocol.md)에 점수 전에 고정했다.

| 캠페인과 평가 모집단 | 방법 | 모델 균등 pinball90 ↓ (MiB) | 피복률 ↑ | 평균 상한 초과량¹ (MiB) | 평균 예측 상한−GPU1 (MiB) | 최대 과소예측 (MiB) |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 주 8모델·512작업·2,048쌍 | GPU1 유지 / donor q90 | 4.752 | 94.68% | 35.57 | 0 | 56.0 |
| 주 8모델·512작업·2,048쌍 | **HGB q90** | **2.935** | **89.36%** | **20.07** | **−15.50** | 39.53 |
| 새 입력 `novel-matrix`, 8모델·16작업·64쌍 | GPU1 유지 / donor q90 | 6.038 | 93.75% | 57.88 | 0 | 4.0 |
| 새 입력 `novel-matrix`, 8모델·16작업·64쌍 | HGB q90 | 5.139 | 87.50% | 33.17 | −24.71 | 17.55 |
| 새 입력 `space-filling`, 8모델·40작업·160쌍 | GPU1 유지 / donor q90 | 4.610 | 87.50% | 30.23 | 0 | 24.0 |
| 새 입력 `space-filling`, 8모델·40작업·160쌍 | HGB q90 | 4.035 | 87.50% | 15.12 | −15.10 | 31.79 |

¹ 예측 상한−관측 GPU2 피크의 평균이다. 음수 사례도 포함하므로 양수 초과분만의 평균은 아니다.

주 HGB pinball은 **8/8모델**에서 같은 모델의 두 기준선보다 낮았지만, 실제 피크가 상한을 넘은 셀은 기준선 109개에서 HGB **218개**로 늘었다. Pinball 개선만으로 보수적 상한의 신뢰도를 주장할 수 없는 이유다. 새 입력 두 캠페인은 같은 호스트·대부분 같은 모델의 이전 수집 자료이며 여러 연구에서 이미 결과를 살폈다. 두 캠페인에서 HGB의 평균 pinball은 낮았지만 `novel-matrix`의 피복률은 `93.75→87.50%`, 최대 과소예측은 `4.0→17.55 MiB`로 나빠졌다. `space-filling`에서도 최대 과소예측이 `24.0→31.79 MiB`로 커졌다. 이 분할은 독립 신규 모델 검증이나 운영 보증이 아니다.

## 게이트·재현

사전 게이트의 **주 pinball ≥5% 개선**, **8모델 중 ≥6모델 개선**, **평균 상한 ≥10 MiB 축소**는 통과했다. **주 모델 균등 피복률 ≥90%**와 **각 모델 ≥85%**는 실패했다. 새 입력 두 캠페인의 느슨한 `≥85%` 피복률과 기준선의 105% 이하 pinball 조건은 통과했지만 주 실패를 뒤집지 않는다. Qwen에 같은 작업 donor가 없고 원격 `ubuntu216`은 GPU·모델·호스트가 함께 바뀌므로 두 집단에는 학습기 점수를 내지 않았다.

재현: 연구 루트에서 `OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 /usr/bin/python3 scripts/evaluate_replica_vram_peak.py`. [실행 코드](../scripts/evaluate_replica_vram_peak.py), [짝·단위·누출 테스트](../tests/test_replica_vram_peak.py), 실행별 예측 (`../artifacts/replica_vram_peak_v1/predictions.csv`), 모델별 지표 (`../artifacts/replica_vram_peak_v1/per_model.csv`), [분할·학습기 해시](../artifacts/replica_vram_peak_v1/fold_manifest.json), [집계·게이트](../artifacts/replica_vram_peak_v1/metrics.json)을 남겼다. `metrics.json`에는 추출 SHA-256 `b7bba7963e8a309b6a8502a1d98eefb150476b1381ec016beeb68cbf63fae906`, 사전 규약 SHA-256 `cd8bb79aa9366b62b376feec1af34d2c1c3c716402a851e7e193f0a738f7faa5`, 코드·예측·분할 manifest 해시와 도구 버전이 있다. 집중 테스트 5개가 통과했다.

이 과제는 기존 [단일 GPU 피크 연구](vram_peak_findings.md)와 다른 **GPU 2개 동시 프로세스의 장치별 관측 피크**를 학습했다. 단일 호스트, 한 번씩의 짝 벤치마크, 가까운 encoder 계열, 수집기 프로세스 차이 때문에 이를 응용의 RAM/VRAM 최소 요구나 ETRI VM 후보 호환성으로 승격하지 않는다. 이후 새 장비에서 같은 모델·입력의 반복 피크와 실제 메모리 제한별 성공/실패를 기록하면 그때 용량 판단을 따로 검증할 수 있다.
