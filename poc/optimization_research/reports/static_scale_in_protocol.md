# GPU 2개에서 1개로 줄일 때의 정적 성능 예측: 사전 규약

작성일: 2026-09-28. 이 문서는 아래 실험의 점수를 계산하기 전에 고정한다. 목표는 실제 VM `SCALE_IN`의 효과가 아니라, **같은 호스트에서 별도로 측정한 GPU 1개 형상**이 기존의 배치 지연·요청 처리량 목표를 만족할지 예측하는 것이다. GPU 2개는 두 독립 replica의 합산 벤치마크이며, 두 VM이 아니다. 목표는 수집기 설정에서 만들어졌고 사용자 SLO가 아니다.

## 자료와 분할

- 고정 추출본은 `data/audit_v1/measurements.parquet`(SHA-256 `b7bba7963e8a309b6a8502a1d98eefb150476b1381ec016beeb68cbf63fae906`)이다. 원본은 `/path/to/aiops/runs/khu-hf-*/executions.sqlite3`의 읽기 전용 추출이다.
- 성공·완료·유효 타깃인 `cuda`, CPU affinity 2개, replica 1/2의 동일 `campaign × workload_group` 쌍을 만든다. 같은 형상을 반복한 원격 캠페인은 `started_at, execution_id` 순 첫 행만 쓴다. 주 캠페인은 575작업×9모델, 추가 입력 캠페인은 18·44작업×동일 9모델, 원격은 24작업×새 2모델이다. 짝 개수와 고유성은 실행 중 검증한다.
- 주 캠페인에서 **모델 ID 전체 제외** 9회를 실시한다. 제외 모델의 GPU 2개 현재 행만 입력으로 공개하고 GPU 1개 행은 점수 계산에만 쓴다. 다른 8모델의 주 캠페인 쌍으로 학습한다. 해당 제외 모델의 추가 캠페인 결과는 학습·선택에 넣지 않는다. BERT 네 모델 공동 제외도 보조 시험한다.
- 원격 두 모델은 주 캠페인 9모델 전체로 학습·선택한 모델을 그대로 점수화한다. 원격의 GPU, 호스트, 모델 종류와 조건이 함께 달라지며 대상 모델 수가 2개뿐이므로 별도 스트레스 시험으로 보고한다.

## 입력, 정답, 누출 방지

- 정답은 GPU 1개 행의 `log(batch_p95_ms)`와 `log(examples_per_second / batch_size)`다. GPU 2개 행의 같은 두 실측값이 현재 관측 입력이다.
- 정적 입력은 현재 GPU 2개 행의 batch, 길이, 동시성, 작업 종류, `result_json.model_parameter_bytes`다. 계측 입력은 **현재 GPU 2개 행** `node_summary_json`의 GPU 이용률 평균·최댓값, GPU 메모리 최대, CPU 이용률 평균이다. 두 변형을 따로 학습한다. 실행 중 샘플 수는 쓰지 않는다. `target_throughput_rps`와 `latency_slo_ms`는 결정 점수 계산에만 사용하고 회귀 입력에서 뺀다.
- GPU 1개 행의 어떤 결과·계측·종료시각도 특징을 만들 때 읽지 않는다. `oracle_action`, 파생 `action_outcomes`와 그 GPU 사용률 특징을 사용하지 않는다. 새 모델의 GPU 1개 결과를 바꿔도 예측은 변하지 않아야 한다. 수집 순서는 온라인 action 재연으로 해석하지 않는다.

## 비교와 채택 기준

1. 강한 단순 규칙: `GPU1 latency = GPU2 latency × a`, `GPU1 requests/s = GPU2 requests/s ÷ b`. 기초 규칙은 `(a,b)=(1,2)`. 비교용 `a∈{1,1.5,2,2.5,3,4,6}`, `b∈{2,2.25,2.5,3}`와 공통 안전 여유 `m∈{0,.05,.1,.15,.2,.25,.3,.4,.5,.6,.8,1,1.2}` 로그 단위를 **대상 모델을 제외한 자료만으로** 고른다.
2. donor 중앙값: 다른 모델들의 `log(GPU1/GPU2)` 지연·처리량 응답 중앙값을 현재 GPU 2개 로그 실측에 더한다.
3. 학습기: 현재 로그 성능과 정적 특징으로 위 두 로그 응답을 함께 예측하는 `ExtraTreesRegressor(n_estimators=128,min_samples_leaf=5,max_features=1.0,random_state=42,n_jobs=2)`. 계측 없는 버전과 현재 GPU 2개 계측을 더한 버전을 비교한다.

단순 규칙과 다른 방법의 여유값은 각 바깥 분할의 **donor 모델 전체 제외 교차검증 예측**에서 선택한다. 선택 기준은 `GPU2`가 두 목표를 충족하는 donor 작업 중, 승인 건수 대비 잘못 승인 비율이 5% 이하인 조합에서 실제 안전 승인 건수를 최대화하는 것이다. 동수면 잘못 승인 수, 다음 전체 승인 수가 작은 것을 택한다. 이 5%는 형식적 보장이나 실제 허용 위험이 아닌 오프라인 비교용이다. GPU 2개가 이미 목표에 못 미치는 경우는 축소 검토 대상에서 제외한다.

두 실측 목표를 모두 만족한 GPU 1개 쌍을 `정적 축소 가능`으로 표시한다. 보고할 값은 모델별·캠페인별 지연/요청 처리량 평균 절대 로그오차, 검토 대상 수, 안전 승인, 잘못 승인, 보류, 시험 승인 오차율이다. 추가로 시험 자료의 **사후** 잘못 승인 수가 같은 지점에서 안전 승인 수를 비교하는 안전/승인 곡선을 표시하되, 이를 배포 가능한 문턱 선택으로 해석하지 않는다. 원격·BERT 공동 제외·추가 입력에서는 주 학습분할의 규칙을 그대로 적용한다.

기존 자료를 반복 탐색한 사후 연구다. 학습기가 단순 규칙보다 같은 오류 예산에서 일관되게 안전 승인을 늘리고 지연·처리량 오차도 악화시키지 않아야 연구 후보로 남긴다. 성공해도 새 방법의 최초성, VM 삭제의 안전성, 사용자 지연·비용 효과를 주장하지 않는다.
