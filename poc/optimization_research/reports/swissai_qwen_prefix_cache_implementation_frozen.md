# SwissAI Qwen 접두 재사용 평가 구현 선택 기록

2026-09-29. [주 규약](swissai_qwen_prefix_cache_protocol.md)을 고정한 뒤, 전체 원본의 **미래 재사용 정답·검증/시험 캐시 적중률을 계산하기 전** 아래 모호한 구현 선택을 고정한다. 이 문서는 주 규약의 분할·게이트·주 지표를 바꾸지 않는다.

## 정보 경계와 기준 확률

- 전체 완전 블록 접두열 `P`의 최근 60분 **과거 등장 횟수**를 `c`로 쓴다. `c`는 현재 요청과 같은 시각 요청을 제외하며, 공개 파일의 사전 계산 `reused_buckets`나 과거 요청의 아직 끝나지 않은 미래 재사용 정답을 읽지 않는다.
- 학습 적격 표본의 60분 재사용 양성률 `p_train`을 전역 기준 확률로 고정한다. 빈도 기준 확률은 `(c + 20 × p_train) / (c + 20)`이다. 이는 과거 동일 접두가 하나 늘 때 양성 증거 한 건으로 다루는 단순 휴리스틱이다. 두 기준 확률의 검증 Brier·AP를 학습기와 비교하며 캐시 정책의 선택에는 쓰지 않는다.
- `seconds_since_exact`는 현재 분할 내 **마지막** 동일 `P` 관측에서 현재 시각까지의 초다. 직전 60분에 없더라도 더 오래된 동일 접두가 있으면 경과시간을 보존한다. 없으면 결측으로 둔다. `exact_5m`·`exact_60m`은 과거 *전체* `P` 일치 건수이고, 길이 1·2·4의 접두 등장 횟수에는 더 긴 요청도 포함한다.
- 과거 창은 `[t−5분,t)`와 `[t−60분,t)`이다. 정확히 하한 시각의 요청은 포함한다. 같은 마이크로초 요청끼리는 서로의 특징이나 미래 재사용 정답에 들어가지 않는다. 분할마다 이력과 캐시를 비우며, 검증/시험 첫 60분은 이력 준비용이다.

## 고정 특징과 구현 점검

학습 입력 열은 순서대로 `complete_blocks`, `token_remainder`, `utc_hour`, `utc_weekday`, `arrivals_5m`, `exact_5m`, `exact_60m`, `seconds_since_exact`, `prefix_1_60m`, `prefix_2_60m`, `prefix_4_60m`이다. 접두 길이가 1·2·4에 못 미치는 열과 마지막 동일 접두가 없는 경과시간은 NumPy `NaN`으로 넘긴다. UTC 요일은 월요일 0·일요일 6이다. 원시 버킷 ID·요청 ID·완료/출력 필드는 특징이 아니다.

학습 표본은 적격 훈련 요청을 UTC 날짜별 `SHA256(id)` **바이트 오름차순**으로 최대 5,000개 고른다. 선별은 정답을 보지 않고 수행한다. 양성·음성 지지 게이트는 선별 표본과 별개로 전체 적격 훈련·검증 요청에 적용한다. 같은 시각 그룹의 캐시 적중은 그룹을 상태에 반영하기 전에 한꺼번에 계산한다. 그 뒤 요청 ID 해시 오름차순으로 상태를 갱신한다. 60분 동안 노드 접근이 없었다면 정확히 60분 경계에서 만료한다. 미래 재사용 레이블은 분할 끝 시각 자체가 제외되므로 `t+60분 < split_end`일 때만 완전 관측으로 취급한다.

고정 캐시 문턱 `τ=0`은 LRU와 출력이 정확히 같아야 한다. 4,096블록 검증에서 문턱 6개 가운데 적중 비율이 최대인 하나를 고르고 동률이면 작은 문턱을 택한다. LRU/LFU 두 기준선 중 높은 값보다 **상대 5% 이상** 높아야 시험을 열며, 기준선 적중 비율이 0이면 상대 개선의 분모가 없어 게이트를 닫는다. 시험도 같은 조건과 날짜별 과반 우세를 적용한다. 모델 학습·검증 결과가 난 뒤 문턱·특징·캐시 규칙을 바꾸지 않는다.

이 실험의 적중은 고정 16토큰 블록 수를 세는 오프라인 시뮬레이션 지표다. 실제 GPU KV 메모리 바이트, prefill 절감시간, 사용자 TTFT 또는 배포·스케일 결과를 나타내지 않는다.
