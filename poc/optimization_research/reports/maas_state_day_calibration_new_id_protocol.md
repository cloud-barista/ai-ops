# MaaS 상태별 전날 보정의 bucket 2 새 ID 단회 시험 규약

2026-09-29. **상태: bucket 2 원본 접근 전 동결 대상.** [노출된 bucket 0·1의 개발 결과](maas_state_day_calibration_development.md)를 보고 방법과 문턱을 골랐다. 두 집합의 점수를 새 검증으로 부르지 않는다. 고정 모델은 [bucket 0에서 학습한 저장 단일 로지스틱](maas_existing_model_new_id_findings.md)이다. bucket 1은 그 모델의 새 ID 시험으로 이미 열렸으므로 이번 방법의 검증에는 사용하지 않는다. 이번 목표는 같은 공개 MaaS 주간에서 **처음 보는 ID의 30분 GPU 관측 위험 확률**을 개선하는가이다. 실제 `SCALE_OUT/IN` 결과는 자료에 없다.

## 원본과 한 번의 지원량 평가

[Alibaba MaaS 2026 공식 주간 5분 추적](https://github.com/alibaba/clusterdata/blob/8a6295f9779ddc019add669eeca49c5f9f77b3a7/cluster-trace-v2026-maas/README.md)의 21개 멤버·140,906,827행을 [기존 전량 감사](../data/external/alibaba_maas_2026/SOURCE.md)의 크기·ETag·멤버별 CRC32/SHA-256과 일치시킨다. `SHA256(UTF-8 정규화 instance_id)` 첫 8바이트 정수 `%100==2`인 **bucket 2**만 추출한다. bucket 0·1의 전체 해시 ID와 교집합이 없어야 한다. 원본 익명 ID나 행별 해시 ID를 대외 배포하지 않는다.

기존 `evaluate_maas_state_followup.construct_cohorts`의 split·적격성·정답 정의를 그대로 사용한다. 주 분석은 시험 상대일 **145–146**의 `complete/current_normal`이며 현재 SM<80%, 메모리 사용률<90%인 완전 과거 세 창 및 미래 여섯 창만 점수화한다. 판단 `d=t+600초`, 정답은 `d` 이후 30분 여섯 창 중 SM≥80% 또는 GPU 메모리≥90%가 관측되는 사건이다. 미래 창의 결측·중복·무효는 제외하고 후보 대비 정답 관측률을 기록한다. 적격 행 ≥50,000, 신규 초과 ≥1,000, 적격 ID ≥500, 양성 ID ≥50, 날짜마다 ≥20,000행·≥300양성, 현재 정상 후보의 정답 관측률 ≥75%를 **점수 전에** 요구한다. 전날 각 상태의 만기 완료 행은 날짜마다 ≥300개이고 양성·음성 각각 ≥30개여야 한다. 하나라도 실패하면 확률을 채점하지 않는다.

## 고정 시점과 예측 방법

저장 `new_pooled.joblib`, 학습 전용 여섯 결측 대체 중앙값, `FULL_FEATURES`를 그대로 사용한다. 재학습·하이퍼파라미터 재선택·bucket 2 ID별 보정은 없다. 판단일 `D`의 00:00에, 바로 전날의 적격 `complete/current_normal` 행 중 `decision_s+2100≤D×86400`인 **완전 정답**만 쓴다. 2100초는 30분 정답 창과 가정한 5분 전달 지연이다. 전날 늦게 시작한 판단의 아직 미완료된 정답은 제외한다. 시험일 145는 144일, 시험일 146은 145일의 만기 정답을 사용한다. 날짜 146의 모델은 145일의 **완료된** 결과만 써서 갱신한다. 같은 30분 사건에 중첩된 5분 판단이 있어 독립 표본이라는 가정은 하지 않는다.

`h=any_recent_high∈{0,1}`의 bucket 0 훈련 전용 Beta(1,1)률은 `p_train,0=0.033061253175105165`, `p_train,1=0.7215373459028281`로 고정한다. 전날 bucket 2 적격 만기 행의 같은 상태별 양성률은 `p_D,h=(양성+1)/(행+2)`이다. **주 후보**는 저장 모델의 확률 `p_m`에

`p_candidate = sigmoid(logit(p_m) + logit(p_D,h) − logit(p_train,h))`

를 적용한다. 값은 로그오즈 계산 직전에 `[1e-9,1−1e-9]`로 자른다. 이 수식은 상태별 이전 날짜의 기저 발생률 변화를 저장 모델에 반영한다. 통계적 로그오즈 보정과 Beta 평활은 알려진 구성 요소이며 학술적 최초성을 주장하지 않는다.

모든 비교기는 같은 시험 행을 평가한다. (1) **저장 단일 모델** `p_m`; (2) 같은 전날 만기 라벨·같은 벌점 20·이동 한계 ±0.5로 맞춘 **전역 정확한 로그오즈 절편**; (3) 같은 전날 상태별 Beta 발생률만 예측하는 **단순 표** `p_D,h`; (4) 같은 전날 만기 라벨로 상태별 정확한 절편을 맞춘 **가까운 대안**. 마지막 대안은 주 후보 수식의 고유 이득 여부를 해석하기 위해 반드시 점수화한다. bucket 2 결과를 보고 이 방법들을 재선택하지 않는다.

## 사전 성공 조건과 증거 경계

지원량 통과 후 주 후보의 전체 행 Brier가 저장 모델·전역 정확한 절편·전날 상태별 단순 표 **각각보다 상대 ≥2% 낮아야** 한다. 두 날짜의 Brier는 각각 세 비교기보다 낮아야 하고, ID 동일가중 Brier는 세 비교기의 최선보다 낮아야 한다. AP는 저장 모델 및 상태별 정확한 절편보다 **0.005 이상 낮아지지 않아야** 한다. ID를 단위로 짝지어 2,000회 재표집(seed 43)한 `후보−저장 모델`과 `후보−전역 절편`의 행 Brier 차 95% 백분위 상한은 둘 다 0 미만이어야 한다. 가까운 상태별 정확한 절편보다 전체 행 Brier가 **0.5% 넘게 높으면** 주 후보의 별도 가치를 인정하지 않는다. 모든 조건을 통과해도 이번 한 공개 주간의 새 ID에 대한 **연구용 위험 입력** 결과다.

규약·추출기·평가기·합성 테스트, 원본 감사와 저장 모델·중앙값·개발 JSON의 SHA-256을 bucket 2 원본 접근 전에 `release_manifest.json`에 고정한다. 추출 후에는 출처와 ID 분리를 검사하고 지원량 집계만 저장한다. 지원량을 통과한 경우에만 고정 방법을 **한 번** 점수화한다. 다른 서비스·기간·GPU 세대, 온라인 AI-App만의 성능, 사용자 SLO 또는 실제 VM 조치 효과는 이 시험으로 입증되지 않는다.
