# AgentPerfBench TTFT·TPOT 성분으로 할 수 있는 다음 연구

작성일: 2026-09-29. **결정: A100 4장→8장 성능 반응의 탐색적 학습은 GO, 여러 GPU 형상을 포괄하는 운영 추천과 `prefill-heavy`/`decode-heavy` 특화 학습은 NO-GO.** 여기서 4장→8장은 동일 기종 GPU의 **텐서 병렬도** 변경이다. VM 복제 또는 `SCALE_OUT` 조치의 관측 효과가 아니다. 앞서 [p90 E2EL·요청/s 형상비 전이](agentperf_shape_transfer_findings.md)는 강한 직접 회귀 기준선에 졌다. 이 문서는 그 점수를 재해석하거나 새 방법의 성능을 주장하지 않고, **첫 토큰 시간(TTFT)과 출력 토큰당 시간(TPOT)이 다른 방향으로 움직이는지**라는 별도 질문의 표본 지원량만 감사한다.

## 출처와 관측 범위

[공식 AgentPerfBench 카드](https://huggingface.co/datasets/agent-perf-bench/AgentPerfBench/blob/722f2b9d8a6acd222811f4e210a96865f774f6ee/README.md)의 `trace_replay/summary.parquet`만 읽었다. 고정 revision은 `722f2b9d8a6acd222811f4e210a96865f774f6ee`, 로컬 SHA-256은 `568efbdae473a830ba792317fb09cfba0ea4f667db67b93d28e72637a5c71d1e`이다. 기존 [원본 감사](agentperfbench_feasibility.md)와 같은 정의로, 양수·유한한 `duration_s`, 요청/s, 입력·출력 토큰/s, p90 TTFT·TPOT·E2EL 및 `request_throughput × duration_s = num_requests`인 전 요청 성공 행만 남겼다. 원본 2,932행에서 36행의 0 지표와 724행의 부분 실패를 제외하면 2,172행이다. 지표는 **성공 요청에 대해서만** 집계되며 원본 공개 전에 성공률 75% 미만 설정이 제거됐다. 미공개 실패·미측정 형상의 정답은 없다.

기존 규약처럼 동일 `(model, engine, profile, concurrency, num_requests)`의 2개 이상 형상과 입력 토큰 총량 최대/최소 `≤1.00001`, 출력 총량 `≤1.05`를 적용하면 **485개 비교 그룹, 1,526행**이다. 이 집단의 모든 형상 조합 중 동일 GPU 기종에서 개수만 증가하는 비교는 **928쌍, 404개 그룹, 7개 모델**이다. TTFT·TPOT 변화 방향이 반대인 쌍은 **197/928(21.2%)**, 두 변화의 `|log(8장 또는 더 큰 형상 / 작은 형상)|`이 각각 `log(1.05)`를 넘는 쌍은 **112/928**이며, 후자는 **81개 그룹, 7개 모델**에 걸친다. 이는 서로 독립인 928개 앱이 아니고, 같은 그룹에서 여러 쌍을 만들었다. 각 실행의 반복 측정이 없어 이 크기의 차이가 측정 잡음보다 크다고 증명할 수도 없다.

출력 토큰 일치 조건을 1%로 좁히면 동일 기종·개수 증가 비교가 **491쌍**, 방향 충돌 **80쌍(16.3%)**, 두 로그 변화의 절댓값이 각각 `log(1.05)`를 넘는 충돌 **38쌍/36개 그룹/6개 모델**로 줄어든다. 원본의 출력 토큰 수는 `output_token_throughput × duration_s`로 사후 복원한 값이다. **대상 형상의 이 값으로 표본을 고르면 결과를 본 뒤 평가 집단을 선별**하게 되므로, 이 조건은 민감도 분석에만 적합하다. 같은 프로필·요청 수가 실제 같은 출력 길이를 보장하지 않는다.

동일 기종 GPU 개수 전환의 **정확한 형상 쌍은 18종**이다. 측정한 모델 수는 1모델 7종, 2모델 5종, 3모델 5종, 5모델 1종이다. 모델 하나를 시험으로 빼고도 동일 형상 쌍 donor가 최소 3모델 남는 쌍은 **`A100-40GBx4 → A100-40GBx8` 한 종**뿐이다. 따라서 928쌍의 규모를 새 모델에 대한 폭넓은 형상 반응 학습의 근거로 쓸 수 없다.

프로필 명칭 자체를 입력으로 쓸 수는 있지만, 이 집단의 `prefill-heavy`는 **42행/3모델**, `decode-heavy`는 **36행/2모델**뿐이다. 동일 모델·엔진·하드웨어·동시성·요청 수에서 두 프로필을 모두 가진 경우는 **24개 형상 조건/2모델**이다. 이 표본으로 새 모델의 prefill 대 decode 수요를 분류하거나 앱 텍스트에서 자원 요구를 추출하는 학습을 검증할 수 없다. `p90 E2EL = p90 TTFT + 출력길이 × p90 TPOT` 같은 식도 성립하지 않는다. 각 p90은 서로 다른 요청에서 나올 수 있고 요청별 출력길이·공분산은 summary에 없다.

## 다음 실험의 좁은 과제: A100 텐서 병렬도 4→8

**질문:** 이미 A100 4장으로 같은 LLM 서빙 프로필을 한 번 계측했다면, 같은 GPU 기종 8장으로 옮겼을 때 p90 TTFT와 p90 TPOT를 각각 예측할 수 있는가? 두 성분의 변화 방향이 갈릴 때 이를 놓치지 않는가? 이 과제는 *추론 성능의 형상 응답*이며 CPU·메모리 요구 분석이나 VM 배포/스케일 조치 판단은 아니다.

두 행이 모두 위 품질 조건을 만족하고 동일 `(model, engine, profile, concurrency, num_requests)` 키를 가진 **쌍 자체**를 사용한다. 이 정의는 다른 형상의 결과로 쌍을 배제하지 않는다. 실제 지원은 **130쌍/5모델/7프로필**, 모두 vLLM이다. 쌍의 입력 토큰 총량은 부동소수 오차를 제외하면 동일하다. 출력 총량은 최대 **1.138배**, 5% 초과는 **3쌍**, 1% 초과는 **47쌍**이다. 주 분석 130쌍은 대상 출력 토큰 수로 선별하지 않는다. 출력 차이 ≤5% 집단 **127쌍**, ≤1% 집단 **83쌍**을 정해진 민감도 집단으로만 둔다. 주 분석에서 TTFT·TPOT 방향 충돌은 **36/130쌍**, 두 성분의 로그 변화 절댓값이 모두 `log(1.05)`를 넘는 충돌은 **21/130쌍**이다. 5% 출력 집단에서는 각각 **34/127, 19/127**, 1% 집단에서는 **25/83, 13/83**이다.

| 모델 | 주 분석 쌍 | 두 로그 변화 절댓값 `>log(1.05)`인 방향 충돌 |
|---|---:|---:|
| Llama-3.1-70B | 15 | 0 |
| Llama-3.1-8B | 35 | 7 |
| Mixtral-8x7B | 30 | 1 |
| Qwen3.5-9B | 35 | 8 |
| gpt-oss-20b | 15 | 5 |

이 쌍에는 `prefill-heavy`와 `decode-heavy`가 없고, `coding-singleturn`은 10쌍뿐이다. 따라서 가설은 특정 에이전트 프로필의 보편적 우수성이 아니라 **chat 계열을 주로 포함한 이 벤치마크에서 TTFT·TPOT 동시 예측**으로 좁힌다.

### 학습·검증 규약 후보 — 점수 확인 전에 별도 동결 필요

1. **입력 시점:** A100 4장의 계측이 끝난 시점. 결정 전 사용할 수 있는 값은 등록된 모델 계열·명목/활성 파라미터 규모와 정밀도(카드에서 확인 가능한 정적 메타데이터), `profile`, 설정 동시성·요청 수, A100 4장의 p90 TTFT·TPOT와 그 실행의 평균 입력·출력 토큰 수다. 마지막 토큰 길이는 **앵커 관측**으로만 허용하며, 등록만 된 앱의 무계측 추론에는 쓸 수 없다. 대상 A100 8장의 지연, 처리량, 실행시간, 성공 건수, 출력 토큰 수와 `run_id`는 입력에서 금지한다. 모든 비교 모델에 같은 앵커 정보를 준다.
2. **정답과 분할:** 타깃은 `log(p90_ttft_ms)`와 `log(p90_tpot_ms)` 두 개다. 5모델을 하나씩 완전히 제외해 5 fold로 평가한다. Llama 두 모델을 동시에 제외하는 계열 단위 스트레스도 별도로 수행한다. 전처리·하이퍼파라미터 선택은 각 훈련 모델에서만 하고, 같은 모델의 다른 동시성·프로필을 학습/시험에 섞지 않는다. 쌍 130개가 5개의 독립 시험 모델보다 큰 독립 표본 수를 뜻하지 않는다.
3. **강한 비교군:** (a) 두 성분 각각 앵커값 유지, (b) 두 지연을 GPU 수 비율인 1/2로 예측, (c) 훈련 모델별 로그 반응의 중앙값을 먼저 계산하고 모델 사이 중앙값으로 예측하는 donor 기준선, (d) 동일 입력에서 대상 로그 지연을 직접 예측하는 단순 Ridge 및 ExtraTrees, (e) 같은 입력에서 두 로그 반응을 각각 예측하는 Ridge 및 ExtraTrees. 새 결합법을 시험한다면 *공통 개선 성분과 TTFT–TPOT 차이 성분을 별도 수축*하는 두 출력 모형을 (d)·(e)와 같은 학습 행·입력으로 비교한다. 방법의 수축 강도와 특징은 결과를 보기 전에 문서로 고정하거나 **훈련 모델만** 쓰는 안쪽 모델 제외 검증으로 정한다.
4. **점수와 판단:** 각 대상 모델의 두 성분 MALE을 구한 뒤 모델 동일 가중 평균, 다섯 개별 모델 점수, 4개 계열 스트레스 점수, 변화 방향 적중률, 두 성분 방향 충돌의 모델별 재현율·거짓 경보를 모두 보고한다. 결과를 한 지표로 합쳐 약한 성분을 숨기지 않는다. 출력 총량 ≤5%·≤1% 민감도에서 결론이 유지되는지 본다. 예측 기반 선택을 보조로 계산한다면 목표는 학습 모델에서만 정한 **합성 제약**으로 명시하고, 대상 모델의 실측 중앙값으로 목표를 만들지 않는다. 실제 사용자 SLO 승인, 가격 최적화 또는 운영 추천으로 부르지 않는다.

이 규약이 기존 실험과 다른 이유는 p90 E2EL·요청/s 대신 **첫 토큰과 토큰 생성의 별도 지연** 및 이 둘의 충돌을 정답으로 삼고, 모델 제외 후 같은 GPU 기종·정확한 GPU 개수 쌍의 donor 지원을 요구하기 때문이다. 다만 5개 독립 모델, 성공 실행만 남은 공개 자료, 미측정 실패 형상, 반복 측정 부재로 인해 좋은 점수가 나오더라도 방법 채택과 안전한 인프라 추천을 확증하지 못한다. 실험이 진행되면 점수 전 규약·재현 코드·모델별 결과를 별도 파일로 남기고, 기존 실패 실험의 기준을 소급 변경하지 않아야 한다.
