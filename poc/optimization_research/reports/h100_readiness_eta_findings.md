# H100/vLLM 단계별 준비시간 예측: 모델 전체 제외 탐색

2026-09-29. **학습기는 배포 판단에 채택하지 않는다.** 고정 H100의 Qwen3 네 크기에서 시작 단계별 `/health`까지 남은 시간의 90분위 상한을 학습했다. 첫 [점수 전 규약](h100_readiness_eta_protocol.md)의 단순 단계 분위수보다 pinball 손실은 낮았지만, 더 강한 **모델 크기 직선 + donor 잔차 90분위** 기준선을 첫 점수 뒤에 추가하자 학습기의 고유한 손실 우위는 사라졌다. 조건을 아는 변형의 전체 피복률은 **83.7%**, 모델 4B에서는 **62.7%**여서 이를 신뢰할 수 있는 p90 상한으로 부를 수 없다.

## 자료와 정보 경계

[고정 커밋 원본과 MIT 출처](../data/external/h100_readiness_eta/SOURCE.md)의 SHA-256 검증된 `final.jsonl`은 200개의 성공한 실험이다. Qwen3 0.6/1.7/4/8B × 캐시 조건 C0–C4 × 10회, H100 80GB 한 대와 vLLM 0.26.0의 하루 자료다. 0.6B와 8B를 보류한 분할은 모델 크기 **외삽**이다. 모델 네 개는 모두 같은 Qwen3 계열이다. C0/C1/C3은 `sweep1` 120회, C2/C4는 `rerun` 80회여서 캐시 조건의 차이는 실행 시기와 교란된다.

각 실험의 `pull_start`, `run_start`, `weights_loaded`, `compile_done`, `graph_capture_done`, `engine_ready`에서 첫 `health_ok`까지 남은 초를 예측했다. 입력은 등록 모델명의 명목 크기와 그 단계까지의 경과시간이다. 캐시 사용 변형에만 실험자가 설정한 C0–C4를 더했다. 단계 로그가 판단기에 언제 도착했는지는 기록되지 않았으므로, **기록된 단계 사건 시각에 즉시 알 수 있다**는 오프라인 가정이다. 실제 운영에는 캐시 상태의 관측 필드도 없다. `first_token`은 전체 200회에서 `health_ok` 뒤에 있었고 간격의 중앙값은 약 0.15초였지만, 이는 이 실험의 반복 프로브 결과이지 사용자 트래픽 지연이 아니다.

모델 하나의 50회 전체를 보류하는 4분할을 수행했다. 분할마다 다른 세 모델의 150회로 단계별 `QuantileRegressor`를 적합했다. 단순 기준선은 단계별 또는 단계×조건별 donor 잔여시간 p90이다. 1차 지표는 보류 모델별 50 trial의 pinball 평균을 다시 모델 동일 가중으로 평균했다. 여섯 단계는 같은 200 trial의 반복 관측이라 독립 1,200건으로 해석하지 않는다. [재현 코드](../scripts/evaluate_h100_readiness_eta.py), 첫 행별 예측 (`../artifacts/h100_readiness_eta_v1/predictions.csv`), [전체 단계·조건·모델 점수](../artifacts/h100_readiness_eta_v1/metrics.json).

## 첫 사전 게이트와 사후 강기준선

낮은 pinball이 좋다. 피복률은 실측 남은 시간이 예측값 **이하**인 비율이다. `>5초`는 예측이 실측보다 5초 넘게 짧은 비율이며 실제 사용자 SLO 위험 문턱은 아니다.

| 방법 | 캐시 조건 입력 | p90 pinball (초) ↓ | 피복률 | 과소예측 >5초 |
| --- | --- | ---: | ---: | ---: |
| 첫 단계 p90 기준선 | 없음 | 1.891 | 86.8% | 3.33% |
| 첫 학습기 | 없음 | 1.484 | 89.9% | 0.00% |
| **사후 크기 직선 + 잔차 p90** | 없음 | **1.469** | 89.3% | 0.00% |
| 첫 단계×조건 p90 기준선 | 실험 오라클 | 0.966 | 82.5% | 6.42% |
| 첫 학습기 | 실험 오라클 | 0.387 | 83.7% | 0.17% |
| **사후 조건별 크기 직선 + 잔차 p90** | 실험 오라클 | **0.274** | 82.7% | 0.92% |

첫 규약의 수치 게이트는 두 학습기 모두 통과했다: 조건 미사용 pinball 상대 **21.5%**, 조건 사용 **60.0%** 개선, >5초 과소예측 비율 비악화, 보류 모델 승리 각각 4/4·3/4였다. 그러나 이 기준선은 모델 크기를 무시했다. 점수를 본 뒤 [강기준선 계획](h100_readiness_eta_size_baseline_posthoc_plan.md)을 별도로 기록하고, 원래 점수 파일을 그대로 둔 채 같은 보류 분할에서 단순한 크기 직선과 donor 잔차 p90을 평가했다. 그 결과 학습기는 조건 미사용에서 새 기준선보다 pinball이 **1.0% 높고** 모델 승리 1/4, 조건 사용에서는 **41.4% 높고** 승리 0/4였다. 이 비교는 **사후 반증**이지 처음부터 고정된 독립 시험이 아니다. 원래 사전 게이트 통과를 뒤집어 소급 판정하지 않지만, 학습기가 강한 크기 법칙보다 낫다는 주장은 기각한다.

| 전체 여섯 단계 평균 pinball (초) | 0.6B 외삽 | 1.7B | 4B | 8B 외삽 |
| --- | ---: | ---: | ---: | ---: |
| 학습기, 조건 미사용 | 1.419 | **1.418** | 1.539 | 1.562 |
| 크기 직선, 조건 미사용 | **1.402** | 1.438 | **1.526** | **1.511** |
| 학습기, 조건 사용 | 0.385 | 0.266 | 0.425 | 0.471 |
| 크기 직선, 조건 사용 | **0.255** | **0.217** | **0.307** | **0.315** |

조건 사용 학습기의 보류 모델별 피복률은 0.6/1.7/4/8B에서 **85.0/95.7/62.7/91.3%**다. 조건 미사용도 **93.0/95.0/72.7/99.0%**로 모델마다 다르다. 전체 피복률이 목표 90%에 가까워도 4B의 부족을 가린다. 사후 직선 기준선 역시 4B에서 조건 사용 **51.0%**였으므로 어느 방법도 모델 단위의 안정적인 상한으로 확인되지 않았다. 조건 사용 학습기는 전체 >5초 과소예측을 사후 직선의 0.92%에서 0.17%로 줄였지만, 손실은 높고 그 차이를 실제 사용자 피해 감소로 환산할 SLO가 없다.

단계별 조건 사용 pinball에서 사후 직선/학습기는 `pull_start` **0.476/0.813초**, `run_start` **0.505/0.774초**, `weights_loaded` **0.487/0.565초**였다. `compile_done`에서는 **0.115/0.110초**로 학습기가 근소하게 낮았다. 형상 크기와 단계 경과시간의 추가 결합이 일찍 시작하는 단계에서 단순 크기 법칙을 이기지 못했다. 조건별로는 C0–C4 전부에서 사후 직선의 전체 단계 pinball이 낮았으며, 특히 C4는 **0.190/0.443초**였다. [사후 코드](../scripts/evaluate_h100_readiness_eta_size_baseline_posthoc.py), 행별 결합 결과 (`../artifacts/h100_readiness_eta_size_baseline_posthoc/predictions.csv`), [점수](../artifacts/h100_readiness_eta_size_baseline_posthoc/metrics.json).

## 판정과 검증 범위

첫 학습기를 기본 준비시간 모델로 채택하지 않는다. **실험 캐시 상태를 모르는 경로**에서는 강한 단순 크기 법칙과 비슷한 손실이고, **캐시를 아는 경로**에서는 손실이 더 높으며 캐시 상태 자체가 운영 관측값이 아니다. 어느 경로도 4B에서 p90 피복을 달성하지 못했다. 이 자료는 성공한 self-hosted 시작만 포함하고 VM 생성·삭제, 실패한 배포, 조치 ID, 후속 사용자 요청 SLO가 없다. 따라서 `DEPLOY/UPDATE/SCALE_OUT/SCALE_IN/KEEP`의 정답, 조치 효과 또는 실제 준비 완료시각 보증으로 사용하지 않는다. 다음 직접 검증에는 단계 로그의 `observed_at/available_at`, 앱·버전과 VM/replica별 명령·Ready 시각, 성공/실패 및 첫 사용자 요청 결과가 함께 필요하다. [수집 계약](scale_effect_data_contract_v1.md).

두 실험의 원본·규약·코드·행별 결과 해시는 각 `metrics.json`에 기록했다. 원본 200 trial과 단계 1,200행의 시각 순서·모델/조건 격자를 검사했고, 보류 모델의 라벨을 바꾸어도 그 모델의 예측이 변하지 않는 정보 경계, 캐시 특징 분리, 원래 1,200행과 사후 기준선의 일대일 결합을 **집중 테스트 7개**로 확인했다. 저장 CSV의 pinball도 별도로 다시 계산해 JSON 전체 점수와 맞았다. 점수 후 원래 규약·코드·첫 산출물을 수정하지 않았다.
