# Google 2011 배정 후 계측 피드백으로 남은 자원 피크를 예측하는 규약 v1

작성일: 2026-09-29. 이 규약과 평가 코드·합성 검사를 `00200` 검증 점수 전에 고정한다. 기존 [제출 시점 30분 피크 연구](google_2011_observed_resource_findings.md)는 `SUBMIT` 정보만 사용해 **전체** 30분 피크를 예측했다. 이번 목표는 배정 후 처음 얻은 사용량 보고를 추가해 **그 뒤의** 피크를 예측하는 별도 조건부 과제다. `00050`·`00200`에서 적격 건수와 job 수, 계측 피복은 점수 전에 이미 확인했다. 그러므로 이 검증은 완전 블라인드 신규 가설이 아니다.

## 모집단·시각 경계

- [공식 Google ClusterData 2011 v2.1](https://github.com/google/cluster-data/blob/master/ClusterData2011_2.md)의 `task_events`와 `task_usage`를 `(job ID, task index, machine ID)`로 접합한다. `00050`을 개발, `00200`을 검증, 아직 내려받지 않은 `00475`를 조건부 시험으로 지정한다. 원본 압축 파일은 공식 SHA-256 목록 (`../data/external/google_cluster_2011_2/SHA256SUM`)으로 검증한다.
- 단일 유효 `SUBMIT`과 10분 이내 단일 유효 `SCHEDULE`, 양의 불변 CPU·RAM 요청, 동일 machine ID, `SCHEDULE` 후 30분 동안 종료·실패·추방·재스케줄·요청 업데이트가 없는 task만 대상으로 한다. 사건 조각 끝이 30분 창보다 이르면 제외한다. 이는 **미래 생존을 조건으로 정한 오프라인 평가 모집단**이다.
- `task_usage`의 동일 task·machine에 대해 양의 구간 길이, 유한한 비음수 `maximum CPU rate`(0기반 열 13), `maximum memory usage`(열 10)만 사용한다. `aggregation type=1`은 하위 집계 최대값 합산 위험이 있어 입력·정답과 피복 계산에서 모두 제외한다. `usage.start < SCHEDULE`인 보고의 최대값은 사후 시작 부분만 분리할 수 없어 **입력과 결정 시각 후보에서 제외**한다. 제외된 보고는 입력 피복에도 넣지 않는다.
- 결정 시각 `d`는 `SCHEDULE+300초 ≤ usage.end ≤ SCHEDULE+600초`에 있는 **첫 유효 보고의 종료 시각**이다. 입력 계측은 `usage.end ≤ d`인 보고만 허용한다. 목표 계측은 `usage.start ≥ d`이고 `usage.end ≤ SCHEDULE+1800초`인 보고만 허용한다. `d`를 가로지르는 집계 보고는 어느 쪽에도 넣지 않는다. 결정 전 행은 `SCHEDULE`부터 `d`까지, 목표 행은 `d`부터 30분 끝까지 중복 없는 구간 피복을 계산한다.
- 주 분석에는 두 구간 각각 시간 피복 `≥80%`를 요구하고, **두 구간 모두 `≥90%`**인 집단을 점수 조정 없는 민감도로 함께 보고한다. 사전 계측 구간을 엄격히 제외한 점수 전 읽기 전용 진단의 80% 지원량은 `00050` **3,137 task·75 job**, `00200` **2,808 task·48 job**이었다. 90%는 각각 **354·26**, **1,243·29**이다. 80% 허용은 미관측 구간의 실제 피크를 놓칠 수 있으며, 라벨은 완전한 미래 20~25분 피크가 아닌 **보고된 구간의 최대값**이다. 보고 종료 시각이 실제 계측 **도착 시각**이라는 보증도 없다.

## 결정 시점 입력·정답

정답은 위 목표 보고의 CPU·RAM 최대값 두 개다. 사용량 행의 시작·종료 시각, 목표 피크, 이후 종료 사건, 이후 보고 수, 이후 coverage, machine ID와 원본 job ID는 학습 특징으로 쓰지 않는다. 결정 전에 확인 가능한 `SUBMIT`의 CPU·RAM 요청, scheduling class, priority와 `d`까지 완료된 보고의 CPU·RAM 최대, 완료 보고 수, 결정까지 걸린 초, 입력 피복만 후보 특징으로 쓴다. job ID는 분할·가중·평가에만 쓴다. 출력은 원래 배정 아래의 관측 q90 상한이다. 이것은 최소 안전 CPU·RAM 요청, VM 형상, GPU 수량, SLO 또는 scale 조치 결과가 아니다.

## 고정 후보와 기준선

모든 방식은 같은 적격 행에서 학습하며 CPU·RAM별로 예측한다. `00050`의 적격 job을 안정적인 job ID 해시로 정렬해 처음 25%를 **공동 보정**, 나머지를 적합에 쓴다. 적합과 보정 사이에 같은 job은 없다. 적합 표본에서 각 job의 task 가중치 합을 같게 한다. 후보 선택·초모수 재탐색은 하지 않는다.

1. `request_ratio`: 적합 집합에서 `미래 관측 피크 / 요청`의 job 동일 가중 q90을 구해 각 요청에 곱한다.
2. `recent_peak_margin`: `max(미래 피크 − 결정 전 관측 피크, 0)`의 job 동일 가중 q90을 과거 관측 피크에 더한다.
3. `submit_hgb`: 제출 시점 네 값만으로 같은 **남은 구간 정답**을 예측한다. 원래 30분 정답용 저장 모델을 바꾸어 재사용하지 않는다.
4. `feedback_hgb` 후보: 동일한 네 값에 결정 전 피크·피크/요청 비율·보고 수·결정 지연·입력 피복을 더한다.

두 HGB는 각 축에 `HistGradientBoostingRegressor(loss='quantile', quantile=0.9, max_iter=150, max_leaf_nodes=15, max_depth=3, min_samples_leaf=30, learning_rate=0.05, l2_regularization=1.0, random_state=42)`를 고정한다. 입력 자원·피크·비율은 `log1p`로 변환하고, 비음수 원 단위 정답을 학습한다. 네 방법 모두 **같은 보정 job**에서 `max((관측_CPU−예측_CPU)/s_CPU, (관측_RAM−예측_RAM)/s_RAM)`의 job 동일 가중 q90을 구한다. `s_CPU,s_RAM`은 적합 정답의 양의 중앙값이다. 양의 공동 여유만 각 축에 같은 정규화 배율로 더한다. 이 보정은 단순한 경험적 joint margin이며 적은 job과 분포 이동 때문에 유한표본 보장을 주장하지 않는다. 보정 전 예측도 부수 진단으로 남긴다.

## 점수·게이트·시험 잠금

축별 pinball loss `q=0.9`와 CPU·RAM **동시** 피복을 task→job 평균→job 균등 평균으로 계산한다. 종합 손실은 CPU pinball을 `s_CPU`, RAM pinball을 `s_RAM`으로 나눈 값의 평균이다. 행 균등 점수는 보조다. 가장 강한 기준선은 `request_ratio`, `recent_peak_margin`, `submit_hgb` 중 **검증 종합 손실 최저**로 정하되 후보와 비교할 때 세 기준선 중 최저값 자체를 사용한다. 후보는 아래 조건을 **모두** 통과해야 시험을 열 수 있다.

1. 적합 ≥40 job, 보정 ≥15 job, 검증 ≥30 job·1,000 task; 분할 사이 job ID 교집합 0.
2. `feedback_hgb`의 검증 종합 손실이 세 기준선 중 최저보다 **5% 이상 낮다**. 각 축 pinball은 해당 축에서 가장 좋은 기준선보다 **5% 넘게 나쁘지 않다**.
3. 후보의 검증 job 동일 가중 CPU·RAM 동시 피복 ≥**85%**.
4. 최저 종합 손실 기준선 대비 후보가 이긴 검증 job ≥**60%**. 검증에서 task 수 최다 job 하나를 제외해도 후보 종합 손실이 그 기준선보다 낮다.

검증 실패 시 `00475`는 받거나 읽지 않는다. 통과 시 코드·규약·테스트·개발 원본·적합 모델의 해시와 검증 판정을 동결한 뒤, 공식 버킷의 `00475` `task_events`·`task_usage` **두 파일만** 내려받아 공식 SHA와 대조한다. 처음 시험 읽기 전에 적격 job ≥30·task ≥1,000과 개발 job 중복 0을 확인한다. 시험은 한 번만 채점하고 **검증에서 종합 손실로 선정한 단일 기준선과, 검증에서 축별 손실로 각각 선정한 기준선**을 고정해 위 2~4번 조건을 같은 방식으로 보고한다. 시험 축별 최저 기준선을 새로 선정하지 않는다. 시험 실패를 보고 특징·문턱·후보를 바꾸어 같은 시험을 다시 사용하지 않는다. 90% 피복층은 표본·job 지원량 및 동일한 고정 예측의 점수만 보고, 주 판정을 대체하지 않는다.

이 방법은 일반적인 사용량 피드백 분위수 예측이며 학술적 최초성을 주장하지 않는다. 실제 운영으로 옮기려면 보고의 수신 시각, AI 응용 정체와 사용자 SLO, 대체 자원 형상·실제 배포 전이의 독립 결과가 필요하다.
