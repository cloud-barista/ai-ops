# CPU 사전 측정이 GPU 형상 추천에 도움이 되는가

## 결론

고정 SQLite에는 **CPU 2코어에서 입력 조건 8개를 측정한 뒤** 같은 모델의 GPU 형상을 예측하는 실험을 할 수 있는 짝이 있다. 새 모델 전체 제외 평가에서 CPU 측정은 GPU 관측이 전혀 없는 기준보다 정확했다. 하지만 CPU 2코어·8조건에 평균 **529초**가 들었고, 같은 조건의 GPU 4회 측정(평균 **4.11 GPU-wall초**)보다 예측과 추천이 대체로 나빴다. CPU 8조건을 GPU 4회 측정에 추가하면 비자명한 가상 SLO에서 성공이 **24건** 늘었지만 잘못 승인도 **11건** 늘었다. 효과는 8모델에 고르게 나타나지 않았다. 따라서 현재 자료는 CPU 사전 측정을 기본 GPU 추천 절차로 채택하거나 새로운 알고리즘의 효용·독창성을 주장할 근거가 되지 않는다.

## 짝지을 수 있는 자료와 시간 순서

CPU 2코어·replica 1과 GPU 1개·CPU 2코어를 모델 revision, 작업, 배치, 길이, 동시성, 반복 수, dataset, 입력 인코딩으로 정확히 대응시켰다. 적격 행의 중복 workload를 하나로 세면 다음과 같다.

| 캠페인 | CPU 2코어 행 | 서로 다른 CPU 조건 | GPU와 짝인 조건 | 짝이 있는 모델 |
| --- | ---: | ---: | ---: | ---: |
| `khu-hf-cpu-scaling-local` | 20 | 2 | 2 | 1 |
| `khu-hf-diverse-cpu-matrix` | 16 | 8 | 8 | 7 |
| `khu-hf-live` | 880 | 8 | 8 | 7 |
| `khu-hf-local-exhaustive` | 64 | 64 | 64 | 8 |
| `khu-hf-local-novel-matrix` | 8 | 8 | 8 | 8 |
| `khu-hf-local-space-filling` | 8 | 8 | 8 | 8 |
| `khu-hf-remote-216` | 53 | 14 | 14 | 2 |

주 실험의 인코더 8모델에는 각각 CPU **2코어·8개 입력 조건**이 있으며, 각 모델의 GPU 대상은 64개 조건 × 8개 GPU/CPU 형상이다. Qwen의 주 캠페인에는 CPU 측정이 없어 제외했다. 다른 캠페인은 반복 실행, 새 입력 조건당 CPU 측정 1개, 또는 호스트·모델·작업이 함께 바뀌는 자료라 주 모델 평가에 섞지 않았다.

64개의 CPU 측정은 모두 **해당 짝 GPU 측정이 시작되기 전에 끝났다**. 하지만 어느 모델도 CPU 8개 전부가 그 모델의 첫 GPU 측정보다 먼저 끝나지 않았다. 이 실험의 “CPU 8개를 먼저 측정” 절차는 실제 수집 순서를 재현한 것이 아니라 **오프라인에서 순서를 바꾼 가상 정책**이다. 모델 크기는 등록 시 알 수 있다는 가정으로 CPU 결과의 정적 메타데이터에서 읽었다. CPU 방법은 평가 모델의 GPU 결과값과 GPU `result_json`을 읽지 않는다.

## 방법과 비교 조건

주 캠페인의 모델 ID 하나를 통째로 제외하고, 남은 모델의 GPU 형상별 배치 p95 지연과 샘플 처리량을 학습했다. CPU 절대 성능도 남은 인코더 모델에서 학습했다. 각 donor의 CPU 잔차와 GPU 앵커 잔차는 **그 donor를 제외한 내부 교차검증**에서 만들었다. 이 짝 잔차에 Ridge 회귀를 맞춰 새 모델의 CPU 2코어 관측 8개를 GPU 1개·CPU 2코어 성능의 임시 추정값으로 바꾸고, 부드러운 커널로 64개 입력 조건에 전파했다. 임시 추정값은 실제 GPU 측정으로 고정하지 않고 관측 잡음을 크게 뒀다. 최종 8개 자원 형상은 donor 모델로만 학습한 자원 반응 모델이 예측했다.

비교는 같은 외부 모델 분할과 같은 GPU 형상 모집단을 사용한다. `GPU 4회`는 CPU와 짝이 있는 8개 조건 중 정적 입력 좌표만으로 4개를 골랐다. `GPU 4회 + CPU 8개`는 정확히 같은 GPU 4개를 쓰며 CPU 정보를 추가한다. `GPU 8회`는 CPU와 짝이 있는 동일 8개 조건의 GPU 측정이다. GPU가 없는 CPU 방법은 평가 대상 모델의 GPU 결과를 전혀 읽지 않는다. [실험 코드](../scripts/cpu_preprofile_transfer.py), [누출 검사](../tests/test_cpu_preprofile_transfer.py), [분할·예측·지표](../artifacts/cpu_preprofile_transfer_v1/metrics.json).

| 방법 | CPU wall초/모델 평균 | GPU-wall초/모델 평균 | 지연 로그 절대오차 | RPS 로그 절대오차 | 수집 목표 SLO 성공/가능 | 잘못 승인 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| GPU 관측 없음 | 0 | 0 | 0.638 | 0.629 | 250/309 | 35 |
| CPU **2코어·8조건** | 529.24 | 0 | 0.399 | 0.386 | 276/309 | 38 |
| GPU 4회 | 0 | 4.11 | 0.231 | 0.158 | 295/309 | 9 |
| GPU 4회 + CPU **2코어·8조건** | 529.24 | 4.11 | 0.235 | 0.153 | 297/309 | 13 |
| GPU 8회 | 0 | 8.27 | 0.244 | 0.143 | 298/309 | 10 |

오차는 8개 형상 중 GPU 1개·CPU 2코어 앵커를 뺀 7개 후보, 총 3,584개 행에서 계산했다. 추천은 8개 후보 전체에서 GPU 수와 CPU 코어의 사전식 순서로 선택했다. GPU 4회가 GPU 8회보다 지연 오차가 작은 것은 조건 선택과 공분산 보간의 차이이며, 예산 증가의 단조 이득을 뜻하지 않는다. CPU와 GPU wall은 **서로 다른 자원 시간**이므로 가격과 가용성을 모르면 비용으로 환산할 수 없다. CPU 8개 합계는 모델별 12.7~1,272초로 편차도 크다.

## 생성 SLO의 비자명한 선택

수집기의 원래 목표는 대부분 처리량으로 결정되므로, 별도 진단으로 각 외부 모델을 제외한 donor의 지연·RPS 20~80% 분위수에서 5×5 가상 목표를 만들었다. 같은 workload에 25개 질의가 붙으므로 독립 표본 25개가 아니다. 아래 표는 CPU/GPU 사전 측정에 사용된 **8개 입력 조건을 모두 제외**한 56개 조건/모델만 세고, 8개 형상 중 **1~7개만 실제 가능**한 3,124개 질의다. “정확한 최소 형상”은 실제 가능한 선택 가운데 GPU 수, 다음으로 CPU 코어 수가 최소인 후보와 같다는 뜻이다. [재현 코드](../scripts/evaluate_cpu_preprofile_resource.py), [세부 지표](../artifacts/cpu_preprofile_resource_v1/metrics.json).

| 방법 | 성공/3,124 | 잘못 승인 | 정확한 최소 형상 | GPU 1개로도 가능한데 GPU 2개 추천 |
| --- | ---: | ---: | ---: | ---: |
| GPU 관측 없음 | 1,748 | 262 | 1,318 | 427 |
| CPU **2코어·8조건** | 2,065 | 349 | 1,714 | 349 |
| GPU 4회 | 2,667 | 160 | 2,345 | 318 |
| GPU 4회 + CPU **2코어·8조건** | 2,691 | 171 | 2,401 | 286 |
| GPU 8회 | 2,681 | 177 | 2,347 | 332 |

GPU 4회에 CPU 측정을 더하면 성공은 24건, 최소 형상 일치는 56건 늘고 GPU 2개 과추천은 32건 준다. 동시에 잘못 승인은 11건 증가한다. 성공 차이 24건 가운데 Albert가 +19건이고 BERT L4-H256은 −17건이다. 최소 형상 일치의 +56건 중 Albert가 +47건, GPU 2개 과추천 감소 32건 중 Albert가 28건이다. 따라서 한두 모델에 집중된 **상충 결과**다. 여기서 “가능한 형상을 놓침”은 미선택뿐 아니라 잘못된 형상을 선택해 실제 목표를 위반한 경우도 포함한다.

## 연구 판단

CPU 사전 측정은 GPU 사용 전에 모델 규모를 가늠해야 하는 상황의 **실험용 보조 신호**다. 현재 데이터에서는 GPU 4회 측정보다 wall 시간이 훨씬 크고, CPU 2코어 성능의 높은 지연 상관이 실제 추천 이득으로 일관되게 이어지지 않는다. 위 방식은 CPU→GPU 잔차 보정과 기존 커널·조건부 자원 반응을 조합한 탐색적 가설이며, 독립 모델·호스트·사용자 SLO로 검증된 고유 알고리즘으로 주장하지 않는다. CPU 4/8/16코어 응답 곡선은 이 실험에 **사용하지 않았다**. 추가 CPU 측정의 값은 먼저 실제 취득 비용과 함께 별도로 검증해야 한다.
