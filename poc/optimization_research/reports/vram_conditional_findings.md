# 작업 종류·모델 크기 조건부 GPU 예약 피크 상한 실험

## 결론

경희대의 응용 요구사항 분석에 쓸 수 있는 **관측 GPU 예약 메모리 피크**의 예측폭을 개선했다. 기존 모델은 다른 작업 종류의 잔차까지 한데 모아 보정했기 때문에 encoder에는 과도한 상한을 냈다. 같은 작업 종류의 donor에 가중치를 주고 등록 모델 크기가 비슷할수록 더 큰 가중치를 주는 조건부 90% 분위수 보정을 실험했다. 고정 대역폭 `h=1`은 지원되는 encoder 8모델의 모델 제외 평가에서 기존 전역 비율 보정과 같은 모델 평균 커버리지를 유지하면서 평균 초과 배정량과 90% 분위수 손실을 줄였다.

| 평가 캠페인 | 전역 보정: 커버리지 / 초과 MiB / 손실 MiB | 조건부 `h=1`: 커버리지 / 초과 / 손실 | 작업 종류만: 커버리지 / 초과 / 손실 |
| --- | ---: | ---: | ---: |
| 주 캠페인 · 512행 | `95.1% / 162.4 / 20.85` | **`95.1% / 106.7 / 16.02`** | `90.4% / 100.7 / 16.14` |
| 새 입력 조건 · 16행 | `93.8% / 160.9 / 31.81` | **`93.8% / 99.0 / 26.78`** | `93.8% / 91.7 / 26.50` |
| 공간표본 조건 · 40행 | `95.0% / 194.5 / 29.16` | **`95.0% / 131.6 / 23.76`** | `95.0% / 124.4 / 23.38` |

`h=1`의 초과 배정은 전역 보정보다 세 캠페인에서 각각 `34%`, `38%`, `32%` 낮다. **모델 크기 가중의 추가 이득은 작다.** 작업 종류만으로 보정하는 단순 비교군이 새 입력·공간표본 조건의 분위수 손실에서는 `h=1`보다 조금 낫다. 고정 `h=2`는 주/새 입력/공간표본 분위수 손실을 `15.48/25.90/22.87 MiB`까지 더 낮추지만, 주 캠페인 모델 평균 커버리지가 `92.0%`로 내려가고 작은 BERT 모델의 커버리지가 `98% → 75%`로 떨어진다. 따라서 연구용 학습기에는 `h=1`을 저장했다. **새 모델에 대한 90% 커버리지 보장이나 최소 VRAM·OOM 판정은 제공하지 않는다.**

## 자료와 알고리즘

고정 SQLite 추출 자료 (`../data/audit_v1/measurements.parquet`)에서 성공·eligible, 로컬 CUDA GPU 1개, replica 1개, CPU affinity 2개 실행을 골랐다. 주 캠페인 `575`행·9모델에서만 Ridge와 보정을 학습했다. 새 입력 조건 `18`행, 공간표본 조건 `44`행은 평가만 했다. 이 두 캠페인은 **주 캠페인보다 먼저 수집**되었으므로 시간상 미래 검증으로 부르지 않는다. 모델 ID를 통째로 제외한 주 캠페인 8개 encoder의 512행과 해당 모델들의 새 입력 16행·공간표본 40행을 주 결과로 삼았다. 생성형 Qwen은 같은 작업 종류의 donor 모델이 없으므로 세 캠페인에서 모두 숫자 예측을 보류했다. 보류 기록은 파일 (`../artifacts/vram_conditional_v1/abstentions.csv`)에 남겼다.

등록 시 모델 파라미터 바이트 `P`를 확보했다고 **가정**한다. 이 값은 자료에서는 실행 후 `result_json`에 기록되어 있으므로 실제 API가 실행 전에 같은 메타데이터를 제공해야 한다. 요청 batch·길이·동시성·작업 종류도 정적 입력이다. 실행 후 GPU 피크와 모니터링 정보는 추론 입력으로 쓰지 않는다. 정답 `y`는 `torch.cuda.max_memory_reserved()`에 해당하는 관측 예약량이다. 캐싱 할당자의 예약량이라 **최소 실행 가능 VRAM이나 OOM 확률이 아니다**. 기존 [메모리 적합성 감사](memory_feasibility_review.md)에서 이 자료에 OOM 사례가 없음을 확인했다.

기존 [전역 상한 모델](vram_upper_findings.md)과 같은 점 예측기 `m(x)=max(P, exp(Ridge(log y; x)))`를 쓴다. 각 donor 모델 `j`를 한 번씩 제외하고 그 모델의 실행 `c`에 대한 비율 `r_jc = y_jc / m_{-j}(x_jc)`을 얻는다. 새로운 모델의 작업 종류를 `t`, 등록 파라미터 크기를 `P`라 하면 다음 가중 경험적 90% 분위수로 상한을 계산한다.

```
w_jc ∝ I(task_j = t) · (1 / donor j의 셀 수)
       · exp[-{log(P_j / P)}² / (2h²)]
U_h(x) = m(x) · max(1, weighted_quantile_0.9(r_jc; w_jc))
```

한 donor 모델이 64셀이고 다른 모델이 적은 셀만 있더라도 각 모델의 기본 총 가중치는 같다. `h=1`은 크기 비율의 로그 차이에 완만한 가중을 준다. 조건부 비교군 `h=2`와 크기 가중이 없는 `task_only`도 같은 점 모델·donor 분할을 쓴다. 전역 비교군은 모든 작업 종류의 비율을 섞는다. 모든 보정 비율은 **대상 모델 전체를 뺀 주 캠페인 donor에서만** 구했다. [코드](../scripts/evaluate_vram_conditional.py)와 [누출·보류·직렬화 검사](../tests/test_vram_conditional.py)에서 이를 확인한다.

## 전이 및 실패 사례

| 공동 제외 평가 | 방법 | 주: 커버리지 / 초과 MiB / 손실 MiB | 새 입력: 커버리지 / 초과 / 손실 | 공간표본: 커버리지 / 초과 / 손실 |
| --- | --- | ---: | ---: | ---: |
| BERT 4종 | 전역 | `100% / 292.6 / 29.26` | `100% / 343.3 / 34.32` | `100% / 361.4 / 36.14` |
| BERT 4종 | 조건부 `h=1` | `100% / 181.5 / 18.15` | `100% / 214.6 / 21.46` | `100% / 234.0 / 23.40` |
| BERT 4종+DistilBERT | 전역 | `100% / 372.3 / 37.23` | `100% / 433.7 / 43.36` | `100% / 456.9 / 45.69` |
| BERT 4종+DistilBERT | 조건부 `h=1` | `100% / 235.1 / 23.50` | `100% / 273.1 / 27.31` | `100% / 297.5 / 29.75` |

계열 공동 제외에서 과배정은 감소했다. 하지만 ALBERT를 단독 제외한 주 캠페인 `h=1` 커버리지는 **62%**, 최대 부족은 `320 MiB`다. 전역 보정의 `66% / 300 MiB`보다 나쁘다. ALBERT처럼 파라미터 바이트만으로 내부 메모리 동작을 설명하기 어려운 모델에서 한계가 남는다. 모델 평균 95%가 개별 모델의 90%를 보장하지 않는다.

고정 대역폭을 대상 결과를 보고 고르는 문제를 확인하려고, 각 바깥 모델 제외 fold 안에서 다시 donor 모델만 하나씩 제외해 `h=0.5/1/2/task_only` 중 90% 분위수 손실이 낮은 대역폭을 선택했다. 이 **donor 내부 선택법은 실패**했다. ALBERT 바깥 fold에서 `h=0.5`를 골랐고, 지원 encoder의 주 캠페인 커버리지가 `88.7%`, 손실이 `18.13 MiB`였다. 고정 `h=1`의 `95.1% / 16.02 MiB`보다 나쁘다. donor가 적을 때 자동 대역폭 선택을 채택하지 않는다. 전체 주 캠페인으로 선택하면 `h=2`가 나오지만, 위 바깥 fold 결과가 그 선택법의 불안정을 보여준다.

모델별 손실 차이를 다시 표집한 기술적 bootstrap (`../artifacts/vram_conditional_v1/paired_model_bootstrap.csv`)에서 `h=1`과 전역 보정의 90% 분위수 손실 차이는 주 캠페인 `−4.83 MiB`였고 8모델 재표집 2.5~97.5% 구간은 `−9.09~−0.51 MiB`였다. 새 입력 조건의 구간은 `−10.09~+0.36 MiB`로 0을 포함한다. **방법 후보와 대역폭을 같은 SQLite 파일럿을 본 뒤 정했으므로 이 구간은 확증적 신뢰구간이 아니다.** 같은 파일의 세 캠페인도 독립 검증 자료가 아니다.

## 산출물과 사용 경계

행별 예측 (`../artifacts/vram_conditional_v1/forecasts.csv`), 모델 제외 요약 (`../artifacts/vram_conditional_v1/supported_loomo_summary.csv`), 계열 공동 제외 결과 (`../artifacts/vram_conditional_v1/aggregate_metrics.csv`), 모델별 결과 (`../artifacts/vram_conditional_v1/per_model_metrics.csv`), donor 내부 선택 기록 (`../artifacts/vram_conditional_v1/donor_selection.csv`), 연구용 `h=1` 학습기 (`../artifacts/vram_conditional_v1/research_estimator.joblib`), [입력·코드·모델 해시](../artifacts/vram_conditional_v1/manifest.json)를 저장했다. 학습기는 고정 로컬 GPU/CPU 프로필, 학습에 없던 모델, 같은 작업 종류 donor 2개 이상만 받는다. 이 결과는 메모리 요구 분석의 **연구 신호**이며 자동 GPU 형상 추천이나 운영 OOM 안전 판정에는 연결하지 않는다.

```bash
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python scripts/evaluate_vram_conditional.py
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python -m unittest discover -s tests -p 'test_vram_conditional.py' -v
```
