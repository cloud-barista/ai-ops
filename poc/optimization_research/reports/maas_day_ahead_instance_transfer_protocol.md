# Philly 전날 잔차 보정의 Alibaba MaaS 인스턴스 전이: 탐색 규약

2026-09-29. 이 규약은 [Philly 새 기계의 기계+GPU 슬롯 보정](philly_slot_day_calibration_holdout_findings.md)을 **다른 공개 GPU 계측 도메인**의 `전체 인스턴스+개별 인스턴스` 계층으로 옮길 때의 수식과 판정을 정한다. Alibaba MaaS 원본의 기존 [모델 시험](maas_instance_risk_findings.md)에서 시험일 145–146의 성능과 라벨 집계를 이미 봤으므로, 이번 결과는 **후향 탐색**이다. 방법을 고른 뒤 같은 시험일을 독립 검증이라고 부르지 않는다.

## 자료·정답·지원량

[Alibaba MaaS 공식 주간 5분 자료](https://github.com/alibaba/clusterdata/blob/8a6295f9779ddc019add669eeca49c5f9f77b3a7/cluster-trace-v2026-maas/README.md)의 21개 조각 전체 감사와 고정 약 1% ID 표본을 [기존 원본 감사](../data/external/alibaba_maas_2026/SOURCE.md)대로 재사용한다. `evaluate_maas_instance_risk.py`의 자료 적격성·시점 정의를 변경하지 않는다. 판단 `d=t+600초`의 최근 세 창이 유일하고 유효하며, `d`부터 30분의 미래 여섯 창도 유일하고 유효한 판단만 평가한다. 정답은 여섯 창 중 **SM 사용률≥80% 또는 GPU 메모리 사용률≥90%**가 한 번이라도 관측되면 1이다. 현재 창의 두 임계값이 모두 미만인 **정상층**만 주 분석으로 사용한다. 이는 사용자 SLO나 GPU 부족/OOM, 실제 VM 스케일 명령의 정답이 아니다.

기존 학습 상대일 140–143에서 Beta(1,1) 평활한 `any_recent_threshold` 조건별 양성률을 고정 기본확률 `p₀`로 쓴다. 기존 검증 144일에서 이 기준선이 선택됐는지 재확인하고 저장 시험 예측과 전 행 일치시킨다. 기준선 선택·계수에는 시험 145–146일을 쓰지 않는다.

지원량은 시험일 현재 정상층 전체 **≥50,000행·새 초과 사건≥1,000건**과, 그중 전날 입력 시각으로 정한 적격 1시간 앵커가 **인스턴스당 ≥6개**인 행 **≥20,000건·새 초과 사건≥500건**을 모두 요구한다. 한 조건이라도 실패하면 확률을 채점하지 않는다. 1시간 앵커는 인스턴스×UTC 시간에서 가장 이른 적격·현재 정상 판단이며, 정답값을 보고 바꾸지 않는다. 단회 지원량에는 라벨의 집계 수만 사용한다.

## 고정 전이 방법과 같은 정보량 비교

매 시험일 00:00에 전날 앵커 중 `판단+30분 정답 창+5분 전달 가정≤당일 시작`인 완전 결과만 쓴다. 이를 한 시간의 다른 판단으로 소급 대체하지 않는다. **두 보정법 모두 같은 전날 결과**를 사용한다.

1. **기본확률 `p₀`**: 선택된 기존 학습 표.
2. **전역 전날 정확한 절편**: 전날 모든 적격 인스턴스 앵커의 `p₀`와 `y`에서 `Σ[y−sigmoid(logit(p₀)+δ)]−20δ=0`을 풀고 `δ∈[-0.5,0.5]`로 자른다.
3. **전역+인스턴스 잔차**: 같은 전역 절편을 먼저 적용한 앵커 예측 `p_g`에서, 해당 인스턴스의 `δ_i=clip(Σ(y−p_g)/(Σp_g(1−p_g)+20),−0.5,0.5)`를 계산한다. 인스턴스의 전날 앵커가 없으면 `δ_i=0`; 최종 확률은 `sigmoid(logit(p₀)+δ+δ_i)`이다.

벌점 20과 이동 한계 0.5는 Philly에서 고정했던 값 그대로이며 이번 MaaS 점수를 보고 튜닝하지 않는다. 전역 기준선과 후보가 같은 앵커 라벨을 사용한다. 현재 사용률 초과층은 보조 표로만 점수화하지 않으며, 주 분석의 샘플을 미래 정답이나 예측 오차로 다시 고르지 않는다.

## 지표와 후속 결정

주 지표는 현재 정상층 145–146일 **같은 행의 Brier**, 보조 지표는 날짜별 Brier, 인스턴스 동일가중 Brier, AP, 전날 앵커 ≥6개 행의 Brier, 인스턴스별 승패다. `전역+인스턴스 잔차`가 **두 비교기 각각보다 전체 Brier 상대 ≥5% 낮고, 두 날 각각 낮으며, 인스턴스 동일가중 Brier와 AP(허용 하락 0.005)도 악화하지 않고, 앵커 ≥6개 층에서 전역 절편보다 Brier 상대 ≥5% 낮아야** 새 ID 해시 bucket 1의 별도 확인 자료 수집을 검토한다. 지원량과 이 조건을 모두 통과해도 지금 집합의 결과는 탐색이다. 실패하면 새 bucket 1을 이 후보 때문에 열지 않는다.

실제 앱 종류는 주간 인스턴스 표에 없고, 공개 원본에는 명령 발행·Ready·사용자 요청별 지연·반사실 결과가 없다. 이번 계층 보정이 성공하더라도 AI-App의 `SCALE_OUT/IN` 정책으로 승격하지 않는다.
