# BurstGPT 요청 시점 출력 토큰 분위수 평가 규약

2026-09-28. 시험 구간의 모델별 예측 손실을 계산하기 전에 고정한다. 공개 자료의
행 수·누락·출력 분포는 사전 품질 감사에서 이미 확인했다. 이 검증은 새로운
알고리즘의 학술적 독창성이나 실제 VM·GPU 증감 효과를 입증하지 않는다.

## 목표와 원자료

- [BurstGPT v2.0 `BurstGPT_3.csv`](../data/external/burstgpt_v2/SOURCE.md)의
  SHA256은 `2299986a07388aa303ec2c41d1131e756db650a39ed6ef9dfe7cc3d7f9a43b8f`이다.
  5,344,021행, 상대일 225–334의 원본 시각을 사용한다. 상대일은
  `floor(Timestamp / 86400)`이며 실제 달력 날짜는 공개되지 않았다.
- 요청 시점에 입력 토큰 수를 알고 있다고 가정하고 `Request tokens > 0`인
  행만 **입력 측 규칙**으로 선정한다. 대상은 4,956,059건이며 그중 출력 0은
  1건이다. 상태 열이 없으므로 이를 성공 요청의 완전한 집합이라고 부르지
  않는다. 목표값은 기록된 `Response tokens`의 90% 분위수이다.
- 특징은 `Model`, `Log Type`, `log1p(Request tokens)`뿐이다. `Timestamp`는
  순서·상대일·과거 피드백 선택에만 사용한다. `Response tokens`,
  `Total tokens`, `Elapsed time`, `Session ID`는 특징에서 제외한다.
  `Elapsed time=0`의 뜻이 불명확하므로 완료 시각 추정에도 사용하지 않는다.

## 시계열 경계와 피드백

- 명목 학습 기간: 상대일 225–294. 검증: 295–314. 시험: 315–334.
- **일 단위 배치 피드백 가정:** day `d` 시작 전에는 요청일이 `d-2`
  이하인 행의 출력 로그가 모두 전달됐다고 가정한다. 최근 이력은 요청일
  `d-8`부터 `d-2`까지의 7일이다. 같은 날과 전날의 결과는 쓰지 않는다.
  실제 완료일·로그 전달 지연은 자료에서 확인할 수 없으므로, 이 가정이
  개별 응답 완료 후 최소 24시간 경과를 보장하는 것은 아니다.
- 최초 고정 모델과 정적 분위수는 검증 시작 day 295에 이 배치 규칙상
  가용한 day 225–293만 학습한다. day 294는 명목 학습 기간에 속하지만
  피드백 경계로 제외한다. 검증이나 시험 중 모델 가중치는 다시 학습하지
  않는다.
- 적응형 잔차는 모델 학습에 포함되지 않은 day 295 이후의 행에 대해서만
  계산한다. day `d`의 잔차 보정에 `d-8`..`d-2`의 목표값과 고정 모델
  예측값을 쓴다. 시험 중에도 이전 시험일 중 이 창에 들어온 결과만
  추가할 수 있다.

## 후보와 고정 하이퍼파라미터

모든 경험적 분위수는 NumPy `quantile(..., 0.9, method="higher")`로
계산한다. 예측값은 최소 0으로 제한한다. 코호트는 `Model × Log Type`이다.

1. `static_global`: day 225–293 전체의 출력 토큰 p90.
2. `static_cohort`: 같은 기간의 코호트별 출력 토큰 p90.
3. `rolling_cohort`: 배치 가정으로 가용한 최근 7개 요청일의 코호트별 p90.
4. `rolling_bin`: 같은 7개 요청일의 코호트 × 입력 토큰 고정 구간별 p90.
   구간은 `1–64`, `65–256`, `257–1024`, `1025–4096`, `>4096`이다.
   셀에 100건 미만이면 같은 창의 코호트 p90을 사용한다.
5. `hgb_base`: `HistGradientBoostingRegressor`의 직접 p90 예측.
   범주 특징 두 개, 반복 140회, 최대 잎 15개, 최소 잎 표본 60건,
   L2 10, 학습률 0.05, 조기 중단 끔, seed 42. 학습 기간에서만 범주
   번호를 정하고 모르는 값은 결측 범주로 넣는다.
6. `hgb_adaptive`: 고정 `hgb_base` 예측에 가용한 과거 7일의
   **코호트별 학습 외 잔차 p90**을 더한다. 코호트 잔차 100건 미만이면
   전체 잔차 p90으로, 그마저 100건 미만이면 0으로 대체한다.

검증 day 295–302는 잔차의 학습 외 7일 이력을 만드는 준비 기간이다.
**day 303–314의 모든 동일 요청**에서 여섯 후보를 비교한다. 이 기간의
하루별 평균 p90 pinball 손실을 12일에 동일 가중치로 평균한 값이 최소인
방법을 시험 전 선택한다. 동률이면 요청 가중 손실, 이어 위 번호 순서를
사용한다. 선택과 코드·규약·원본·모델·검증 산출물 해시를 별도 manifest에
고정한 뒤 시험 점수를 계산한다. 시험을 보고 방법·분할·문턱을 수정하지
않는다.

## 보고할 점수와 해석

- 요청 가중 p90 pinball 손실(토큰), **일별 동일 가중** pinball 손실,
  `P(실제 출력 ≤ 예측)`, 평균 예측 토큰 수를 모두 보고한다.
- 전체·4개 코호트·각 시험일·연속 5일 블록의 점수를 보고한다. 선택된
  방법과 모든 기준선을 동일한 시험 요청에서 비교한다.
- 입력 토큰이 요청 수락 전에 확정된다는 가정이 필요하다. 공개 자료에는
  모델 아키텍처·KV 캐시 계수·GPU 메모리·VM 사양·사용자 SLO·배포/스케일
  행동이 없다. 출력 토큰 상한의 통계적 예측은 KHU의 요구사항 분석을
  위한 길이 신호이며, 이 자료만으로 인프라 형상이나 행동 효용을
  승인할 수 없다.
