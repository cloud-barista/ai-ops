# MaaS 상태별 전날 확률 보정: 새 인스턴스 ID 단회 시험

2026-09-29. **판정: `NEW_ID_STATE_DAY_NO_GO`.** [이미 공개된 bucket 0·1에서 설계한 보정법](maas_state_day_calibration_development.md)을 [원본 접근 전 고정한 규약](maas_state_day_calibration_new_id_protocol.md)대로 새 bucket 2 ID **795개·51,577개 현재 정상 판단**에 한 번 평가했다. 후보의 행 Brier는 저장 모델 `0.025798→0.025445`로 **1.37%**, 강한 전역 전날 절편 `0.025710→0.025445`로 **1.03%** 낮아졌다. 두 날짜 모두 낮았지만 사전 **각각 2%** 기준에 못 미쳤고, ID 재표집 구간에도 0이 포함됐다. 따라서 위험 입력으로 채택하지 않는다.

## 자료와 정보 경계

[Alibaba 공식 주간 5분 추적](https://github.com/alibaba/clusterdata/blob/8a6295f9779ddc019add669eeca49c5f9f77b3a7/cluster-trace-v2026-maas/README.md)의 21개 조각·원본 140,906,827행을 기존 감사의 크기·ETag·CRC32·SHA-256으로 다시 검증했다. 원본 ID 해시 `%100==2`인 [새 표본](../data/external/alibaba_maas_2026_bucket2/SOURCE.md)은 46,753개 ID·1,425,039행이다. bucket 0·1과 원시 ID 해시 교집합이 없고, 추출 감사 (`../data/external/alibaba_maas_2026_bucket2/instance_week_5min_bucket2_audit.json`)의 무결성 검사가 통과했다. [접근 전 release manifest](../artifacts/maas_state_day_calibration_holdout_v1/release_manifest.json)는 규약·추출/평가 코드·시험·저장 모델과 이전 개발 결과의 해시를 고정했다.

확률 점수 전에 [지원량 감사](../artifacts/maas_state_day_calibration_holdout_v1/support_audit.json)에서 현재 정상 후보 62,534개 중 미래 여섯 창이 완전한 판단 **51,577개(82.48%)**, 신규 초과 **2,297개**, 양성 ID **256개**를 확인했다. 145일은 24,935판단·1,401사건, 146일은 26,642판단·896사건이었다. 각 날짜의 전날 완료 라벨은 상태 0·1의 행·양성·음성 하한을 모두 충족했다. 사전 지원량 기준 일곱 개가 전부 참이어서 단회 점수화를 진행했다.

정답은 판단 이후 30분의 여섯 5분 창에서 SM 사용률≥80% 또는 GPU 메모리 사용률≥90%가 한 번이라도 관측되는 사건이다. 현재 정상·완전 과거/미래가 있는 행만 평가했다. 저장된 단일 로지스틱을 재학습하지 않았다. 매 UTC일 00:00에 **전날 판단의 정답 창이 완료되고 가정한 5분 전달 지연도 끝난 행만** 이용했다. 후보는 전날 `any_recent_high` 상태별 Beta 발생률과 학습 기간 상태별 발생률의 로그오즈 차를 저장 모델에 더한다. 비교기는 저장 모델, 같은 전날 라벨을 쓴 전역 정확한 절편, 전날 상태별 단순 Beta 표, 상태별 정확한 절편이다.

주 후보의 저장 모델·전역 절편·단순 Beta 대비 Brier 감소는 각각 **1.37%·1.03%·4.51%**였다. ID 단위 짝지은 2,000회 재표집(seed 43)의 `후보−저장 모델` 행 Brier 차는 **−0.000352**, 95% 백분위 구간 **[−0.000754, 0.0000108]**이다. `후보−전역 절편`은 **−0.000265**, 구간 **[−0.000632, 0.0000724]**였다. 두 상한 모두 0보다 높다. 후보와 상태별 정확한 절편의 전체 차는 작고, 후자가 146일에는 조금 더 낮았다. [전체 결과와 여섯 채택 조건](../artifacts/maas_state_day_calibration_holdout_v1/results.json)에서 **전체 2% 감소**와 **ID 재표집 상한 <0**의 두 조건이 거짓이다.

## 검산과 해석

[독립 검산 코드](../scripts/verify_maas_state_day_calibration_holdout.py)는 저장된 51,577행의 Brier·ID 동일가중 Brier·AP·날짜별 점수·재표집 구간을 다시 계산했다. 원시 표본에서 같은 저장 모델과 전날 만기 라벨만으로 여섯 방법의 확률을 별도로 재생하자 최대 절대 차가 모두 **0**이었다. [검산 결과](../artifacts/maas_state_day_calibration_holdout_v1/independent_verification.json). 새 ID를 보고 방법이나 문턱을 조정하지 않았고, 단회 평가기는 결과 재실행을 거부한다.

후보의 평균 점수 개선은 관측됐지만 **사전 채택 폭과 ID 간 불확실성 기준을 충족하지 못했다**. 개발·시험 ID가 다르더라도 같은 MaaS 서비스의 같은 주간이다. 정답 전달 시각은 실제 기록이 아닌 창 완료+5분 가정이며, 중첩 5분 판단도 독립 표본이 아니다. 원본에는 사용자 요청별 SLO, VM 생성·Ready, 실제 증감 명령과 대체 조치 결과가 연결되지 않는다. 관측 GPU 위험 예측을 `SCALE_OUT/IN` 조치 효과나 승인 정답으로 취급하지 않는다. 로그오즈·Beta 보정 요소의 학술적 최초성도 주장하지 않는다.
