# BurstGPT 앞선 기간의 출력 토큰 p90 규칙 재현

2026-09-28. [`BurstGPT_3.csv` 분석](burstgpt_output_tokens_findings.md)의 **사후 비교**에서 유망했던 `rolling_bin`을 고정하고, 같은 서비스의 더 이른 [`BurstGPT_1.csv`와 `_2.csv`](../data/external/burstgpt_v2_12/SOURCE.md)에서 다시 평가했다. [사전 규약](burstgpt_12_output_tokens_protocol.md)은 `_2`의 시험 예측 손실을 계산하기 전에 정했고, [`selection_manifest.json`](../artifacts/burstgpt_12_output_tokens_v1/selection_manifest.json)에 원본·규약·코드·학습 모델 SHA256과 주 방법을 고정했다.

## 결론

**상대 손실의 재현 기준은 통과했다.** 고정 `rolling_bin`의 시험 60일 동일 일 가중 p90 pinball 손실은 28.877토큰으로 최근 코호트 기준선 31.319토큰보다 **7.80% 낮았다**. 사전 기준에 지정한 다른 기준선보다도 낮고, 최근 코호트 기준선 대비 10일 블록 6개 중 5개 및 전체 코호트 4개 모두에서 우세했다.

**안전한 상한 기준은 실패했다.** 3,784,215개 요청의 `rolling_bin` 경험적 포괄률은 **82.90%**로 명목 p90의 90%에 못 미쳤다. 첫 10일 블록은 76.51%, `GPT-4 | API log`는 73.54%였다. 이 규칙을 출력 길이의 신뢰할 만한 상한이나 GPU/VM 용량 판단에 채택하지 않는다. 손실 개선과 용량 상한 적합성은 별도 판단이다.

## 모집단과 시험 경계

원본 두 파일은 총 5,288,173행이다. 입력 측 규칙인 `Request tokens > 0`으로 선정하면 첫 파일 1,404,310행, 둘째 파일 3,784,215행이다. 이 중 출력 0은 각각 16·2행이며, 결과를 보고 제거하지 않았다. 고정 모델과 정적 기준선은 첫 파일 day 0–59의 **1,389,856행**으로만 학습했다. Day 60의 14,454개 적격 행은 고정 학습에서 제외했고, day 62 예측부터 최근 이력에 포함했다. 둘째 파일 day 61–120의 적격 요청 전부가 보류 시험이다.

모델·로그 유형·입력 토큰 수만 요청 시점 특징으로 사용했다. 각 예측일 `d`의 최근 이력은 요청일 `d−8`부터 `d−2`까지다. 이는 완료·로그 전달 시각이 없는 원본에 부여한 **일 단위 배치 피드백 가정**이며, 실제 운영에서 응답이 그때까지 확정됨을 입증하지 않는다.

## 고정된 시험 점수

| 방법 | 동일 일 가중 손실 ↓ | 요청 가중 손실 ↓ | 포괄률 | 평균 예측 토큰 |
| --- | ---: | ---: | ---: | ---: |
| **최근 코호트×입력 구간 `rolling_bin` — 사전 고정** | **28.877** | **12.640** | 82.90% | 65.14 |
| 최근 코호트 p90 | 31.319 | 13.923 | 82.45% | 65.51 |
| 고정 HGB p90 | 34.004 | 16.959 | 92.60% | 125.94 |
| 정적 코호트 p90 | 39.115 | 21.072 | 97.90% | 209.69 |
| 정적 전체 p90 | 60.821 | 30.346 | 97.64% | 277.00 |

손실 단위는 출력 토큰이다. HGB와 정적 방법의 높은 전체 포괄률도 그룹별 안전 기준을 만족하지 않는다. 예를 들어 HGB의 `GPT-4 | API log` 포괄률은 35.12%, 정적 코호트의 `GPT-4 | Conversation log`는 67.32%다. 비교 방법 중 어느 것도 전체·모든 10일 블록·모든 코호트의 90% 포괄률을 동시에 만족하지 않았다. 주 방법을 시험을 본 뒤 다른 방법으로 바꾸지 않았다.

| 시험일 | 적격 요청 | `rolling_bin` 동일 일 가중 손실 | 최근 코호트 손실 | `rolling_bin` 포괄률 |
| --- | ---: | ---: | ---: | ---: |
| 61–70 | 1,168,824 | 7.478 | **7.332** | 76.51% |
| 71–80 | 1,242,218 | **9.468** | 9.835 | 90.77% |
| 81–90 | 1,065,860 | **19.830** | 27.123 | 79.64% |
| 91–100 | 90,698 | **44.079** | 48.402 | 96.37% |
| 101–110 | 3,214 | **51.257** | 53.169 | 88.61% |
| 111–120 | 213,401 | **41.152** | 42.056 | 82.50% |

후반부 101–110일은 3,214행뿐이다. 날짜를 같은 비중으로 평균하는 규약에서는 이 희소 기간도 다른 10일과 같은 비중을 갖는다. 이 값은 실제 운영량의 평균 손실을 뜻하지 않으므로 요청 가중 점수도 함께 제시했다. 날짜별 표본 수·손실·포괄률과 네 코호트별 정확한 값은 [`test_metrics.json`](../artifacts/burstgpt_12_output_tokens_v1/test_metrics.json)에 있다. 네 코호트의 `rolling_bin` 포괄률은 ChatGPT API 82.91%, ChatGPT 대화 89.95%, GPT-4 API 73.54%, GPT-4 대화 89.57%다.

## 시험 고정과 검산

- 평가 전 manifest SHA256: `a86d06570e19164ec627070411a00ceb9516fbbe636128121b448398310c6887`. 원본 `_1`/`_2` SHA256, 규약 `1cd43727edc0165f837bde825333a9d49f4b2beb7a124ffbcd07a2723c5bbb45`, 코드 `91e38010452870ede9628490abfef8982a9594b7e7b37a38cb1317f76a8ad600`, 학습 모델 해시가 들어 있다. 시험 함수가 이 값들을 다시 검사한 뒤 점수화했다.
- 행별 예측 (`../artifacts/burstgpt_12_output_tokens_v1/test_predictions.parquet`) 3,784,215개의 원본 행 번호·시각·모델·호출 유형·입력·출력 토큰이 `_2`의 적격 행 전부와 정확히 일치했다. 저장된 행별 예측에서 다섯 방법의 요청 및 일별 손실·포괄률을 별도 코드로 재계산했고 점수 JSON과 일치했다. Day 61·62·81·101·120의 코호트별 첫 요청 90개에 대해서도 별도 원본 조회로 `rolling_bin` p90을 재계산해 불일치가 없었다.
- 추가 읽기 전용 독립 감사에서 원본 3,784,215행의 키·정답, 보고 지표 1,495개, 비어 있지 않은 day×cohort×입력 구간의 최근 이력 예측 셀 858개를 재구성해 모두 일치했다. 이 중 136개는 표본 수 부족에 따른 코호트 fallback 셀이었다.
- [합성 단위 테스트](../tests/test_burstgpt_12_output_tokens.py) 6개가 통과했다. 요청 측 적격 조건, day60 피드백 경계, 미래 라벨 불변성, 고정 토큰 구간, 손실·게이트 분리, 10일 블록 요약을 확인한다.

재현 명령:

```bash
python -m unittest discover -s tests -p test_burstgpt_12_output_tokens.py
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 python scripts/evaluate_burstgpt_12_output_tokens.py prepare --output artifacts/burstgpt_12_output_tokens_repro
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 python scripts/evaluate_burstgpt_12_output_tokens.py test --output artifacts/burstgpt_12_output_tokens_repro
```

같은 산출물 경로에 기존 manifest가 있으면 `prepare`는 덮어쓰지 않고 거부한다. 코드나 규약을 바꾸려면 별도 버전과 새 시험 자료가 필요하다.

## 연구 해석의 한계

이 결과는 같은 서비스의 **미래 기간 `_3`에서 발굴한 규칙을 과거 기간 `_1/_2`에 역방향 적용**한 재현성이다. 출처가 독립적인 서비스나 시간순 미래 배포 검증이 아니다. 게다가 원본에는 성공 상태, 실제 출력 로그 가용 시각, 프롬프트 의미, 모델의 정확한 버전, 배정 GPU/VM, 지연 SLO, 용량 부족, 배포·스케일 행동과 그 효과가 없다. 통계적 출력 토큰 길이는 경희대 응용 요구 분석의 한 신호가 될 수 있지만, 이 자료만으로 CPU·GPU·메모리·노드 수 또는 `DEPLOY`/`SCALE_OUT`/`SCALE_IN` 판단을 학습·검증할 수 없다. 입력 길이에 따른 출력 길이 분위수 추정과 최근 창 보정은 기존 연구 주제이므로 학술적 독창성도 주장하지 않는다.
