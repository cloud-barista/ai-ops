# SwissAI 요청 오류 상태 위험: 점수 전 규약

2026-09-28. 경희대의 배포·제어 판단에 **관측된 오류 상태의 사전 위험 신호**를 더할 수 있는지 탐색한다. 정답은 공개 로그의 요청별 `status == ERROR`다. `DEFAULT`가 실제 서비스 성공이나 사용자 SLO 충족을 뜻한다고 가정하지 않는다. 오류의 원인, VM 부족, 배포·스케일 행동의 효과는 이 자료로 알 수 없다.

## 자료와 동결 경계

- 원본은 [SwissAI 전량 감사](swissai_trace_full_audit.md)의 `requests_sorted.parquet`다. 16,329,237행, SHA256 `d5c2bf4cc038f936a9713f8fc7c0430703ddd1c03ed0518fb65aaf68e160997b`다. 원시 모델 문자열은 출력 산출물에 기록하지 않는다.
- UTC 생성 시각으로 학습 `2025-05-16 00:00` 이상 `2025-08-16 00:00` 미만, 검증 `2025-08-16` 이상 `2025-09-16` 미만, 시험 `2025-09-16` 이상 `2025-10-24` 미만을 고정한다. 그 앞 24시간인 5월 15일은 과거 이력의 준비 구간이다. 요청 수만 읽은 사전 감사에서 각각 7,965,677 / 300,467 / 736,928행이다. 시험 날짜의 요청량이 매우 불균일하고 9월 28–29일에는 기록이 없으므로 요청 수와 달력 블록을 모두 보고한다.
- 이 날짜와 방법을 고르기 전에 첫 두 학습 월의 오류 건수는 이미 점검했다. 5월 16일–7월 16일은 983,352/2,053,906, 7월 16일–8월 16일은 734,983/5,911,771이었다. 시험 구간의 오류율·방법 점수는 아직 계산하지 않았다. 이전 사전 감사가 시험 열을 메모리로 읽기는 했으나 오류 분포를 집계하거나 출력하지 않았다. 따라서 엄격한 파일 비열람 검증이 아니라 **시험 점수 전 고정 평가**다.
- 로그는 완료시각 대신 실제 결과 전달시각을 제공하지 않는다. 과거 오류 이력은 `finished_utc_us + 1시간` 이후에만 사용할 수 있다고 **가정**한다. 더 보수적으로 각 UTC 시간의 요청은 해당 시간 시작 전에 가용한 이력만 쓴다. 완료시각이 없는 요청은 이력에 넣지 않지만, 기록된 상태 자체는 대상 정답으로 평가한다. `reported_input_tokens`의 요청 시점 가용성이 불명확하므로 입력에서 제외한다.
- 원본의 시간대 없는 완료시각은 전량 감사처럼 UTC로 해석한다. 별도 민감도에서 **시간대 없는 완료시각의 결과를 과거 이력에서 전부 제외**하고, 같은 고정 예측기를 다시 점수화한다. 이는 대체 시간대가 맞다는 가정이 아니라 완료시각 해석 위험에 대한 보수적 하한이다.

## 고정 질문과 비교법

질문은 **현재 시점에 알 수 있는 모델 ID와 과거 도착·완료 상태로 다음 요청의 기록상 `ERROR` 확률을 단순 기준선보다 정확하게 추정하는가**다. 정답을 보고 모델별 원인이나 자원 행동을 추론하지 않는다.

각 요청의 생성 시간 직전까지 가용한 전역·동일 모델 오류/전체 완료 수를 과거 1시간, 24시간, 전체 이력으로 계산한다. 생성된 요청 수의 직전 1시간 전역·동일 모델 값, UTC 시간·요일도 입력한다. 같은 생성 시간대의 요청은 **같은 이전 시간까지의 이력**을 받는다. 모형에는 대상 요청의 `status`, 완료시간, 출력 토큰, 같은 시간대의 사후 결과를 넣지 않는다. 학습기는 일별 최대 5,000건을 고정 시드 42로 뽑아 학습하는 단일 `HistGradientBoostingClassifier(max_iter=100, max_leaf_nodes=15, max_depth=4, learning_rate=0.05, min_samples_leaf=200, l2_regularization=10, early_stopping=False, random_state=42)`다. 학습에서는 표본의 미래 정답이 가용 이력에 들어가지 않도록 시간 결합을 먼저 수행한다. 검증·시험은 전량 점수화한다.

강한 단순 비교 네 가지는 다음과 같다. 전체 학습의 오류율에 Beta(1,1) 수축을 적용한 **고정 전역률**; 학습 완료 결과 중 모델별 오류 수를 전역률의 100 pseudo-count로 수축한 **고정 모델률**; 과거 24시간 전역 오류 수를 고정 전역률의 1,000 pseudo-count로 수축한 **최근 전역률**; 과거 24시간 모델별 오류 수를 최근 전역률의 100 pseudo-count로 수축한 **최근 모델률**이다. 정적 기준의 학습 사건은 검증 시작까지 결과가 가용한 것만 쓴다. 새 모델은 전역률로 돌아간다. 검증의 요청 가중 Brier가 가장 낮은 단순 기준선을 시험의 주 비교로 고정한다. 학습기는 검증 점수로 초모수를 바꾸지 않는다.

**지원범위 인식 오류 위험 후보**는 학습기의 확률과 함께 `ACCEPT/ABSTAIN`을 출력한다. 다음 세 조건이 모두 참이면 수락한다: (1) 해당 모델의 지난 24시간 가용 완료 결과가 100건 이상, (2) 최근 가용 완료 결과가 6시간 이내, (3) 학습 시점에 가용한 해당 모델 결과가 100건 이상이거나 지난 24시간 결과가 500건 이상. 이 문턱은 시험·검증 오류 점수를 보기 전에 고정한다. 수락 시 학습기 확률, 보류 시 검증 선택 단순 기준선 확률로 **혼합 위험 점수**를 낸다. 이 보류는 배포 명령을 자동으로 취소한다는 뜻이 아니라 연구 신호의 근거 부족 표시다. 게이트의 기여는 같은 수락 행에서 학습기와 기준선을 비교하고, 전체 행에서 혼합 점수를 게이트 없는 학습기 및 기준선과 비교해 확인한다. 피드백 지연, 모델별 위험, 최근 도착량을 결합한 구체적 구성은 평가 대상 가설이며 관련 온라인 위험·선택 예측 원리의 최초성은 주장하지 않는다.

## 품질·평가 기준

검증과 시험의 기록 상태는 `DEFAULT` 또는 `ERROR`만 허용한다. 각 구간은 요청 10만 건 이상, 오류와 비오류가 각각 1,000건 이상이어야 한다. 시험의 7일 완전 블록 다섯 개는 각각 1,000건 이상이어야 한다. 미달하면 해당 점수를 채택 근거로 쓰지 않고 원인을 보고한다. 비어 있는 날짜를 요청 0건 또는 정상 운영이라고 해석하지 않는다.

주 지표는 **전량 요청 가중 Brier**이며 로그손실, 평균 정밀도(AP), 관측 오류율·평균 예측확률, 7일 블록별 Brier 및 모델이 학습에 있었는지에 따른 층별 Brier를 함께 보고한다. 날짜별·익명 모델별 요청/오류 빈도와 naive 완료시각 이력 제외 민감도도 보고한다. 모델 종류·날짜 구성 이동이 큰 만큼 블록 단위 오차도 본다. 기본 학습기의 탐색적 성공 조건은 시험 Brier가 검증 선택 단순 기준선보다 상대 5% 이상 낮고, 다섯 완전 시험 블록 중 최소 4개에서 더 낮으며, 학습에 있던 모델/새 모델 두 층이 각각 1,000건 이상이면 둘 다 악화하지 않는 것이다. **지원범위 후보**의 별도 성공 조건은 수락률 20% 이상과 수락 10,000건 이상, 같은 수락 행에서 기준선보다 Brier 상대 5% 이상 낮음, 전체 혼합 점수가 게이트 없는 학습기 및 기준선 양쪽보다 Brier 상대 2% 이상 낮음이다. 어느 조건이든 실패하면 해당 방법을 경희대 판단기에 채택하지 않는다. 성공해도 다른 서비스·시간의 독립 검증이나 실제 `DEPLOY/UPDATE/SCALE_OUT/IN` 정책 효과는 입증되지 않는다.

원본과 규약·코드·모형의 SHA256, 검증에서 선택한 기준선을 `prepare` manifest에 기록한 뒤 별도 `test` 단계가 해시를 확인하고 시험 점수를 계산한다. 각 단계는 기존 manifest·시험 결과를 덮어쓰지 않는다.
