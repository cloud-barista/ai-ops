# 저장된 GPU 형상 모델의 선택 결과: 사후 감사

## 결과

저장된 `performance_v1` Extra Trees 예측으로 같은 호스트의 GPU 복제본 1/2개 × CPU affinity 2/4/8/16코어 중 최소 형상을 골랐다. 수집기가 만든 원래 목표에서 **시험 90작업 중 54작업**을 승인했고, 그 54개는 한 번의 실측에서 모두 배치 p95 지연·요청/초 목표를 만족했다. 실측상 가능한 작업은 55개이므로 1개를 보류했다. 같은 저장 파일에 있는 `model_id×device` 훈련 중앙값 기준선은 42개를 승인해 36개가 성공하고 6개가 실패했다. 별도 입력 캠페인에서는 저장 모델이 10작업 중 9개, 33작업 중 25개를 승인했고 관측 실패는 0개였다.

| 캠페인 | 작업 / 실측 가능 | 저장 모델 선택 / 성공 / 잘못 승인 / 정확 최소 | 훈련 중앙값 선택 / 성공 / 잘못 승인 / 정확 최소 |
| --- | ---: | ---: | ---: |
| 시험 `local-exhaustive` | 90 / 55 | 54 / 54 / 0 / 50 | 42 / 36 / 6 / 36 |
| 별도 `local-novel-matrix` | 10 / 9 | 9 / 9 / 0 / 8 | 7 / 7 / 0 / 7 |
| 별도 `local-space-filling` | 33 / 26 | 25 / 25 / 0 / 23 | 19 / 17 / 2 / 17 |

`정확 최소`는 선택한 형상이 실측 목표를 충족하면서, GPU 수를 먼저, CPU affinity 코어 수를 다음으로 비교한 최소 가능 형상과 일치한다는 뜻이다. 가격이나 VM 노드 수를 뜻하지 않는다. 캠페인별 결과를 별도로 표시했다. 10개와 33개 별도 캠페인 그룹은 학습 지원 범위 안에 있었고, 새 모델·호스트의 독립 검증 표본은 아니다.

## 쉬운 원 목표와 민감도

원 목표에서 시험 작업 90개 중 **35개는 가능 형상이 0개, 32개는 8개 모두 가능**했다. 일부 후보 1~7개만 가능한 23개 가운데 저장 모델은 22개를 올바르게 선택하고 1개를 보류했다. 세 캠페인을 기술적으로 합치면 133개 중 43개가 0개 가능, 54개가 8개 모두 가능, **36개만 부분 가능**했다. 원 목표의 저장 모델은 이 부분 가능 36개에서 34개를 올바르게 선택하고 2개를 보류했다. 선택 후보의 최소 예측 상대 여유가 10% 미만인 원 목표 사례는 저장 모델에서 7/88개였다. 이 범위는 오류 설명용이며 승인 문턱으로 사용하지 않았다.

원 지연 목표에 `{0.75, 1, 1.25}`, 원 요청/초 목표에 `{0.75, 1, 1.25}`를 곱해 **같은 측정을 재사용한** 9개 민감도 목표도 계산했다. 다음은 시험 90작업의 저장 모델 점수다. `1.00/1.00`은 원 목표를 다시 계산한 일치 검사다.

| 지연 × / 요청·초 × | 실측 가능 | 저장 모델 선택 | 성공 | 잘못 승인 |
| --- | ---: | ---: | ---: | ---: |
| 0.75 / 0.75 | 60 | 56 | 55 | 1 |
| 0.75 / 1.00 | 55 | 54 | 54 | 0 |
| 0.75 / 1.25 | 50 | 49 | 45 | **4** |
| 1.00 / 0.75 | 60 | 56 | 55 | 1 |
| 1.00 / 1.00 | 55 | 54 | 54 | 0 |
| 1.00 / 1.25 | 50 | 50 | 46 | **4** |
| 1.25 / 0.75 | 60 | 56 | 55 | 1 |
| 1.25 / 1.00 | 55 | 54 | 54 | 0 |
| 1.25 / 1.25 | 50 | 50 | 46 | **4** |

따라서 원 목표의 관측 오승인 0건은 목표를 바꿔도 유지되는 안전성 근거가 아니다. 별도 `space-filling`에서는 요청/초 목표를 0.75배로 낮춘 세 조합마다 29개를 승인해 3개가 실제 해당 목표를 위반했다. 각 목표·캠페인·기준선의 수치는 [집계 JSON](../artifacts/saved_gpu_shape_decision_audit_v1/metrics.json)에, 모든 2,660개 결정 행은 CSV (`../artifacts/saved_gpu_shape_decision_audit_v1/decision_rows.csv`)에 있다. 9개 목표는 같은 작업의 같은 실행을 반복 질의한 것이며 9배 많은 독립 사용자 요청이 아니다.

## 정보 경계와 재현

[실험 전 고정한 규약](saved_gpu_shape_decision_audit_protocol.md)의 네 원본 SHA-256을 실행 때 검사했다. 1,164개 저장 예측 중 적격 CUDA 시험·별도 캠페인 1,064행을 `(host, execution_id)`로 물리 측정과 일대일 결합했다. 저장된 캠페인·모델·장치·작업 ID와 두 실측 결과를 원본에 대조했고, 원 시험 720행은 고정 분할 명세와 정확히 일치했다. 모든 작업의 8형상 격자와 단일 목표를 확인했다. 요청/초는 저장된 샘플/초를 batch 크기로 나누었다. 저장 모델 파일의 해시만 확인했고 모델을 로드하거나 다시 학습하지 않았다.

재현: `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 scripts/audit_saved_gpu_shape_decisions.py`. [감사 코드](../scripts/audit_saved_gpu_shape_decisions.py)의 합성 시험은 단위 변환, 형상 순서, 보류·오승인, 불완전 격자, 원본·분할 불일치를 검사하며 5개가 통과했다. 집계 JSON은 규약·원본·코드·행 CSV 해시를 기록한다.

이 감사는 저장 예측과 시험 결과를 이미 본 뒤 수행한 **사후 기술 분석**이다. 원 목표는 실제 사용자 SLO가 아니고 지연은 배치 p95다. 같은 호스트의 두 GPU 복제본은 두 VM의 배포·스케일 결과가 아니다. 저장 모델의 새 채택 기준이나 운영 안전 보장으로 해석하지 않는다.
