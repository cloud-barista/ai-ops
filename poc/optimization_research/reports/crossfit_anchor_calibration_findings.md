# 기준 측정 오차 교차검증 보정 실험

## 가설과 평가

새 모델의 GPU 1개·CPU 2코어 측정값과 정적 성능 모델의 해당 예측값 사이 오차를 이용하면, 다른 GPU·CPU 형상의 예측 오차도 보정할 수 있다고 가정했다. 외부 평가에서는 모델 ID를 통째로 제외했고, 보정기의 학습값은 나머지 모델들 안에서 다시 모델 하나씩 제외해 만든 예측 오차만 사용했다. 최종 평가 모델에서 사용한 관측값은 기준 형상의 지연시간과 요청 처리량뿐이다.

비교 대상인 `same_static_anchor_shift`는 같은 정적 입력과 같은 기본 ExtraTrees 모델을 사용하되, 기준 형상의 오차를 모든 후보 예측에 그대로 더한다. 두 방법 모두 나머지 7개 후보의 측정값을 예측 입력으로 사용하지 않는다. 미측정 후보값을 바꾸어도 예측이 같다는 테스트를 추가했다.

## 관측 결과

| 같은 호스트, 모델별 평균 절대 로그오차 | 교차검증 오차 보정 | 동일 정적 입력의 단순 기준 오차 보정 | 앞선 기준값 조건부 상대 모델 |
| --- | ---: | ---: | ---: |
| 지연시간 | 0.257 | 0.277 | 0.219 |
| 요청 처리량 | 0.185 | 0.116 | 0.090 |

기준 측정 실패 326개 조건에서 GPU 2개·CPU 2코어의 두 번째 측정을 100번 허용했을 때, 실제 SLO를 만족하는 후보를 각각 **91개**, **93개**, **98개** 찾았다. 가능한 후보는 총 108개였다. 새 보정기는 지연시간 오차를 조금 줄였지만 처리량 오차와 최종 측정 순위를 악화시켰다. 외부 입력 조건인 novel-matrix와 space-filling 캠페인에서도 처리량 오차가 악화했다. 따라서 이 보정 방법은 현재 제안 방법으로 채택하지 않는다.

두 후보를 비교할 때 후보마다 독립 실행 1회의 성능값과 수집기가 생성한 SLO를 사용했다. 위 차이는 탐색적 실험 결과이며 실제 배포 환경에서의 우위를 뜻하지 않는다.

재현: `python scripts/crossfit_anchor_calibration.py` 및 `python -m unittest discover -s tests -q`. 세부 모델별 결과와 예측값은 `artifacts/crossfit_anchor_calibration_v1/`에 저장된다.
