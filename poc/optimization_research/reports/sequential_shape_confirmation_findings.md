# 저장 GPU 추천 뒤 형상 확인 순서: 사후 재생

2026-09-29. **판정: 측정 순서의 탐색 결과, 운영 채택 보류.** 기존 Extra Trees 모델이 추천한 형상을 먼저 한 번 측정하고 실패하면 나머지 형상을 자원 순서로 확인하는 절차를, 이미 전부 실측된 8후보 작업에서 재생했다. 주 시험 90작업의 원래 목표에서는 평균 확인 횟수가 **4.48→3.77회**로 줄었고 실측 가능한 55작업 모두를 찾았다. 다만 그중 **4작업에서 실측상 최소보다 큰 형상**을 골랐고, 별도 캠페인 일부에서는 GPU 측정시간 지표가 늘었다. 새 예측 모델을 학습하거나 독립 시험을 한 결과는 아니다.

## 비교 절차와 자료

GPU 복제본 1/2개 × CPU affinity 2/4/8/16코어로 이루어진 형상 8개를, 같은 호스트·같은 입력 조건별로 비교했다. 자원 순서는 **GPU 수 우선, 그다음 CPU 코어 수**다. 기존 [저장 모델의 형상 선택 감사](saved_gpu_shape_decision_audit_findings.md)와 같은 물리 측정·저장 예측·시험 분할을 SHA-256으로 고정해 결합했다. 시험 90작업과 별도 입력 캠페인 10·33작업, 총 133작업에서 누락 없는 8후보 측정을 확인했다. 각 형상의 합격 기준은 배치 p95 지연과 `examples_per_second / batch_size`로 환산한 요청/초가 수집기 생성 목표를 동시에 만족하는지다.

비교한 절차는 다음 세 가지다.

1. **자원 순서 확인:** 가장 작은 형상부터 하나씩 측정하고 처음 합격한 형상을 택한다.
2. **모델 추천 우선 + 실패 시 전체 탐색:** 모델이 합격으로 예측한 최소 형상을 먼저 측정한다. 실패하면 아직 측정하지 않은 형상을 자원 순서대로 확인한다. 예측 합격 형상이 없으면 처음부터 자원 순서로 확인한다.
3. **추천 형상 한 번만 확인:** 모델이 합격으로 예측한 최소 형상을 한 번 측정해 합격할 때만 선택한다. 실패하거나 예측 합격 형상이 없으면 보류한다.

각 절차는 **측정한 형상의 합격 여부만** 다음 확인과 선택에 사용한다. 나머지 실측은 재생이 끝난 뒤 최소 형상과 놓친 작업을 평가하는 데만 쓴다. GPU 측정시간은 각 확인의 기록된 `wall_seconds × replica_count` 합이다. 실제 VM 비용이나 배포 시간은 아니다.

## 원래 생성 목표의 결과

| 캠페인 | 작업 / 실측 가능 | 단조성 위반 작업 | 자원 순서 평균 확인·GPU초 | 모델 우선 평균 확인·GPU초 | 모델 우선 성공 / 정확 최소 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 주 시험 | 90 / 55 | 14 | 4.48회 · 10.99초 | **3.77회 · 10.61초** | 55 / 51 |
| 별도 novel-matrix | 10 / 9 | 2 | 1.70회 · **2.45초** | 1.70회 · 2.75초 | 9 / 8 |
| 별도 space-filling | 33 / 26 | 7 | 3.21회 · 7.52초 | **2.61회 · 7.23초** | 26 / 24 |

주 시험에서 실측 가능한 작업만 보면 평균 확인은 자원 순서 2.24회, 모델 우선 1.07회다. 전체 90작업 평균이 더 높은 이유는 실측 불가능한 35작업에서 양쪽 모두 8개를 확인하기 때문이다. 모델 우선은 실측 가능한 모든 작업을 찾지만, 처음 확인한 큰 형상이 합격하면 더 작은 형상을 보지 않고 멈추므로 정확한 최소 형상 수가 줄어든다. `novel-matrix`에서는 확인 횟수가 같고 GPU 측정시간은 늘었다.

형상을 큰 순서로 올렸을 때 합격이 다시 실패로 바뀌는 작업이 주 시험 **14/90**개다. 그러므로 합격이 자원 크기에 따라 단조 증가한다는 가정에 의존하는 이진 탐색은 이 자료에서 유효하지 않다. 세부적으로는 요청 처리량 또는 배치 p95의 단일 실행 변동도 원인일 수 있지만, 이번 한 번씩의 측정만으로 원인을 분리하지 않았다.

## 요청/초 목표를 1.25배로 강화한 같은 측정의 재질의

| 캠페인 | 실측 가능 | 모델 단독 승인 / 그중 실패 | 한 번 확인 후 합격 | 자원 순서 평균 확인·GPU초 | 모델 우선 평균 확인·GPU초 | 모델 우선 정확 최소 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 주 시험 90작업 | 50 | 50 / **4** | 46 | 4.98회 · 12.62초 | **4.27회 · 12.02초** | 48 / 50 |
| novel-matrix 10작업 | 9 | 9 / 0 | 9 | 2.50회 · 4.69초 | **1.70회 · 3.79초** | 9 / 9 |
| space-filling 33작업 | 23 | 20 / **2** | 18 | **3.85회 · 9.39초** | 3.73회 · 9.71초 | 19 / 23 |

한 번 확인 절차는 기존 추천의 관측 실패 4건과 2건을 그 **동일한 측정값에서** 승인하지 않았다. 이것은 측정된 실패를 승인하지 않는 절차의 직접적인 결과다. 미래 반복 실행에서 안전하다는 증거가 아니며, 주 시험의 실측 가능 50작업 중 4개, `space-filling`의 23작업 중 5개를 보류한다. 모델 우선 전체 탐색은 이들을 다시 찾아냈지만 `space-filling`에서는 GPU 측정시간이 9.39→9.71초로 늘고 4작업에서 최소 형상을 벗어났다.

## 재현과 채택 경계

[재현 코드](../scripts/evaluate_sequential_shape_confirmation.py)는 원본 해시·분할·8형상 완결성을 기존 검증기로 재확인하고, 원래 목표와 지연 `{0.75, 1, 1.25}` × 요청/초 `{0.75, 1, 1.25}` 아홉 조합을 계산한다. [전체 결과](../artifacts/sequential_shape_confirmation_v1/results.json)와 작업별 재생 행 (`../artifacts/sequential_shape_confirmation_v1/replay_rows.csv`)에 수치를 보존했다. 기존 원 목표 감사의 세 캠페인 승인·성공·오승인 건수와 일치하는지도 자동 검사한다. [계약 시험](../tests/test_sequential_shape_confirmation.py) 3개는 비단조 합격, 실패 후 실제 확인 순서, 미확인 후보 결과의 영향 차단을 검사한다.

이 분석은 **이미 결과를 열람한 같은 로컬 자료**의 사후 탐색이다. 목표는 실제 사용자의 SLO가 아니고 지연은 배치 p95다. 각 형상은 한 번만 실행됐으므로 반복 측정의 통과 확률을 알 수 없다. 두 GPU 복제본은 같은 호스트의 두 장치이며 두 VM으로의 Scale-out 결과가 아니다. 모델 우선 확인은 일부 작업에서 측정 횟수를 줄이는 후보 절차로만 보존한다. 실제 배포 판단에 쓰려면 새 입력·반복 실행, 사용자 SLO, 확인 예산, VM별 비용과 실패·전환 기록이 필요하다. 이 단순 절차를 독창적인 학습 알고리즘이나 운영 안전 성과로 주장하지 않는다.

같은 SQLite의 **다른 반복 캠페인**에서 진행한 [다음 실행 합격 감사](repeat_confirmation_findings.md)는 경계 근처의 합성 목표에서 직전 한 번 합격해도 다음 벤치마크가 실패할 수 있고, 3회 연속 확인도 두 수집기 버전에서 일관된 위험 감소를 보이지 않음을 확인했다. 두 캠페인의 조건이 직접 겹치지 않아 이 수치를 위 8후보 작업의 실패율로 옮기지는 않는다.
