# 제안: 여러 요청 조건을 한 형상으로 감당하는 AI-App 추천

**상태: 제안만 작성. 학습·점수 계산 전.** 기존 [연구 목록](novelty_gap_and_next_experiment.md)은 대부분 요청 조건 *하나*마다 GPU·CPU 형상을 선택한다. 경희대의 `Deployment Spec`은 여러 입력 길이·배치·동시성 조건을 같은 형상으로 처리할 수 있어야 한다. 질문은 다음과 같다. **새 AI-App의 소수 K8 측정만으로, 미측정 요청 조건 묶음의 최소 90%를 만족하는 가장 작은 GPU·CPU 형상 하나를 추천할 수 있는가?** 이는 정적 형상 용량의 문제이며 실제 scale action 판단은 아니다.

## 사용할 자료와 정보 경계

- 고정 SQLite 추출 (`../data/audit_v1/measurements.parquet`)의 local-exhaustive GPU 성공 측정: 9모델, 575개 모델·입력 조건, 조건마다 8형상. 같은 모델의 조건은 `batch_size < 12 && max_length < 512`인 **보통 수요**, 나머지 **높은 수요**의 두 묶음으로 미리 나눈다. 현재 정적 조건 개수는 encoder 모델마다 41/23개, Qwen은 35/28개다. 이는 실제 사용자 요청 빈도가 아니라 **조건을 균등하게 한 번씩 평가하는 가상 서비스 범위**다.
- 외부 대상 모델 H의 측정은 기존 K8 공간 선택 앵커 (`../artifacts/cross_model_covariance_v1/split_manifest.csv`) 8개만 예측 입력으로 허용한다. 추천·점수화 대상은 그 외 조건이다. 원본 수집 SLO는 작업마다 다른 생성 목표다. 보조 목표 25쌍은 H를 뺀 donor 실측 분위수로 정해 묶음 안에서 공통 적용한다. 둘 다 실제 사용자 SLO가 아니다. 요청/초는 `examples_per_second / batch_size`로 계산한다.
- 형상 `r`의 묶음 충족률은 **동일한 r**에서 묶음의 미측정 조건 중 두 목표를 모두 만족한 비율이다. 목표는 충족률 ≥0.90이다. 성공 형상 중 GPU 수, CPU affinity 코어 수 순으로 가장 작은 것을 정답으로 삼는다. 실제 VM 가격·용량·메모리, 모델 실패와 운영 전환 지연은 이 정의에 없다. GPU 2개는 같은 호스트의 두 독립 replica다.

## 시험 점수 전에 거칠 자료 적격성 게이트

먼저 **예측기 학습·선택 점수를 보지 않고** 완전 실측표에서 각 묶음·목표에 90%를 만족하는 형상이 몇 개인지만 센다. 0개면 판단 불가, 8개 모두면 최소 형상이 자명하다. **1~7개인 비자명 사례**가 원본 SLO 18개 묶음 중 ≥4개·≥3모델, donor 고정 합성 SLO 최대 450개 묶음 중 ≥30개·≥5모델에 걸쳐 있어야 학습 평가를 진행한다. 묶음당 미측정 조건은 ≥10개여야 한다. 하나라도 실패하면 여기서 중단하고 이 SQLite는 묶음 추천 효과를 평가하기에 부족하다고 보고한다. 이 게이트도 같은 H 결과를 본 자료 선택이므로 후속 점수는 독립 검증이 아니다.

## 방법·기준선·분할

제안할 작은 모델은 **후보 형상 하나가 요청 조건 묶음의 90%를 충족하는 사건**을 직접 예측한다. 입력은 이미 확보한 K8의 후보별 예측에서 계산한 충족 조건 비율, 로그 지연/처리량 여유의 10백분위수, 묶음 크기·배치/길이 분포, GPU·코어 수다. 대상은 같은 형상을 묶음 전체에 적용했을 때의 실측 충족률 ≥0.90 여부다. L2 로지스틱(`C=1`) 한 가지만 먼저 시도하고, 예측 성공 확률 ≥0.90인 후보 중 최소 형상을 고른다. 확률 문턱과 특징은 시험 전 고정한다. 이 학습 대상은 기존의 셀별 성능 오차·후보 하나의 합격 라벨·정적 `ABSTAIN`과 다르다. 별도의 신규 원리 또는 학술적 최초성은 주장하지 않는다.

기준선은 (1) **K8의 조건별 예측 합격률 ≥0.90**로 최소 형상 선택, (2) 각 조건의 양쪽 로그 예측에 **고정 0.05 안전 여유**를 둔 같은 선택, (3) 항상 GPU2·16코어 선택의 용량 상한 진단이다. 모든 방법은 대상 모델에서 같은 K8 측정·후보·요청 조건을 사용한다. 보수적인 방법이 승인을 줄여 위반을 숨기지 않도록 추천 수, 성공, 잘못 추천, 실제 가능한 묶음 누락, 성공 중 정확한 최소 형상 비율을 같이 보고한다. 첫 두 기준선과는 모델별 **동일 추천 수**의 순위 진단도 별도로 한다. 이 동수 진단은 예측상 목표 미달 묶음을 강제 승인할 수 있으므로 운영 정책으로 해석하지 않는다.

모델 H를 통째로 제외하는 9개 바깥 분할을 사용한다. 제안 모델을 학습할 donor D의 K8 예측은 **H와 D를 모두 제외한** 기본·조건부·공분산 학습으로 다시 만든다. 기존 D의 LOOMO 결과는 H를 학습에 포함하므로 재사용하지 않는다. 같은 `workload_group`의 여덟 형상과 25개 합성 목표는 분할·재표본화에서 함께 유지한다. 25개 목표를 독립 표본 25개로 취급하지 않고 학습 가중치도 donor 모델별로 맞춘다. 실질적으로 donor는 H당 8모델뿐이라 복잡한 학습기·세부 집단 성능 주장은 피한다. 주 평가는 각 H의 K8 미측정 조건 묶음이다. BERT 4종 공동 제외와 novel-matrix/space-filling 입력 조건은 주 방법을 고정한 뒤 분포 변화 진단에만 쓴다. 그 캠페인도 이미 여러 번 탐색됐으므로 새 독립 시험이라고 부르지 않는다.

## 사전 성공·중단 기준과 비용

적격성 게이트를 통과한 경우, **9모델 주 시험에서** 조건별 K8 합격률과 고정 0.05 중 더 좋은 기준선보다 동수 추천의 잘못 추천을 **상대 10% 이상** 줄이고, 성공한 정확 최소 형상 건수는 줄이지 않으며, 모델별 잘못 추천 차이가 **6/9모델 이상에서 개선**되어야 연구 후보로 남긴다. 기준선의 잘못 추천이 0이면 상대 개선은 정의하지 않고 이 자료로 우위를 주장하지 않는다. 원본 목표와 합성 목표 양쪽에서 같은 방향이어야 한다. BERT 공동 제외 또는 새 입력 조건에서 기준선 대비 악화가 확인되면 적용 범위를 제한하고, 같은 시험 표본에서 문턱·묶음 경계를 재조정하지 않는다. 이 기준을 만족해도 새 모델/호스트·사용자 SLO 검증 전에는 운영 추천기로 채택하지 않는다.

적격성 계수는 575개 조건×목표 26종×8형상의 읽기 전용 연산으로 수분 이내, GPU 실행 0회다. 학습까지 가면 바깥 9분할의 8 donor를 각각 다시 제외하는 최대 **72개 pseudo-target K8 예측**, 그 내부 prior용 재적합까지 대략 **600회 안팎의 100-tree CPU 학습**이 필요하다. 2 CPU worker에서 약 **30~90분**을 상한 예산으로 두고 첫 두 분할의 실측 속도로 다시 추정한다. 예상 원시 입력은 4,600행, 합성 묶음 질의는 최대 450개이며 GPU 측정 추가는 없다.

**한계:** 같은 9모델·생성 SLO를 반복 사용해 생기는 선택 편향이 크다. 조건 균등/최악형 묶음은 실제 요청 확률을 모르기 때문에 선택한 가정이다. 기존 SQLite의 `SCALE_OUT/IN` 기록은 정적 측정의 재가공이며 실제 VM 제어 결과가 없어 이 질문을 운영 행동의 효과로 연결하지 않는다. [원본/파생 DB 감사](untapped_signal_audit.md)
