# 저장된 GPU 형상 선택기의 연속 SLO 민감도면: 채점 전 규약

2026-09-29. 이 분석은 이미 열람한 로컬 벤치마크와 저장 예측을 다시 읽는 **후향 진단**이다. 새 모델·보정 상수·승인 문턱을 학습하거나 독립 시험 성능을 주장하지 않는다. 목표는 앞선 9점 민감도 감사에서 놓칠 수 있는, 생성 SLO 주변의 잘못된 승인·불필요한 보류 구간을 정확히 계산하는 것이다.

## 고정 자료와 지원량 게이트

- 앞선 [저장 형상 감사](saved_gpu_shape_decision_audit_protocol.md)의 고정 원본 4개(측정 Parquet, 저장 모델, 저장 예측 Parquet, 분할 CSV)의 SHA-256을 검사한다. 모델 파일은 **해시만 확인**하며 로드·재학습하지 않는다.
- 그 감사의 `validated_gpu_rows()`를 그대로 호출하여 `(host, execution_id)` 일대일 결합, 원본 값 일치, 유효 CUDA 시험/별도 캠페인, 완전한 GPU 복제 수 1/2 × CPU affinity 2/4/8/16의 8형상, 그룹 내부 배치 크기·목표 일치를 확인한다.
- 원래 감사의 행별 CSV SHA와 입력 해시를 확인한다. 새 선택 함수를 원래 목표와 3×3 민감도 점 모두에서 돌려 **2,660개 기존 결정 행**의 선택·성공·오승인·최소 형상 결과를 재생한다. 하나라도 다르면 연속 면적을 채점하지 않는다.
- 캠페인을 합치지 않는다. 원 생성 목표에서 부분가능(실측 8후보 중 1–7개 합격)한 고유 작업군이 주 시험에서 **20개 미만**이면 주 결론도 기술적 지원량 미달로 보류한다. 별도 두 캠페인은 고유 부분가능 작업군이 각각 10개 미만이면 모델 우열을 주장하지 않고 참고 기술만 한다. 기존 감사에서 주 시험은 23개, `novel-matrix`는 2개, `space-filling`은 11개였다. 이 조건은 연속 면적의 오류율이나 모델 채택 게이트가 아니다.

## 연속 면적의 정의

각 작업군의 수집기 생성 목표를 `(L₀,R₀)`라 한다. 지연 상한과 요청/초 하한에 각각 배수 `(a,b)∈[0.75,1.25]²`를 곱한다. **로그 배수 평면에서 균등한 면적**을 사용한다. 이 범위와 가중법은 앞선 9점의 양끝에서 정했고 결과를 보기 전에 고정한다. 실제 사용자의 SLO 분포라는 뜻은 없다.

후보별 실측·예측 배치 p95를 `Lᵢ`, 처리 샘플/초를 batch 크기로 나눈 요청/초를 `Rᵢ`라 한다. 각 후보의 `Lᵢ/L₀`, `Rᵢ/R₀` 중 열린 범위 안에 있는 값을 두 축의 경계로 모으고 0.75·1.25를 붙인다. 비교 정책은 저장 Extra Trees 전체 8후보 선택, 저장 모델·장치 훈련 중앙값 전체 8후보 선택, 그리고 **고정 (GPU 1개, CPU affinity 2코어) 후보만의 훈련 중앙값 합격 판단**이다. 마지막 정책은 그 한 후보의 저장 중앙값 예측이 지연·요청/초 목표를 모두 통과할 때만 선택하고 아니면 보류한다. 실측 oracle는 정책으로 점수화하지 않고 가능 여부·최소 형상의 정답에만 쓴다. 각 직사각형의 기하평균 중점에서 모든 후보의 합격 여부와 사전식 최소 선택이 일정하므로 `Δlog(a)×Δlog(b)`가 해당 결정의 **정확한 면적**이다. 경계 자체는 면적 0이며 기존 9점 재생에서는 원 감사와 같은 `≤`·`≥`를 쓴다.

방법별로 작업군당 전체 면적 중 승인, 실측 성공, 잘못 승인, 실제 가능하지만 보류, 실제 가능한데 잘못 승인, 최소 실측 형상 정확 선택의 비율을 낸다. 방법과 무관한 실제 가능 영역을 0·1–7·8개 합격 형상으로 나눈 비율도 낸다. 캠페인 집계는 **고유 작업군 각각을 동일 가중**으로 평균한다. 모델별 집계를 함께 제시하고 같은 작업의 여러 직사각형을 독립 표본처럼 세지 않는다. 실측 oracle는 달성 가능 상한일 뿐 실행 가능한 알고리즘이 아니다. GPU 수가 먼저, CPU affinity 코어가 다음인 선택 순서를 쓰며 실제 비용·VM 수로 바꾸지 않는다.

## 채점 후 결론 경계

연속 면적은 저장 예측기의 **합성 목표 변동 민감도**만 설명한다. 면적에서 유리한 새 문턱을 고르거나 이미 열람한 시험 성능으로 정책을 채택하지 않는다. 이 로컬 단일 호스트의 GPU 2개 값은 같은 호스트의 두 독립 복제본 벤치마크로, VM Scale-out/in 조치와 전후 사용자 요청의 결과가 아니다.
