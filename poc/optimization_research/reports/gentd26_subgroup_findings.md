# GenTD26 요청 지연의 그룹별 사후 보정

## 결론

Alibaba GenTD26의 성공한 이미지 생성 요청 6,244건에서, **검증 구간으로 선택한 모델 ID별 최근 잔차 보정**은 1시간 피드백 지연을 가정했을 때 p90 pinball loss를 **2.911초 → 2.770초**로 낮췄다. 전체 관측 커버리지는 **90.1% → 90.4%**였다. 그러나 `IMG_2_IMG` 649건의 커버리지는 **80.9% → 83.4%**에 그쳐, 그룹별 90% 상한을 달성했다고 볼 수 없다. 결과는 후향적 탐색이며 배포 또는 스케일 조정 성능의 증거가 아니다.

## 실험 설계

- 원본: [GenTD26 `lora_request_trace.csv`](https://github.com/alibaba/clusterdata/tree/8c132fb7717fbd44cf434cf81f2cd865a80072d5/cluster-trace-v2026-GenAI), SHA256 `263fb88f1095f62d360cf89ded8cfc24fa2c5d111c1b16e7aaa9ccbfc4b37d78`. 타깃은 `SUCCEED` 요청의 `exec_time_seconds`다.
- 학습 모델: 기존 [요청 지연 실험](../scripts/evaluate_gentd26_request_latency.py)의 고정된 HistGradientBoostingRegressor p90 모델을 재사용했다. 기본 1시간 지연 모델은 학습 컷오프까지 결과가 가용하다고 가정한 요청 12,779건으로 학습했고 SHA256은 `05a410545e2acee0785613aae5f82e66f0390edf952a2105585d6f1b292730be`이다. 0초 민감도는 별도 학습한 0초 모델을 사용한다.
- 2024-11-29 이전 요청은 기본 모델 학습, 11-29~11-30은 잔차 초기화, 12-01~12-03은 정책 선택, 12-04~12-08은 시험에 썼다. 요청별 모델 ID와 `predict_type`은 요청 생성 시점에 알 수 있는 입력이다.
- 기본 정책은 피드백이 가용하다고 가정한 최근 요청의 잔차 `실행시간 − 기본 p90`의 90% 분위수를 기본 예측에 더한다. 전역 잔차 창은 검증 데이터에서 고른다.
- 후보 정책은 모델 ID 또는 요청 종류의 최근 잔차 50/100/200/500건을 쓴다. 해당 그룹의 가용 피드백이 20/50/100건 이상 있을 때만 보정하고, 그룹 잔차 분위수와 전역 잔차 분위수를 `그룹건수 / (그룹건수 + shrinkage)` 비율로 섞는다. shrinkage 후보는 0/50/200이다. **72개 그룹 후보와 전역 기준** 중 검증 pinball loss가 가장 낮은 정책 하나를 선택했다.
- 검증 점수에도 같은 피드백 가용 시각 조건을 적용했다. 1시간 지연에서는 정책 선택 구간의 6,115건 중 **시험 시작 전 피드백이 가용하다고 가정한 5,810건**만 점수를 매겼다. 나머지 305건은 선택 점수에서 제외했고, 시험 중에는 가용 시각이 지난 뒤에만 잔차 풀에 들어갈 수 있다. 0초 지연에서는 6,113건이 선택 점수에 들어갔다.
- 피드백 사용 가능 시점은 원본에 완료 시각이 없어 `gmt_create + exec_time_seconds + 추가 지연`으로 *가정*했다. 같은 시험 안에서는 각 요청 생성 시점까지 이 가정상 피드백이 가용한 과거 요청만 보정에 사용한다. 실제 큐 대기나 기록 지연이 이 가정보다 길 수 있으므로, 이것만으로 운영상 누출이 없음을 보장할 수 없다.

## 시험 결과

| 피드백 추가 지연 | 검증 선택 전역 창 | 검증 선택 그룹 정책 | 전역 pinball / 커버리지 | 그룹 pinball / 커버리지 |
|---|---:|---|---:|---:|
| 0초 | 2,000 | 모델 ID, 최근 100건, 최소 20건, shrinkage 50 | 2.862초 / 90.2% | **2.673초 / 90.2%** |
| 1시간 | 2,000 | 모델 ID, 최근 500건, 최소 50건, shrinkage 200 | 2.911초 / 90.1% | **2.770초 / 90.4%** |

1시간 지연 정책에서 시험 요청의 94.6%는 모델 ID별 잔차가 최소 지원 건수를 채웠다. 지원이 부족한 요청은 전역 보정을 그대로 사용했다. 기존 1시간 지연 전역 예측 파일과 본 실험의 전역 예측은 행별 최대 차이가 **0초**였다.

| 1시간 지연, 시험 하위집단 | 건수 | 전역 커버리지 | 모델 ID 보정 커버리지 | 전역 pinball | 모델 ID 보정 pinball |
|---|---:|---:|---:|---:|---:|
| `IMG_2_IMG` | 649 | 80.9% | 83.4% | 5.717초 | 5.441초 |
| `M0003` | 595 | 74.1% | 86.4% | 7.142초 | 6.133초 |

전체 pinball은 4.9% 낮아졌지만, 날짜별로는 12-07에 전역 정책보다 높았다. 따라서 이 결과만으로 변동 상황의 안정성이나 90% 하위집단 보장을 주장할 수 없다. 요청 종류별 고정 정책은 `IMG_2_IMG` 커버리지를 88.1%까지 올리는 대신, M0003 커버리지를 더 낮춰서 두 문제를 동시에 해결하지 못했다.

## 해석과 사용 범위

같은 모델 ID의 피드백이 가용하다고 가정한 최근 요청은 전역 요청보다 해당 모델의 지연 변화를 더 잘 반영했다. 다만 이 실험은 **시험 데이터에서 드러난 하위집단 문제를 보고 설계한 후향 탐색**이다. 후보값은 검증 구간으로 골랐지만, 완전히 독립적인 새 기간의 검증이 필요하다. 1시간 추가 지연도 실제 완료 시각의 대용일 뿐이다. GenTD26은 공개 운영 추적이지만 로컬 SQLite의 AI 모델, GPU, VM과 연결되지 않는다. 이 결과로 GPU 수량, 배포 성공률, 실제 사용자 SLO, VM scale-out의 인과 효과를 추정할 수 없다.

재현: 기본 1시간 지연은 `python scripts/evaluate_gentd26_subgroup.py`; 0초 민감도는 `python scripts/evaluate_gentd26_subgroup.py --feedback-lag-seconds 0 --output artifacts/gentd26_subgroup_zero_lag_v1`. 각 실행의 전체 후보와 예측은 [1시간 결과](../artifacts/gentd26_subgroup_v1/metrics.json)와 [0초 결과](../artifacts/gentd26_subgroup_zero_lag_v1/metrics.json)에 있다. 피드백 가용·선택 경계·지원 fallback·기본 지연 검사는 `python -m unittest discover -s tests -p 'test_gentd26_subgroup.py' -v`의 5개 테스트에서 통과했다.
