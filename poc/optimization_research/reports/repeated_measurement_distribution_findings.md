# 소수 반복 측정으로 미래 벤치마크 성능 분포를 예측한 결과

## 결론

고정된 AI 응용·GPU 형상의 **나중 한 번 실행**에서 배치 p95 지연과 요청 처리량이 얼마나 달라질지 예측했다. 같은 수집기 안에서 다른 모델의 반복 변동을 학습해 대상 앱의 처음 2회 결과와 결합하면, 대상 앱 2회만으로 분산을 추정하는 것보다 예측구간이 안정적이었다. 2회만 쓴 대상 셀 Student-t, 즉 Cauchy 기준선과 비교해도 donor 수축의 CRPS가 네 수집기·지표 조합 모두에서 낮았다. 하지만 5회 이상을 측정하면 **대상 앱 자체의 표본분산과 Student-t 기준선이 CRPS 또는 NLL에서 자주 더 좋았다.** donor 수축을 범용적으로 우월한 새 알고리즘으로 채택할 근거는 없다.

이 결과는 [기존 변동 감사](repeat_variability_findings.md)의 셀별 표준편차 요약과 다르다. 대상 모델을 donor 학습에서 완전히 제외하고, 과거 회차만으로 **미래 단일 측정의 확률분포**를 만든 뒤 proper score와 예측구간으로 평가했다. 배포된 응용의 실제 사용자 SLO나 VM Scale-out 효과는 평가하지 않았다.

## 자료와 잠근 평가

원본 SQLite 추출 측정 스냅샷 (`../data/audit_v1/measurements.parquet`)의 `khu-hf-live` GPU 반복을 사용했다. 같은 호스트의 수집기 `v1`은 16개 고정 GPU 셀을 63회, `v2`는 같은 수의 셀을 47회 측정했다. 각 버전의 마지막 20회는 평가에만 썼고, 앞 43/27회만 학습 후보로 두었다. 모델 8종을 하나씩 완전히 제외했다. `run_id` 숫자 접미사는 시간 순서가 아니다. `v1`의 `round-100`이 `round-001`보다 먼저 실행됐으므로 실제 시작 시각으로 정렬했다. 학습 실행의 가장 늦은 종료 시각이 평가 실행의 첫 시작 시각보다 이른지도 검사했다.

주요 `immediate_first_k` 시나리오는 각 수집기 버전의 처음 `k=2,3,5,10`회에서 donor와 대상 모델을 함께 읽는다. 따라서 donor 학습에 대상 측정 시점보다 늦은 회차를 쓰지 않는다. `cutoff_last_k` 검사는 학습 prefix의 마지막 `k`회 대상 측정과 그 이전 donor 전체를 사용한다. 예측을 만드는 함수는 대상의 선택 `k`회 결과 외에 같은 모델의 어떤 성능 결과도 읽지 않는다. 모든 방법의 로그 성능 평균은 대상 `k`회 평균으로 같고, 비교 대상은 미래 실행의 **분산·분포**다.

전역 donor 분산과 GPU 복제 수별 donor 분산은 각 donor 셀 평균에서의 제곱잔차를 셀별 자유도 합으로 나눈다. 제안 비교식은 `v = (5×v_donor + (k−1)×v_local)/(5+k−1)`이고, GPU 수별 prior에도 같은 식을 쓴다. 비교 기준은 donor prior 단독, 대상 셀 표본분산만 사용한 정규분포, 그리고 소표본 Student-t(`df=k−1`)다. 2회 측정의 Student-t는 Cauchy이며 별도 CRPS 닫힌 식을 수치 CDF 적분으로 검증했다. 모두 같은 대상 `k`회 측정 비용을 쓴다. 공식과 분할의 상세 내용은 [탐색 실험 규약](repeated_measurement_distribution_protocol.md)에 있다.

## 주요 결과: 처음 k회만 사용할 때

CRPS는 미래 로그 성능분포의 1차 점수이며 **작을수록 좋다**. 각 대상 셀의 미래 20회 평균 → 같은 모델의 셀 평균 → 8모델 동일 가중 평균이다. 90% 포함률은 이 구간에 미래 단일 실행값이 들어간 비율이다. `k=2`의 Student-t 결과는 Cauchy 분포다.

| 수집기·지표 | k | GPU수별 donor CRPS | GPU수별 수축 CRPS / 90% 포함률 | 대상 셀 정규 CRPS / 포함률 | 대상 셀 Student-t CRPS / 포함률 |
| --- | ---: | ---: | ---: | ---: | ---: |
| v1·배치 p95 | 2 | 0.0999 | **0.0965 / 0.910** | 0.1026 / 0.684 | 0.1172 / 0.889 |
| v1·요청/초 | 2 | 0.0464 | **0.0461 / 0.960** | 0.0481 / 0.829 | 0.0601 / 0.988 |
| v2·배치 p95 | 2 | 0.1351 | **0.1324 / 0.881** | 0.1362 / 0.679 | 0.1506 / 0.954 |
| v2·요청/초 | 2 | 0.0281 | 0.0274 / 0.885 | **0.0261 / 0.692** | 0.0278 / 0.941 |
| v1·배치 p95 | 5 | 0.0942 | 0.0904 / 0.921 | **0.0877 / 0.892** | 0.0889 / 0.917 |
| v1·요청/초 | 5 | 0.0363 | 0.0349 / 0.947 | **0.0335 / 0.948** | 0.0345 / 0.965 |
| v2·배치 p95 | 5 | 0.1207 | 0.1174 / 0.908 | **0.1170 / 0.845** | 0.1173 / 0.917 |
| v2·요청/초 | 5 | 0.0270 | 0.0258 / 0.880 | 0.0244 / 0.798 | **0.0242 / 0.872** |

`k=2`의 대상 셀 단독 정규분포는 적은 표본으로 분산을 과소평가하기 쉬웠다. 특히 v1/v2 배치 지연의 포함률이 0.684/0.679로 낮았다. donor 수축의 포함률은 0.910/0.881이었다. Cauchy는 같은 두 번의 측정만 쓰지만 꼬리가 두꺼워 구간폭이 더 컸다. 예를 들어 v2 지연 구간폭은 Cauchy `2.196`, 수축 `0.681` 로그 단위였다. 반면 v2 요청 처리량은 대상 셀 단독 정규분포의 CRPS가 이미 수축보다 좋고, Cauchy의 NLL은 `−1.947`로 수축의 `−1.353`보다 좋다. `k=5`에서는 대상 셀 단독 또는 Student-t가 네 조합 모두에서 가장 낮은 CRPS를 냈다. 정규분포 단독의 v2 포함률은 지연 0.845, 처리량 0.798로 낮으므로 점수와 구간 보정을 함께 봐야 한다.

NLL도 한 방향으로 정리되지 않는다. `k=5`에서 v1/v2 배치 지연의 GPU수별 수축 NLL은 `−0.383/−0.123`, 대상 셀 Student-t는 `−0.580/−0.214`로 Student-t가 좋다. v2 요청 처리량도 `−1.667`보다 Student-t `−2.036`이 좋다. Student-t는 넓은 꼬리를 사용해 90% 구간폭이 커질 수 있다. 전체 `k=2,3,5,10`의 두 지표·두 수집기·두 시간 시나리오의 CRPS, NLL, 포함률, 구간폭은 요약표 (`../artifacts/repeated_measurement_distribution_v1/summary.csv`)에 있다.

GPU수별 수축과 GPU수별 donor를 같은 8개 모델에서 짝지어 비교하면, `immediate_first_k`의 `k=2` CRPS 차이(수축−donor)는 v1/v2 배치 지연에서 `−0.00341/−0.00275`, 요청 처리량에서 `−0.00034/−0.00068`이었다. Cauchy와의 차이는 v1/v2 지연에서 `−0.02066/−0.01820`, 요청 처리량에서 `−0.01404/−0.00040`이었다. 마지막 수치는 작고 모델 단위 재표본추출의 기술적 95% 구간 `−0.00302~+0.00225`가 0을 포함한다. `k=5`에는 donor에 대해서는 개선했지만 대상 셀 Student-t에는 대부분 우월하지 않았다. 예를 들어 v2 요청 처리량의 `k=5` 차이(수축−Student-t)는 `+0.00151`, 8모델 중 수축이 나은 모델은 1개였다. 그 기술적 95% 구간은 `+0.00060~+0.00250`이다. 선택한 자료 자체를 반복 탐색했고 모델이 8개뿐이므로 이를 독립 검증의 신뢰구간으로 읽지 않는다. 모델별 점수 (`../artifacts/repeated_measurement_distribution_v1/per_model.csv`), 쌍체 차이 (`../artifacts/repeated_measurement_distribution_v1/paired_comparisons.csv`)

## 시간 절단과 비용

`cutoff_last_k`에서도 GPU수별 수축은 `k=2` 지연에서 v1/v2 CRPS `0.1052/0.1254`로 대상 셀 정규분포 `0.1142/0.1299`보다 낮았다. 하지만 `k=5` 요청 처리량에서는 v1/v2 수축 `0.0396/0.0255`, 대상 셀 Student-t `0.0363/0.0241`로 후자가 좋았다. v1 지연의 `k=5` NLL은 donor-global `−0.179`, 수축-global `−0.145`로 수축이 오히려 나빴다. 따라서 시작 직후와 평가 직전 어느 시점을 잡는지도 결과에 영향을 준다.

| 주요 시나리오 | 대상 모델당 선택 측정 GPU-wall 평균 | 대상 모델 제외 donor prior 학습 GPU-wall 평균/분할 |
| --- | ---: | ---: |
| v1, k=2 | 8.72초 | 61.02초 |
| v1, k=5 | 21.57초 | 151.01초 |
| v2, k=2 | 9.55초 | 66.85초 |
| v2, k=5 | 23.15초 | 162.03초 |

GPU-wall은 각 실행의 `replica_count × wall_seconds`를 합산했다. 대상 모델에 평균 2개의 자원 셀이 있으므로 표의 대상 비용은 **한 셀 비용이 아니라 모델의 모든 측정 셀 비용**이다. donor 비용은 모델 제외 분할마다 다른 7모델의 훈련 실행 총량으로, 실제 서비스에서 기존 기록이 있다면 재측정하지 않아도 되지만 새로 수집한다면 공짜가 아니다. 기존 SQLite의 나머지 대상 반복을 가려 만든 비교라 표는 실제 절약된 실행 시간이 아닌 반사실 측정 예산이다. 측정별 예측·비용 (`../artifacts/repeated_measurement_distribution_v1/forecasts.csv`)

## 연구 방향과 한계

현재 SQLite로 지지되는 연구 과제는 **동일 형상의 재측정 결과가 얼마나 흔들릴지 확률적으로 예측하고, 측정 횟수 2·5·10회의 점수·구간·GPU 시간을 함께 평가**하는 것이다. 고정 5 pseudo-count 수축은 아주 적은 반복에서 단독 정규·Cauchy 분포의 불안정을 줄이는 간단한 후보지만, 5회 이후 강한 대상 셀 기준선을 이기지 못했다. 따라서 다음 모델 개발에서 수축계수를 고르더라도 반드시 모델 전체 제외 donor에서만 선택하고, 대상 셀 Student-t와 같은 측정비용으로 비교해야 한다.

원리는 이미 알려진 경험적 베이즈 분산 수축([Smyth 2004](https://www.math.tau.ac.il/~yekutiel/eBayes/smyth_2004.pdf)) 및 소표본 Student-t 예측구간([NIST](https://www.itl.nist.gov/div898/software/dataplot/refman1/auxillar/predlimi.htm))과 겹친다. CRPS와 로그점수는 확률예측 평가의 기존 방법([Gneiting·Raftery 2007](https://sites.stat.washington.edu/people/raftery/Research/PDF/Gneiting2007jasa.pdf), [scoringRules 논문](https://www.jstatsoft.org/article/view/v090i12))을 사용했다. 이 방법의 원리 최초성은 주장하지 않는다.

자료는 한 호스트의 고정 조건 16개와 수집기 버전 둘뿐이다. `v1`과 `v2`는 따로 평가했지만 서로 독립적인 새 모델 집단이 아니다. 미래 20회는 상관된 반복이며, 평가·방법 설계에 같은 SQLite를 여러 번 확인했다. 수집 설정의 SLO는 `v2` 전체 24개 CPU/GPU 조건에서 충족 여부가 한 번도 바뀌지 않아 **재측정 정책이 실제 배포나 Scale-out/in 성공률을 높인다는 검증은 불가능하다.** 여기서 처리량은 `examples_per_second / batch_size`인 벤치마크 요청/초이며 실사용 트래픽 처리량이 아니다.
