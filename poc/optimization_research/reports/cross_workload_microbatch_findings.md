# 서로 다른 GPU 작업 조건의 정확한 일괄 추론 결과

2026-09-29. [사전 규약](cross_workload_microbatch_protocol.md)에 따라 저장된 ExtraTrees와 동결된 45개 작업 조건을 사용했다. [구현](../scripts/assess_gpu_shape_microbatch.py)은 유효한 여러 8후보 격자의 원본 예측만 묶고, 각 요청의 검증과 SLO 평가는 기존 GPU 형상 평가기에 맡긴다. 저장 모델·원본 SQLite·기존 평가기·Go PoC는 바꾸지 않았다.

## 결과

모델 ID 해시 순서로 5개 개발 모델과 4개 평가 모델을 분리했다. 개발 모델의 모델별 중앙 block time 평균은 배치 크기 2/4/8에서 각각 `104.652/83.648/59.735 ms`였으므로 `8`을 고정했다. 다음 표는 각 모델의 **작업 조건 5개 × 합성 SLO 25개 = 125개 질의** 전체를 처리한 중앙 시간과 별도 프로세스의 peak RSS다. 기준선은 작업 조건마다 기존 `assess_gpu_shape_many`를 한 번 호출한다. 모델 적재와 입력 읽기는 시간에서 제외했고, RSS에는 포함했다.

| 분리 | 모델 | 기준선 ms | 배치 8 ms | 속도 향상 | 기준선/배치 peak RSS MiB |
| --- | --- | ---: | ---: | ---: | ---: |
| 개발 | DistilBERT base | 134.368 | 57.562 | 2.334× | 428.37 / 428.51 |
| 개발 | BERT L2 H128 | 130.036 | 59.520 | 2.185× | 432.58 / 428.06 |
| 개발 | BERT L4 H512 | 137.477 | 60.307 | 2.280× | 432.89 / 429.32 |
| 개발 | ALBERT base | 132.919 | 59.410 | 2.237× | 430.83 / 431.53 |
| 개발 | Qwen2.5 0.5B | 128.108 | 61.876 | 2.070× | 429.40 / 428.93 |
| 평가 | BERT base | 133.656 | 60.582 | 2.206× | 428.80 / 429.24 |
| 평가 | BERT L4 H256 | 130.061 | 61.246 | 2.124× | 429.75 / 428.95 |
| 평가 | ELECTRA small | 139.051 | 58.851 | 2.363× | 428.81 / 428.61 |
| 평가 | RoBERTa base | 133.860 | 60.136 | 2.226× | 427.96 / 429.57 |

평가 모델의 중앙 시간 평균은 기준선 `134.157 ms`, 배치 경로 `60.204 ms`로 **2.228배** 빨랐다. 평가 모델 각각 빨랐고, 최대 peak RSS 비율은 약 `1.004`로 2배 한도 안이었다. 모델별 5회 측정값과 provenance는 [결과 JSON](../artifacts/cross_workload_microbatch_v1/results.json)에 있고, 순서 셔플 규칙은 [평가 코드](../scripts/evaluate_cross_workload_microbatch.py)에 있다.

peak RSS는 모델·Parquet를 읽고 예열한 뒤까지 포함하는 프로세스 전체 고수위다. 따라서 배치 추론 구간에서만 추가된 임시 메모리의 정밀한 상한은 아니다.

## 정확성 및 게이트

- 고른 배치 크기 8에서 9모델 × 5격자 × 8후보 = **360개 원본 예측**의 상태·보류 사유·수치가 각 격자별 예측과 정확히 같았다. 개발 모델에서는 크기 2/4/8 모두 같은 결과였다.
- 9모델 × 5격자 × 25 SLO = **1,125개 최종 JSON**이 기존 `assess_gpu_shape_many`의 결과와 정확히 같았다. 각 반복에서 격자 순서를 섞어도 같았다. 추가로 9모델 전체를 한 호출에 섞은 1,125개 결과도 같았으며, [별도 재현 결과](../artifacts/cross_workload_microbatch_v1/mixed_parity.json)의 정규 JSON SHA-256은 `87834d2c56f7b1924adecbaaf3bfa40e4a4821cf7e8f0f4a07943abb5fbcc924`였다.
- 잘못된 SLO, 후보 7개, 지원되지 않는 revision, 후보 역순, 반복 질의, 모델 혼합, 객체가 아닌 요청 등 9개 경계 입력의 상태·이유·순서도 같았다. [새 합성 테스트](../tests/test_assess_gpu_shape_microbatch.py) 4개와 관련 기존 GPU/SLO 테스트 22개가 통과했다. 기존 동결 manifest 검사는 아래의 보관 문서를 대조하도록 복구했고, 현재 문서 해시를 요구하는 엄격한 `verify_manifest`는 그대로 남겼다.
- 사전 게이트인 완전 동등성, 평가 모델별 속도 개선, 평가 모델 평균 2배 이상 속도 개선, 모델별 peak RSS 2배 이하를 모두 통과했다.

## 해석과 데이터 경계

이는 **이미 학습된 같은 호스트·알려진 모델의 오프라인 형상 추론 계산**을 묶는 방법이다. 지연·처리량 예측기 자체를 재학습하거나 개선하지 않았으며, 새 AI 모델의 예측 정확도·실제 사용자 지연·VM 배포·Scale-out/in 효과를 시험한 결과가 아니다. 모델 ID를 나눈 것은 배치 크기를 평가 모델의 시간에 맞춰 고르는 일을 제한하기 위한 것이다. 저장 성능 모델은 이 아홉 모델의 다른 작업 조건을 이미 학습했다. 개발 전에 전체 45개 격자의 **원본 예측 호출시간**을 탐색적으로 한 번 확인했으므로 평가 시간을 완전히 미노출 외부 시험으로 주장하지 않는다.

동결된 기존 `slo_reuse_v1` manifest는 원래 `scale_decision_feasibility.md` SHA `b81fc60d…`를 기록하지만, 현재 그 문서의 SHA는 `de851656…`다. 나중에 덧붙은 PAX 해석 문단을 제외한 [보관 규약 원문](../artifacts/slo_reuse_v1/frozen_protocol.md)의 SHA가 manifest와 **정확히 일치**함을 확인했다. 재현 스크립트는 이 원문의 해시와 현재 코드로 재생성한 **선택된 45격자·모델·원본 등 나머지 모든 필드**를 확인한다. 현재 문서를 직접 요구하는 엄격한 검사는 여전히 변경을 검출한다. [결과 JSON](../artifacts/cross_workload_microbatch_v1/results.json)에는 두 해시를 함께 남겼다.

재현: `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 /usr/bin/python scripts/evaluate_cross_workload_microbatch.py`; 전체 모델 혼합 검사는 같은 명령에 `--verify-mixed`를 붙인다. 연구용 함수는 배치 크기와 원본 출력만 다루며 VM 형상이나 배포 행동을 반환하지 않는다.

## 후속 동등성·실패 경계 확인

[전체 격자 검증기](../scripts/verify_gpu_shape_microbatch_exhaustive.py)를 고정 모델·원본에 실행해 주 CUDA 캠페인의 **575개 작업 조건·4,600개 후보** 전체를 기존 평가기와 비교했다. 최종 JSON의 불일치는 0건이었고, `RESEARCH_ESTIMATE` 355건·`ABSTAIN` 220건이었다. [집계와 결과 해시](../artifacts/cross_workload_microbatch_v1/exhaustive_parity.json)를 보존했다. 이들은 모두 저장 모델이 학습한 응용과 같은 원본의 생성 SLO이므로 독립 정확도 평가가 아니다.

합친 후보 수에만 `MemoryError`를 내는 예측기에서는 처음 구현이 예외를 전파했지만 기존 8후보 호출은 성공한다는 차이를 찾았다. 이제 합친 호출이 예외를 내거나 결과 개수가 맞지 않으면 원래 8후보 격자별로 다시 예측한다. 격자별 호출도 실패하면 그 예외를 그대로 전파한다. [회귀 테스트](../tests/test_assess_gpu_shape_microbatch.py)가 두 경우를 확인했고, 수정 뒤 위 575개 전체 동등성도 다시 통과했다. 이 수정은 예측기가 합친 입력에서 실패할 때의 의미를 맞춘 것으로, 앞의 정상 경로 속도 수치를 새로 측정한 결과는 아니다.
