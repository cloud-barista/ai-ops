## 선택과 점수

1. 후보의 배치 p95 지연 `L`, 처리 샘플/초 `E`, batch 크기 `B`에서 요청/초는 `E/B`다. 원 생성 목표 `(L₀, R₀)`를 후보 8개가 공유해야 한다. 추가 민감도 목표는 `L₀×{0.75,1,1.25}`와 `R₀×{0.75,1,1.25}`의 9개 곱집합이다. 이는 **같은 실측을 재사용한 합성 목표**이며 사용자 요청 9개가 아니다.
2. 저장 모델 예측과 저장된 `model_id×device` 훈련 중앙값 기준선은 각각 같은 규칙을 쓴다. 두 예측 지표가 모두 목표에 합격하는 후보 중 `(GPU 복제본 수, CPU affinity 코어 수)`의 사전식 최소를 선택한다. 없으면 `ABSTAIN`이다. 같은 규칙을 실측에도 적용해 oracle 가능 여부와 최소 형상을 정한다. 예측값·실측값의 비양수·비유한, 결측, 열 불일치 또는 불완전 격자는 점수 대신 오류로 처리한다.
3. 그룹당 `oracle_feasible`, `selected`, `true_success`, `false_approval`, `missed_feasible`, `correct_min_shape`를 기록한다. 마지막 항목은 선택이 실제 가능하며 oracle 최소 형상과 같을 때 참이다. 원 목표의 **실측 합격 후보 0/1–7/8개**를 난도로 나눠 전체·캠페인·모델별 선택/오승인/미선택을 요약한다. 합성 목표의 9개 점수는 목표별로 제시하고 같은 작업군의 반복을 독립 사례로 세지 않는다.
4. 선택한 후보의 두 예측 여유값을 목표로 나눠 작은 값을 `minimum_predicted_relative_margin`으로 기록하고 `<0.10`, `[0.10,0.25)`, `≥0.25`로 요약한다. 이 사후 범위는 오류가 결정 경계에 가까운지 보기 위한 설명이며 새로운 승인 문턱으로 사용하지 않는다.

산출물은 행별 CSV와 집계 JSON, 보고서다. 구현은 고정 해시·일대일 결합·단위 변환·격자·원 SLO 단일성·선택 순서를 검증하고 합성 fixture로 회귀 검사한다. 숫자 선택 후 정책 문턱을 조정하지 않는다. 배치 p95와 생성 목표는 실제 사용자 지연 SLO가 아니며, GPU 복제본은 VM 노드 수가 아니다. 실제 배포·스케일 효과의 근거로 쓰지 않는다.
