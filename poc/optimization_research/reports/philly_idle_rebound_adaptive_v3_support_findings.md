# Philly 유휴 재활성화 v3: 점수 전 앵커·지원량 결과

2026-09-28. [탐색 규약](philly_idle_rebound_adaptive_v3_protocol.md)의 **확률 점수 전** 단계만 실행했다. 기존 Philly 개발군의 12월 이전 정규화 자료를 읽고, 검증 기간 `[2017-11-16,12-01)`의 입력 적격 판단과 입력만으로 고른 앵커를 집계했다. 제안법·기준선 확률, Brier, 후행 12월 행별 정답, `[5,15)` 다른 기계의 이번 정답은 계산하지 않았다.

| 점수 전 항목 | 결과 | 규약 기준 |

| 검증 입력 적격 판단 | 4,839건·13기계 | 기존 적격성 감사와 일치 |
| 입력만으로 선택한 2시간 간격 앵커 | 1,240건 | 미래 관측·정답으로 소급 선택 금지 |

지원 조건은 각 판단보다 **엄격히 이른** `앵커 판단+7,500초` 만기의 완전 정답에만 적용했다. fleet은 목표 기계를 빼고 누적 양성 10건, 판단 날짜 5일, 감쇠 가중 유효 표본 100을 요구한다. local은 해당 기계의 누적 양·음성 각 3건, 날짜 3일, 유효 표본 20을 요구한다. 분모는 예측할 수 있는 검증 입력 후보 전체다. 학습 라벨을 온라인 상태에 다시 넣지 않았다. 검증 fleet ID는 원본 정규화 감사의 21개 ID와 일치하고 모두 해시 버킷 `<5`임을 확인했다.

[동결 manifest](../artifacts/philly_idle_rebound_adaptive_v3/freeze_manifest.json)의 SHA256은 `d0d0f24915773d0f7536d2737c9fabe65d1d3b18d90999d8e8a2c6c8815a55d4`다. [지원량 JSON](../artifacts/philly_idle_rebound_adaptive_v3/score_free_support.json)의 SHA256은 `1eddb9f400c7aefa0a5260743a71cd3a672cd24c3377ef36331664f17c96f7fa`다. 원본 Parquet SHA256은 `15f1af4669acb9823d0e6d96291e799cf33f8a9c1813d4faf51b0b9eb618ad58`; 기존 검증 JSON과 적격성 JSON도 manifest의 실제 해시로 확인했다. [지원량 감사 코드](../scripts/audit_philly_idle_rebound_adaptive_v3.py)는 12월 행을 로더에서 차단하며 기존 산출물 덮어쓰기를 거부한다. [합성 테스트](../tests/test_philly_idle_rebound_adaptive_v3.py) 9개가 통과했다.

두 지원량 문턱이 통과했으므로 **별도 검증 확률 실험을 시작할 자료 지원은 있다**. 이는 Brier 개선이나 `SCALE_IN`의 운영 효과를 뜻하지 않는다. v3는 기존 검증 결과와 개발군 12월 양성 총수를 알고 설계한 탐색 방법이다. 다음 단계에서 검증을 채점한다면 규약의 고정 Beta·다섯 적응 기준선과 동일행으로 비교하고, 사전 채택 조건을 통과하기 전에는 후행 날짜·다른 기계의 이번 정답을 열지 않는다.
