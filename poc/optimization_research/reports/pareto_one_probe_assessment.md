# 우세 형상 한 번 측정으로 배포 가능성을 판정할 수 있는가

## 결론

현재 SQLite에서 이 방식은 **경희대 고유 알고리즘으로 채택하지 않는다.** GPU 2개·CPU affinity 2코어 형상이 주 캠페인 575개 작업 중 463개에서 지연과 처리량 모두 다른 7개 형상을 지배했다. 하지만 새 작업에서 지배 여부는 그 형상 하나를 측정해서 알 수 없다. 실제 생성 SLO에서는 가능한 작업 357개를 모두 찾았어도 최소 자원 형상보다 평균 GPU를 0.703개 더 사용했다. 훈련 모델에서만 만든 25개 목표 조합에서는 실제 가능한 질의 6,746개 중 17개를 불가능하다고 잘못 판정한다. 이 17개는 **고유 작업 6개**의 측정값을 여러 목표에서 반복 사용한 결과다.

## 판단의 논리적 경계

작업의 자원 후보를 `r`이라 하고 지연은 작을수록, 요청/초는 클수록 좋다고 하자. 어떤 형상 `r*`가 **이미 모든 후보를 지배한다고 증명된 경우에만**, `r*`의 SLO 실패에서 전체 후보의 실패를 결론낼 수 있다. `r*`가 통과하면 가능 형상이 하나 있다는 사실은 직접 관측된다. 그러나 과거 모델에서 GPU 2개·CPU 2코어가 자주 우세했다는 사실은 새 모델에서의 우세를 증명하지 않는다. 한 번의 통과도 더 적은 GPU·CPU로 가능한지 알려주지 않는다.

주 캠페인 575개 완전한 8형상 작업 중 단일 형상이 두 성능 지표에서 나머지를 모두 지배하는 작업은 494개다. 그중 GPU 2개·CPU 2코어의 지배는 463개다. 외부의 새 입력 조건에서는 각각 novel-matrix 12/18, space-filling 41/44개로 같은 형상의 지배 비율이 달랐다. 모델 전체 제외 9개 분할에서 donor만으로 최빈 우세 형상을 고르면 모두 GPU 2개·CPU 2코어가 선택된다. 같은 입력 조건의 donor만으로 최빈 형상을 고르면 정확한 우세 형상 일치가 463→467/575로 네 건 늘지만, 생성·합성 목표의 가능 작업을 추가로 찾지 못하고 CPU 코어 사용은 늘어난다. 따라서 이 학습 규칙은 고정 규칙보다 결정상 이점이 없다.

## 효용 평가의 한계

수집기가 만든 원래 SLO에 대해 GPU 2개·CPU 2코어를 직접 측정한 값으로 가능 여부를 묻는다면, 관측상 가능 작업 357/357개가 통과하고 불가능 작업 218/218개가 실패한다. 이는 이 특정 목표와 호스트에서의 **사후 오프라인 정확도**다. GPU2/core2의 배치 p95 지연은 575/575개에서 원래 지연 목표를 충족하므로, 이 형상의 합격·불합격은 사실상 처리량 한 제약이 결정한다. 8형상 4,600행에서도 처리량만 통과하고 지연만 실패한 것은 5행뿐이다. 따라서 357/357은 이중 제약 판단의 강한 시험이 아니다. 가능한 357개 중 **251개**는 GPU 1개 후보로도 목표를 만족하므로, 측정한 GPU 2개 형상을 그대로 추천하면 251개에서 GPU 하나를 더 사용한다(가능 작업당 평균 0.703개). GPU 2개 측정은 두 복제 프로세스가 각각 전체 작업을 실행한 결과로, 실제 VM Scale-out 후 온라인 요청의 가능성을 측정하지 않는다. [복제 측정 의미](replica_benchmark_semantics.md)

훈련 donor만으로 만든 25개 지연·요청 처리량 목표에서는 14,375개 작업·목표 질의 중 가능한 것이 6,746개다. GPU 2개·CPU 2코어 직접 측정만으로 판정하면 가능한 6,729개를 찾고 17개는 놓친다. 17건은 Qwen 3개, ALBERT 1개, ELECTRA 2개 작업의 결과가 목표 조합에서 반복된 것이다. 한 번 측정했으므로 **측정한 그 형상을 승인할 때의 성능 오승인**은 없다. 반면 지배를 가정해 실패를 전체 불가능이라고 선언하는 경우에는 위 17건의 잘못된 불가능 판정이 발생한다. 이 규칙은 최소 자원 형상 추천과도 목적이 다르다.

모델당 8개 기준 형상을 측정해 64개 입력 조건에 예측을 전파하는 기존 방식과, 입력 조건마다 GPU 2개를 한 번씩 측정하는 방식은 **예산의 단위가 다르다.** 주 캠페인 575개 작업을 각각 직접 검증하면 관측된 GPU-wall 비용의 합은 **2,868.65초**다. 기존 모델당 8회 측정의 9모델 합계는 **62.598초**, 즉 전체 작업을 직접 검증하는 쪽이 약 **45.83배** 비싸다. 따라서 한 작업의 GPU 2개 실행 시간을 모델당 8회 전체 시간과 직접 비교해 측정 비용 절감을 주장하지 않는다. 입력 조건을 몇 개나 배포 판단에 사용할지 정해지지 않았고 실제 배포 비용·사용자 SLO도 없다.

## 선행연구와 통계적 제한

[FleetSieve](https://arxiv.org/html/2608.19659)는 처리 용량과 꼬리 지연의 불확실성을 함께 사용해 가능·보류·불가능을 조건부로 판정하고 측정을 중단하는 방식을 이미 제안한다. [Paragon](https://mast.stanford.edu/pubs/paragon_qos_aware_scheduling_for_heterogeneous_datacenters/)과 [Quasar](https://people.csail.mit.edu/delimitrou/papers/2014.asplos.quasar.pdf)는 과거 작업과 소수 프로파일을 이용한 QoS 자원 선택의 선행 사례다. Pareto 지배의 논리적 귀결과 자주 우세한 형상 한 번 측정만으로는 별도 알고리즘 신규성이 없다.

새 **모델**을 독립 보정 단위로 볼 때 donor는 최대 8개다. 90% split conformal 보정을 시도하면 필요한 순위는 `ceil((8+1)×0.9)=9`인데 점수는 8개뿐이어서 유한한 상위 분위수 임계값을 얻지 못한다. 575개 입력 조건을 독립 모델 575개처럼 취급할 수 없다. 또한 [Conformal Risk Control](https://proceedings.iclr.cc/paper_files/paper/2024/file/f3549ef9b5ff520a7e41ff3cc306ab2b-Paper-Conference.pdf)의 보장 조건을 현재 정적 측정 정책에 그대로 옮길 수 없다.

따라서 이 규칙은 필요하다면 **실측 후보를 고르는 단순 기준선**으로만 남긴다. 새 알고리즘 기여를 주장하려면 새 모델에서 우세 형상을 알 수 있는 추가 정보, 동일 GPU-wall 예산의 결정 이득, 실제 사용자 SLO 및 독립 검증이 필요하다. 현재는 기존 SQLite만 사용할 수 있다.

## 재현 근거

- 주 캠페인 Pareto front 494건과 GPU2/core2 463건은 [기존 감사 코드](../scripts/evaluate_counterfactual_slo.py)의 `pareto_summary()`와 [저장된 집계](../artifacts/counterfactual_slo_v1/metrics.json)로 확인한다.
- donor 전용 25개 목표는 같은 코드의 `training_threshold_grid()`로 생성한다. 각 제외 모델의 8형상 실측에서 하나라도 목표를 만족하는지와 GPU2/core2 실측이 목표를 만족하는지를 비교한다. 목표를 만드는 데 제외 모델 결과를 사용하지 않는다.
- 575개 직접 측정 비용은 동결 측정 스냅샷 (`../data/audit_v1/measurements.parquet`)의 GPU2/core2 행에 대해 `sum(2 × wall_seconds)`로 계산했다. 8회 기준 측정 비용은 분할·프로브 기록 (`../artifacts/cross_model_covariance_v1/split_manifest.csv`)에서 `budget=8`, `selector=space_filling`인 9행의 `gpu_wall_probe_seconds`를 합산했다. 원본 스냅샷 SHA-256은 `b7bba7963e8a309b6a8502a1d98eefb150476b1381ec016beeb68cbf63fae906`이다.
