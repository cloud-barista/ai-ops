# BERT 계열 공동 제외 후 GPU 1개 계측값의 복제 예측 효과

## 검증 질문과 분할

GPU 1개 실행의 GPU·CPU 계측값이 GPU 2개 실행의 성능 예측에 도움이 된다는 [기존 모델별 제외 결과](telemetry_conditioned_scaling_findings.md)가 가까운 BERT 계열 모델을 학습에 남겼기 때문인지 확인했다. 등록 BERT 네 종(`bert-base`, `L-2_H-128`, `L-4_H-256`, `L-4_H-512`)을 **한꺼번에 학습에서 제외**했다. 학습 donor는 RoBERTa, ALBERT, DistilBERT, ELECTRA, Qwen이다. 비교 기준선, 전체 계측, 샘플 수 제외 계측 모델 모두 이 donor의 주 캠페인 데이터로만 학습했다.

평가 대상의 **같은 작업 GPU 1개·CPU 2코어 실측 성능과 `node_summary_json`**은 현재 상태 입력으로 제공했다. GPU 2개·CPU 2코어의 성능과 모니터링은 예측 함수에 전달하기 전에 가리고, 점수 계산에만 썼다. 주 캠페인 256개, novel-matrix 8개, space-filling 20개 GPU 2개 작업을 평가했다. 세 캠페인은 동일 `icns` 호스트, RTX PRO 5000 Blackwell, 수집기 v2 자료다. novel/space 조건은 주 학습 그리드에 없다. 이 설정은 이미 실행 중인 응용의 같은 호스트 복제 후 **정적 용량** 예측이다.

## 네 BERT 모델의 예측 오차

모델별 평균 절대 로그오차(MALE)를 네 모델에 다시 평균했다. 처리량은 초당 요청 수다.

| 평가 조건 | 기준선 지연 / 처리량 | 전체 계측 지연 / 처리량 | 샘플 수 제외 지연 / 처리량 |
| --- | ---: | ---: | ---: |
| 주, 256작업 | **0.2695 / 0.0952** | 0.2756 / **0.0947** | 0.2759 / 0.0959 |
| Novel, 8작업 | 0.3089 / **0.0878** | **0.3050** / 0.0986 | 0.3073 / 0.0889 |
| Space, 20작업 | 0.3313 / 0.1155 | **0.3257 / 0.1050** | 0.3299 / 0.1085 |

주 캠페인에서 전체 계측의 처리량 이득은 **0.0005 로그 단위**로 매우 작고, 샘플 수를 빼면 이득이 사라진다. Novel에서는 두 계측 방식의 처리량 오차가 커진다. Space에서는 개선이 남지만, 전체 계측의 모델별 이득 `0.0453` 중 대부분이 `bert-base` 하나에서 나오고 `L-4_H-512`에서는 오히려 나빠진다. 지연은 조건별 방향이 엇갈린다.

비교를 위해 기존 모델별 제외 결과에서 **같은 네 BERT 모델만** 다시 집계하면, 주 캠페인의 처리량은 기준선 `0.0900`, 전체 계측 `0.0902`였다. 따라서 원래 아홉 모델 평균의 주 캠페인 처리량 개선도 이 네 모델에서는 관찰되지 않았다. 공동 제외 후의 작은 차이를 계열 제거로 인한 뚜렷한 변화라고 해석할 수 없다.

## 정적 GPU 1→2 판단

실제 사용자 목표가 없으므로 **학습 donor의 GPU 2개 성능 분위수에서만** 지연·처리량 목표를 각각 5개씩 만들었다. 현재 GPU 1개가 목표를 못 맞추고 예측상 GPU 2개가 둘 다 만족할 때만 복제를 승인했다. 한 작업에서 나온 25개 가상 질의는 서로 상관된다.

| 조건 | 실제 복제로 구제 가능한 질의 | 기준선 성공 / 오승인 | 전체 계측 성공 / 오승인 | 샘플 수 제외 성공 / 오승인 |
| --- | ---: | ---: | ---: | ---: |
| 주, 256작업 | 1,520 | 1,407 / 294 | 1,418 / 299 | 1,408 / 296 |
| Novel, 8작업 | 60 | 55 / 6 | 55 / 6 | 55 / 6 |
| Space, 20작업 | 163 | 140 / 20 | 140 / 25 | 140 / 25 |

주 캠페인의 성공 11건 증가는 승인 16건 증가와 오승인 5건 증가를 동반한다. Space에서는 성공은 그대로이고 오승인이 5건 늘었다. 따라서 **처리량 오차 개선이 이 분할의 판단 개선으로 이어지지 않았다.** 목표와 결과는 실제 시간 순서의 Scale-out 행동이나 VM 생성 결과가 아니다.

## DistilBERT까지 제외한 보조 분할

DistilBERT도 대상에 넣으면 donor는 RoBERTa, ALBERT, ELECTRA, Qwen 네 종이다. 다섯 대상 전체의 처리량 오차는 전체 계측 방식에서 주 `0.1000→0.0960`, Space `0.1515→0.1284`로 줄고 Novel `0.1220→0.1246`으로 커졌다. 그러나 같은 분할의 **BERT 네 대상만** 보면 주 `0.0920→0.0921`로 여전히 이득이 없고, Space `0.1312→0.1095`만 개선됐다. 다섯 대상 집계의 주 캠페인 이득에는 DistilBERT가 크게 기여한다.

다섯 대상의 가상 목표에서 전체 계측 방식의 성공/오승인은 주 `2,062/642`로 기준선 `2,054/637`보다 모두 늘었다. Space는 `180/51` 대 `178/52`로 소폭 개선됐지만 작업 25개에서 만든 상관 질의다. Novel은 두 방법 모두 성공 57건, 오승인 21건이다. 분할을 더 엄격하게 해도 판단의 일관된 이득은 확인되지 않는다.

## 해석

기존 SQLite만으로 한 **사후 스트레스 테스트**다. 네 BERT 모델을 함께 빼도 RoBERTa와 ALBERT처럼 구조적으로 관련된 encoder가 donor에 남는다. 새 호스트·GPU·사용자 SLO로 일반화하는 증거는 아니다. GPU 2개는 같은 호스트의 두 replica이며 두 VM이 아니다. 또한 `latency_p95_ms`는 배치 p95이고, 이 자료에는 시간에 따른 실제 복제 action과 전환 비용이 없다.

현재 자료에서 계측값은 특정 새 입력 조건의 **처리량 예측 후보**로 남길 수 있다. 그러나 BERT 계열 공동 제외, Novel 조건, 가상 판단을 함께 보면 일관된 배포·스케일링 이득이나 새로운 원리의 성능 우위를 입증하지 못했다.
