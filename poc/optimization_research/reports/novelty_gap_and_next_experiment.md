# AI-MCMP 고유 방법 연구: 현재 근거와 다음 검증

## 현재 결론

기존 SQLite로 **학습과 모델 단위 제외 평가**를 수행했다. 새 모델의 소수 기준 측정으로 자원별 성능을 예측하는 방향은 유효하다. 그중 과거 모델의 예측 오차 2차 모멘트를 전이하는 방법은 **같은 입력 조건 격자**에서 강한 기준선보다 나았다. 이를 [경희대의 응용별 형상 추천 방법 후보 v1](anchor_residual_transfer_method_v1.md)로 구체화했다. 그러나 새로운 입력 조건에서는 처리량 개선이 재현되지 않았다. 현재는 제한된 연구 후보 구현으로 보관하며, 학술적 최초성이나 운영 배포 정책으로 확정하지 않는다.

## 데이터가 답할 수 있는 문제

주 캠페인은 한 로컬 GPU 호스트에서 9개 모델, 575개 모델·입력 조건, 조건마다 GPU 1/2개 × CPU affinity 2/4/8/16코어의 8개 후보를 측정했다. 아래 실험은 모델 ID 하나를 통째로 제외하고 나머지 8개 모델로 학습한다. 새 모델은 GPU 1개·CPU 2코어의 입력 조건 8개만 측정한다. 나머지 조건과 자원 후보를 예측해 실측과 비교한다. 비용은 측정된 `GPU 개수 × wall_seconds`다. 이 자료는 **앱 특성을 반영한 형상 추천의 성능 예측**에 적합하다.

주 캠페인의 SLO는 수집 때 생성됐고 배치 p95 지연을 사용한다. 4,600개 후보 가운데 처리량 SLO는 통과하고 지연 SLO만 실패한 행은 5개다. 따라서 현재 SLO 선택 결과는 실사용자 지연 제약을 검증하지 않는다. 자연어 요청과 요구 형상의 정답, 시간 순서가 있는 운영 상태·scale action과 그 결과, 가격·VM 비용 정보도 없다. 이 자료로 요구사항 분석이나 scale-out/in 정책의 학습 효과를 평가할 수 없다.

기존 SQLite에는 RTX 5070 Ti 원격 캠페인의 새 causal LM 2개와 공통 8형상 작업 조건 24개도 있다. 모델·호스트·작업 종류가 함께 달라지는 **스트레스 테스트**는 가능하지만, 이 2개 모델만으로 어느 변화가 오차를 일으켰는지 분리할 수 없다. 원격 SLO도 수집기에 고정된 값이며 대부분 후보가 통과한다. 별도 FCA 분산추론 자료의 자원 형상은 이 8형상 실험과 달라 같은 희소 측정 검증에 직접 합칠 수 없다.

기존 8형상의 성능 Pareto 집합도 단순하다. 575개 입력 조건 중 **494개**는 지연이 가장 낮고 요청/초가 가장 높은 **한 형상**이 나머지를 모두 지배한다. 성능 목표를 다양하게 만들어도 대다수 조건의 *가능 여부*는 이 형상 하나로 판정된다. 자원 비용을 포함한 최저비용 선택은 별도 문제지만, SQLite에는 실제 VM 가격이 없다.

[같은 수집기 버전의 반복 실행](repeat_variability_findings.md)에서는 16개 고정 GPU 조건의 47회 실행에서 배치 p95 지연/처리량 로그 표준편차의 조건별 중앙값이 **0.168/0.022**였다. 이 16개 조건은 주 캠페인의 575개 작업 조건과 정확히 겹치지 않으므로 주 실험의 오차 하한으로 옮길 수 없다. 그래도 작은 지연 오차 개선을 해석할 때 반복 측정 변동을 별도로 검증해야 한다는 근거다.

| [모니터링 값의 작업별 대응 순열 대조](telemetry_permutation_control_findings.md) | GPU 1개 텔레메트리 4개를 작업 간 섞으면 GPU 2개 처리량 MALE 0.0961→0.1167, 같은 배치 안에서 섞으면 0.1094. 정렬된 입력이 두 대조의 32/32 시드보다 좋음. | 현재 SQLite에서 작업에 맞는 계측값에 예측 정보가 있다는 내부 근거. 인과성·계열 전이·Scale-out action 개선이나 새로운 원리 증거는 아님. |
| [새 입력 조건에서 공분산 보간](cross_model_covariance_findings.md) | 같은 모델의 새 novel-matrix 조건 16개: 공분산 0.320/0.379, 커널 0.346/0.361. space-filling 40개: 공분산 0.369/0.352, 커널 0.350/0.324. 새 조건 프로브 0회. | 처리량은 두 외부 캠페인에서 모두 악화됨. 공유 격자 이점을 일반화할 수 없음. |

| [반복 측정의 새 조건 전이](live_repeat_transfer_findings.md) | 같은 수집기 버전의 live 47회 반복·16 GPU 셀 중앙값에서 공분산/커널 지연 0.2275/0.2292, 처리량 0.2683/0.2681. 생성 SLO를 적용할 수 있는 6개 GPU쌍에서 선택 성과 동일. | 별도 시간에 측정한 새 입력 조건에서 공분산 고유의 이득이 거의 없음. |

공분산 전이 실험은 다른 모델들을 내부 교차 검증으로 예측해 얻은 기준 형상의 로그 오차를 사용한다. 원래 구현은 오차의 **비중심 2차 모멘트**를 prior로 쓰므로 조건 간 공변동과 이전 모델의 공통 오차 방향이 섞인다. 별도 분해 실험에서 평균을 제거한 공분산은 성능을 거의 유지했고, 공통 평균 오차만 옮기면 이득이 사라졌다. 새 모델의 8개 실측 로그 오차를 prior에 조건화해 미측정 기준 성능을 추정하고, 기존 조건부 자원 반응 모델로 다른 GPU·CPU 형상에 전파한다. 공유 격자가 없으면 부드러운 커널로 대체한다. 모델의 파라미터 바이트 수는 등록 시 이미 알려진 정적 메타데이터라는 가정이 있다. 미측정 새 모델 성능을 prior, 선택 또는 예측 입력에 사용하지 않는 테스트를 넣었다.

## 선행연구와 주장할 수 있는 범위

[Paragon](https://people.csail.mit.edu/delimitrou/papers/2013.asplos.paragon.pdf), [PowerTrain](https://arxiv.org/html/2407.13944), [MaverIQ](https://ut-sysml.ece.utexas.edu/publications/prints/sc2025_liakopoulos.pdf)은 새 응용/모델의 소수 측정과 이전 지식의 자원 성능 전이를 다룬다. [Jamshidi 등의 설정 가능 시스템 성능 전이](https://pooyanjamshidi.github.io/resources/papers/tl-robot-seams17.pdf)는 기존 환경의 성능 상관관계와 새 환경의 일부 측정으로 설정별 예측을 갱신한다. [LimeQO](https://zixy17.github.io/pdf/limeqo_sigmod25.pdf)는 작업×설정 성능 행렬과 비용을 고려한 측정을, [FleetSieve](https://arxiv.org/html/2608.19659)는 SLO 결정에 중요한 부하·설정의 능동 측정을 다룬다. [Bonilla 등의 multi-task GP](https://papers.nips.cc/paper_files/paper/2007/hash/66368270ffd51418ec58bd793f2d9b1b-Abstract.html), [MAGMA](https://link.springer.com/article/10.1007/s10994-022-06172-1), [Empirical Gaussian Processes](https://arxiv.org/html/2602.12082)는 과거 작업의 공분산 또는 공통 prior를 새 작업의 적은 관측에 활용한다. 마지막 연구는 과거 곡선에서 경험적 공분산을 구하고 새로운 입력 위치로 보간하는 문제까지 다룬다. [Feasibility-Aware Decision-Focused Learning](https://papers.nips.cc/paper_files/paper/2025/hash/ef158a0d4f5364741a571b8d1d44fb1b-Abstract-Conference.html)은 예측한 제약 조건의 가능성과 선택의 질을 함께 다룬다. 따라서 **소수 측정, 경험적 공분산 전이, SLO/비용 기반 측정 선택, 가능성에 민감한 결정 손실 자체를 최초의 원리로 주장할 수 없다.**

가능한 연구 질문은 더 좁다. *AI 응용마다 작은 기준 형상의 요청 조건 몇 개를 측정할 때, 어떤 이전 모델의 오차 구조가 자원 형상 선택에 유용한가? 격자가 달라질 때 전이를 언제 줄이거나 포기해야 안전한가?* 지금 결과는 첫 질문의 공유 격자 사례를 지지하고, 둘째 질문에 필요한 실패 사례를 보여준다. 이 두 질문을 함께 해결하는 재현 가능한 규칙과 강한 기준선 대비 이득이 있어야 이 프로젝트의 방법론적 기여를 논할 수 있다.

측정 위치와 이전 모델을 고르는 후속 가설에도 선행 경계가 있다. [L2S](https://pooyanjamshidi.github.io/resources/papers/l2s.pdf)는 원천 설정의 영향 정보를 이용해 새 환경의 측정을 고르고, [SimTune](https://tfjmp.org/publications/2020-bigdata.pdf)은 유사한 원천 환경을 선별해 설정 튜닝을 전이한다. [FleetSieve](https://arxiv.org/html/2608.19659)는 지연·처리량 결정에 중요한 측정을 고르며, [비용 민감 다중작업 탐색](https://www.cs.princeton.edu/~rpa/pubs/swersky2013multi.pdf)도 선행한다. 따라서 프로브 선택이나 donor 가중 자체도 새 원리로 주장하지 않는다.

## 현재 선택과 향후 검증 기준

1. **방법 후보의 범위:** 같은 입력 격자를 공유하는 encoder 모델에는 내부 모델 제외 잔차의 **중심화 공분산·평균 0 prior**가 커널보다 나았다. 그러나 BERT 계열 공동 제외에서 지연 이점이 사라지거나 역전되고, 반복 측정의 새 조건에서도 고유 이득은 없었다. 격자 밖 보간, 원격 새 모델, 자원 형상 전체 잔차 전이, 지원 범위 게이트, 비슷한 donor 가중, 고정·순차 프로브 선택은 강한 기준선 대비 공동 개선을 입증하지 못했다. 새 조건의 부드러운 지연 반응과 실행 중 모니터링의 처리량 예측은 보조 가설로 남지만, 모니터링 방식도 BERT 계열 제외에서 처리량 이득이 불안정하고 의사결정 개선은 확인되지 않았다. 현재는 공유 격자의 성능 예측 연구 후보와 현재 응용의 GPU 복제 성능 예측 후보만 남긴다. 실제 배포·스케일 정책이나 고유 알고리즘으로 채택하지 않는다.
2. **강한 기준선:** zero-shot, 전역 평균 보정, 같은 프로브를 쓰는 직접 ridge 보정, 부드러운 커널만 쓰는 보정, 모든 기준 형상을 측정한 참고치를 모두 비교한다. 같은 새 모델·입력 조건·GPU 측정 시간을 분모로 한다. 학습되지 않은 모델 크기와 새 작업 종류에는 별도 층을 만든다.
3. **독립 자료가 확보되면:** 공유 격자 중심화 공분산 방식의 혼합비 50%, 프로브 8개, 커널·관측 잡음·예산 계산식을 평가 전에 고정한다. 먼저 **새 모델 ID를 기존 호스트에서** 측정해 효과의 재현성을 확인한다. 다음으로 다른 GPU/VM 호스트별로 과거 모델의 donor 기록을 확보한 뒤, 각 호스트에서 새 모델을 제외해 평가한다. 과거 donor가 전혀 없는 새 호스트로의 전이는 하드웨어 특징을 포함한 별도 모델이 필요하므로 다른 문제로 구분한다. 실제 요청 지연 p95·요청/초·배포 비용을 반복 측정하고, 수집기 버전과 warmup을 고정하며 실행 순서를 무작위화한다. 사용자가 정한 지연·처리량 SLO를 별도로 기록한다. 먼저 소규모 파일럿으로 변동과 실행 비용을 재고, 그 결과로 확증 평가의 모델 수와 반복 수를 산정한다. **현재는 새 자료를 사용할 수 없으므로 이 단계는 보류한다.**
4. **판정:** 1차 지표는 미측정 형상의 지연·요청 처리량 오차를 **모델 및 호스트 단위**로 함께 평가한 결과다. 2차 지표는 같은 GPU-wall 예산에서 실측 SLO 성공, 위반, 실제 VM 비용이다. 두 지표의 모델·호스트 단위 차이와 불확실성 구간을 모두 공개한다. 처리량이나 격자 밖 조건에서 기준선보다 나빠지면 적용 범위를 제한하거나 전이 규칙을 폐기한다. 지금의 생성 SLO 결과만으로 배포 정책을 채택하지 않는다.
