# Philly 기계 전체 유휴 후 GPU 재활성화: 점수 전 탐색 규약

**상태: 모델 학습·검증·시험 점수 전 동결 대상.** 작성일 2026-09-28. 이 규약은 [Philly GPU 슬롯별 30분 고사용률 위험](philly_gpu_risk_findings.md) 및 [다른 기계에서의 확인](philly_machine_holdout_findings.md)과 다른 정답을 시험한다. 기존 평가는 현재 슬롯의 사용률이 80% 미만일 때 다음 30분의 슬롯별 80% 초과를 예측했다. 이번에는 **기계에 있는 모든 GPU가 30분 동안 낮은 사용률을 보인 뒤, 기계의 어느 GPU가 2시간 안에 다시 활성화되는지**를 예측한다. 경희대 `SCALE_IN` 판단에 앞서 사용할 수 있는 *유휴 지속 위험 입력*의 연구다. GPU가 다시 바빠지는 것이 VM 축소 실패 또는 사용자 SLO 위반이라는 뜻은 아니다.

이 라벨·10%/50% 임계값과 `<5` 기계군의 대략적인 양성 건수는 **규약을 쓰기 전에 읽기 전용으로 탐색**했다. 따라서 `<5` 기계군의 12월 점수는 탐색 결과다. `[5,15)` 해시 버킷의 기계는 다른 30분 위험 연구에서 이미 이용했지만, 이 **새 유휴·재활성화 라벨의 행별 결과나 점수는 아직 보지 않았다.** 그것도 같은 Philly 클러스터·같은 2017년 기간이므로 독립 서비스 검증은 아니다. 로지스틱 회귀, Beta 확률표, 보수적 위험 순위나 GPU 사용률 예측 자체의 학술적 최초성은 주장하지 않는다.

## 출처와 점수 전 보존

- [Microsoft Philly 공개 추적](https://github.com/msr-fiddle/philly-traces/blob/29a1b87fa2d9ed80b83c9e3a37f3a88d382b031d/README.md)의 고정 commit은 `29a1b87fa2d9ed80b83c9e3a37f3a88d382b031d`다. 원본 압축 SHA256 `2037ccf63a725a02be718b0e1aeee6142c90b7f62d0d849295120e9f6ba13d2c`와 정규화 감사의 `integrity_pass`를 확인한다. 원본은 DNN 훈련 클러스터의 GPU별 분 단위 사용률이고 AI-App 요청/지연·VM 증감 명령을 담지 않는다.
- 모델 개발 원본은 [해시 버킷 `<5`](../data/external/msr_philly_2017/SOURCE.md)의 21기계·1,704,704행, 정규화 Parquet SHA256 `15f1af4669acb9823d0e6d96291e799cf33f8a9c1813d4faf51b0b9eb618ad58`이다. 별도 기계 시험은 [해시 버킷 `[5,15)`](../data/external/msr_philly_2017_holdout/SOURCE.md)의 47기계·4,040,392행, 정규화 SHA256 `146fe4318d6634120bdc10b2af9522be6c0a113c3213fb386a007b4d21edbdf8`이다. 두 ID 집합은 겹치지 않는다. 같은 원본 클러스터이며 원본 전체 압축본은 로컬에 보존하지 않았다.
- [자료 적격성 코드](../scripts/audit_philly_idle_rebound.py)는 원본·정규화 감사와 Parquet 해시/행수/기계 해시 버킷을 확인하고, 집계된 후보·정답 **건수만** JSON으로 낸다. 학습·예측 확률·Brier·행별 라벨은 계산/저장하지 않는다. 합성 경계 검사는 [테스트](../tests/test_philly_idle_rebound_audit.py)에 둔다. 동결 manifest에는 규약·감사 코드·테스트·두 Parquet의 SHA256을 기록한다. 감사 코드는 manifest가 다르면 중단한다.
- 개발 자료의 적격성 감사 후 학습 코드와 검증 선택을 별도 manifest로 동결한다. `[5,15)` 기계군의 **12월 적격성/양성 건수도 이 선택 manifest가 있기 전에는 감사하지 않는다.** 감사 코드는 선택 manifest가 가리키는 **실제** `joblib` 모델, 선택 Python 코드, 검증 지표 JSON, 개발 적격성 JSON의 해시를 확인한다. 검증 JSON 안의 규약·원본·모델·코드 해시, 검증 행 수, 세 기준선 Brier와 세 로지스틱 `C`의 Brier도 대조하고, 기준선 및 `C` 선택이 아래 동률 규칙에 맞아야만 잠금을 푼다. 64자 문자열만 적힌 manifest는 해제 근거가 아니다. 기계군은 학습, 정규화, 하이퍼파라미터/기준선 선택, 임계값 선정에 일절 사용하지 않는다.

## 시점, 코호트, 정답

첫 원시 행에서 정해진 기계별 GPU 슬롯 수(2/4/8)를 유지한다. 기계·분 중복, 첫 행과 다른 슬롯 폭, `row_usable=false`, 유한하지 않거나 `[0,100]` 밖인 **기대 슬롯 중 어느 하나**가 있으면 그 분은 무효다. UTC 5분 창 `[t,t+300)`의 정확한 5개 분 `t,t+60,...,t+240`이 고유·유효할 때만 각 슬롯의 평균을 내고, 기계 값 `u_t`를 **슬롯별 5분 평균 중 최대**로 정한다. 기계 최대를 분마다 구한 뒤 평균하지 않는다. 미관측 분·창을 사용률 0으로 바꾸지 않는다.

판단은 UTC **30분 격자**의 `d=t+600초`에 한다. 최신 입력창 `[t,t+300)`은 `t+300`에 끝나고, 추가 **5분 전달 지연을 가정**하여 `d`에 사용할 수 있다고 둔다. 실제 계측 수신 시각은 추적에 없어 이 가정은 온라인 가용성을 입증하지 않는다. 입력 코호트는 `[t-1500,t+300)`의 연속 6개 창이 모두 유효하고 `u<10%`인 기계뿐이다. `u=10%`는 유휴 조건에서 제외한다. 중간 `[d-300,d)` 창은 그 시점에 전달 지연이 끝나지 않았으므로 입력에도 정답에도 쓰지 않는다.

정답은 **결정 이후** `[d,d+7200)`의 연속 24개 유효 창에서 `u≥50%`가 하나라도 있으면 `rebound=1`, 그렇지 않으면 `0`이다. 미래 24개 창 중 하나라도 미관측·무효이면 정답을 `unknown`으로 보존하고 모델 적합/점수에서 제외한다. `u=50%`는 재활성화에 포함한다. 정답의 마지막 창이 끝나고 전달 지연 5분이 지난 `d+7500초`를 라벨 가용시각으로 둔다. 원본에는 작업 시작·종료, 사용자의 실제 요청 SLO, 머신 예약 변경 시각, VM 제어 명령이 없으므로 재활성화의 원인·행동 효과를 추정하지 않는다.

| 집합 | 판단 `d`의 반열린 UTC 범위 | 라벨 완결 조건 |
| --- | --- | --- |
| 개발 학습 | `[2017-10-04, 2017-11-16)` | `d+7500 ≤ 2017-11-16 00:00` |
| 개발 검증 | `[2017-11-16, 2017-12-01)` | `d+7500 ≤ 2017-12-01 00:00` |
| 개발 후행 시험 | `[2017-12-01, 2017-12-16)` | `d+7500 ≤ 2017-12-16 00:00` |
| 다른 기계 최종 확인 | 위와 같은 12월 후행 시험만 | 학습·선택 동결 뒤에만 정답 확인 |

검증과 시험에서 판단 이전의 완결된 과거 창을 이전 분할에서 가져올 수 있다. 과거 2시간·24시간 특징은 **최신 사용 가능 창을 끝으로 하는 24개·288개 5분 격자 창**에서 계산한다. 사용 가능한 실제 창만 통계량에 넣고, 기대 창 수 대비 유효 창 비율을 별도 특징으로 둔다. 24시간의 일부가 결측이거나 관측 시작 전이면 그것만으로 후보를 버리지 않는다. `최근 24시간 ≥50% 사용`의 마지막 시각이 없으면 나이를 24시간으로 자르고 `관측된 이전 고사용률 없음` 표시를 붙인다. 최근 6개 유휴 창은 항상 완전해야 한다. 따라서 모델은 미관측값을 0% 사용률로 간주하지 않는다.

## 고정 비교 방법과 선택

모든 방식은 같은 적격 후보에만 점수를 낸다. 기준선은 학습 라벨로 만든 (1) Beta(1,1) 평활 전역 재활성화율, (2) 직전 **2시간** 유효 창에서 `u≥50%`였는지에 조건부인 Beta 확률표, (3) 직전 24시간 마지막 `u≥50%`까지 경과시간 `≤2시간`, `>2–6시간`, `>6시간`, **관측된 이전 고사용률 없음** 네 구간의 Beta 확률표다. 조건부 표의 각 셀은 전역 학습 발생률을 중심으로 20건의 pseudo-count를 넣어 수축한다. 결측 창 때문에 과거 고사용률을 확인하지 못한 경우 (2)는 별도 `unknown` 셀이고, (3)은 `없음` 표시와 유효 창 비율로 누락 여부를 함께 보고한다. 세 기준선 중 **검증 Brier 최저**를 대표로 고정한다. 동률이면 (3), (2), (1) 순서다. 시험 뒤 기준선을 바꾸지 않는다.

연구 모델은 하나의 L2 로지스틱 회귀다. 입력은 최근 유휴 6창의 `u` 여섯 값, 과거 2시간과 24시간에서 **유효 창만의** `u` 평균/최대, 두 구간의 유효 창 비율, 관측된 마지막 `u≥50%`까지의 경과시간(24시간 상한)과 없음 표시, 첫 행에서 정해진 GPU 슬롯 수, 판단 시각 UTC 하루 주기의 사인/코사인이다. 과거 2시간·24시간에는 최근 6창이 포함되므로 평균/최대는 정의된다. 모든 연속 특징의 중앙값/표준화는 **학습 후보만**으로 적합하고 표준편차 0은 1로 둔다. 클래스 가중치나 기계 ID 특징은 쓰지 않는다. 정규화 강도 `C∈{0.1,1,10}` 중 검증 Brier 최저를 고르고 동률이면 작은 C를 고른다. 검증·시험 라벨로 회귀계수를 재적합하지 않는다. 같은 기계의 서로 겹치는 2시간 정답 창을 독립 사건처럼 취급하지 않는다.

학습/선택 코드의 구현·합성 테스트·모델/기준선 선택값과 파일 해시를 **개발 후행 시험 및 다른 기계군의 확률/성능을 보기 전에** 별도 선택 manifest에 고정한다. 기존 다른 목표의 Philly 모델 확률을 이 새 라벨의 기준선으로 옮기지 않는다.

## 자료 게이트, 점수, 연구 GO 판정

먼저 원본 lineage·버킷·창/시점 구현 검사를 통과해야 한다. 개발 학습·검증·후행 시험 각각, 그리고 별도 기계군의 12월 시험에서 다음을 요구한다: 30분 유휴 입력 후보 중 미래 24창 완전 관측 비율 **≥90%**, 완전 정답 **≥500**, 재활성/비재활성 **각 ≥100**, 완전 정답 기계 **≥10**, 재활성 기계 **≥5**, 재활성 UTC 날짜 **≥5일**, 동일 기계의 양성 판단을 2시간 초과 간격으로 묶은 대략적 재활성 구간 **≥20개**. 한 조건이라도 실패하면 해당 집합의 모델 성능을 계산하지 않고 부족한 지지량을 보고한다. 이 묶음 수는 독립 사건의 엄격한 수가 아니다. **기계×UTC일**에 유휴 판단이 4건 이상 있는 집합도 10개 이상이어야 하며, 그중 미래 완전 관측률이 50% 미만인 기계일은 10% 이하여야 한다. 미관측 미래가 20건 이상이면, 미래 완전/미완전 후보의 과거 288창 유효 비율 평균 차이가 **20%포인트 이하**여야 한다. 넘으면 자료 선택 편중 우려로 해당 집합의 성능 시험을 중단한다. 미관측 후보가 20건 미만이면 차를 보고만 한다. 기계일별 관측률의 10백분위와 미관측/관측의 과거 이력 유효율을 함께 기록한다. **기계의 기록 마지막 1–23개 미래 창만 남아도 그 유휴 판단을 분모에서 빼지 않고 정답 미관측으로 센다.** 계측 관측률은 라벨이 0인 비율과 구분한다. 24시간 이력 완전/부분 건수와 최소 유효 창 수를 보고하되, 이력이 부분적이라는 이유만으로 별도 품질 게이트를 만들지 않는다.

주 지표는 같은 행의 **Brier score**다. 기계 동일 가중 Brier, AP, 평균 예측과 실제 재활성화율, 기계·날짜별 성적, 12월 1–7일/8–15일 고정 반구간을 보조로 보고한다. 동일 기계의 겹치는 2시간 정답과 클러스터의 공통 날짜 충격을 따로 살피기 위해 기계 단위와 **UTC 날짜 블록 단위**의 짝지은 2,000회 재표집(seed 43) Brier 차 95% 구간을 모두 보고한다. 두 구간 모두 날짜/기계 수가 적고 다른 클러스터 전이 구간은 아니다. 예측 확률이 가장 낮은 **20% 판단**에서 실제 재활성화 비율을 모델과 고정 기준선에 같은 건수로 비교한다. 동점은 `SHA256(machine_id UTF-8 || ':' || decision_utc_s 십진수)` 오름차순이다. 20%는 시험 라벨을 보지 않고 각 방법의 예측 순위로 고르며, 실제 `SCALE_IN` 권고 수치가 아니다.

**후속 연구 GO**는 자료 게이트를 모두 통과하고, 로지스틱의 Brier가 검증 선택 기준선보다 개발 후행 시험과 다른 기계 시험에서 각각 **상대 ≥5% 낮고**, 다른 기계 시험의 **기계·날짜 두 재표집 차 상한이 모두 0 미만**이며, 두 집합의 기계 동일 가중 Brier와 두 시험 반구간 Brier가 모두 낮고, 양쪽 시험의 하위 20% 위험층 실제 재활성화 비율이 기준선보다 높지 않을 때로 고정한다. 어느 하나라도 실패하면 제안 특징/모델을 채택하지 않는다. 통과해도 한 DNN 학습 클러스터에서 **관측 사용률 재활성화 위험**을 더 잘 순위화한 탐색 결과일 뿐, 새 알고리즘의 고유성·안전한 VM 축소·사용자 SLO 개선은 별도 증거가 필요하다.
