# 적은 반복 측정으로 미래 벤치마크 분포 예측: 실험 규약

## 연구 질문과 기존 감사와의 차이

같은 AI 응용·GPU 형상을 여러 번 측정할 때, 처음 몇 번의 실행과 **다른 모델에서 학습한 변동 폭**만으로 나중 한 번 실행의 배치 p95 지연과 요청 처리량 분포를 얼마나 잘 예측할 수 있는가? 이는 형상별 평균 성능이나 GPU 1→2개 처리량을 예측하는 기존 연구와 다른 학습 목표다. [반복 측정 변동 감사](repeat_variability_findings.md)는 셀별 표준편차를 기술했다. 여기서는 대상 모델을 학습에서 완전히 제외하고, 시간상 미래 실행의 **확률 밀도·90% 예측구간**을 점수화한다.

대상은 기존 `khu-hf-live` SQLite에서 추출한 성공한 GPU 벤치마크다. 수집기 `v1` 63회와 `v2` 47회는 버전별로 분리한다. 각 버전은 같은 GPU 셀 16개, 모델 8종을 반복했다. CPU affinity 한도는 2코어다. 동일 호스트·동일 고정 조건의 **미래 단일 실행**이 예측 대상이며, 새 모델·새 호스트·실사용자 요청의 SLO는 아니다.

## 잠근 분할과 비교 방법

각 버전의 실행을 **실제 시작 시각**으로 정렬한다. `v1` 앞 43회와 `v2` 앞 27회만 학습·초기 측정에 쓰며, 버전별 마지막 20회는 평가에만 쓴다. `run_id`의 숫자 접미사를 시간순으로 가정하지 않는다. 실제로 `v1`의 `round-100`은 가장 먼저 실행됐다. 대상 모델을 하나씩 제외한 나머지 7모델에서 각 셀 로그 성능의 평균을 빼고 제곱잔차를 모아 전역 분산 `v_donor`를 학습한다. 분모는 donor 관측 수에서 donor 셀 수를 뺀 잔차 자유도다. 별도로 GPU 복제 수(1개/2개)가 같은 donor 셀만 모은 `v_donor_gpu`도 같은 방식으로 학습한다. 대상 모델의 다른 셀은 donor 학습에 쓰지 않는다.

주요 `immediate_first_k` 시나리오는 버전의 **처음** `k ∈ {2, 3, 5, 10}`회에서 대상 셀과 donor 모델을 모두 측정한 뒤 미래를 예측한다. `cutoff_last_k` 견고성 검사는 prefix의 **마지막** `k`회에서 대상 셀을 측정하고 donor prior에는 prefix 전체 43/27회를 사용한다. 두 시나리오 모두 예측 시점 전의 donor 자료만 쓰고 대상 셀의 선택한 `k`회 외 다른 결과는 가린다. 대상 셀 선택 결과로 로그 성능 평균 `μ_k`와 불편 표본분산 `v_local`을 계산한다. 여섯 비교 방법은 다음과 같다.

| 방법 | 로그 성능의 미래 단일 실행 예측 방식 |
| --- | --- |
| donor-global | `v_donor` |
| donor-by-GPU-count | `v_donor_gpu` |
| target-local | `v_local` |
| fixed-shrink-global-5 | `(5 × v_donor + (k−1) × v_local) / (5 + k−1)` |
| fixed-shrink-GPU-5 | `(5 × v_donor_gpu + (k−1) × v_local) / (5 + k−1)` |
| target-only Student-t | 자유도 `k−1`, 위치 `μ_k`, 척도 `sqrt(v_local × (1 + 1/k))`; `k=2`는 Cauchy |

앞의 다섯 분산 방법은 `Normal(μ_k, v × (1 + 1/k))` 예측분포를 사용한다. Student-t는 소표본에서 꼬리가 두꺼운 기준선이다. `k=2`의 자유도 1은 Cauchy이며, `z=(y−μ_k)/s`와 `s=sqrt(v_local×(1+1/k))`일 때 `CRPS=(2s/π)×[z arctan(z)−0.5 log(1+z²)+log(2)]`를 사용한다. 이 식은 CDF 적분을 수치 계산해 대조했다. 모든 방법은 동일한 대상 `k`회 측정을 사용한다. `1 + 1/k`는 초기 평균 추정의 불확실성을 근사한다. 수치 계산에서만 로그 표준편차 하한 `0.001`을 적용한다. 수축식의 5는 미래 평가 결과로 조정하지 않는다. 위 분산 결합은 고정 휴리스틱이며 정확한 베이즈 사후분포라고 주장하지 않는다.

평가는 대상 모델별로 각 셀의 마지막 20회 평균 점수를 낸 뒤, 셀과 모델에 동일 가중치를 준다. 배치 p95 지연과 `examples_per_second / batch_size` 요청 처리량을 **별도로** 평가한다. 1차 점수는 연속순위확률점수(CRPS)이며, 평균 음의 로그우도(NLL), 90% 로그 예측구간 포함률, 평균 로그 구간폭도 보고한다. CRPS와 구간폭은 자연로그 단위다. 선택한 `k`회 측정의 GPU-wall 비용은 `replica_count × wall_seconds`의 합계이며, 시작·종료 시각 차이도 기록한다. NLL은 연속 밀도라 음수가 가능하다. 마지막 20회를 독립적인 20개 응용으로 세지 않는다. `immediate_first_k`를 우선 보고하고 `cutoff_last_k`는 시간 절단 견고성 검사로 구분한다.

## 누출 검사와 해석 제한

- 대상 모델의 마지막 20회 결과를 바꿔도 **예측 평균·분산·구간·비용은 같고 점수만 달라야 한다.**
- 대상 모델의 모든 결과를 바꿔도 donor prior는 같아야 한다. 같은 모델의 다른 셀도 donor가 될 수 없다.
- `v1` 결과를 바꿔도 `v2` 예측은 같아야 하며, 그 반대도 같다.
- 각 대상 셀의 선택한 `k`회와 donor 학습 자료는 평가 20회보다 먼저 끝나야 한다. 선택한 `k`회 외 다른 대상 셀 결과는 쓰지 않는다. `immediate_first_k`에서 donor prior는 같은 처음 `k`회만 학습한다.

**탐색 이력:** 이 규약을 작성하기 전에 같은 자료의 `k=5`, 5 pseudo-count 수축을 읽기 전용으로 시험했다. 초기 파일럿은 `run_id` 숫자 접미사를 시간순으로 잘못 정렬했고, 첫 `k`회 대상 측정에 더 늦은 donor prefix를 섞었으며, 수축에서 `k`를 표본분산의 가중치로 사용했다. 그 수치는 폐기했다. 별도 시간순 파일럿에서 GPU 수별 donor prior와 Student-t 비교 필요성도 확인했으며, `cutoff_last_k`에서 `v1` 지연 NLL은 전역 prior보다 수축이 소폭 나빠질 수 있음을 보았다. 이후 표본분산 자유도에 맞춰 `(k−1)` 가중치와 pooled donor 분산의 자유도 분모를 고정했다. 첫 전체 실행 뒤 독립 감사에서 `k=2` Cauchy 기준선의 CRPS가 유한함을 확인해 추가했다. **이 문서는 독립 검증의 사전등록이 아닌, 탐색 결과를 본 뒤 수정한 실행 규약이다.** 기존 SQLite에는 선택한 `k`회 외 대상 반복이 이미 있으므로 측정 비용은 실제 절약 기록이 아니라 **가린 결과를 이용한 반사실 비용 계산**이다. 원래 수집 SLO는 `v2` 24개 전체 CPU/GPU 조건에서 충족 여부가 한 번도 바뀌지 않는다. 이 자료로 재측정에 따른 실제 배포·Scale-out/in 성과를 주장하지 않는다.
