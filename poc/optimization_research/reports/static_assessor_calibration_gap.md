# 정적 8후보 평가기의 보정·선택적 보류: 신규 실험 가능성 점검

2026-09-28. **판정: 현재 자료로 새로운 보정법의 엄밀한 확인 실험은 NO-GO.** 선택 후보만 보정하는 별도 연구 가설은 정의할 수 있지만, 지금 남아 있는 분할은 이미 모델 선택 또는 정책 평가에 사용됐다. 기존 90개 시험 작업군에서 보정 없는 정책도 위반이 0건이라 위험 감소를 확인할 관측 사건이 없다. 아래 수치는 *새 방법을 학습하거나 채점하기 전*의 데이터·기존 산출물 점검이다.

## 현재 자료와 재사용 경계

| 구분 | 8후보 GPU 작업군 | 이번 판단에서의 역할 |
| --- | ---: | --- |
| 주 캠페인 전체 | 575개 × 8행, 9모델·한 호스트 | 배치 p95·샘플/초의 한 번씩 측정된 정적 후보 결과. GPU 2개는 같은 호스트의 복제본. |
| 원래 성능 모델 train/validation/test | 396 / 89 / 90개 | 저장 모델 (`../artifacts/performance_v1/performance_model.joblib`)은 원래 train 396개로 학습했고, ExtraTrees 종류는 validation 89개에서 골랐다. test 90개는 이미 성능 평가에 사용했다. |
| [기존 GPU 정책 평가](../scripts/evaluate_gpu_policy.py)의 train/calibration/validation/test | 297 / 99 / 89 / 90개 | 원래 train에서 모델별 11개씩 99개를 보정용으로 옮기고 **별도 모델을 재학습**했다. 그 99개는 저장 모델의 학습에 이미 포함된 작업군이다. |
| 별도 novel-matrix / space-filling 캠페인 | 전체 18 / 44개, 기존 정책의 지원 범위 안 10 / 33개 | 두 캠페인 모두 기존 정책에서 예측·성공을 채점했다. 신규 확인 시험으로 재사용할 수 없다. |

분할은 `workload_group` 단위여서 하나의 입력 조건에 속한 8후보가 함께 움직인다. 그러나 9모델·호스트 1개가 모든 주 분할에 공통이고, 사용자 SLO가 아니라 수집기가 생성한 목표다. [원래 학습 코드](../scripts/train_performance.py)의 모델 선택은 원래 train 396개를 사용했으므로 기존 정책의 99개 보정 작업군이 ExtraTrees 선택에 **간접적으로** 참여했다. [기존 평가 보고서](gpu_policy_research.md)도 이 때문에 엄밀한 유한표본 보장을 주장하지 않는다. 현재 [오프라인 평가기](../scripts/assess_gpu_shape.py)는 저장된 **396개 학습 모델**을 사용하고 예측을 명시적으로 `Uncalibrated`라고 표시한다. 기존 297개 학습 모델의 보정 상수 `q=0.7113706871`을 이 평가기에 붙이는 것은 다른 예측기의 잔차를 재사용하는 오류다.

기존 정책의 시험 90개 중 실측 가능 작업군은 55개였다. 보정 없는 점 예측은 **54개 선택·위반 0개**, 90% 그룹 동시 보정은 **37개 선택·위반 0개**였다. 54개 승인에서 0개 위반의 정확 95% 이항 구간 상한도 약 **6.60%**다. 보정의 위험 개선을 현재 시험 결과로 확인할 수 없고, 새 정책의 선택률 증가는 이미 공개된 시험에 대한 사후 최적화로 오해될 수 있다. 같은 모델·호스트의 별도 캠페인에서 보정 없는 정책도 지원되는 9개·24개를 선택해 모두 성공했다. 이를 독립 재현으로 세지 않는다.

후속 [저장 모델 자체의 사후 선택 감사](saved_gpu_shape_decision_audit_findings.md)는 위의 재학습한 정책 모델과 구분된다. 저장 모델도 원 목표에서 우연히 54개를 선택해 관측 위반이 0개였지만, 동일 실측에 요청/초 목표를 1.25배 적용하면 잘못 승인한 사례가 4개다. 이 민감도 질의는 독립 시험이나 새 보정 학습 자료가 아니다.

## 중복되지 않는 가설은 무엇인가

가설 후보는 **점 예측 정책이 먼저 고른 한 후보만 검증하고, 불확실하면 그 작업군 전체를 `ABSTAIN`하는 선택형 보정**이다. 후보를 고르는 함수는 SLO와 예측값만 사용한다. 보정 작업군에서는 그 *고정된 선택 후보*의 단측 로그 잔차 `max(log(실측 배치 p95/예측 p95), log(예측 요청/초/실측 요청/초))`만 모은다. 선택 후보가 없으면 보류한다. 신규 작업군에서는 선택 후보의 예측 SLO 여유가 사전 보정 분위수를 넘을 때만 그 **같은 후보**를 승인한다. 보정 후 다른 후보로 다시 선택하면 이 선택 후보 점수의 적용 대상이 바뀌므로 금지한다. 한 작업군에서 여러 생성 SLO를 평가할 때도 목표마다 작업군을 독립 사례로 세지 않는다.

이 가설은 [기존 8후보 최대 잔차 보정](gpu_policy_research.md)의 보호 대상을 ‘여덟 후보 전체’에서 ‘사전 선택한 한 후보’로 좁혀 불필요한 보류를 줄이려는 것이다. 따라서 기존 `adaptive_group_90`의 나무 분산 정규화, [cold-start 선택 보류](cold_start_selective_safety_findings.md)의 새 모델 donor 학습, [K8 비대칭 여유](asymmetric_margin_findings.md)의 8회 현행 모델 프로브와도 입력·보정 단위가 다르다. 선택 후보가 모델별로 다른데 같은 99개 작업군을 섞으면 가능한 주장은 **동일한 작업군 생성 분포에서의 주변(marginal) 선택 후보 경계**뿐이다. 승인된 작업만의 위반율 ≤10%, 모델별 90% 보장, 새로운 모델·VM에 대한 보장은 따라오지 않는다. 모델 전체를 독립 보정 단위로 보면 donor 8개에서 90% split-conformal 순위는 `ceil(9×0.9)=9`인데 점수가 8개뿐이어서 유한 문턱이 나오지 않는다.

## 새 점수 계산 전 게이트

새 방법을 비교하려면 다음을 **시험 라벨 채점 전에** 충족하고 프로토콜·모델/자료 SHA를 고정해야 한다.

1. 고정된 모델이 실제로 학습하지 않은 보정 작업군과, 방법 선택·탐색·보고에 사용하지 않은 확인 작업군을 확보한다. 같은 `workload_group`의 8후보는 분할하지 않는다. 추론 입력에 목표 결과·사후 계측을 넣지 않는다. 현재 저장 모델에는 원래 train의 99개를 보정용으로 쓸 수 없고, validation은 ExtraTrees 종류 선택에, test와 별도 캠페인은 기존 평가에 이미 사용됐다. **현재 상태에서 실패.**
2. 각 작업군에 GPU 1/2 × CPU affinity 2/4/8/16의 여덟 실측 후보, 유효한 배치 p95·샘플/초·batch 크기·목표값·호스트/모델 식별자를 요구한다. 처리량은 샘플/초를 batch 크기로 나눠 요청/초로 맞춘다. 기존 주 캠페인의 575개 그룹은 이 정적 형식 검사를 통과하지만, 한 번 실행된 벤치마크이므로 반복 실행 안정성은 확인하지 못한다.
3. 명목 90% 그룹 보정이라면 선택 후보 잔차가 정의된 독립 보정 작업군을 최소 9개 확보한다. 다만 9개는 **유한 분위수의 산술적 최소**일 뿐 충분한 정확도를 뜻하지 않는다. 새 모델 전이를 주장한다면 보정·시험의 독립 단위를 모델로 올리고 별도 신규 모델을 확보해야 한다. 현재 9개 기존 모델의 leave-one-model-out에는 바깥 모델당 donor 8개뿐이라 90% 모델 단위 문턱은 무한대다. **신규 모델 일반화 게이트 실패.**
4. 목표가 운영 요구사항·스케일 판단이라면 실제 사용자 SLO, 시간순 행동·전환 결과, 다른 VM/호스트 결과가 있어야 한다. 현재 값은 생성된 배치 벤치마크 목표이며 정적 측정만 있으므로 **운영 효과 게이트 실패**다. 새 자료에서도 점 정책에 위반이 전혀 관측되지 않으면 ‘위험 감소’가 아니라 선택률·보류 비용만 기술한다.

## 결론과 재개 조건

**현 평가기에 보정 상수를 추가하거나 새 정책의 안전성 개선을 발표하지 않는다.** 위 선택 후보 보정법 자체는 구현 가능한 탐색 가설이지만, 현재의 99/89/90 분할로 다시 시험하면 확인성이 없다. 데이터가 추가되면 학습기 선택과 보정 자료를 완전히 분리하고, 새 캠페인의 아직 열지 않은 작업군에서 ‘성공 승인·잘못 승인·실측 가능 보류·GPU/CPU 초과’를 기존 점 정책 및 8후보 그룹 보정과 짝지어 비교한다. 가능하면 사용자 지연·요청 처리량 SLO와 호스트별 반복 측정을 함께 수집한다. 그때도 보정법의 보장 범위는 검증된 표본 단위·분포와 동일한 정적 후보 판단으로 제한한다.

근거 파일: 측정 스냅샷 (`../data/audit_v1/measurements.parquet`) SHA-256 `b7bba7963e8a309b6a8502a1d98eefb150476b1381ec016beeb68cbf63fae906`, 원래 분할 (`../artifacts/performance_v1/split_manifest.csv`), [GPU 정책 지표](../artifacts/gpu_policy_v1/metrics.json). 수치는 현재 동결 스냅샷의 `eligible & campaign=khu-hf-local-exhaustive & device=cuda` 필터, 원래 `assign_splits(seed=42)`, 기존 `fit_calibration_split(seed=42)`에서 재집계했다. 새 방법의 점수·선택값은 계산하지 않았다.
