# GenTD26 요청 실패 상태 위험: 검증 결과

2026-09-28. **사전 탐색 검증 게이트는 통과했지만 후보를 판단기에 채택하지 않는다.** 요청 시점의 모델·작업 종류·프롬프트 및 생성 설정으로 학습한 로지스틱 모델의 날짜 동일 가중 Brier는 검증에서 고른 **사전 정의 모델×작업종류 빈도 기준선**보다 **15.75% 낮았다**. 그러나 검증 실패 92건 중 **54건이 학습에서 전량 실패한 세 모델 ID**에 속했다. 이를 제외한 사후 민감도에서는 후보가 고정 기준선보다 나빴고, 사후 추가한 더 단순한 모델별 빈도 기준선의 Brier도 후보보다 낮았다. 따라서 현재 확인된 범위는 기록된 `FAILED` 상태의 후향적 탐색이다.

## 점수 전에 고정한 비교

[검증 전 규약](gentd26_request_failure_protocol.md)과 [평가 코드](../scripts/evaluate_gentd26_request_failure.py)는 원본·규약·코드·합성 테스트의 SHA-256을 먼저 고정했다. 원본 요청 CSV SHA-256은 `263fb88f1095f62d360cf89ded8cfc24fa2c5d111c1b16e7aaa9ccbfc4b37d78`이다. 규약·코드·테스트 SHA-256은 각각 `d449343c4ef45190dd5b86cd3e5644e6193176180a21dfe2480a4107964ed729`, `b3edcc0ea9e4552196fa2271897fbd34e9aff1ca8ae454224924a2b52cfd55ab`, `885a8fe47483eb5addc2435a6d4df166bfe1230efc1347f103710733680d8d6f`이다. 실제 [freeze manifest](../artifacts/gentd26_request_failure_v1/freeze_manifest.json)의 SHA-256은 `0ed06c00ed938acaa126076b555960d31a2abee3011042bfc43cc35665d0acd7`이다. 저장된 [검증 지표](../artifacts/gentd26_request_failure_v1/selection/selection_metrics.json)·행별 검증 예측 (`../artifacts/gentd26_request_failure_v1/selection/validation_predictions.csv`)·학습 모델 (`../artifacts/gentd26_request_failure_v1/selection/model.joblib`)의 SHA-256은 각각 `f4a999bfc25734d4ba05d01edde92596c04a343f03214b9c5e248d07addb19ef`, `ea8d53f99b64c745bb02f2d68e28011adbb9585e5fd3cd177290c207efe06ecb`, `36d1cdc178666a5e463fbc7252c1fd0c890bd9e76c8682a49affd9e5d8163034`다.

학습은 2024-11-29 이전의 확정 상태 요청 **13,208건·실패 231건**, 검증은 11-29~12-03의 **7,263건·실패 92건**이다. 학습·검증 기간의 `PENDING` 21건을 제외했고 `PROCESSING`은 0건이었다. 검증 실패는 4일·`groupId` 37개에서 나왔으며, 가장 많은 한 그룹이 10/92건이다. 모델 입력은 요청 제출 시점의 모델 ID, 작업 종류, 프롬프트 길이, 이미지·추론 단계·LoRA 수다. `groupId`, 최종 상태, 기록된 실행시간은 입력에서 제외했다. 학습기 설정은 고정했으며, `global`·`type`·`model`·`model_type` 네 학습 기간 빈도 기준선 중 검증 날짜 동일 가중 Brier가 가장 낮은 **`model_type`**을 비교 대상으로 골랐다.

## 저장된 검증 점수

| 같은 7,263건의 지표 | 선택 기준선 `model_type` | 로지스틱 후보 |
| --- | ---: | ---: |
| 날짜 동일 가중 Brier ↓ | 0.006053 | **0.005100** |
| 요청 동일 가중 Brier ↓ | 0.008039 | **0.006355** |
| `groupId` 동일 가중 Brier ↓ | 0.003802 | **0.003201** |
| log loss ↓ | 0.041499 | **0.036369** |

관측 실패율은 **92/7,263 = 1.267%**다. 후보의 평균 예측값은 이를 약 0.50%p 웃돈다. 날짜별 Brier는 아래와 같다. 후보가 이긴 날은 **3/5일**이며 11월 29·30일에는 악화했다. 특히 11월 30일에는 실패가 0건이어서 그날의 AP는 정의하지 않았다.

| 검증 날짜 | 요청 / 실패 | 기준선 Brier | 후보 Brier |
| --- | ---: | ---: | ---: |
| 11-29 | 791 / 2 | **0.000727** | 0.001263 |
| 11-30 | 267 / 0 | **0.000240** | 0.000552 |
| 12-01 | 1,349 / 20 | 0.012627 | **0.012295** |
| 12-02 | 2,132 / 27 | 0.007947 | **0.004398** |
| 12-03 | 2,724 / 43 | 0.008726 | **0.006994** |

점수 전에 정한 네 채택 조건은 모두 참이었다: 날짜 동일 가중 Brier 상대 개선 **15.75% ≥5%**, 날짜 승리 **3/5**, 전체 AP 비악화, 학습에서 본 모델의 요청 Brier **0.007672→0.006004** 비악화. 학습에서 보지 못한 모델의 검증 요청은 **31건·실패 3건**뿐이다. 이 판정은 **검증에서 기준선을 골라 같은 검증에서 후보를 비교한 탐색 통과**다. 아래 사후 민감도를 이 사전 판정으로 소급 반영하지 않는다.

점수 전에 명시한 `groupId` 층별 사후 민감도는 중요한 예외를 보여 준다. `groupId`는 모델 입력이 아니고 운영상 의미·시간에 따른 안정성이 확인되지 않았다.

| 검증 `groupId` 층 | 요청 / 실패 / 그룹 | 기준선 Brier | 후보 Brier | 기준선 AP → 후보 AP |
| --- | ---: | ---: | ---: | ---: |
| 학습에서 본 그룹 | 1,798 / 22 / 146 | **0.013273** | 0.013625 | 0.060043 → 0.063663 |
| 새 그룹 | 5,465 / 70 / 1,173 | 0.006316 | **0.003964** | 0.787765 → 0.792378 |

따라서 전체 검증 개선을 기존 그룹의 안정적 위험 개선으로 해석하지 않는다. 새 그룹층의 수치도 그룹 ID의 의미가 알려지지 않았고 같은 서비스·기간의 모델 구성이 겹치므로 독립 그룹 일반화의 근거가 아니다.

## 사후 반증: 모델 ID 집중도와 더 단순한 빈도 기준선

별도 읽기 전용 [감사 코드](../scripts/audit_gentd26_request_failure_selection.py)는 원본의 학습·검증 상태만 읽고 저장된 검증 예측을 `source_row`로 일대일 결합했다. 원본·freeze manifest·규약·동결 평가 코드·합성 테스트·검증 지표·행별 예측·모델 파일의 SHA-256을 확인한 다음 다섯 방법의 저장 점수를 다시 계산해 일치시켰다. [사후 감사 JSON](../artifacts/gentd26_request_failure_v1/posthoc_selection_audit.json)에 입력 경로·해시와 아래 수치를 기록했다. 감사 코드 SHA-256은 `9f8566c67ac5f6bca05f1a7f13ed2952229ffee00a436f14cc4705bb81aaefa8`이고 JSON SHA-256은 `3ee60ebb3c731d251dfa3719af9ad3283b2284e7eefebe6c56a985bdc24cd5c5`다. 이 감사는 **검증 결과를 본 뒤 설계**했으며 사전 비교나 독립 시험이 아니다.

학습에서 요청이 10건 이상이고 그 요청이 **모두 `FAILED`**인 모델 ID는 다음 셋이었다. 이 기준을 사후 적용하면 세 모델의 검증 **54건 모두 실패**였고 전체 검증 실패 92건의 **58.7%**를 차지했다.

| 모델 ID | 학습 실패 / 요청 | 검증 실패 / 요청 |
| --- | ---: | ---: |
| `M0013` | 69 / 69 | 32 / 32 |
| `M0055` | 19 / 19 | 9 / 9 |
| `M0061` | 21 / 21 | 13 / 13 |

세 모델을 제외한 **7,209건·실패 38건**에서 고정 `model_type` 기준선의 요청 Brier는 **0.005678**, 후보는 **0.005872**였다. 날짜 동일 가중 Brier도 **0.004460→0.004779**로 후보가 나빴고 후보의 날짜 승리는 **1/5일**이었다. 즉 전체 검증의 후보 우위는 이 세 모델의 라벨 집중에 크게 의존했다.

같은 감사에서 사후에 추가한 **전역률로 1 pseudo-count 수축한 모델별 빈도**는 `g=(학습 실패+1)/(학습 요청+2)`, `p_m=(모델 학습 실패+g)/(모델 학습 요청+1)`로 계산했다. 학습에 없는 모델은 `g`를 쓴다. 이는 사전 네 기준선이나 후보 선택에 들어가지 않았다. 이 단순 방법의 전체 검증 날짜 동일 가중 Brier는 **0.004466**, 요청 Brier는 **0.005684**로 후보의 **0.005100/0.006355**보다 낮았고 5일 모두 Brier가 낮았다. AP는 단순 방법 **0.604750**, 후보 **0.620191**이므로 순위 지표에서는 후보가 높았다. `groupId`를 학습에서 본 층의 Brier도 단순 방법 **0.013098 < 후보 0.013625**, 새 층은 **0.003245 < 0.003964**였다. 사후 추가 비교는 원래 탐색 게이트를 다시 정의하지 않지만, **학습기의 실용적·고유한 우위를 주장할 근거가 부족함**을 보여 준다.

## 사용 범위와 다음 검증

원본에는 최종 상태가 **언제 확정되고 전달됐는지** 없다. 학습 기간의 `FAILED`가 실제 검증 시작 전에 가용했는지 증명할 수 없으므로 이 모델은 온라인 판단기로 검증되지 않았다. 실패 원인도 없다. 이 원본의 기존 실행시간 실험에서 같은 시기 데이터를 이미 사용했고, 이번 과제 설계 전에 후행 시험의 실패 **빈도·날짜·모델·그룹 분포**를 감사했다. 원래 검증 평가 코드에는 시험 채점 단계가 없고 그 [선택 지표 파일](../artifacts/gentd26_request_failure_v1/selection/selection_metrics.json)의 `test_score_opened`는 그대로 `false`다. 별도로 동결한 [후행 기간 민감도 평가](gentd26_request_failure_temporal_findings.md)에서 한 번 점수를 계산했으며, 사전 검증 게이트와 구분한다. 후행 평가는 완전한 블라인드 시험이 아니다.

다음에는 다른 날짜 또는 독립 AI 서비스에서 요청 생성·상태 확정·기록 전달 시각과 실패 사유를 연결해야 한다. 모델 ID와 `groupId`를 겹치지 않게 나눈 평가, 실패가 충분한 여러 날짜의 보정·Brier·AP, 단순 모델별 빈도 기준선, 이미 본 그룹과 새 그룹의 별도 결과가 필요하다. 실제 경희대 `DEPLOY/UPDATE/SCALE_OUT/SCALE_IN` 판단 효과에는 이와 별도로 당시 VM/GPU 형상, 명령·완료 시각, 사용자 SLO와 조치 전후 결과가 있어야 한다. 현재 실패 확률로 VM 수량이나 조치 효과를 추정하지 않는다.
