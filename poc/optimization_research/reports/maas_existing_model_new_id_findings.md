# 저장된 MaaS GPU 위험 모델의 새 인스턴스 ID 시험

2026-09-29. **판정: `NEW_ID_SIGNAL_NO_GO`.** 기존 [MaaS 상태·결측 인식 연구](maas_state_followup_findings.md)의 저장 단일 로지스틱을 **새 인스턴스 ID 787개·55,436개 현재 정상 판단**에 고정 적용했다. Brier는 기존 확률표 `0.023850→0.022807`로 **4.38%**, 더 강한 학습 전용 정상 상태별 Beta 표 `0.023543→0.022807`로 **3.13%** 낮아졌다. 하지만 [새 ID 원본 접근 전 고정한 규약](maas_existing_model_new_id_protocol.md)의 **두 비교기 각각 대비 5% 감소** 조건에 못 미쳐 위험 입력으로 채택하지 않는다.

## 원본·재현 경계

[Alibaba 공식 주간 5분 추적](https://github.com/alibaba/clusterdata/blob/8a6295f9779ddc019add669eeca49c5f9f77b3a7/cluster-trace-v2026-maas/README.md)의 21개 원본 조각을 이전 [전량 감사](../data/external/alibaba_maas_2026/SOURCE.md)의 멤버별 해시·CRC32·스키마와 다시 비교했다. 원본 140,906,827행에서 SHA-256 ID bucket 1을 [별도 추출](../data/external/alibaba_maas_2026_bucket1/SOURCE.md)해 **46,938개 ID·1,431,995행**을 확보했다. 기존 bucket 0의 1,462,865행도 다시 집계했고, 평가 로더에서 양쪽 원시 ID 해시의 교집합이 없음을 확인했다. 추출 감사 (`../data/external/alibaba_maas_2026_bucket1/instance_week_5min_bucket1_audit.json`)와 [접근 전 release manifest](../artifacts/maas_existing_model_new_id_v1/release_manifest.json)에 출처·규약·코드·모델 해시를 보존했다.

새 ID 추출 전에 저장 모델과 학습 중앙값으로 기존 53,513개 완전·현재 정상 시험 예측을 다시 계산했다. `p₀`, 단일 모델, 상태별 모델의 최대 절대 확률 차는 모두 `1e-12` 미만이었다. 학습 기간 `complete/current_normal`의 `any_recent_high`별 Beta(1,1)률 **0.033061/0.721537**도 다시 산출해 강한 단순 비교기로 고정했다. [bucket 0 예측 재현](../artifacts/maas_existing_model_new_id_v1/bucket0_selfcheck.json).

## 확률 점수 전 지원량

추출 완료 뒤에만 [지원량 감사](../artifacts/maas_existing_model_new_id_v1/support_audit.json)를 실행했다. 현재 정상 입력 후보는 66,636개이고 미래 여섯 창의 정답이 모두 유효한 것은 **55,436개(83.19%)**다. 신규 초과는 **2,287건·230개 ID**, 적격 ID는 **787개**였다. 145일은 26,449판단·1,221사건, 146일은 28,987판단·1,066사건이었다. 양성 사건에 기여한 최대 단일 ID 비중은 3.54%였다. 사전 행·사건·ID·양일·정답 관측률 지원량 기준은 전부 통과했다. 이 단계에는 모델 확률을 계산하지 않았다.

## 단회 새 ID 평가

정답은 판단 이후 30분의 여섯 5분 창 중 SM 사용률≥80% 또는 GPU 메모리 사용률≥90%가 한 번이라도 관측되는 사건이다. 모든 방법에 같은 현재 정상·과거/미래 완전 행을 사용했다. 저장된 단일 로지스틱은 새 ID로 재학습·보정하지 않았다.

| 방법 | 전체 행 Brier ↓ | ID 동일가중 Brier ↓ | AP ↑ | 145일 Brier ↓ | 146일 Brier ↓ |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기존 `p₀` | 0.023850 | 0.113884 | 0.451153 | 0.027109 | 0.020877 |
| 학습 전용 정상 상태별 Beta | 0.023543 | 0.120867 | 0.451153 | 0.026601 | 0.020753 |
| **저장 단일 로지스틱, 주 후보** | **0.022807** | **0.098390** | 0.545267 | **0.025668** | **0.020196** |
| 저장 상태별 로지스틱, 보조 | 0.023182 | 0.099283 | **0.546341** | 0.025996 | 0.020615 |

동점을 무작위로 해결하는 **날짜별 상위 5% 판단 경보**에서 주 후보의 기대 신규 초과 포착은 145일 **711.00건**, 146일 **641.00건**이었다. 두 단순 비교기는 각각 **636.22·571.25건**이었다. ID 단위 짝지은 2,000회 재표집(seed 43)의 `주 후보−정상 Beta` 행 Brier 차는 **−0.000736**, 95% 백분위 구간 **[−0.001119, −0.000377]**이다. 두 날짜·ID 동일가중·AP·경보·재표집의 사전 보조 조건은 통과했지만, **전체 5% 개선 조건 하나가 실패**했다. 위 숫자를 기존 bucket 0의 결과에 합쳐 같은 시험으로 취급하지 않는다.

## 판정과 한계

이번 평가가 보여 주는 것은 같은 MaaS 주간의 **처음 보는 ID에서 저장 모델이 두 단순 표보다 평균 확률 오차와 경보 순위가 일부 개선됐지만, 사전 채택 폭에는 못 미쳤다**는 사실이다. 모델은 bucket 0의 시험 점수를 본 뒤 주 후보로 정했다. 따라서 이번 결과는 새 ID에 대한 확인이지만 새 시기·서비스·GPU 세대 일반화가 아니다. 미래 창이 모두 관측된 부분집합만 점수화했고, 5분 정답 전달 시각도 실제 로그가 아닌 가정이다. 주간 원본에는 온라인/오프라인 앱 종류, VM 증감 발행·Ready, 요청별 지연·사용자 SLO, 대체 조치 결과가 연결되지 않는다. 관측 GPU 초과 위험이 낮아졌다는 점수를 `SCALE_OUT/IN`의 효과나 승인 정답으로 바꾸지 않는다.
