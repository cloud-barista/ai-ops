# BurstGPT 관측 가능 완료시간 부분집합 탐색

2026-09-28. [사전 평가 규약](burstgpt_external_validation_protocol.md)을 작성하고 [원본 품질을 감사](burstgpt_data_audit.md)한 뒤 결과를 계산했다. 실행 코드는 [`evaluate_burstgpt_observed_duration.py`](../scripts/evaluate_burstgpt_observed_duration.py), 수치·데이터/코드 해시는 [`metrics.json`](../artifacts/burstgpt_observed_duration_v1/metrics.json)에 있다. 원본은 [공식 BurstGPT v2.0](https://github.com/HPMLL/BurstGPT/releases/tag/v2.0)의 `BurstGPT_3.csv`다.

## 먼저 결정할 수 있는 결론

**전체 요청에 대한 독립 재현 검증은 불가능하다.** 5,344,021건 중 3,175,935건(59.4%)의 완료 경과시간이 정확히 0초이며, 응답 토큰이 양수인데도 0초인 요청이 2,794,838건이다. 0초 비율은 시기·모델·호출 유형에 따라 크게 달라진다. 0초를 정확한 응답시간이나 무작위 결측으로 간주할 근거가 없다. 아래 수치는 양수 완료시간이 기록된 요청만의 **탐색적 결과**다. 이 결과로 전체 요청의 p90 보장, AI 응용의 VM 형상, 스케일 행동을 승인하지 않는다.

## 방법

입력은 요청 시점에 알 수 있는 `Model`, `Log Type`, `Request tokens`만 사용했다. 결과 토큰 수와 전체 토큰 수는 제외했다. 첫 30일 중 요청 제출·완료·추가 1시간이 모두 경계 전에 있는 1,060,918건으로 히스토그램 그래디언트 부스팅 p90을 학습했다. 30–40일은 보정 초기화 기간으로 두고, 40–110일을 겹치지 않는 10일 시험 블록 7개로 나눴다. 시험 중 새 요청을 예측하기 전에는 **그 시각까지 결과가 도착한 과거 요청**만 전역 최근 2,000건과 모델별 최근 500건의 잔차 버퍼에 반영했다. 각 블록의 추가 여유값은 블록 시작 전 최근 10일의 가용 라벨에서만 고정했다. 전체·호출 유형·모델 순으로 경험적 92% 커버리지를 목표로 비음수 여유값을 더했다.

## 양수 라벨 부분집합의 시험 점수

시험 1,035,150건의 p90 pinball 손실/포괄률은 다음과 같다. 시간 단위는 초이며 표본은 **전체 요청이 아니라 관측 가능한 부분집합**이다.

| 방법 | pinball 손실 | 포괄률 |
| --- | ---: | ---: |
| 고정 기본 모델 | 3.062 | 93.5% |
| 전역 최근 잔차 | 2.353 | 89.7% |
| 모델별 최근 잔차 | 2.153 | 89.0% |
| 모델별 잔차 + 검증 여유값 | 2.179 | 94.1% |

모델별 잔차는 전역보다 7개 시험 블록 모두에서 pinball 손실이 낮았다. 검증 여유값을 더한 정책은 7개 블록 모두 양수 라벨 부분집합에서 90%를 넘었고, `ChatGPT` 94.7%, `GPT-4` 93.0%, `API log` 94.4%, `Conversation log` 92.3%였다. **이 통과 모양은 원본의 선택 편향 때문에 사전 규약의 독립 재현성 통과로 해석하지 않는다.**

| 시험 시작 상대일 | 양수 라벨 / 전체 | 전역 손실 | 모델별 손실 | 여유값 포괄률 |
| ---: | ---: | ---: | ---: | ---: |
| 40 | 183,548 / 899,879 (20.4%) | 2.495 | 2.268 | 95.8% |
| 50 | 134,987 / 352,759 (38.3%) | 2.280 | 2.074 | 93.8% |
| 60 | 48,287 / 174,598 (27.7%) | 2.877 | 1.943 | 96.0% |
| 70 | 46,504 / 247,509 (18.8%) | 2.998 | 2.969 | 92.4% |
| 80 | 255,640 / 611,215 (41.8%) | 1.661 | 1.521 | 93.1% |
| 90 | 178,205 / 631,436 (28.2%) | 2.776 | 2.588 | 94.3% |
| 100 | 187,979 / 226,739 (82.9%) | 2.512 | 2.395 | 93.8% |

이처럼 같은 10일 블록에서도 이용 가능한 라벨 비율이 18.8–82.9%로 달라진다. 유효 라벨만의 높은 포괄률을 전체 서비스 요청에 외삽하기 어렵다. 다른 모델이나 서비스로 학습한 가중치를 옮긴 결과가 아니라, 같은 보정 절차를 독립 로그에서 다시 학습한 결과다.

## 일별 비교와 피드백 지연 가정

70개 상대일 각각에서 같은 요청의 손실을 짝지어 비교하면 모델별 잔차의 전역 대비 평균 일별 손실 차이는 `-0.243초`, 모델별이 더 낮은 날은 `60/70일`이었다. 여유값까지 더하면 전역 대비 `-0.208초`, `54/70일`이었다. 이는 양수 라벨 부분집합 안의 변화이며 날짜별 라벨 선택 차이를 제거하지 못한다.

기본 학습 모델은 **1시간 지연 가정으로 고정**하고, 온라인 잔차 공개 시점과 각 블록 여유값 선정을 0·1·6시간으로 바꾼 부수 분석은 다음과 같다. 모든 행은 양수 라벨 부분집합이다.

| 추가 피드백 지연 | 전역 손실 / 포괄률 | 모델별 손실 / 포괄률 | 여유값 손실 / 포괄률 | 여유값의 최저 10일 블록 포괄률 |
| ---: | ---: | ---: | ---: | ---: |
| 0시간 | 2.195 / 90.9% | 1.998 / 90.9% | 2.019 / 93.2% | 92.1% |
| 1시간 | 2.353 / 89.7% | 2.153 / 89.0% | 2.179 / 94.1% | 92.4% |
| 6시간 | 2.570 / 87.5% | 2.410 / 86.9% | 2.500 / 95.2% | 90.1% |

실제 로그 전달 지연은 공개되지 않았다. 6시간일수록 최근 결과를 덜 볼 수 있어 보정 손실이 높아졌고, 과거 보정 구간에서 고른 여유값이 커져 관측 부분집합 포괄률도 높아졌다. 이 분석은 지연별 모델 재학습까지 포함하지 않는다.
30일 경계까지 학습 가능한 양수 라벨은 0시간 1,062,660건, 1시간 1,060,918건, 6시간 1,048,612건이다. 위 비교는 이 차이로 기본 모델을 다시 맞춘 완전한 절차 비교가 아니다.

## 남은 검증

완료 시각이 일관되게 기록된 별도 공식 로그를 확보해 원본을 감사하고, 새 시험 분할·성공 기준을 **성능 점수 확인 전에** 확정해야 한다. 전후 인프라 형상과 배포·스케일 사건이 없는 자료는 여전히 `DEPLOY/UPDATE/SCALE_OUT/SCALE_IN` 행동 결과를 검증하지 못한다.
