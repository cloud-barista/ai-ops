# GenTD26 요청 실패 상태 위험: 검증 전 탐색 규약

2026-09-28. 경희대의 응용 요구 분석과 운영 판단에 제공할 수 있는 **요청 실패 상태의 관측 위험 신호**를 평가한다. 정답은 Alibaba GenTD26 `lora_request_trace.csv`의 `predict_status == FAILED`이며 `SUCCEED`와만 비교한다. `PENDING`·`PROCESSING`은 아직 결과가 확정되지 않은 상태로 보고 제외한다. 실패 원인, 사용자 SLO 위반, VM 부족, 배포·업데이트·스케일 조치의 효과는 이 라벨에서 알 수 없다. 연구 신호가 좋아도 실제 조치를 자동 승인하지 않는다.

## 원본과 이미 알려진 정보

- [공식 데이터 설명](https://github.com/alibaba/clusterdata/blob/8c132fb7717fbd44cf434cf81f2cd865a80072d5/cluster-trace-v2026-GenAI/README.md)과 [출처 기록](../data/external/gentd26/SOURCE.md)의 요청 CSV를 사용한다. 원본 SHA-256은 `263fb88f1095f62d360cf89ded8cfc24fa2c5d111c1b16e7aaa9ccbfc4b37d78`이다.
- 이전 [실행시간 연구](gentd26_request_latency_findings.md)는 성공한 26,392건의 `exec_time_seconds`만 학습했고 실패 상태는 학습 목표가 아니었다. 다만 이 원본과 아래 기간은 이미 여러 실험에 쓰였다. 이번 감사에서 `FAILED`의 시험 기간 **빈도와 날짜·모델·groupId 집중도도 열람**했다. 따라서 시험 예측 점수를 나중에 계산하더라도 완전히 미개봉인 독립 시험이라고 부르지 않는다. 이번 스크립트에는 시험 채점 명령을 만들지 않는다.
- 현재 원본에서 상태는 `SUCCEED` 26,392건, `FAILED` 398건, `PENDING` 30건, `PROCESSING` 3건이다. 아래 분할의 확정 상태 수는 학습 13,208건/실패 231건, 검증 7,263/92, 시험 6,319/75다. 시험의 실패는 5일 중 4일·모델 12종·groupId 24개에서 나왔고 최대 한 groupId가 21/75건을 차지한다. 이는 점수 전 지원량 진단이지 독립 검증 결과가 아니다.

## 고정 분할과 정보 경계

- 요청 생성시각 `gmt_create` 순으로 학습은 2024-11-29 00:00 **미만**, 검증은 11-29 00:00 이상 12-04 00:00 미만, 잠금 시험은 12-04 00:00 이상으로 고정한다. 파일의 생성시각은 단조 증가한다. `select`는 시험의 첫 시각을 만나면 읽기를 중단하고 시험 상태·실행시간을 분석하지 않는다. 원본 전체 바이트는 SHA-256 무결성 검사에만 사용한다.
- 특징은 제출 시점에 주어진 `predict_type`, `checkpoint_model_version_id`, `prompt_length`, `negative_prompt_length`, `num_images_per_prompt`, `num_inference_steps`, `num_lora`뿐이다. 부정 프롬프트 길이 결측은 0과 결측 표시로 표현한다. 모델 ID는 익명 범주이고 미지 모델은 one-hot 0으로 돌아간다. `groupId`는 사전 가용성·운영 의미가 불명확하므로 **모델 입력에서 제외**하고 군집 진단에만 쓴다. `gmt_create`는 분할에만 쓰고, `predict_status`, `exec_time_seconds`, 이후 로그 및 다른 시각의 모니터링 값은 특징으로 쓰지 않는다.
- 원본에는 실패·성공 상태의 **확정 시각이나 기록 전달 시각이 없다**. 따라서 학습 기간 상태가 검증 시작 전에 실제로 가용했는지를 증명할 수 없다. 이 실험은 최종 상태를 사후 확보한 **정적 후향 평가**다. 검증 기간의 상태를 온라인 이력으로 되먹임하지 않는다.

## 고정 비교

학습 행만으로 다음 네 기준선을 만든다. 전체 실패율은 Beta(1,1)으로 평활하고, 모델별·작업종류별률은 각각 전체률의 100 pseudo-count로 수축한다. 모델×작업종류률은 해당 두 부모율의 산술평균을 50 pseudo-count로 사용한다. 학습에 없는 모델·조합은 부모 수축값으로 돌아간다. 네 기준선은 `global`, `type`, `model`, `model_type`이다.

후보 학습기는 하나의 `LogisticRegression(C=1, max_iter=2000, solver=lbfgs, class_weight=None, random_state=42)`다. 모델 ID·작업종류를 학습 집합으로만 적합한 one-hot으로 만들고, 숫자 특징은 음수가 아님을 확인한 뒤 `log1p` 및 학습 집합의 평균·표준편차로 표준화한다. 숫자 특징은 프롬프트 길이 둘, 부정 프롬프트 결측 표시, 이미지 수, 추론 단계 수, LoRA 수, 이미지 수×단계 수다. 확률은 계산 안정성을 위해 `[1e-6, 1-1e-6]`으로 제한한다. 재표집, class weight, 검증 기반 초모수 검색, 시험 기반 재학습은 하지 않는다.

네 기준선 중 **검증 날짜별 Brier를 먼저 구한 뒤 다섯 날짜를 동일 가중 평균**한 값이 가장 낮은 것을 주 기준으로 선택한다. 동률 `1e-12` 이내에는 위 순서를 쓴다. 후보 학습기는 고정 설정 그대로 그 기준선과 같은 검증 행에서 비교한다.

## 점수 전 지원·채택 기준

학습에는 확정 상태 10,000건 이상, 실패 200건 이상, 실패 groupId 30개 이상이 있어야 한다. 검증에는 확정 상태 5,000건 이상, 실패 75건 이상, 실패 groupId 20개 이상, 실패가 있는 날짜 3일 이상이 필요하다. **고정한 검증 날짜 11월 29일~12월 3일의 5일 각각에 요청이 있어야 한다.** 검증 실패의 최대 한 groupId 비중이 30%를 넘으면 중단한다. 결측 또는 유한하지 않은 필수 입력이 확정 상태 행에 있으면 조용히 대체하지 않고 중단한다. 미확정 상태 수와 날짜별·groupId별 실패 집중도는 별도 보고한다.

주 손실은 날짜 동일 가중 Brier다. 전체 요청 가중 Brier, log loss, average precision(AP), 관측 실패율, 평균 예측 확률, 날짜별 Brier·AP, `groupId` 동일 가중 Brier, 학습에서 본/처음 본 모델별 진단도 기록한다. **사후 민감도**로 검증 요청을 학습에 이미 나온 `groupId`와 새 `groupId`로 나누고 각 층의 요청·실패·고유 그룹 수, 후보와 선택 기준선의 요청 가중 Brier·AP를 따로 보고한다. `groupId`의 운영 의미와 식별자 안정성이 불명확하고 학습 특징에도 쓰지 않으므로 이 층별 숫자를 독립 그룹 일반화의 근거로 삼지 않는다. AP는 실패가 없는 날짜나 층에서 정의하지 않고 전체 검증에서는 계산한다. 기준선 선택과 후보 비교는 **검증 데이터에 맞춘 탐색**이다.

후속 별도 시험 규약을 설계할 가치는 아래 항목을 모두 만족할 때만 있다고 본다: (1) 후보의 날짜 동일 가중 Brier가 검증 선택 기준선보다 상대 **5% 이상 낮다**; (2) **정확히 다섯** 검증 날짜 중 **최소 3일**에서 Brier가 엄격히 낮다; (3) 전체 AP가 선택 기준선보다 낮지 않다; (4) 학습에서 이미 보인 모델의 검증 행에서 요청 가중 Brier가 기준선보다 높지 않다. 하나라도 실패하면 이 후보를 경희대 판단기에 채택하지 않고 원인을 보고한다. 통과해도 검증에서 기준선을 고른 선택 편향, 작은 실패 수, 독립 서비스 부재를 고려해 **탐색 통과**로만 기록한다. 시험 라벨 분포가 이미 알려졌으므로 별도 잠금 시험을 수행해도 완전한 블라인드 재현은 아니다.

`freeze`는 원본·규약·평가 코드·합성 테스트의 SHA-256과 라이브러리 버전을 기록하고 기존 산출물을 덮어쓰지 않는다. `select`는 모두 다시 확인한 후 학습·검증만 읽어 예측과 지표를 새 `selection/` 디렉터리에 원자적으로 저장한다. 실행 전에 코드와 규약의 독립 검토를 마친다. 현재 문서 작성 시점에는 이 과제의 **학습기 예측 점수는 계산하지 않았다**.
