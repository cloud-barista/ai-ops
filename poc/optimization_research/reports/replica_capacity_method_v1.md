# 현재 응용 계측을 이용한 GPU 복제 용량 예측: 연구 방법 후보

## 목적과 방법

첫 방법이 **배포 전** 적은 기준 측정으로 여러 CPU/GPU 형상을 평가한다면, 이 방법은 응용의 **현재 GPU 1개·CPU 2코어 벤치마크**가 이미 실행된 뒤 동일 호스트에서 GPU 2개·CPU 2코어 복제의 처리 용량을 예측한다. 이는 경희대의 재형상화 판단에 들어갈 성능 신호다. 실제 VM Scale-out action의 성공·전환 비용·온라인 요청 지연을 예측하는 모델은 아니다.

작업 조건 `c`와 현재 실행의 요청 처리율 `R₁`을 입력으로, GPU 2개 복제본의 합산 요청 처리율을 `log R̂₂ = log R₁ + log 2 + h(c, log R₁, log L₁, t₁)`로 예측한다. `h`는 과거 모델의 GPU1/GPU2 짝 측정에서 GPU 2배 기준을 벗어나는 상대 반응을 학습한 ExtraTrees 예측기다. `t₁`은 **GPU1 벤치마크 실행 행에서 수집한 노드 전체의 계측 요약**이다. GPU 사용률 평균·최댓값과 GPU 메모리 사용량 최댓값은 수집기가 노드의 모든 GPU 샘플에서 계산하고, CPU 사용률 평균은 노드 단위다. 따라서 특정 복제 프로세스만의 사용률은 아니다. 각 값을 `log1p` 변환한다. 비교 기준선은 같은 현재 실행의 성능과 작업 정보만 쓰며 `t₁`을 쓰지 않는다. 샘플 수는 실행 시간의 대리변수일 수 있어 주 방법에서 제외한다. 지연 예측에는 계측의 일관된 이점이 없어 기준 모델을 유지한다.

처리량은 원본의 `examples_per_second`를 `batch_size`로 나눈 **요청/초**로 학습·평가한다. GPU 2개 실행은 각 GPU 프로세스가 같은 전체 입력 프로파일을 실행한 뒤 처리율을 합친 기록이므로, `R₂`는 두 복제본의 **벤치마크 합산 용량**이다. 같은 총 요청을 분할해 처리한 속도 향상이나 VM 두 대의 온라인 처리량이 아니다. [수집 프로토콜 검증](replica_benchmark_semantics.md)

## 확인된 예측 이점

주 캠페인 9모델을 하나씩 완전히 제외해 이전 모델로만 학습했다. 대상 모델에서는 같은 작업의 GPU1 성능과 계측만 예측 입력으로 허용했고 GPU2 결과는 점수 계산에만 사용했다. 아래는 GPU2 요청/초의 모델별 평균 절대 로그오차(MALE)이다. 낮을수록 좋다.

| 평가 조건 | 현재 성능만 사용 | 현재 성능 + 계측 4개 | 해석 |
| --- | ---: | ---: | --- |
| 주 캠페인 575작업 | 0.1120 | **0.0961** | 9모델 중 8모델 개선 |
| 새 space-filling 44작업 | 0.1707 | **0.1251** | 9모델 중 8모델 개선 |
| 새 novel-matrix 18작업 | 0.1193 | **0.1152** | 차이가 작고 불확실 |

기준선과 제안법은 모두 평가할 각 작업의 GPU1 실행 **한 번씩**을 입력으로 쓴다. 주 캠페인 575회는 합계 **532.705 GPU-wall초**, 모델당 평균 **59.19초**였고, novel 18회와 space 44회는 각각 **17.634초**, **36.487초**였다. 계측 기록 자체의 추가 비용은 자료에 없다. 따라서 배포 전 8회 기준 측정 방법의 비용과 직접 같은 예산으로 비교하지 않는다. 주 캠페인의 GPU1 실행별 `running` 계측 샘플은 중앙값 4개이며 **575회 중 285회는 3개 이하**였다. 순간 사용률의 안정된 추정으로 해석하기 어렵다.

작업 간에 계측 벡터 전체를 32가지 시드로 재배치하면 주 캠페인 오차 평균은 `0.1167`이 된다. 배치 크기가 같은 작업끼리만 바꿔도 `0.1094`다. 원래 작업과 맞는 계측의 `0.0961`보다 모두 커져, 단순한 배치 크기 또는 계측 주변분포 이상으로 **작업별 대응 관계에 예측 정보가 있다**는 내부 근거를 준다. [모델별 학습 결과](telemetry_conditioned_scaling_findings.md), [순열 대조](telemetry_permutation_control_findings.md)

## 적용 경계와 방법상의 차이

현재 실행의 계측을 사용해 다음 형상의 용량을 예측하는 원리는 [MLscale](https://research.ibm.com/publications/using-machine-learning-for-black-box-autoscaling) 같은 연구가 선행한다. 여기의 제한된 차이는 **GPU 1개 실측 처리율의 2배를 기준으로 하는 상대 반응**, AI 응용의 batch·길이·동시성, 현재 복제본의 GPU/CPU 계측을 결합해 **같은 호스트의 GPU 복제 용량**을 예측하고, 대응 관계 순열로 계측의 정보 기여를 확인한 구체적인 구성이다. 이 정도의 방법·검증 조합상의 기여로 취급하며 새로운 오토스케일링 원리라고 주장하지 않는다.

예측 오차 감소가 곧 Scale-out 승인 개선은 아니다. donor 기반 25개 가상 목표에서 주 encoder의 기준 모델과 **제안한 샘플 수 제외 방식**은 성공/잘못 승인 **1,959/349 대 1,948/330**으로 상충했다. Novel 조건은 **69/5 대 74/6**, space-filling은 **148/22 대 152/27**로 성공과 오승인이 함께 늘었다. BERT 네 모델을 한꺼번에 제외하면 주 캠페인의 계측 처리량 이점은 `0.0952→0.0959`로 사라지고 novel 조건도 `0.0878→0.0889`로 악화된다. [정적 판단](telemetry_conditioned_scaling_findings.md), [계열 제외](telemetry_family_holdout_findings.md)

따라서 이 후보의 **확인된 사용처는 현재 실행 행의 노드 계측으로 같은 호스트 GPU2 합산 처리 용량을 연구용으로 추정하는 것**까지다. 노드 전체의 GPU 지표에는 다른 GPU의 활동도 섞일 수 있으며, 개별 프로세스의 병목을 식별하지 못한다. 단일 호스트, 제한된 AI 모델, 배치 p95, 생성 SLO 자료이므로 노드 수·VM 생성, Scale-in 안정성, 전환 시간, 실제 서비스 SLO를 판단하지 않는다. 이노그리드가 제공할 사전 모니터링 규격과 ETRI의 VM 결과 데이터가 확보될 때에만 동적 행동 판단으로 확장한다.
