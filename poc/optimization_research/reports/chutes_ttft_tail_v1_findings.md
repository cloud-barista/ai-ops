# Chutes의 인스턴스·캐시 기반 첫 토큰 지연 예측: 검증 미채택

2026-09-29. **인스턴스 부하 분포와 캐시 관측을 추가한 모델은 검증에서 미채택했다.** 모델별 다음 5분 TTFT p90 오차가 기본 학습기보다 1.6% 높고, 개선된 평가 모델은 19개 중 8개뿐이다. 사전에 정한 5% 개선·모델 과반 문턱을 모두 넘지 못했으므로 **시험 row group 74–76은 받거나 열지 않았다.** 이는 실제 `SCALE_OUT/IN` 조치 평가가 아니라 관측 TTFT 위험 입력의 실험이다.

## 고정한 자료와 정보 경계

[공식 Harvard MadSys/Chutes 데이터 카드](https://huggingface.co/datasets/harvardMadsys/chutes_metadata) revision `85722e694bf7bb8a5a5ccdf70424fa5998372467`의 45개 샤드 중 `train-00044-of-00045.parquet` 한 파일, 그 안의 연속 **row group 65–73**에서 필요한 10열만 읽었다. 기존 개발 표본 65는 이미 관찰한 자료이고, 새로 추출한 66–73은 검증용 마지막 73까지다. 원본 파일의 고정 크기 2,046,207,562 bytes와 Hugging Face 연결 SHA-256 `ca99b91b33d04bf56f3d0b26241c4a083a7e1579f0f571887eee4ee1004c90dd`를 확인했다. 새 추출 파일의 개별 SHA-256은 [`extracted_sha256.json`](../artifacts/chutes_ttft_tail_v1/extracted_sha256.json)에 있다. 이 추적의 시각은 저자가 정규화한 **상대 시각**이며 실제 날짜가 아니다. 라이선스는 CC BY 4.0이다.

[점수 전 규약](chutes_ttft_tail_v1_protocol.md), [평가 코드](../scripts/evaluate_chutes_ttft_tail_v1.py), [6개 인과·경계 검사](../tests/test_evaluate_chutes_ttft_tail_v1.py)의 해시는 row group 66–73 요청 값을 읽기 전 [`frozen_manifest.json`](../artifacts/chutes_ttft_tail_v1/frozen_manifest.json)에 고정했다. 원본 ID의 65–73 전체 중복, 전체 시작시각 정렬, 분할의 5분 창 포함, 출처 및 추출 해시를 검사했다. 결정 시각 `t`의 인스턴스 분포·캐시·TTFT는 **`t` 이전에 완료된 요청**만 썼다. 원본에는 인스턴스 배정이 언제 알려졌는지 없어서 시작만 한 요청의 최종 `instance_id`는 입력에서 제외했다. 학습·검증의 정답은 창 종료 뒤 60분 내 완료된 요청만 사용했으며 각각 적합·검증 게이트 전까지 완료되도록 시간 여유를 뒀다.

## 지원량과 점수

등록 모델 35개는 학습 구간의 **과거 적격 결정**과 유효한 미래 정답 창만으로 고정했다. 과거 30분에 완료된 유효 TTFT가 100개 이상일 때만 예측 대상으로 삼았다. 미래 유효 TTFT가 100개 이상인지는 **온라인 선택에 쓰지 않고** 경험적 p90을 안정적으로 채점할 오프라인 층을 정의하는 데에만 썼다. 따라서 아래 점수는 미래에 충분한 유효 TTFT가 기록된 창에 조건부다.

| 지원량 | 학습 | 검증 |
| --- | ---: | ---: |
| 등록 모델 × 모든 5분 결정 격자 | 4,620 | 1,925 |
| 과거 정보만으로 적격 | 3,602 (78.0%) | 1,379 (71.6%) |
| 과거 적격이고 미래 TTFT ≥100인 채점 창 | 2,483 (53.7% of grid) | 969 (50.3% of grid) |
| 검증에서 고정한 평가 모델·주 지표 창 | — | 19개 모델·908개 창 |
| 과거 입력의 유효 캐시 기록 ≥90%인 적격 창 | 100% | 100% |

검증의 주 점수는 19개 평가 모델 각각의 `|log(예측 p90 / 관측 p90)|` 평균을 다시 균등 평균한 MALE이다. 낮을수록 좋다. 두 학습기는 같은 학습 행·모델 균등 가중치·고정 HGB 설정을 사용했다. [`validation.json`](../artifacts/chutes_ttft_tail_v1/validation.json)에 모델별·행 전체·시간 블록 점수가 모두 있다.

| 방법 | 모델 균등 MALE | 행 전체 MALE |
| --- | ---: | ---: |
| 직전 5분 완료 TTFT p90, 표본 부족 시 30분 대체 | 0.25915 | 0.25990 |
| 과거 30분 완료 TTFT p90 | 0.32404 | 0.32755 |
| **기본 학습기:** 모델·도착량·완료량·토큰·과거 TTFT | **0.25416** | **0.25731** |
| **후보:** 기본 학습기 + 완료된 요청의 인스턴스 분포·캐시 | 0.25827 | 0.26184 |

후보는 기본 학습기보다 모델 균등 MALE이 **1.62% 높다**. 직전 5분 기준선보다는 약 0.34% 낮지만 사전 기준인 5%에 못 미친다. 후보가 기본 학습기보다 나은 모델은 **8/19개(42.1%)**, 충분한 1시간 블록은 **1/5개**였다. 검증 게이트는 세 기준선 *모두*보다 5% 이상 낮은 오차와 평가 모델의 60% 이상 개선을 요구했다. 두 조건 모두 실패했다. 검증 결과를 보고 특징이나 하이퍼파라미터를 바꾸지 않았으며, `fetch --through 76`은 코드가 검증 실패를 읽고 거부하는 것까지 확인했다. `rg074`–`rg076` 파일과 `test.json`은 없다.

## 정답 기록의 결측과 해석

사후 **설명용** 감사 [`validation_quality.json`](../artifacts/chutes_ttft_tail_v1/validation_quality.json)은 검증 전 고정 코드를 바꾸지 않고, 같은 등록 모델의 스트리밍 시작을 서로 배타적인 사유로 분류했다. [재현 스크립트](../scripts/audit_chutes_ttft_validation_quality.py)가 고정 결과의 정답 건수와 정확히 일치하는지 검사한다.

| 스트리밍 요청 분류 | 학습 | 검증 |
| --- | ---: | ---: |
| 시작 요청 전체 | 2,623,340 | 1,164,833 |
| TTFT 없음·유한하지 않음 | 470,691 | 448,064 |
| TTFT > 요청 완료 소요시간+1ms | 31,263 | 10,370 |
| 완료시간 부재·비양수 소요시간 | 0 | 0 |
| 창 종료 60분 뒤 완료 | 0 | 0 |
| 유효 정답 | 2,121,386 (80.9%) | 706,399 (60.6%) |

모델별 유효 비율 중앙값은 학습 **97.7%**, 검증 **약 97.0%**였지만, 검증에서 한 고빈도 모델은 349,303개 시작 중 77,012개(22.0%)만 유효했다. 이 모델의 TTFT 결측 270,601개가 검증 전체 결측 448,064개의 **60.4%**를 차지했다. 결측이 실패·중단·수집 지연 중 무엇인지 원본에는 없다. 따라서 정답은 실제 사용자 요청 전체의 첫 토큰 SLO가 아니다. 검증 평가 창 908개 중 **250개는 지난 30분에 완료된 요청의 관측 인스턴스가 1개뿐**이었고, 19개 평가 모델 중 7개는 이 인스턴스 수가 검증 창 동안 바뀌지 않았다. 추가 인스턴스 특징이 항상 구별되는 신호를 준다고 보기도 어렵다. 이 분포는 실패를 설명하는 관찰이며 원인을 식별한 결과는 아니다.

## 적용 결정과 재현

이 구간에서 모델별 TTFT p90을 예측할 때는 **기본 학습기보다 복잡한 인스턴스·캐시 후보를 채택하지 않는다**. 기본 학습기의 검증 이득도 한 서비스의 정규화된 약 하루 범위와 미래 지원량 조건에 한정된다. `instance_id`는 요청이 간 서빙 인스턴스이고 유휴 인스턴스·VM 준비·실제 GPU 구성·스케일 명령을 나타내지 않는다. 이 자료만으로 경희대의 `DEPLOY/UPDATE/SCALE_OUT/SCALE_IN/KEEP` 조치나 노드 수의 정답을 학습했다고 주장하지 않는다.

```bash
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python -m unittest discover -s tests -p 'test_evaluate_chutes_ttft_tail_v1.py' -v
python scripts/evaluate_chutes_ttft_tail_v1.py fetch --through 73
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python scripts/evaluate_chutes_ttft_tail_v1.py validate
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python scripts/audit_chutes_ttft_validation_quality.py
```

규약은 검증 실패 시 시험 원본을 열지 않도록 요구한다. 새 가설을 시험하려면 새 자료·별도 보류 기간과 새 점수 전 규약이 필요하다.
