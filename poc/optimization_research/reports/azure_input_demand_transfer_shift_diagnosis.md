# Azure 입력 수요 모델의 서비스 전이 실패: 사후 진단

이 문서는 [Coding 후향 평가](azure_code_input_demand_findings.md)와 [Conversation 독립 이전 시험](azure_input_demand_cross_service_findings_v1_1.md)이 끝난 뒤 작성한 **설명용 진단**이다. 이미 공개된 Conversation 정답을 사용하므로 여기서 선택한 보정법을 독립 검증 성과로 볼 수 없다.

저장된 Coding 90분위 모델의 5분 예측을 직전 1시간 평균 입력 토큰 수로 나누어 비교했다. 원본 SHA-256을 검사하고 두 서비스를 같은 5분 규칙으로 다시 집계하는 [재현 코드](../scripts/diagnose_azure_input_demand_transfer_shift.py)와 [수치 JSON](../artifacts/azure_input_demand_transfer_shift_diagnosis_v1/summary.json)을 남겼다.

| 구간 | 적격 5분창 | 실제 `다음 5분/직전 1시간 평균`의 90분위 | 모델 예측 비율 중앙값 | 피복률 |
| --- | ---: | ---: | ---: | ---: |
| Coding 학습 | 852 | 1.231 | 1.130 | 88.50% |
| Coding 후향 평가 | 864 | 1.237 | 1.142 | 93.17% |
| Conversation 이전 시험 | 1,440 | 1.100 | 1.153 | 97.85% |

Conversation 표본의 상대 수요 변동폭이 Coding보다 좁은 반면, 고정 모델이 내는 비율은 Coding 평가와 비슷하거나 높다. 이것은 Conversation에서 모델이 90분위 예측을 과하게 덮고 손실이 늘어난 현상과 **일치한다**. 차이를 만든 원인을 따로 분리하거나 다른 서비스의 분포를 예측한 증거는 아니다.

추가로 이미 공개된 Conversation 정답에서 직전 완료 하루의 `실제/예측` 비율을 이용해 다음 날 예측에 곱하는 보정을 탐색했다. 이 시간 순서는 미래 값을 직접 읽지 않지만, **Conversation 실패를 본 뒤 보정법을 선택**했다. 보정 HGB의 5일 평균 pinball은 약 279,934이고, 같은 보정을 적용한 가장 강한 단순 기준선인 최근 1시간 90분위는 약 292,685다. 상대 개선은 **4.36%**로 기존 5% 기준에 못 미친다. HGB는 5월 16일 피복률 **84.38%**로 기존 85% 하한에도 못 미친다. 이 탐색 수치는 독립 시험 결과 파일에 반영하지 않는다.

**결정:** 기존 Coding 모델의 무보정 전이는 NO-GO 그대로다. 하루 보정은 새 독립 서비스와 동일하게 보정한 단순 기준선을 포함한 평가를 사전 고정한 뒤에야 다시 시험할 수 있다. 어느 수치도 전체 서비스 유입량, GPU 수요, 실제 VM 배포·스케일 조치의 효과를 나타내지 않는다.
