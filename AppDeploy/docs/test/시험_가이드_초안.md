# 시험 가이드

## 자동 검증

```powershell
$env:GOCACHE = ".\\.gocache"
go test ./...
go vet ./...
```

필요하면 로컬 E2E만 다시 실행한다.

```powershell
go test ./internal/server -run TestLocalRuntimeAPIEndToEnd -count=1 -v
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\local-demo.ps1
```

## 핵심 시나리오

| 시나리오 | 검증 내용 |
| --- | --- |
| App 등록 | Spec 검증, 중복 검사, 원본 JSON 보존 |
| Local placement | READY 필터, 자원/GPU/label/runtime 검사, 비용·동률 규칙 |
| 동시 배포 | 예약 원자성 및 자원 부족 오류 |
| Local runtime | 실제 프로세스 실행, PID, stdout/stderr, 상태, stop |
| 상태/로그 | RUNNING, COMPLETED, RUNTIME_FAILED, STOPPING, STOPPED |
| ETRI 설정 | Provider 선택, endpoint 누락 오류, local fallback 금지 |

## 수동 API 확인

```powershell
Invoke-RestMethod http://localhost:8080/api/v1/healthz
Invoke-RestMethod http://localhost:8080/api/v1/target-profiles
Invoke-RestMethod http://localhost:8080/openapi.yaml
```

실제 ETRI API와 원격 VM 인증은 계약·접속정보가 제공될 때 별도 통합시험으로
검증한다. 현재 테스트는 Mock과 로컬 프로세스 경로를 사용한다.
