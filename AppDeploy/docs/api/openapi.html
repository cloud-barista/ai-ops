Credentials

프로세스 메모리 전용 SSH Credential을 등록·조회·삭제한다. Secret은 응답, 로그, 영속 저장소에 노출하지 않는다.

Register an in-memory SSH credential

SSH Credential과 신뢰 가능한 경로에서 확인한 OpenSSH SHA256 host key fingerprint를 프로세스 메모리에 등록하고 cred://runtime/{credential_id} 참조를 반환한다. SSH 연결은 이 fingerprint와 일치하는 서버만 허용한다. Secret은 응답, 로그, 일반 파일 저장소에 기록하지 않으며 서버 재시작 시 등록 정보가 소멸한다. 기본적으로 TCP peer와 HTTP Host가 모두 loopback인 요청만 허용하고, Origin이 있으면 Host와 같은 origin이어야 한다. AIAPP_CREDENTIAL_API_ALLOW_REMOTE=true를 명시한 경우에만 원격 peer/Host를 허용하며, 운영 환경의 원격 사용은 TLS와 인증을 적용한 reverse proxy를 전제로 한다. POST 본문은 application/json만 허용한다.

Delete an in-memory SSH credential

지정한 cred://runtime/{credential_id} Credential을 프로세스 메모리에서 삭제한다. Target Profile의 참조 여부와 관계없이 Profile과 독립적으로 삭제할 수 있다. Target Profile 삭제도 Runtime Credential을 연쇄 삭제하지 않는다. 삭제 후 SSH Runner를 사용하는 다음 실제 VM 연결은 Credential 누락으로 실패한다. dry-run은 원격 연결이나 Credential 해석을 수행하지 않는다. 환경변수 기반 Credential에는 영향을 주지 않는다.

Artifacts

서버 프리셋 또는 업로드한 소스를 배포 가능한 package artifact로 생성한다.

Build a package artifact from a preset or uploaded source

JSON 요청은 서버에 설정된 ai-ops-geon 프리셋을 Linux amd64 tar.gz package로 생성한다. multipart 요청은 Go, Python, Node.js, Linux binary, Shell script 유형의 소스 ZIP 또는 단일 파일을 업로드해 package로 생성한다. 임의의 서버 소스 경로나 build command는 받지 않고 유형별 고정 build/entrypoint 규칙만 사용한다. 응답의 artifact_uri와 app_spec은 Web, CLI, Shell client에서 App 등록 또는 POST /apps에 바로 사용할 수 있다. Package 기반 배포 client는 응답의 app_spec 등록과 Target resource check를 조합하고, check status가 available일 때만 deployment를 생성한다.

Profiles

Runtime Profile과 Target Profile을 등록·조회·삭제한다. 삭제 시 STOPPED가 아닌 Deployment 참조를 보호하고 보존 이력은 유지한다.

Register Runtime Profile

배포 실행 방식과 Runtime Adapter를 정의하는 Runtime Profile을 등록한다. CPU VM은 cpu/cpu_vm, GPU VM은 gpu/gpu_vm, AI-Infra 연동 준비는 aiinfra/etri_aiinfra 조합을 사용한다.

Create deployment

배포 요청은 app_version_id, target_profile_id 조합으로 보낸다. Runtime Profile은 제거되었으며, 레거시 runtime_profile_id가 포함되어도 실행에는 사용하지 않는다. 실행 방식과 Adapter는 Target Profile의 runtime 설정에서 결정한다. 서버는 이 요청을 DeploymentManifest로 정규화하고, 이후 검증·매칭·Runtime Adapter 호출은 해당 Manifest를 기준으로 처리한다.
