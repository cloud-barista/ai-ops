    Runtime 종류mockProfile IDrt-mock-001Adaptermock운영 모드local_mock

    같은 화면의 Target Profiles에서 추가를 누릅니다.

02
실제 VM · SSH Credential 필요

CPU VM에 애플리케이션 배포

로컬 script Artifact를 SSH로 업로드하고 대상 VM에서 프로세스로 실행합니다.

⌄

  1. 웹에서 Credential 등록

    의 SSH Credentials에서 cpu-vm-001, SSH 사용자, 신뢰된 경로에서 확인한 host key fingerprint와 private key 파일을 등록한 뒤 발급된 cred://runtime/cpu-vm-001을 Target에서 선택합니다. 이 Secret은 프로세스 메모리 전용이므로 서버를 재시작하면 사라집니다.

    재시작 후에도 같은 설정을 다시 쓰려면 아래 환경변수 방식을 fallback으로 사용할 수 있습니다. 실제 키 경로로 바꾼 후 같은 PowerShell에서 서버를 실행하고 Target에는 cred://local/cpu-vm-001을 입력합니다.

    $env:AIAPP_CPUVM_RUNNER = "ssh"
$env:AIAPP_CREDENTIAL_CRED_LOCAL_CPU_VM_001_SSH_USER = "ubuntu"
$env:AIAPP_CREDENTIAL_CRED_LOCAL_CPU_VM_001_SSH_KEY_PATH = "C:\secure\cpu-vm.pem"
$env:AIAPP_CREDENTIAL_CRED_LOCAL_CPU_VM_001_SSH_HOST_KEY_FINGERPRINT = "SHA256:<신뢰된-base64-fingerprint>"
$env:AIAPP_CREDENTIAL_CRED_LOCAL_CPU_VM_001_SSH_TIMEOUT = "30s"
go run ./cmd/web

    Secret은 전용 Credential 등록 폼 또는 로컬 환경변수로만 전달하고 Target, 일반 JSON, 로그, Git에는 넣지 마세요.

  2. CPU App 등록

    RuntimecpuArtifact 종류scriptArtifact URIfile:///C:/work/my-app/run.sh실행 명령 / 인자bash / run.sh --port=18080GPU / 서비스 포트0 / 18080

    URI는 웹 서버가 실행되는 컴퓨터에 실제로 존재하는 파일이어야 합니다.

  3. CPU Runtime과 Target 등록

    Runtime ID / 종류rt-cpu-001 / cpuAdapter / 모드cpu_vm / vm_processTarget ID / 종류target-cpu-001 / cpuCSP / Host / SSHlocal / VM 주소 / 22Credential refcred://runtime/cpu-vm-001 (ENV fallback: cred://local/cpu-vm-001)Artifact / Log 경로/tmp/aiapp/artifacts / /tmp/aiapp/logs

  4. 자원 점검

    Target을 점검해 available인지 확인합니다. 실패하면 먼저 VM 주소, SSH 사용자·키, 방화벽, 디렉터리 권한을 확인합니다.

  5. 배포·Health·추론·중지

    배포가 RUNNING이 되면 에서 Health를 확인합니다. 앱이 제공하는 경로(예: /predict)와 JSON Body로 호출하고, 완료 후 배포 화면에서 중지합니다.

    예상 결과: Health HTTP 200, 추론 응답 표시, 중지 후 STOPPED.

03
NVIDIA GPU · 드라이버 필요

GPU VM에 모델 서버 배포 및 추론

GPU readiness를 확인하고 모델 서버를 실행한 뒤 추론 결과와 성능 메트릭을 기록합니다.

⌄

  1. GPU와 Credential 사전 확인

    대상 VM에서 nvidia-smi가 성공해야 합니다. 의 SSH Credentials에서 gpu-vm-001, 신뢰된 경로에서 확인한 host key fingerprint를 함께 등록하고 Target에는 발급된 cred://runtime/gpu-vm-001을 선택합니다. 메모리 전용 Secret은 서버 재시작 시 사라집니다.

    재시작 후에도 재사용할 fallback이 필요하면 아래 환경변수를 설정한 같은 PowerShell에서 서버를 실행하고 cred://local/gpu-vm-001을 사용합니다.

    $env:AIAPP_GPUVM_RUNNER = "ssh"
$env:AIAPP_CREDENTIAL_CRED_LOCAL_GPU_VM_001_SSH_USER = "ubuntu"
$env:AIAPP_CREDENTIAL_CRED_LOCAL_GPU_VM_001_SSH_KEY_PATH = "C:\secure\gpu-vm.pem"
$env:AIAPP_CREDENTIAL_CRED_LOCAL_GPU_VM_001_SSH_HOST_KEY_FINGERPRINT = "SHA256:<신뢰된-base64-fingerprint>"
$env:AIAPP_CREDENTIAL_CRED_LOCAL_GPU_VM_001_SSH_TIMEOUT = "60s"
go run ./cmd/web

  2. GPU App 등록

    Runtime / GPUgpu / 1Artifact URIfile:///C:/work/model-server/run.sh실행 명령bash실행 인자run.sh --port=18081서비스 포트18081권장 요구량 예시CPU 4 / Memory 16Gi / Storage 20Gi

  3. GPU Runtime과 Target 등록

    Runtimegpu / gpu_vm / vm_processTarget 종류gpuCredential refcred://runtime/gpu-vm-001 (ENV fallback: cred://local/gpu-vm-001)GPU 설정NVIDIA / count 1 / driver required

    웹 화면에서 Target 종류를 gpu로 선택하면 NVIDIA GPU 설정이 자동으로 포함됩니다.

  4. Readiness 후 배포

    자원 점검 결과의 GPU와 Runtime이 모두 available인지 확인한 후 배포합니다. 모델 다운로드나 초기 로딩 때문에 CPU App보다 오래 걸릴 수 있습니다.

    예상 결과: 로그에 gpu-vm-adapter가 기록되고 최종 상태가 RUNNING.

  5. 추론 및 메트릭 기록

    Health를 먼저 확인하고 모델 서버 경로(예: /generate)를 POST로 호출합니다. 호출 시간은 Monitoring의 메트릭 기록에 latency_ms, throughput_rps로 남깁니다.

  6. 중지 및 GPU 확인

    배포를 중지해 STOPPED를 확인하고, 필요하면 VM에서 해당 프로세스와 GPU 메모리가 해제됐는지 확인합니다.
